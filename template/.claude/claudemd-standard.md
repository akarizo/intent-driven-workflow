# CLAUDE.md 层级规范（claudemd-standard）

> 规范驱动 · 适用本模板安装的任意仓库。项目根 `CLAUDE.md` 中由 `CLAUDE.md.snippet` 注入的「CLAUDE.md 层级规范」段是本文件 TL;DR；本文件是权威全文，`/claudemd-sync` 与 `/claudemd-distill` 以它为硬约束基线（取代两命令历史引用、装机后并不存在的 `template/CLAUDE.md.snippet`）。
>
> 本文件随模板 `install.sh --upgrade` 刷新；想演进规范改这里。

## 0. 四大不变量（总纲）

1. **单一真相**：一条事实只存在于一个层级的一处（LCA 放置 + 去重）。
2. **指针优先**：有正式归宿（ADR/openspec/backlog/代码/测试）的知识只留一行指针，不内联。
3. **结构固定、排版密集**：段骨架稳定 + 一事一行 → diff 局部化、人可一眼 review、token 经济。
4. **预算中性**：CLAUDE.md 是**无条件前置进每次请求**的 system prompt 片段 —— 成本无条件、收益有条件。故写入必须**加一行就减一行**（§12），加法与减法在同一个动作里完成，禁「先攒着、以后再压」。

> **成本模型（本规范的全部推论都从这条来）**：
> `EV(一条) = P(本会话命中) × P(不写就会做错) × 代价(做错) − size × 全部会话数`
> 分子是三个 <1 的概率连乘，分母是无条件常数 → **只有「高频 × 必错 × 高代价」三者同时成立才为正**。「有点用」不够格。

## 1. 目的与适用范围

- **目的**：让任意层级 CLAUDE.md 的内容「精确归位、可被人 review、经得住 churn」。
- **适用**：单仓与 monorepo 通用；从全局 `~/.claude/CLAUDE.md` 到模块叶子 `<dir>/CLAUDE.md` 全层级。
- **不管什么**：本规范只管 CLAUDE.md「放什么、放哪、怎么排」；不裁决具体业务约束的对错。

## 2. 层级模型 + LCA 放置铁律

层级（高 → 低）：

```
🌐 ~/.claude/CLAUDE.md      对所有仓库为真：全局开发原则、命令执行纪律、通用工具用法
📦 <repo>/CLAUDE.md          跨子项目共享：边界划分、部署矩阵、CI、跨切面契约
   <repo>/<sub>/CLAUDE.md    单子项目 / 边界上下文：该 tier 的约束 / 架构 / 契约
      <sub>/<mod>/CLAUDE.md  单模块 / 子包叶子：模块内隐性知识
```

**LCA 铁律**：设一条事实为真的单元集合为 S，写在 S 的**最低公共祖先**层级，且只写一处。

- 决策动作：「这条对哪些单元为真？」→ 列 S → 取 LCA。
- **去重**：父层已含 → 子层禁重复；子层要强调只写 `详 ../CLAUDE.md`。
- **下沉**：某段在父层只服务单个子单元且已膨胀 → 下沉到该子单元文件，父层留指针。

| 事实示例 | 对谁为真 | 正确落点 |
|---|---|---|
| 全局命令执行纪律（禁某危险用法） | 所有仓库 | 🌐 global |
| image 仓名与源码目录解耦的约定 | 本仓所有子项目 | 📦 仓库根 |
| 某子项目专属的 DB / 框架约束 | 仅该子项目 | `<sub>/CLAUDE.md` |
| 某模块入口的加载顺序铁律 | 仅该模块 | 模块叶子 |
| 跨「后端 + 部署」的网络约束 | 两个子项目 | 📦 仓库根（两者 LCA） |

## 3. 头部三件套契约（每层强制，叶子不豁免）

每个 CLAUDE.md 前三块固定：

1. **标题**：`# <单元名> · Claude 记忆[（tier）]`，tier 如 backend/web/chart/模块名。
2. **scope 引用块**（`>` 起，1–3 行）：① monorepo 相对路径 + 部署物/依赖位置；② ↑父指针 `../CLAUDE.md`；③ ↔兄弟指针；④ ↓子指针（有子文件时）；⑤ 相关 ADR。
3. **一句话定位**：单元是什么 + 关键技术栈 / 角色。

> 叶子层即使内容极薄，scope 引用块也**至少**写明 ↑父指针 —— 保证从任意深度可向上导航。

## 4. 固定骨架模板

```
# <单元名> · Claude 记忆[（tier 如 backend/web/chart）]

> <monorepo 相对路径>；<部署物/依赖位置>。↑父见 `../CLAUDE.md`；↔兄弟见 `../sibling/CLAUDE.md`；↓子见 `sub/CLAUDE.md`；相关 ADR-000X。
<一句话：这个单元是什么 + 关键技术栈/角色>

## 核心约束          # 违反即出事故的铁律；无则省略此段
## 架构              # 依赖图 / 数据流 / 关键结构事实
## 入口              # console_script / 公共 API + 一句话职责
## 契约              # 对外接口的破坏性边界（OpenAPI / schema）
## 构建 / 测试       # 跑 check/test 的真命令 + CI 触发条件
## 部署              # 镜像名 / chart 行为 / env 注入（独立部署单元才有）
## <领域段 A>        # ◄── 自由扩展区：业务陷阱 / 协议怪癖 / 历史遗留
## <领域段 B>
## 已废弃 / 禁用      # 别做什么 + 为何 + 取代者
## 表达约定          # "跑 X" = "<真命令>" 词典
## Backlog           # 指向 backlog 文件名，不内联正文
```

规则：

- 段**按上顺序**出现；用到哪段留哪段，未用直接省（不留空段）。
- 固定槽段名**不可改名**（保 routing 与 diff 稳定）；领域段名自由。

## 5. 固定段目录权威表

> sync「追加到最相关章节」的权威依据：先按此表定段，再落行。

| 段 | 性质 | 放什么 | 不放什么（→ 别处） | 典型行式 |
|---|---|---|---|---|
| 头部三件套 | 强制 | 标题 + scope 引用块 + 一句话定位 | 任何细节 | 见 §3 |
| 核心约束 | 固定槽 | 违反即出 bug/事故的铁律 | 一般约定 → 表达约定 | `- **<点题>**：<铁律> — <为何/拦截手段>` |
| 架构 | 固定槽 | 依赖图、数据流、单例/中间件结构 | 逐文件清单（代码自解释） | 代码块画依赖图/数据流 |
| 入口 | 固定槽 | CLI / console_script / 公共 API + 职责 | 实现细节 | `- \`cmd\` —— 一句话职责` |
| 契约 | 固定槽 | OpenAPI/schema 破坏性边界、跨服务字段约定 | 完整字段表 → spec/openapi | `- <字段> nullable→required = 破坏性（ADR-000X）` |
| 构建/测试 | 固定槽 | 跑 check/test 真命令、CI 触发 | 通用工具用法 | `- "跑 check" = \`<cmd>\`` |
| 部署 | 固定槽 | 镜像名、chart 行为、env 注入 | 集群级矩阵 → 仓库根 | 表格 |
| 〈领域段〉 | 自由扩展 | 业务陷阱、协议怪癖、历史遗留（带指针/日期） | 能上推父层的共享事实 | `- **<怪癖>**：… \`file:line\`（YYYY-MM-DD）` |
| 已废弃/禁用 | 固定槽 | 别做什么 + 为何 + 取代者 | 还在用的东西 | `- 旧 X 已废，用 Y 取代（原因）` |
| 表达约定 | 固定槽 | "跑 X" = "<命令>" 高频词典 | 一次性命令 | `- "看前端" = \`<cmd>\`` |
| Backlog | 固定收尾 | 指向 backlog 文件名 | 待办正文 | `<相对路径>/backlog/<file>.md` |

## 6. 自由扩展区规则

- **位置**：固定在「部署」之后、「已废弃/禁用」之前。
- **命名**：用业务词（如 `登录鉴权`、`某协议解析`），可带 `（ADR-000X）`/日期后缀。
- **排序**：自由；建议越核心 / 越常踩坑越靠前。
- **下沉判据**：领域段 > ~25 行且只服务单文件/单模块 → 抽到更低层 CLAUDE.md 或专门 doc，本段留一句话 + 指针。

## 6b. 模块/叶子级 carve-out（两支柱·覆盖 §3–§5）

模块/叶子离代码最近、内容门槛最高 → **不套 §5 固定段目录**；改用两支柱:

- **支柱① 导向（必配）**：`## 结构与职责`（组件/子模块 → 一句话职责,意图粒度·锚目录）+ `## 扩展点`（留了哪些 seam + 如何加新的:步骤/契约/注册点）。cx 给签名/结构,但**不给意图与扩展路径** → 这部分够格。
- **支柱② 防错**：`## 不变量 / 陷阱`（跨文件约束·时序·反直觉,每条带 `path:line`）+ `## 禁用`。

硬规则:
- **禁镜像代码**:函数签名罗列 / 调用机制复述 / `ls` 文件清单一律删或转指针(cx 即文档)。⚠ 把**易变实现机制当事实写 → 必腐**(代码一改,复述即成误导)。
- **必带锚点 + 扩展点须真实**:治理代码的每条事实带 `path:line`/`path`;**扩展 seam 写前 `grep`/Read 核验真实存在,禁臆造**(臆造扩展指导比没有更糟)。
- **单文件局部陷阱下沉代码**:写进出事点 docstring/注释(随代码走最抗腐),CLAUDE.md 至多一行指针;代码已自-documenting(命名/注释) → 直接指针、不复述。
- **头部压缩**:标题 + 一行 `>`(↑父 + 路径) + 一句话定位;不枚举 ↔兄弟↓子。
- **预算 ≤ ~40 行**;litmus:"刚读完本模块全部代码的专家,还会(搞错/不知如何扩展/找不到)吗?" 否则删。

## 7. 路由协议 6 步

```
新事实到手 →
 ⓪ 准入闸门（四问，任一 ✗ 即不入 CLAUDE.md）：
      Q1 典型会话里会命中吗?        ✗ → 进 ADR / docs，本文件至多留指针
      Q2 不写模型就会做错吗?        ✗ → 删（模型默认行为已正确）
      Q3 做错了会「静默」吗?        ✗ → 删（会报错/测试红 = 一个循环就教会了）
      Q4 能写成测试 / lint / hook 吗? ✓ → **写那个**；解释放进 assert message，
                                         本文件只留一行「防线索引」
      四问全过 → ① （这是不可归约核心：静默失败 + 无法机械拦截）
 ① 定真值范围：它对哪些单元为真?（列单元集合 S）
 ② 取 LCA 选文件：S 的最低公共祖先层级的 CLAUDE.md
 ③ 正式归宿判定：已被 ADR / openspec / backlog / 代码 / 测试 承载?
       有 → 只写一行指针、禁内联展开      无 → ④
 ④ 归段：按 §5 段目录定固定槽;领域知识 → 自由扩展区
 ⑤ 查重查矛盾：该段已有同主题条目?
       有 → 原地更新/合并、禁追加重复行;
       与既有矛盾 → 先解决（哪个对）、不并存
 ⑥ 预算闸（**同一动作内完成**）：先按 §12 算写入后字节数
       未超 → 直接写；
       超线 → **当场**从同文件删 / 指针化等量内容再写，或显式向用户申请扩预算。
       禁「先写进去，等以后跑 distill」—— 减法一旦推迟就永远滞后于加法。
```

## 8. 指针纪律

- **4 类格式**：ADR `（ADR-000X）`；代码 `path:line` 或 `path`；backlog `<相对路径>/<file>.md`；跨层 `详 <相对路径>/CLAUDE.md`。
- **禁悬空**：写指针前必须验证目标存在（`ls` / `find` / `cx`）；目标被删 → 指针同步删/改。
- **指针 > 内联**：有正式归宿时只保留「一句话摘要 + 指针」。
- **机械校验**：指针可验证性由 `claudemd-lint` 兜底（反引号内路径不存在 = fail），不靠人肉自觉。⚠ 悬空指针比没有指针更坏 —— 它先花 token 说了一遍，再要求 agent 花一次工具调用去证伪。

## 9. 排版密度规范

强制项：

- 分隔用 `·` `/` `→`；不写整段散文。
- 每个 bullet 以 `**bold 点题**：` 起头，扫读者一眼抓重点。
- 危险/反模式用 ⚠ 前缀。
- 维度矩阵（env × X、现象 × 第一刀）用**表格**。
- 依赖图 / 数据流 / 目录树用**代码块**。
- 一事一行；多条相似 → 合并成一行或一个表格行。

对照：

- ❌ 散文：「这个模块负责处理用户的登录请求，它会先验证 token，然后……」
- ✅ 密集：「**登录**：先验 token（`api/deps.py:54`）→ 命中 service-token 跳 JWT → 返 service 身份」

## 10. 日期与时效

- **必带 `（YYYY-MM-DD）`**：决策、破坏性契约变更、急救态（workaround）、废弃态。
- **不带**：稳态硬约束（如「表名前缀 `x_`」—— 不会过期）。
- 急救态额外标注 `**急救**（<backlog-id>）：…`，让它显眼、可追踪、好清理。

## 11. 排除清单 · 禁入任何 CLAUDE.md

| 禁入项 | 正确归宿 |
|---|---|
| 代码可推导的结构 / 签名 / 文件清单 | 代码本身（cx 导航） |
| git 历史、谁改了什么、commit 摘要 | git log |
| 瞬时状态、本轮任务进度、调试日志、TODO 草稿 | session / backlog / issue |
| 被纠正过的「以为如此」的猜测 | 直接删，不留痕 |
| **变更史叙述**（「此前 X、后来改成 Y、那次回退埋下 Z」） | ADR / git log —— 见下方祈使句判据 |
| **已被测试 / lint / hook 拦住的约束的完整解释** | 测试的 assert message 或 docstring（随代码走，不腐烂）；本文件只留一行「防线索引」 |

> **判据一（时效）**：一条信息若「明天看代码/git 就能重新得到」或「下周就不成立」，它不进 CLAUDE.md。
> **判据二（祈使句）**：读者是**即将动手的 agent**，不是全知的审阅者。一行若<b>不能改写成祈使句</b>（「MUST / 禁 / 先做 X 再做 Y」），只能读作「当时发生了什么」→ 它属于 ADR，不属于本文件。

## 12. 尺寸预算（**按字节，不按行**）

> ⚠ **为什么不用行数**：行数可被「行长通胀」无声架空 —— 实测某仓 12 周内行数 4.6×、字节 14.6×，行均长 104B → 330B，全程「行数合规」。**用行数管一份按 token 计费的文件，等于用件数管货运重量。**

| 层 | 硬闸门 | ≈ token | 依据 |
|---|---|---|---|
| 仓库根 | **≤ 8 KB** | ~2.5k | 每会话必付，控在 200k 窗口 1.5% 内 |
| 子项目 | **≤ 16 KB** | ~4.5k | 单次会话最多命中 1–2 个 |
| 模块叶子 | **≤ 10 KB** | ~3k | 只在触碰该目录时加载 —— 成本条件性，可比子项目宽松 |
| **单行** | 提醒 > 200 B · **拦截 > 400 B** | — | 字节预算已堵死通胀，故单行只拦真正伤 diff 局部化的巨行 |
| memory 常驻索引 | **提醒 > 28 KB** | ~8k | 只算 `MEMORY.md`；二级索引按需 recall **不计入**（否则会惩罚「下沉」这个正确行为） |
| memory 索引单行 | 提醒 > 400 B · **拦截 > 700 B** | — | 实测 p95=400 / max=882（n=218）。**刻意宽于上面的 200/400** —— 索引行要装 `❗❗` 坑位前置警告，压到 CLAUDE.md 的行长等于摘防护 |
| *（install.sh 注入段）* | *≤ 4.5 KB* | *~1.3k* | *由模板负责，**不计入**项目根预算 —— 项目作者控制不了它* |

- **换算口径**：CJK 字符 ≈ 0.9 token、ASCII ≈ 0.28 token。字节是硬数据、token 是估算，**闸门一律判字节**。
- **闸门宽严按「加载条件」定，不是拍脑袋**：根每会话必付故最紧；子项目单次会话最多命中 1–2 个；叶子只在触碰该目录时加载、且那通常意味着正在做该模块的深度工作 —— 故最宽。
- **叶子超线的第一处置是「按子目录再拆一层」**（如  溢出 → 分出 ），拆不动才谈压缩。
- **加载机制决定成本**（官方 docs `code.claude.com/docs/en/memory` 实证）：
  - **launch 时加载**：cwd 及其**所有祖先**目录的 CLAUDE.md + 裸 `@path` import（递归至多 4 跳）。
  - **按需加载**：cwd **子目录**下的 CLAUDE.md —— 「included when Claude reads files in those subdirectories」。
  - ⚠ **裸 `@` 会抵消按需加载**：`@./sub/CLAUDE.md` 把子项目内容无条件拉进 launch。子项目 / 叶子层一律禁用。
  - ⚠⚠ **反引号内的 `@` 不解析**：官方原文「Import parsing skips Markdown code spans and fenced code blocks」。`` `@./sub/CLAUDE.md` `` 是**死记号**——既不加载，又会让人误以为「已自动加载」而错估成本。**写指针就别带 `@`。**
- **超线处置**：见 §7 ⑥，**当场**减、不推迟。累积多轮后的全量大扫除才用 `/claudemd-distill`。
- distill 不该跑的时机（命令自带 guardrail）：活跃重构期 / 文件已在预算内且无冗余。
- 全部闸门由 `claudemd-lint` 机械执行（字节、行长、悬空指针、`@` 误用），不靠人肉自觉。

## 12b. 分流去向：CLAUDE.md 不是唯一的记忆载体

> 官方指引同调：「Keep it to facts Claude should hold in **every** session…… If an entry is a multi-step procedure or **only matters for one part of the codebase**, move it to a skill or a path-scoped rule instead.」

超预算时**先问「这条该不该在常驻层」**，再谈压缩。五个载体按加载条件排：

| 载体 | 何时进上下文 | 装什么 | 常驻成本 |
|---|---|---|---|
| **CLAUDE.md** | 每会话（祖先层）/ 触碰子树（子目录层） | 每会话必命中的铁律 · 表达约定 · **路由表** | 全额 |
| **`memory/`**（`~/.claude/projects/<slug>/`） | **索引每会话必付 · 正文按需 recall** | 查证得来的事实 · 踩坑根因 · 外部系统真实行为 | **一行索引**（非零！） |
| **`.claude/rules/*.md` + `paths:` frontmatter** | **仅当读到匹配 glob 的文件** | 只治理某片目录/某类文件的约束（「改 `af_rom/**` 必守的 5 条」） | 零（未命中时） |
| **Skill** | description 匹配到任务时 | 多步流程 · 深度领域契约（脚本作者面、协议怪癖） | 一行 description |
| **测试 / lint / hook** | 永远生效（不占上下文） | 一切可被断言的约束 | 零 |

- **路由表**（放 CLAUDE.md）是分流的接口：一行一条「改什么 → 先读哪里」，用 ~15 行替代几千 token 正文。
- ⚠ **`paths:` 规则优于自造 PreToolUse hook** —— 原生机制、随读文件触发、无需维护脚本。
- 判据：**「只在改某片代码时才有用」= 它不该在常驻层**，无论它多重要。

### CLAUDE.md ↔ memory 的分界

唯一的第一性问题是**「这条事实需要在每一次会话开头就生效吗」**。落成可判定的判据：

- **不知道它会「做错事」→ CLAUDE.md**。它是**约束**（「pr 提本仓库不提 fork」「lint+typecheck 全绿才算完成」）。
- **不知道它只是「多花时间」→ memory**。它是**发现**（「某接口分页字段实际叫 `next_cursor`」「某 bug 的根因」）。
- 两边都像 → **只进 CLAUDE.md**，memory 侧连指针都不留（LCA：常驻层级更高者赢）。

⚠ **memory 的准入门槛不为零**：每写一条就给**所有**会话永久加一行常驻索引。它的价值必须能被「命中时省下的重新查证」摊平 —— 粗判据：**未来 10 次会话用不到 1 次的，不该进 memory**，归宿是文档或 issue。

**二级索引下沉**：已完结、低命中率的条目移入 `index-*.md`（如 `index-shipped-changes.md`），从常驻层退出、仍可 recall。**`index-` 前缀是硬约定** —— `memory-lint` 靠它零歧义识别并递归展开；不守约定的二级索引，其条目会被误报为孤儿。超预算的第一处置是下沉，不是删知识。

## 13. 与 /claudemd-commit · /claudemd-distill · claudemd-lint 的合约

| 工具 | 时机 | 模式 | 用本 spec 的哪部分 |
|---|---|---|---|
| `claudemd-lint` | pre-commit / CI / 每次写入后 | 机械拦截，不含判断 | §8 指针纪律 · §12 预算 |
| `memory-lint` | 每次写入 memory 后 / CLI 全量 | 机械拦截，不含判断 | §12 memory 两档预算 · §12b `index-` 约定；**不裁决「值不值得记」**（软判断） |
| `/claudemd-commit` | 每轮变更结束 / PR 前 | 增量 + **预算中性**；**自动录入**，较大差异才对齐（`/pr-ship` step 2b 内置调用） | §7 全流程（⓪ 准入 → ⑥ 预算闸）；§5 段目录；§2 LCA |
| `/claudemd-distill` | 累积多轮后 / 结构性重排 | 全量大扫除（文件显著变短） | §11 排除清单 + §8 指针纪律 判去留；§4 骨架 = 必留结构 |

- 本 spec = 三者共同的「硬约束基线」，基线指向**本文件**（`.claude/claudemd-standard.md`）。
- ⚠ **`/claudemd-sync` 已废除**（2026-08-25）：它明写「不要压缩、宁可冗余」且每轮跑，而减法挂在一个更慢的命令上 —— 结构上就是**有齿无掣子的棘轮**，必然单调增长。`/claudemd-commit` 取代它，把加法与减法合进同一个动作。
- distill 不再是「止血手段」而是「定期重排」：日常增长已由 commit 的预算中性约束住。

## 13b. 硬约束 vs 软判断（谁来守）

> 本规范的核心主张是「能机器拦的必须机器拦」。这一节把它应用到规范自己身上：
> 逐条标出**谁负责执行**。凡标「机器」的，人和模型都不必再复核；凡标「判断」的，机器帮不上忙，只能靠流程留痕。

### 机器守（`claudemd-lint`，可判定、零裁量）

| 约束 | 判据 | 触发点 |
|---|---|---|
| 字节预算（分层，注入段单独计） | `len(bytes)` vs 闸门 | hook · pre-commit · CI |
| 巨行（> 400 B 拦 / > 200 B 提醒） | 逐行字节 | 同上 |
| 悬空指针 | 反引号内路径是否存在 | 同上 |
| `@` 语义误用（裸 @ 急切导入 / 反引号内死记号） | 正则 + 层级 | 同上 |
| **跨层重复**（违反「单一真相」） | 归一化行在祖先/后代两层同时出现 | 全仓扫描 |
| **预算中性**（加一减一） | `git diff` 净字节 ≤ 0，否则要 commit message 申报 | commit-msg · CI |
| 头部 `>` scope 块缺失 | 结构 | hook · pre-commit |
| 日期腐烂（> 90 天未触碰） | 日期解析 | 全仓扫描（提醒） |

### 人/模型判断（机器判不了，只能靠流程留痕）

| 判断 | 为什么机器判不了 | 留痕机制 |
|---|---|---|
| 准入四问 Q1 会命中吗 | 需预测未来会话分布 | `/claudemd-commit` 逐条问答写进候选清单 |
| Q2 不写会做错吗 | 需模拟模型的默认行为 | 同上 |
| Q3 做错会静默吗 | 需理解失败传播路径 | 同上 |
| 这条属于哪一层（LCA） | 需判断「对哪些单元为真」 | 同上；写错了跨层重复检测会兜底抓到 |
| 该进 CLAUDE.md / rule / skill / 测试 | 需权衡命中率与可断言性 | §12b 分流表 + commit 报告的「分流去向」段 |

> **关键取舍**：硬约束**管不了「这条该不该写」**，只管住**「写它要付出可审计的代价」**。
> 预算中性闸就是这个思路的落点 —— 它对内容质量零判断，只让**增长必须显式**。
> 棘轮的掣子不需要理解内容，只需要让加法留下记录。

### 启发式信号（WARN 级 · 有假阳性 · 只提示不拦）

介于硬软之间：模式可测但判断权在人。命中不阻断，只把「值得复核」这件事说出来。

| 信号 | 命中什么 | 提示 |
|---|---|---|
| 变更史叙述 | `此前` `后来改成` `曾被` `那次回退` `旧表述` … | §11 祈使句判据 → 该进 ADR/git |
| 防线重复 | `测试钉死` `AST guard` `pre-commit 拦` + 超长行 | §7 Q4 → 解释搬进 assert message，本文件留一行防线索引 |
| 日期腐烂 | `（YYYY-MM-DD）` 超 90 天未触碰 | 复核是否仍成立 |

### 单文件预算例外（唯一合法的「超线还能绿」）

预算是为了逼出取舍，不是为了逼人砍掉真正该留的东西。确认某文件的超线**是内容本身的性质**（而非疏于收敛）时，在该文件里声明：

```
<!-- claudemd-budget: 14336 剩余全是静默失败不变量；按子目录再拆收益 < 拆散代价；下次触碰时按 X/Y 拆 -->
```

- **零上下文成本**：块级 HTML 注释在注入模型上下文前会被剥掉（官方 docs），声明本身不占 token。
- **永不静默**：例外生效时 lint 每次照打一条 warn，把闸门 / 声明值 / 当前值 / 理由一并列出 —— 它是**可见的欠债**，不是豁免。
- **必须写理由**，且理由要能回答「为什么这不是偷懒」；没写理由的声明会被 lint 点名。
- ⚠ **禁用来绕过日常增长** —— 那是 `--diff-gate` 的辖区。例外管「这个文件的稳态体量」，净增量闸管「这次改动的方向」，两者独立生效。

### 接在哪三个触发点上（缺一则规则形同虚设）

| 触发点 | 命令 | 抓什么 · 为什么在这一层 |
|---|---|---|
| **PostToolUse hook**（Write\|Edit） | `claudemd-lint.py --hook` | 写完 CLAUDE.md **当场**回灌结果 —— 在 agent 的循环内，当轮就能修，最便宜 |
| **pre-commit** | `claudemd-lint.py` | 全仓扫描（含跨层重复），拦住本地提交 |
| **commit-msg** | `claudemd-lint.py --diff-gate --base HEAD --msg-file $1` | 预算中性；净增须在 message 写 `claudemd-budget: +N <理由>` |

`.pre-commit-config.yaml` 片段：

```yaml
  - repo: local
    hooks:
      - id: claudemd-lint
        name: CLAUDE.md 硬约束
        entry: python3 .claude/hooks/claudemd-lint.py
        language: system
        files: (^|/)CLAUDE\.md$
        pass_filenames: false
      - id: claudemd-budget-neutral
        name: CLAUDE.md 预算中性
        entry: python3 .claude/hooks/claudemd-lint.py --diff-gate --base HEAD --msg-file
        language: system
        stages: [commit-msg]
        pass_filenames: true
```

> ⚠ **PostToolUse hook 是三层里最重要的一层** —— 另两层只能在事后拦住，而它把反馈放回模型的编辑循环里。
> 一个只在 CI 才响的门禁，等于把修复成本推到最贵的时刻。

### 14b. routing 走查

4. **归段**：属「契约」固定槽。
5. **查重**：web 已有「前后端契约」条 → 原地补，不新开段。
6. → **落点**：`services/web/CLAUDE.md` 契约段，一行 + ADR 指针。
