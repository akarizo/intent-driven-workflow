推荐：在本仓库开一个 change scope-guard-enforced，分四片修：契约 v2 · 内建提供方与精度 · 运行期守卫 · 安装器与文档。修完后，新装和升级都由安装器种好声明，再由 lint 和运行期守卫兜底。afa 侧另开一个接入 change，和模板 change 并行推进。

2 · 修复后的保证（装了模板的任何仓库都满足）

  • I1 计划期必有范围报告：每个 change 在 propose lint 和 preflight 时都会拿到一份范围报告，覆盖 baseline 与 final，包括切片计划要改的文件。
  • I2 全选必须逐项表态：报告全选时，每个触发项都要写理由，并显示在审批页。「没有提供方」也是一个必须表态的状态，不再静默。
  • I3 运行期机械复核：baseline 与 final 开跑前，出现未表态的全选就不跑、判红。批准后再改的理由不算数，以 approve 提交里的为准；模型自己补理由绕不过去。
  • I4 工作流自己的文件不导致全量：分层文件、选测声明、.claude/**、change 工件都不会单独触发全量。
  • I5 新装与升级都满足 I1–I4：安装器负责种声明，lint 和运行期守卫负责兜底。

5 · 内建精度（断点 5）

工作流自有路径不触发全量

  • .claude/** 和 openspec/**（选测声明、检查默认、分层文件、schemas、各 change 工件）改动时，不再命中「依赖图没见过的非 Python 文件 → 全量」。
  • 如果有测试在运行时真读了这些文件，照常按依赖选中这些测试。产品代码的测试不会依赖 Claude Code 配置，所以排除是安全的。

shell 静态闭包并入依赖

  • 实测依赖里出现的 shell 脚本，静态解析其中的 source / . / 字面路径，认得 $(dirname "${BASH_SOURCE[0]}") 等写法。
  • 文件名含变量时，按整个目录的同后缀文件处理。
  • 解析结果传递并入该测试文件的依赖，用于增量选中和全量判定。
  • 解析不了 → 不补，退回原规则（全量），这种情况在计划期就会被点名。

6 · 安装器行为（新装 + 升级）

场景现在修复后
新装（空仓库，或已有项目第一次装）不种声明种 {"builtin": true}。首个 change 写出的 gate.test 如果认不出，lint 会红，并提示改成 cmd（Q3）
升级：现有 change（含 archive）的 gate.test 全部可识别不种补种 builtin；只补缺失的文件，不覆盖
升级：有认不出的 gate.test，例如 afa 的 bash openspec/changes/…/verify/full_suite.sh不种不种，安装摘要醒目提示：本仓库自带选测，须接入 cmd 提供方。之后按 Q2 的规则处理
已有 gate-scope.json不动不动（用户数据），只校验形状并打印出来

约束：安装器不能交互（ADR DRAFT-installer-versioned-with-template 决策 2：stdin 接 /dev/null，新增参数只能是可选的），所以只能自动判定加打印。判定依据是仓库自己的 slices.json 历史，不靠猜。

7 · afa 怎么办（升级场景的真实样本）

  • 升级后：afa 的 gate.test 认不出，所以不会被种 builtin，必须接入 cmd 提供方。在接入之前，按 Q2-A 新 change 会被卡住。
  • 接入 change：沿用上一份 afa 方案，按契约 v2 调整。S3 的范围命令要读取 GATE_SCOPE_PLANNED；登记表按条目比对和 bin 引用索引仍在 afa 侧做，这两项决定 afa 实际能少跑多少。
  • 顺序（Q9-A）：模板 change 和 afa 接入 change 并行推进，两者都合入后再升级 afa，这样 afa 不会被硬红卡住。在飞的 export-xlsx-aparam-override 照常跑完：它的 worktree 用的是自己分支里的旧 .claude，不受影响。

10 · 风险与回退

风险缓解残余
Q2-A 卡住升级后尚未接入的仓库本 change 建立声明时放行；Q9-A 先接入再升级；安装摘要写清怎么接别的已装仓库升级后，要先写一个提供方（恒全量的包装可以一行写完）
builtin 判定靠「gate.test 可识别」，带选测插件的 pytest（如 --testmon）会被当成普通命令文档写明：builtin 等于承诺 gate.test 不自带选测；声明显示在审批页接受
shell 静态解析认不全只会少补依赖，最坏情况退回原规则（全量），并在计划期被点名多跑，但不会漏选
每次 lint / preflight / baseline / final 多跑一次范围计算builtin 在进程内算，近乎零成本；cmd 只算范围，不跑测试，afa 量级约 10 s—
飞行中途因 Q4 停下只有计划期预测错了才会发生；preflight 已用新鲜基线精确复核罕见

回退：revert 本 change，回到「契约可选、没声明就静默」的现状。仓库也可以删掉 gate-scope.json，但在 Q2-A 下删掉就会红，这是有意的：回退必须显式（铁律 10）。
