# DRAFT. 时间预算写在分层文件里，集成层按账本做棘轮

- Status: proposed
- Date: 2026-11-18

## Context

- 门禁对测试耗时只有一条线：单元层单条 3 秒（`DRAFT-test-tiers-unit-baseline-by-audit-probe`）。集成层没有任何上限，放行（`slow_allow`）没有上限也没有期限，层的总量只打印不判。
- afa 2026-11-18 的体检里集成层占测试耗时的 96–98%，两周内用例数 +41%，没有任何规则对此反应。
- 测试账本（`DRAFT-test-ledger-outside-repo-follows-anchors`）让每次 baseline / final 留下逐用例耗时，并把「要不要按账本判红、按什么线判」留给后续决策。全机测试锁（`DRAFT-machine-wide-test-lock`）让测量在独占下进行。
- propose 期用 afa 的 7 次全范围门禁运行与一组同树连跑量了噪声：
  - 单元层稳定：9710 条用例以 3 秒为线，始终超线 6 条，时超时不超 3 条；
  - 集成层不稳定：以 60 秒为线，始终超线 11 条，时超时不超 26 条；没有针对性改动的两次运行之间，每次都有若干条用例「从线下到线上」，加余量也消不掉；
  - 层合计在两次运行之间能差五成以上。
  - 这些数据测于加锁之前；加锁之后的重复测量还没有。
- 本 ADR 修订 `DRAFT-test-tiers-unit-baseline-by-audit-probe` 的一句话：「阈值不可配置」。那一句的理由是被门禁的一方不该能改判据。该 ADR 尚未编号，其余条款（两层、按路径归层、探针判定、放行要人类原话、否决环境变量调阈值、否决一次超线即红）继续有效。

## Decision

1. **预算是仓库级判据，写在分层文件里**：单元层与每个区域可选 `budget = {case_sec, total_sec}`。不放计划文件，不认环境变量。单元层的单条上限缺省仍是 3 秒，可在分层文件里改。
2. **放行有边界**：`slow_allow` 的条目可带 `limit_sec`（放行到多少秒）与 `expires`（到期日）。超过上限判红；到期后这条放行不再算数。放行仍然只认人类原话。
3. **各层处置不同**：
   - 单元层单条：全部判红（探针测、单独重跑确认，机制不变）；
   - 集成层单条：**棘轮**——本 change 新增的用例超线判红；基线账本里已有的用例超线只警告，分「基线时已超线」与「基线时未超线」两类如实列出；
   - 单元层总量：超预算判红；区域总量：超预算只警告。
4. **集成层已有用例「涨过线」不判红**：单次测量分不出真的变慢与噪声。等账本里攒出加锁之后的重复测量，再用数据决定是否收紧；收紧时另立 ADR。
5. **层总量取账本里整层逐用例耗时之和**（实测与沿用都算），不取本次运行的墙钟。
6. **判红只在测量可信时发生**：
   - 排队放弃后不加锁跑出来的那次，新判定与 G10 一样降为警告；显式关锁与平台不支持时照常判；
   - 账本不完整、无耗时的用例过多、基线账本不在本机时不判，并说明原因；
   - 账本模块不可用或判定出错时退回没有预算的行为，只留警告。
7. **改判据要被看见**：分层文件里的预算与放行名单相对基线有变动时，final 逐项列进警告与 PR 正文。只报告，不判红。
8. **模板不替仓库定数字**：除单元层 3 秒外没有任何缺省预算。

否决的方案：

- **集成层与单元层一样全部判红**：历史包袱重的仓库无法启用，等于永远不启用。
- **集成层只报告不判红**：新增的慢用例没有任何阻力，层只会继续变慢。
- **「涨过线」判红**：数据显示几乎每次 final 都会红在没人动过的用例上。
- **按「层合计比基线上涨 X%」判红**：两次运行之间的合计本身就能差五成以上。
- **超线候选在集成层单独重跑确认**：区域命令由仓库自定，库无法只跑其中几条；单独跑还会把共享准备的成本全算在它头上。
- **预算写在计划文件里**：每个 change 自己给自己定线。
- **放行缺省给一个期限**：没有数据支持任何缺省值。

## Consequences

- 仓库第一次有办法给集成层设线，而不必先清完老债；老债在每次收口的报告里都看得见。
- 新增的集成用例超线会让 final 变红。它基于单次测量，可能误判；出路是提速、拆小，或由人类给一条带上限的放行。
- 放行到期、单元层总量超预算会让 baseline 变红，挡住与之无关的 change，直到有人处理。这是有意的：没人必须回应的提醒等于没有。到期前有警告，体检会点名。
- 单元层的线可以被改松。改动会出现在 PR 正文里，由第二处人类审批把关；手工改放行名单仍然只靠评审发现（已知缺口不变）。
- 预算判定依赖测试账本。换机器、清了 git 共用目录之后，集成层单条在重跑 baseline 之前不判红。
- 写或改单元层预算会改变分层指纹，下一次 final 全量（换了线，沿用的用例要重判）。
- 后续的体检与整改命令可以直接复用同一套判定函数，不需要第二份规则。
