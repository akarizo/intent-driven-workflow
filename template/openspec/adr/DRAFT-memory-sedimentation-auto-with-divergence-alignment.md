# DRAFT. 记忆层沉淀自动录入，较大差异才对齐；反复错误有上限地进入载体体系

- Status: accepted
- Date: 2026-11-09
- 关联：DRAFT-memory-as-fifth-resident-carrier（补充原则 4 的落地方式，不取代：lint 仍不裁决「值不值得记」）
- 来源 change：post-ship-hygiene（design D10–D12）

## Context

`/claudemd-commit` 用准入四问、§12b 分流和预算中性控制常驻层的增长。它的 step 6 要求逐类用 AskUserQuestion 确认，而 `/pr-ship` 全程不问询。结果沉淀只能靠人记得在 PR 前单独跑。`submodule-aware-flight`（2026-11-07）就跳过了它。

当轮两条反复出现的错误只进了个人 auto-memory：
- 自举时文档切片先合回，导致门禁连红；
- 合并后 `-d` 失败。

2026-08-25 废除的 C 类「本轮发现的工程偏差」把这类错误挡在常驻层之外。废除理由是 C 类让模型主动发明观察，是增长引擎中唯一的无界项。这一理由成立，但它也把「有证据、反复发生」的错误一并挡在了外面。

用户决策（2026-11-09）：
- 沉淀改为自动识别与录入，只有与既有认知有较大差异的才对齐；
- 反复错误加上限后恢复。

## Decision

1. **自动录入是默认**：通过准入四问和预算闸的新增条目，以及不丢含义的迁移，直接写入。
2. **较大差异必须对齐**，命中以下任一条：
   - 删除或反转既有含义；
   - 与既有条目或在役 ADR 矛盾；
   - 改动铁律或核心约束；
   - 写到仓库外的全局 CLAUDE.md。

   这类条目只能经人确认后落盘。不能当场问询的调用方（如 `/pr-ship`）不落盘，把条目列进 PR 正文，由 PR review 裁决。
3. **E 类反复错误的上界是证据**：同一错误本轮至少 2 次，且每次都有证据指针（门禁红记录、评审条目、fix commit、用户原话）。能机械化的优先立项做防线，常驻层只留一行过渡条目。C 类维持废除。
4. **送出即沉淀**：`/pr-ship` 在 commit 之前内置一步记忆层沉淀，产出独立 commit，可整体 revert。

## Consequences

- **更易**：每个 PR 都带一次沉淀，口头规则和反复错误不再只活在对话和个人 memory 里。
- **更易**：人的注意力只花在「改变既有认知」的条目上，新增条目由 PR review 兜底。
- **更难**：模型判断准入的压力变大。较大差异的四条判据必须写死在命令里，不能靠临场理解。
- **约束后续变更**：再扩大自动录入的范围，例如允许自动删除条目，属于推翻本 ADR 第 2 条，须 supersede。E 类若出现无证据录入，视为本 ADR 被违反。
- **不影响**：`claudemd-lint` / `memory-lint` 的判据与阈值，以及准入四问与预算中性规则本身。
