# DRAFT. 基线经依赖图锚点复用：非测试改动按依赖补跑，跨 change 带预存红只经锚点

- Status: accepted, supersedes ADR-DRAFT-baseline-reuse-by-content-fingerprint（仅「只有测试文件变了才复用全量」与「跨 change 只复用全绿」两项）
- Date: 2026-11-09
- Supersedes: DRAFT-baseline-reuse-by-content-fingerprint（合并时回填真实号；只取代上述两项，其余决策在役：按内容判同、lint / typecheck 沿用、不计入差异的路径、preflight 判过期、基线池入池条件）
- 关联：DRAFT-final-incremental-by-dependency-anchor（沿用其锚点、选测与全量触发规则，保持在役）· DRAFT-builtin-scope-provider-and-shell-closure（触发项单一出处，保持在役）· DRAFT-gate-test-result-handoff-and-runner-contract（同一 change）
- 来源 change：unified-test-result-reuse（design D6–D10、D13）

## Context

基线复用 ADR 规定两件事：只有测试文件变了才复用全量；跨 change 只复用全绿。当时 final 总是全量，这两条是兜底。后来增量 final 引入了锚点与实测依赖图，但基线没有跟进（incremental-final 明确把"不改 baseline 的复用规则"列为非目标）。

afa 实测（2026-11-09 只读盘点，数字为下限）：
- 全量基线 95 次、合计 37,633 秒，复用成功只有 6 次；
- 首个候选被拒的理由：
  - 没有任何候选：64 次 / 28,161 秒。带预存红的仓库进不了基线池，按 change 生成的包装脚本又让 `cmd_key` 各不相同。
  - 有非测试改动：17 次 / 6,337 秒。切片代码落地后再重新规划，必然全量。
  - 候选基线是红的：12 次 / 2,910 秒。

2026-10-15 用户否决"跨 change 带预存红也复用"，理由是整份沿用别人的预存红名单，会留下把红判成绿的窗口。锚点路径不整份沿用名单：锚点失败用例所在的文件一定重跑，预存红按本次结果记录。用户在 2026-11-09 据此重新决策（Q1=A），只对锚点路径放开。

## Decision

1. **基线候选三级**：本 change 旧基线 → 锚点池 → 基线池。
   - 锚点池候选的条件：`gate.test` 指纹与分层指纹都匹配、测到依赖图、未达锚点链上限；
   - 锚点可来自任意 change、任意来源，取 Δ 最小的。
2. **非测试改动按依赖补跑**：经锚点时，Δ 命中全量触发项（与 final 单一出处，含项目声明的 `global`）就不复用；否则只补跑 final 的同一选择集合（依赖与 Δ 相交 ∪ Δ 里的测试 ∪ 锚点失败所在 ∪ 盲区 ∪ 声明的 `blind`）。预存红按补跑结果以 nodeid 形式记录；final 全量时按 nodeid 差分，依赖图未测、无法差分时判红。
3. **跨 change 带预存红只经锚点**：基线池入池条件不变，只收全绿的全量；带预存红的跨 change 复用只能走锚点路径，由"失败文件必重跑"保证别人的红不会被当成绿沿用。
4. **锚点链上限**：锚点记由增量推出的代数，达到 K 代（`gate-scope.json` 的 `anchor_max_hops`，缺省 5）就不作候选。基线与 final 共用这条规则。
5. **红基线按部件复用**：本 change 旧基线的测试部分本身有效（跑了、可度量、运行期间没被改动）时可复用；verify、lint、typecheck 与检查照常判定。
6. **指纹归一**：`cmd_key` 取命令直接引用的文件及其静态 shell 闭包的内容，把本 change 名归一后再算。本 change 门禁脚本只按 gate.test 闭包影响测试结论。

否决的方案：
- **基线池也放开带红**：池条目没有依赖图，做不到"失败文件必重跑"。
- **锚点路径只对本 change 开放**：首次基线（afa 占比最大的一类）照样没有候选。
- **按锚点年龄设上限**：依赖图的漂移来自一次次增量推导，与时间无关（用户 Q2=A）。
- **只归一命令文本**：afa 指纹分裂的原因在脚本内容里。

## Consequences

- **更易**：
  - 重新规划、首次基线、红基线修好后重跑，在锚点可用时都只补跑受影响的测试；
  - 各 change 用同一模板生成的包装脚本能互相命中。
- **更难**：判定器的可信计算基多了"基线经锚点"一条路径，基线结论也开始依赖依赖图的完整性。
- **盲区**：
  - 依赖图漏记的依赖可能让基线把实际已红的用例记成绿，与增量 final 是同一类、已接受的盲区；
  - 兜底：失败文件必重跑、全局与声明的全局路径触发全量、盲区必重跑、链长上限、`--full`；
  - 项目启用前要对账。
- **代价**：
  - `cmd_key` 算法变化，升级后每个项目一次性全量；
  - 链长上限让已在增量的项目周期性多一次全量。
