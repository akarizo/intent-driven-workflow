# DRAFT. 重新起飞时已落地的切片不再派执行体

- Status: proposed
- Date: 2026-11-18
- 关联：DRAFT-measurements-stay-out-of-plan-files（修掉了「批准必然过期」）· DRAFT-wave-integration-check-and-cross-slice-fix（已落地的 wave 仍做集成检查）
- 来源 change：wave-integration-guard（design 调查三 · D8）

## Context

飞行中途发现 owns 漏列时，路径是：停飞 → 改计划 → 人类重新批准 → 重新起飞。前三步现在已经便宜（只改 owns 不让基线过期）。最后一步不便宜：工作流每次都从完整的 waves 重新开始，已经合回的切片会再派一遍执行体，结果正确但每片白花一个主模型的执行体。运行时的按调用顺序回放帮不上：上次交回红结论的那一片会原样回放成红。

## Decision

1. **脚本判定「已落地」**（`slice-gate.py landed`）：门禁行绿、行里的 commit 是 HEAD 的祖先、从那个 commit 起该片的切片包、规格与计划条目（owns 之外）都没变。
2. **工作流据此跳过执行体**：已落地的切片不派执行体。
3. **评审不省**：重新起飞会覆盖上一次的评审结论，所以已落地的切片照常派评审。
4. **集成检查不省**：有已落地切片的 wave 仍做集成检查，上一次飞行停在集成检查红时不会在红的分支上接着派。

否决的方案：

- **用运行时的续跑（按调用顺序回放缓存）**：红结论会被回放；只在同一会话内有效。
- **只看门禁行绿不绿**：人类改了某片的 scenario 或切片包之后，这一片该重做。

## Consequences

- 补 owns 之后的重新起飞只花没落地那几片的执行体。
- 已落地切片的评审每次重新起飞都会再做一遍；要省这部分得让收口步骤合并上一次的评审结论，本决策不做。
- 「已落地」的判定依赖 `gate-report.md` 已经入库且没被手改。
