# S4 · 编排与文档：工作流、agent 定义、命令与同名 skill、git-discipline、README、WORKFLOW_zh

## 做什么

让 Workflow 与 Agent 回退两条路径都接上 S1–S3 的命令，并把子仓纪律写进 agent 定义与文档。规则原文见 `specs/submodule-flight-orchestration/spec.md`，决策见 `design.md` D2、D7。

命令接口以 design 为准，S1–S3 尚未合入不影响本片：
- `slice-gate.py merge <S>=<sha> ...` → 输出 `{ok, merged, failed, warnings}`，退出 0 / 1；
- `slice-gate.py sub-sync [--change-dir D] [--expect-branch B]` → 输出 `{ok, synced, failed, warnings}`，失败项以 `G0 submodule` 开头。

## 怎么做

1. **`template/.claude/workflows/opsx-apply.js`**：
   - **wave 合回**（`callInteg`）：把「再按第 1 项把切片 … 的 commit 合回当前分支：<shas>（冲突则 abort 并返回 ok:false）」改为：
     「再按第 1 项运行 `python3 ${hooksDir}/slice-gate.py merge S1=<c1> S2=<c2>` 合回切片 …（它逐片 git merge --no-ff 并处理 submodule gitlink；退出非 0 → 把它 JSON 的 failed 原样作为返回的 failed、ok:false，不再往下）」
     其中 pairs 由 `merged` 与各自 `commit` 拼成，空格分隔。
   - **finalize 的 `mergeFix`**：改为运行 `python3 ${hooksDir}/slice-gate.py merge fix=${fix.commit}`。仍须位于 `slice-gate.py final` 之前；退出非 0 → 返回 ok:false 且 failed 写「merge fix 冲突」，不再往下。
   - **fix prompt**：在基点校验那一行之后、`start fix` 那一行之前，插入一行：
     「再运行 `python3 ${hooksDir}/slice-gate.py sub-sync --change-dir ${changeDir}` + (branch ? ` --expect-branch ${branch}` : '') + `` ` ``（按 gitlink 填充隔离 worktree 的 submodule；无 submodule 时是空操作）；非 0 退出 → 不做任何改动，直接返回 `{"slice":"fix","ok":false,"commit":"<实际 HEAD>","failed":<它 JSON 的 failed>}`」
     随后 start 那一行的「再 / 先」措辞相应调整。`baseRejected` 不用改：sub-sync 的失败以 G0 开头。
   - **评审**（`reviewPrompt`）：`git show ${gate.commit}` 改为 `git show --submodule=diff ${gate.commit}`。
2. **`template/.claude/agents/integrator.md` 第 1 项**：改为运行 `python3 .claude/hooks/slice-gate.py merge <S>=<sha> ...`（按 prompt 给的顺序），并写明三点：
   - 它逐片执行 `git merge --no-ff <sha> -m "integrate: <S>"`；
   - submodule gitlink 冲突由脚本在子仓内合并后钉；合回后子仓检出与 gitlink 同步；
   - 任何真冲突由脚本自行 abort 并退出 1，integrator 把它的 failed 原样返回，不要手工 merge 或解冲突。

   ⚠ 正文须保留 `git merge` 字样（既有用例 `test_integrator_agent_contract` 断言它）。
3. **`template/.claude/agents/slice-executor.md`**：
   - **「开工」第 2 条补一句**：start 会按 gitlink 填充隔离 worktree 的 submodule；子仓未就绪时以 `G0 submodule` 非 0 退出，原样返回。
   - **「纪律」段加一条**：**owns 落在 submodule 内**时，按顺序做：
     1. 先 `git -C <子仓路径> add <子仓内相对路径>` + `git -C <子仓路径> commit -m "<type>(<scope>): <S> <标题>"`；
     2. 再在父仓 `git add <子仓路径> <父仓 owns 文件>`，把 gitlink 并入同一个切片 commit。

     漏掉 gitlink 会被 `G6 gitlink` 拦下；不在子仓里切分支、不 push。该条须含 `git -C`、`gitlink`、`submodule` 字样。
4. **`template/.claude/commands/opsx-apply.md` 与 `template/.claude/skills/openspec-apply-change/SKILL.md`**：在「Workflow 不可用 …」回退段里，把 integrator 合回改述为「integrator 用 `slice-gate.py merge` 合回」，并在 fix 的基点校验之后写「再跑 `slice-gate.py sub-sync`」。两处须保持一致（`tests/test_template_docs.py::test_command_skill_sync` 等既有用例会对拍）。
5. **`template/.claude/skills/openspec-git-discipline/SKILL.md`**：新增 `## Submodule` 小节，写在 Worktree Isolation 之后，内容如下：
   - 隔离 worktree 的子仓由 `slice-gate.py start` / `sub-sync` 从 change 家子仓借出 **linked worktree**，不 clone、不访问远端；
   - gitlink 随切片 commit 提交；
   - 合回只经 `slice-gate.py merge`；
   - 家子仓的分支由合回推进，起飞前须检出等于 gitlink（preflight 校验）；
   - 不支持嵌套 submodule 与新增或删除 submodule 的切片，这类改走 `--gate=per-task`。
6. **`README.md` 与 `docs/WORKFLOW_zh.md`**：在飞行模式说明处各补一句：含 submodule 的仓库同样走飞行模式，机制见 git-discipline 的 Submodule 小节。
