# S3 · 合回脚本：slice-gate.py merge

## 做什么

新增子命令 `merge <S>=<sha> ...`，由 integrator 第 1 项一律调用。它逐片 `git merge --no-ff`，并处理 gitlink：快进直钉，分叉时在家子仓内合并后再钉。合回后检出与 gitlink 同步，失败全回滚。规则原文见 `specs/submodule-merge/spec.md`，决策见 `design.md` D5。本片**不改**工作流脚本与文档（S4 已按本接口写好）。

## 依赖接口（S1、S2 已提供，`template/.claude/hooks/slice-gate.py`）

- `_gitlinks(root)`、`_sub_ready(root, p)`、`_sub_has(root, p, sha)`
- `_is_ancestor(root, anc, desc)`：传子仓路径即可在子仓里判断
- `start` 已能在隔离 worktree 里填充子仓，夹具 `run_executor` 依赖它

## 怎么做（`template/.claude/hooks/slice-gate.py`）

1. **参数**：位置参数若干，每个形如 `<S>=<sha>`。格式错 → `die`（退出 2）。在 `main()` 注册 `merge`。
2. **开跑前复核**：对 `_gitlinks` 中每个 `_sub_ready` 的 P，子仓 HEAD 须等于 `rev-parse HEAD:P`，且子仓不在合并中（没有 `MERGE_HEAD`）。不满足 → 一片不合，输出：
   `{"ok": false, "merged": [], "failed": ["merge: <P> 的检出 … 与 gitlink … 不一致，先同步"], "warnings": []}`
3. **逐片（按参数顺序；任一片失败即停）**：
   1. `git merge --no-ff --no-commit -m "integrate: <S>" <sha>`，记下 rc 与 stderr。
   2. `conflicted` = `git diff --name-only --diff-filter=U -z`。`mb` = `git merge-base HEAD <sha>`。`links` = `git diff --raw -z --no-renames <mb> <sha>` 中新 mode 为 160000 的路径。
   3. **非 gitlink 冲突**：`conflicted - links` 非空 → `git merge --abort`，记 `merge <S>: 冲突文件 a, b`。rc ≠ 0 且无冲突（例如 sha 无效）→ 有 `MERGE_HEAD` 时先 abort，记 `merge <S>: <stderr 首行>`。
   4. 对每个 P ∈ links（按路径排序），取 `ours = rev-parse HEAD:P`（失败即视为新增 submodule）、`theirs = rev-parse <sha>:P`：
      - ours 不存在 → 回滚，记 `merge <S>: <P> 是新增 submodule，不支持（改走 --gate=per-task）`；
      - `ours == theirs` → 跳过；
      - 子仓未填充或 theirs 不在子仓 → 回滚并记失败；
      - `_is_ancestor(子仓, ours, theirs)` → 目标为 theirs；反之为祖先 → 目标为 ours；
      - 否则（分叉）→ 在子仓执行 `git merge --no-ff --no-edit -m "integrate: <S>" <theirs>`。失败则依次执行：子仓 `merge --abort`；本片已合过的其他子仓 `reset -q --keep <各自合前 HEAD>`；父仓 `merge --abort`。记 `merge <S>: <P> 子仓合并冲突（<子仓冲突文件>）`，停止。成功则目标为子仓新 HEAD。
      - 最后执行 `git update-index --cacheinfo 160000,<目标>,<P>`。
   5. 存在 `MERGE_HEAD` → `git commit -q -m "integrate: <S>"`。不存在（已是最新）→ 不提交，仍视为合回成功。
   6. **同步检出**：对每个 P ∈ links，若子仓 HEAD ≠ `HEAD:P`：
      - 子仓在分支上，且 HEAD 是目标的祖先 → `git -C P merge -q --ff-only <目标>`；
      - detached → `git -C P checkout -q --detach <目标>`；
      - 其余 → warning。
   7. `merged.append(S)`。
4. **输出**：`{"ok": not failed, "merged", "failed", "warnings"}`，`print(json.dumps(..., ensure_ascii=False))`，`sys.exit(0 if ok else 1)`。
