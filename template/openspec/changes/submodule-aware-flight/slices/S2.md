# S2 · 子仓填充与续跑：start 借出家子仓、sub-sync、快照恢复覆盖子仓、preflight 就绪校验

## 做什么

让隔离 worktree 的子仓按 gitlink 就绪，并让重派、快照、起飞前校验在子仓上与父仓语义一致。规则原文见 `specs/submodule-worktree-sync/spec.md`，决策见 `design.md` D1、D4、D6。本片**不做**合回（S3）和文档（S4）。

## 依赖接口（S1 已提供，`template/.claude/hooks/slice-gate.py`）

- `_gitlinks(root)` → `{路径: 索引 sha}`
- `_sub_ready(root, p)` → 子仓已填充（`<root>/<p>/.git` 存在）
- `_sub_has(root, p, sha)` → sha 是子仓里的提交
- `changed_files` 已展开 gitlink；`cmd_gate` 已有 `G6 gitlink` 与 `refs/flight-sub/<change>/<S>` 锚定

## 怎么做（`template/.claude/hooks/slice-gate.py`）

1. **`_home_root(root, branch)`**：在 `git worktree list --porcelain` 中找含 `branch refs/heads/<branch>` 的那一块，返回它的 `worktree` 路径（realpath）。找不到或 `branch` 为空 → None。
2. **`_need_subs(root, owns)`**：返回 `_gitlinks` 中至少有一条 owns 以 `P + "/"` 开头的 P 集合。owns 可能是 glob，按前缀判断即可。
3. **`_sub_sync(root, branch, need)`** → `(synced, failed, warnings)`，逐个 P（按路径排序）处理：
   - **已填充**：子仓 HEAD ≠ `HEAD:P` → warning `<P> 的检出 … 与 gitlink … 不一致（未改动）`。MUST NOT 改动已填充的子仓。
   - **未填充**：`home = _home_root(root, branch)`，依次检查，命中即停：
     - `home` 为 None 或 realpath 等于 root；
     - `home/P` 未填充；
     - `HEAD:P` 不在 `home/P` 的对象库；
     - `<root>/<P>` 存在且非空；
     - `git -C <home>/<P> worktree add --detach <root>/<P> <HEAD:P>` 失败。

     每一项命中时，P ∈ need → `failed` 追加以 `G0 submodule: <P> ` 开头的一条。措辞要点：
     - 家未初始化 → 含 `git submodule update --init <P>`，并写明在哪个目录运行；
     - 定位不到家 → 含 `--expect-branch`；
     - 其余照实写 stderr 首行。

     P ∉ need → 只记 warning。
   - **填充成功** → `synced.append(P)`。若 `<root>/<P>/.gitmodules` 存在 → warning：嵌套 submodule 不填充（本机制不支持嵌套）。
4. **`cmd_start`**：在 `_base_check` 之后（无 `--expect-branch` 时直接）调用 `_sub_sync(root, args.expect_branch, _need_subs(root, 本片 owns))`。位置在 `--resume-checkpoint` 的找回门禁结论之前。
   - `failed` 非空 → 与基点校验同形打印 `{"slice", "ok": false, "commit": "", "failed": failed, "warnings": warnings, "summary": "submodule 未就绪"}`，`sys.exit(1)`，不写标记。
   - 成功时若 `synced` 或 `warnings` 非空，在打印的 JSON 里加 `"submodules": {"synced": …, "warnings": …}`（不写进标记文件）。
5. **新子命令 `sub-sync`**：
   - 参数：`--expect-branch`（可选）、`--change-dir`（可选，给了时 need = 全部切片 owns 的 `_need_subs`）。
   - 打印 `{"ok": not failed, "synced", "failed", "warnings"}`，退出 0 / 1。
   - 在 `main()` 里注册。
6. **快照（D4）**：
   - 拆出 `_ckpt_commit(repo, head, files, msg)`：用临时 `GIT_INDEX_FILE` 执行 `read-tree`、`add -A -- files`、`write-tree`、`commit-tree -p head`，返回 sha。父仓与子仓共用。
   - **`_checkpoint`**：父仓段原来的 `if not files and head == marker.base: return` 改为「跳过父仓段」，继续做子仓段。子仓段：对每个 `_sub_ready` 且 owns 有 `P/` 前缀的 P，按以下步骤处理：
     1. 取 `git -C P status --porcelain -z -uall` 中匹配「去掉 `P/` 前缀的 owns」的文件（排除字节码）；
     2. `base_rec = rev-parse <marker.base>:P`，取不到时为 None；
     3. 有文件，或子仓 HEAD ≠ `base_rec` → 用 `_ckpt_commit` 在子仓生成快照，`git -C P update-ref <_ckpt_ref(change_dir, S)> <sha>`。
   - **`_ckpt_restore(root, ref, owns)`**：父仓「无快照 / 基点不符」时不再提前 return，记下 note 后继续处理子仓。子仓段对每个 `_sub_ready` 且有 `P/` owns 的 P，按以下步骤处理：
     1. 在子仓解析同名 ref；
     2. 子仓 HEAD 须是快照的祖先；
     3. 取 `diff --name-only -z --no-renames HEAD <snap>` 中匹配子仓 owns 的文件：在快照里存在 → `git -C P checkout <snap> -- f`，不存在 → 删除；
     4. `restored.append(P + "/" + f)`。

     返回的 note 在 restored 非空时为空串（与现状一致）。
   - **`_ckpt_delete_all(root, ref)`**：父仓 `_ckpt_delete` 加上每个 `_sub_ready` 子仓里的 `update-ref -d`。`cmd_start` 首轮、`cmd_gate` 绿、`cmd_record` 里删快照的调用改用它。`_gate_ref` 只在父仓，不动。
7. **preflight（D6）**：`cmd_preflight` 在 `lint_plan` 报错检查之后、`load_baseline` 之前，对 `_need_subs(root, 全部切片 owns)` 的每个 P 校验三项：
   - 已填充；
   - `HEAD:P` 存在且在子仓对象库；
   - 子仓 HEAD = `HEAD:P`。

   任一不满足即 `die("submodule 未就绪：\n  - " + …)`。每条点名 P、给出 gitlink 前缀与修法，例如：
   `<P> 的检出 x 与父仓 HEAD 的 gitlink y 不一致：子仓改动先 git add <P> 并提交，或在子仓检出 gitlink`
