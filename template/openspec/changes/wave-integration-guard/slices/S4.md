# S4 · 工作流与 agent 定义：集成检查、跨片修复、停飞范围、已落地切片

## 做什么

改 `opsx-apply.js`：每个 wave 合回的同一次 integrator 派发里要一次集成检查；红了当场派一个跨片修复执行体，绿了合回，仍红按红的种类定停飞范围；`args.landed` 里的切片不再派执行体。`integrator.md` 与 `slice-executor.md` 各补一段。规则原文见 `specs/wave-fix/spec.md` 的前三条 Requirement 与 `specs/retakeoff-landed/spec.md` 的第二条，决策见 `design.md` D3、D4、D8、D10。

## 依赖的接口

本片只拼 prompt，不调用任何子命令；测试用 mock agent。子命令的形状见 `slices/_interfaces.md` 的 S2、S3 节（`wave-check` 的参数与 JSON、`landed` 的输出）。它们在后面的 wave 才落地，所以本片写进 agent 定义的话必须对「子命令还不存在」也成立（见「注意」）。

## 怎么做

TDD：`tests/test_wave_workflow.py` 的 9 条骨架现在是红的。

### `template/.claude/workflows/opsx-apply.js`

1. 头部注释：args 清单加 `landed`（可选，`slice-gate.py landed` 的输出 `{S1: "<commit>", …}`）；结构说明那两行补上「每个 wave 合回后做集成检查，红了当场跨片修复」。
2. `const landed = args.landed || {}`；`const wavesOut = []`。
3. `MERGE` schema 加可选的 `check`（`type: ['object', 'null']`）。
4. wave 循环里，在算出 `skipped` 之后：
   - `const landedHere = allWave.filter((s) => landed[s] && !skipped.includes(s))`；它们记 `results.push({ slice: s, ok: true, commit: landed[s], failed: [], landed: true })`；
   - `wave` 再去掉 `landedHere`；`log` 里写明跳过了哪些已落地的切片；
   - 现有 `if (!wave.length) continue` 改成：`wave` 与 `landedHere` 都空才 `continue`。
5. 集成检查的命令：`const waveCmd = (extra) => \`python3 ${hooksDir}/slice-gate.py wave-check --change-dir ${changeDir} --wave ${i + 1} --of ${waves.length}\` + (extra || '')`。
6. integrator 的派发（`callInteg`）：
   - 有本次合回的切片（`merged.length`）→ 在现有 prompt 的「最后再按第 0 项把飞行记录提交」之后追加一步：运行 `waveCmd()`（agent 定义的集成检查一项），把它打印的 JSON 原样放进返回 JSON 的 `check` 字段，再按第 0 项提交一次飞行记录；`merge` 退出 1 时不运行它；它报 `invalid choice`（hooks 未升级，子命令不存在）→ `check` 写 `null`。返回 JSON 的说明改成 `{ok, merged, failed, warnings, check}`。原有的句子一个都不要删（`tests/test_agents_workflow.py`、`tests/test_submodule_docs.py` 钉着其中的词）。
   - 没有本次合回、但 `landedHere` 非空 → 另一条短 prompt：本 wave 的切片上次飞行已合回，不要运行 `merge` 与 `record`；按第 0 项提交飞行记录 → 运行 `waveCmd()` → `check` 的规则同上 → 再提交一次飞行记录；返回 `{ok: true, merged: [], failed: [], warnings: [], check}`。这条 prompt 里不要出现字符串 `slice-gate.py merge`。
   - 两种都用同一个 label `integrate:w${i + 1}`（重派加 `:retry`）、同一个 `typed('integrator')`，仍然只有一处派发调用带这个 label 模板（`test_label_contract_matches_workflow_script` 要求模板与 `typed(...)` 同一行且只出现一次）。
7. 集成检查的结论（紧跟 integrator 返回之后；`integ` 为空或 `ok: false` 时跳过这一段，现有 blocked 逻辑不变）：
   - `const chk = integ.check`；`!chk` → `wavesOut.push({ wave: i + 1, skipped: 'integrator 未带回集成检查结果' })`；
   - `chk.ok` → `wavesOut.push({ wave: i + 1, ok: true, failed: [], tests: chk.tests || null, fix: null })`；
   - 否则进入跨片修复（下一条）。
8. 跨片修复：
   - `runWaveFix(retry)`：`agent(prompt, { label: \`fix:w${i + 1}\` + (retry ? ':retry' : ''), phase: 'Fix', isolation: 'worktree', schema: GATE, model: models.executor, effort: efforts.executor, ...typed('slice-executor') }).catch(() => null)`。
   - prompt 各行：
     - `rules('slice-executor')` + 你在仓库根。这是 OpenSpec change 的**跨片修复**，不是切片：wave ${i + 1} 合回后的集成检查红了。不运行 `slice-gate.py start` 与 `slice-gate.py gate`；不受任何切片的 owns 限制，但只改让下列失败项变绿所必需的文件。
     - 重派时：上一轮修复执行体未返回或被 G0 基点校验拒绝，从头修。
     - 基点校验与 `sub-sync` 两行：从现有 Fix 阶段的 prompt 里照搬（`git merge-base --is-ancestor $(git rev-parse ${branch}) HEAD`、`slice-gate.py sub-sync …`），失败时返回的 JSON 把 `"slice":"fix"` 换成 `"slice":"wave"`。把这两行抽成 Fix 阶段与这里共用的小函数，不要复制两份。
     - 记下此刻的 `git rev-parse HEAD`，后面叫 `<base>`。
     - `失败项：${JSON.stringify(chk.failed)}`。红的集成检查就是先失败的测试；缺陷需要新测试才能钉住时照 TDD 补。
     - 逐条 commit（`fix:` 前缀），不 push，不提交 `${changeDir}` 下的飞行记录文件。
     - 收尾运行 `waveCmd(' --fix-base <base>')`，把 JSON 原样作为最终输出。
   - `let wf = await runWaveFix(false)`；`!wf || baseRejected(wf)` → `wf = (await runWaveFix(true)) || wf`（`baseRejected` 现在定义在 Fix 阶段里，把它提到循环之前）。
   - **绿**（`wf && wf.ok && wf.commit && !baseRejected(wf)`）：
     - 派 integrator：label `integrate:w${i + 1}:fix`，`typed('integrator')`，schema `MERGE`；prompt：按第 0 项提交飞行记录 → `python3 ${hooksDir}/slice-gate.py merge wavefix${i + 1}=${wf.commit}`（报 `invalid choice` → 按第 1 项的回退 `git merge --no-ff`；退出 1 → 原样返回 failed、`ok:false`，不再往下）→ `python3 ${hooksDir}/slice-gate.py record --change-dir ${changeDir} --json '<wf 的 JSON 原文，用现有的 shq 引号函数>'` → `timeline.py record wave-fix --note "wave ${i + 1}"` → 再提交飞行记录。抛错或未返回重派一次（label 加 `:retry`）。
     - 合回成功 → push 一个评审：label `review:wavefix${i + 1}`，prompt 用 `reviewPrompt` 的同一套句式，审 `git show --submodule=diff ${wf.commit}`，「切片包」那一行换成「这是 wave ${i + 1} 集成检查红之后的跨片修复，失败项：…」。`wavesOut.push({ wave: i + 1, ok: true, failed: chk.failed, fix: { commit: wf.commit, ok: true, files: (wf.fix || {}).files || [], outside_owns: (wf.fix || {}).outside_owns || [] } })`。
     - 合回失败 → 按「仍红」处理，理由用合回的 `failed`，`kind: 'gate'`。
   - **仍红**：
     - 理由：修复交回了红结论 → `kind: 'gate'`，`wave ${i + 1} 集成检查红，跨片修复后仍红：${wf.failed.join('; ')}（修复提交 ${wf.commit}，未合回）`；两次都没返回 → `kind: 'infra'`，`wave ${i + 1} 集成检查红，跨片修复执行体未返回（已重派一次）：${chk.failed.join('; ')}`；G0 拒绝 → `kind: 'infra'`，理由用它的 `failed`。`blocked.push({ slice: \`wave${i + 1}\`, kind, reason })`。
     - `const last = (wf && !baseRejected(wf) && wf.failed && wf.failed.length) ? wf.failed : chk.failed`；
     - `last.some((f) => f.startsWith('G15'))` → 置一个标志 `stopAll = i + 1`；
     - 否则把本 wave 已合回的切片（`merged` 与 `landedHere`）加进一个只用于依赖判断的集合 `waveBlocked`。
     - `wavesOut.push({ wave: i + 1, ok: false, failed: last, fix: wf ? { commit: wf.commit, ok: false, files: (wf.fix || {}).files || [], outside_owns: (wf.fix || {}).outside_owns || [] } : null })`。
9. 循环开头的依赖跳过：
   - `stopAll` 已置 → 本 wave 的每个切片都 `blocked.push({ slice: s, kind: 'infra', reason: \`wave ${stopAll} 集成检查红（守护），后续切片不再派发\` })`，`continue`；
   - `blockedIds` 现在取自 `blocked`，把 `waveBlocked` 并进去；因它被跳过的切片理由写 `依赖的切片所在的 wave ${n} 集成检查红：…`（文案里要有「集成检查」；`test_workflow_stops_only_dependents_when_tests_red` 只断言 S3 被 blocked、S4 被派发）。
10. 评审：对 `landedHere` 的切片也 push 评审，门禁 JSON 给 `{ slice: s, ok: true, commit: landed[s], failed: [] }`。
11. `return` 加 `waves: wavesOut`。Fix 与 Finalize 阶段不变。

### `template/.claude/agents/integrator.md`

在「## 3. 全量门禁」之前或之后加一项（不改现有各项的编号，新项用下一个号）：**wave 集成检查**——仅当 prompt 点名时运行 `python3 .claude/hooks/slice-gate.py wave-check --change-dir … --wave <i> --of <n>`，把它打印的 JSON 原样放进返回 JSON 的 `check` 字段；它退出 1（红）是正常结论，照样带回，不要自己修、不要重跑；它报 `invalid choice`（hooks 未升级、子命令不存在）→ `check` 写 `null`，`warnings` 记一句。「纪律」里补「集成检查红了不自己修」。正文必须同时出现 `wave-check`、「点名」、`invalid choice`、`null`。

### `template/.claude/agents/slice-executor.md`

在「## 只有四种情况可以不做完就返回」之前加一节「## 跨片修复（prompt 明说时才适用）」，四五行：这是 wave 集成检查红之后的修复派发，不是切片；不运行 `start` 与 `gate`（没有切片标记，owns 限制不适用）；只改让 prompt 列出的失败项变绿所必需的文件，不提交飞行记录；收尾运行 prompt 给的带 `--fix-base` 的 `slice-gate.py wave-check`，把 JSON 原样返回；其余纪律（TDD、一轮多动作、不 push）照旧。frontmatter 不动。

## 注意

- **自举**：本片在 wave 1 合回，本 change 这趟飞行的工作流脚本是起飞时载入的旧版，不会点名集成检查；`integrator.md` 的新项写成「仅当 prompt 点名」正是为此。不要把它写成每次合回都做。
- `tests/test_agents_workflow.py` 与 `tests/test_workflow_resume.py` 在本片 owns 内。现有用例的 mock 里 integrator 返回值没有 `check`，按第 7 条走「跳过」分支，`blocked` 不变，绝大多数用例不用动。确实因为本片而要改的断言（例如整体比较返回值键的）只改必要的那几处，GWT 注释同步。
- `test_label_contract_matches_workflow_script`：`` `integrate:w${i + 1}` ``、`'final-gate'`、`` `review:${s}` `` 三个模板各自只能出现在一行里且与对应的 `typed('…')` 同行。新 label 写成 `` `integrate:w${i + 1}:fix` `` 与 `` `review:wavefix${i + 1}` ``，它们不含上面三个模板的完整文本，不会被数进去；但已落地 wave 的那条 integrator prompt 必须复用同一个派发调用（传不同的 prompt 字符串），不能新写一处带 `` `integrate:w${i + 1}` `` 的调用。
- 模型对账（`session-decompose.py`，不在本片 owns 内，不用改）：`fix:w1` 带 `typed('slice-executor')` 与 `phase: 'Fix'`，两条路都判为 executor；`integrate:w1:fix` 以 `integrate:` 开头；`review:wavefix1` 以 `review:` 开头。
- 工作流脚本不许用 `Date.now` / `Math.random` / `import()`，改完 `node --check` 要过（`test_workflow_script_valid`）。
- `test_workflow_dispatches_cross_slice_fix_on_red` 断言修复 prompt 含 `不受`、`--fix-base`、`slice-gate.py wave-check`、`git merge-base --is-ancestor` 与失败项原文；合回 prompt 含 `merge wavefix1=<sha>` 与 `record --change-dir`。
- `test_workflow_skips_landed_slices` 的第二种情形：第一个 wave 全部已落地，`integrate:w1` 的 prompt 含 `wave-check`、不含 `slice-gate.py merge`。
