# S1 · slice-gate.py：检查的 slice 命令（全局守护）

## 做什么

让 `gate.checks` 的检查可以多带一条 `slice` 命令：lint 认它并与仓库默认清单对账，`plan_sha` 把它计入，baseline 先跑一遍并记录，切片门禁每次都跑、红了记 `G15 guard`。规则原文见 `specs/slice-guards/spec.md` 的前三条 Requirement，决策见 `design.md` D1。

本片不做 `wave-check`（S2），但要把「核对基线记录并运行守护」写成 S2 能直接调用的函数。

## 怎么做

TDD：`tests/test_guard_slice.py` 的 8 条骨架现在是红的（第 9 条 `test_gate_without_guards_unchanged` 是守卫，一直要绿）。

1. **字段与 lint**
   - `CHECK_FIELDS` 加 `"slice"`。`_lint_checks`：`slice` 存在且不是 `None` 时须是非空字符串，否则 `checks: <名> 的 slice 须缺省、null 或非空字符串`。`final` 仍必填。
   - `_repo_default_checks`：现在只返回名字列表。让它同时返回「声明了非空 `slice` 的默认检查名」集合（改返回值形状时把唯一的调用点 `lint_plan` 一起改）。`lint_plan`：某默认检查声明了 `slice`、它出现在 `gate.checks` 里但计划里那一项没有非空 `slice` → `checks: 仓库默认检查 <名> 是全局守护（声明了 slice），计划里的同名检查须带 slice`。写进 `gate.checks_skip` 的不报。
   - 文件头注释里 lint 那一段的字段清单加上 `slice`。
2. **`plan_sha`**：在现有 `checks` 那一段之后，若任一检查的 `slice` 非空，追加 `["slice", [[name, slice], …]]`（只列 `slice` 非空的检查）。没有检查带非空 `slice` 时不追加任何东西——`slice: null` 与不写必须得到同一个值。
3. **两个函数**（名字与签名照 `slices/_interfaces.md`）：
   - `_guard_checks(gate)`。
   - `_run_guards(root, change_dir, checks, baseline, phase, log_tag)`：对每个检查——
     - 取基线记录 `baseline["checks"][名]["slice"]`：基线不存在、记录不存在、`exit != 0`、或 `cmd` 不等于计划里的 `slice` → `G15 guard <名>：基线缺记录或与计划不符，重跑 baseline`，不运行；
     - 否则用 `_check_dir` / `_check_env(phase, change, 基线 commit, cdir)` / `_run_check(cmd, root, env, timeout_sec)` 运行；日志用 `_check_log(cdir, log_tag, out)`（它按 `.gate-<phase>.log` 命名，传 `log_tag` 即得 `.gate-slice-S1.log` / `.gate-wave.log`）；
     - 超时 → `_check_msg("G15 guard <名>：超时 N 秒", log, out)`；非 0 → `_check_msg("G15 guard <名>：exit N", log, out)`；
     - 共用目录不可用 → `G15 guard <名>：共用目录不可用：…`。
     - 运行过的记进 `guards[名] = {"exit", "sec"}`。
4. **baseline**（`cmd_baseline` 里「成对检查的 baseline 半」那个循环）：
   - 现在 `bcmd` 为空就 `continue`。改成：`baseline` 与 `slice` 都没有才跳过；`bl["checks"][名]` 在只有 `slice` 时也要建出来（只含 `slice` 一段）。
   - `baseline` 命令处理完之后，若该检查有 `slice`：`_check_env("slice", …)` 运行，结果记 `bl["checks"][名]["slice"] = {"exit", "sec", "cmd"}`；超时加 `timed_out` 并判红；非 0 → `reasons.append(_check_msg("check <名> 的 slice 命令在基线上红（exit N）", log, out))`；超时的文案 `check <名> 的 slice 命令在基线上超时（N 秒）`。
   - 沿用：与该检查 `baseline` 命令相同的条件（`strict_delta == []`、旧记录绿、`cmd` 相同、共用目录仍在）下沿用旧的 `slice` 记录并加 `reused: True`。注意清空共用目录的那一步现在只在跑 `baseline` 命令时发生；只有 `slice` 的检查不清空目录，但要保证目录存在。
   - 日志名 `.gate-slice.log`（基线里没有切片 id）。
5. **切片门禁**（`cmd_gate`）：在 `for key in ("lint", "typecheck")` 循环之后、`hold.release()` 之前：
   - `gchecks = _guard_checks(gate)`；非空时 `gf, guards = _run_guards(root, args.change_dir, gchecks, baseline, "slice", "slice-" + args.slice)`，`failed.extend(gf)`；
   - `result["guards"] = guards`（只在 `gchecks` 非空时加这个键）；
   - 时间线：`segs` 里在分层片段之后、锁片段之前加 `守护 <名> Xs[ / <名> Ys]`（只列运行过的；一个都没运行时不加）。
6. 文件头注释：`gate` 的说明补「G15（计划里带 slice 的检查）」，`baseline` 的说明补一句。

## 注意

- `tests/test_gate_checks_baseline.py` 有对 `bl["checks"]` 形状的断言：没有 `slice` 的检查，记录里不得多出任何键。
- `tests/test_gate_checks_final.py`：`_final_checks` 不动；final 不运行 `slice` 命令。
- `plan_sha` 被 preflight 与基线复用共用，`tests/test_plan_hygiene_baseline.py`、`tests/test_slice_gate_baseline_preflight.py` 钉着旧计划的行为：不带 `slice` 的计划一个字节都不能变。
- `guard_gate` 夹具手写了一份最小的 `gate-baseline.json`（没有 `snapshot`、`cmd_key` 等字段）：`cmd_gate` 读基线的地方不要因为这些字段缺失而抛错（现状不会）。
- `test_gate_g13_needs_green_baseline_record` 的第二种情形：基线记录的 `cmd` 是 `true`，计划里是另一条命令。
- `slice` 阶段不清空、不写共用目录的状态；只写日志。
- 本 change 自己的计划没有任何检查带 `slice`，本片合回后本次飞行的门禁行为不变。
