### `template/.claude/flight-runner-contract.md`

在文末新增一节，节号接现有最后一节（现在最后一节是「## 9. 测试账本」，所以是 `## 10. 全局守护与 wave 集成检查`；动手时最后一节若已不是第 9 节，就接它的下一个号——测试只按标题里的「全局守护」找这一节）。内容：

- **`slice` 字段**：`gate.checks` 的检查可多带一条 `slice` 命令（非空字符串）；`gate-checks.json` 里声明了 `slice` 的默认检查，计划里的同名检查必须带上；它进 `plan_sha`（改了要重跑 baseline）。
- **在哪跑**：baseline（证明起点是绿的，记 `checks.<名>.slice`）、每片门禁（红记 `G15 guard <名>`）、每个 wave 合回后的集成检查（`slice-gate.py wave-check`）。final 不跑它（final 跑的是该检查的 `final` 命令）。
- **环境变量**：`GATE_PHASE` 多两个取值，`slice`（baseline 与切片门禁）与 `wave`（集成检查）；`GATE_CHANGE` / `GATE_BASE_COMMIT` / `GATE_CHECK_DIR` 与 baseline / final 相同。用一张小表列 `GATE_PHASE` 的四个取值与对应时机。
- **并行与只读**：同一 wave 的多个切片会并行调用 `slice` 命令，并且共用 `GATE_CHECK_DIR`；`slice` 命令对共用目录只读（或自己保证并发安全）。日志：门禁 `.gate-slice-<切片 id>.log`，基线 `.gate-slice.log`，集成检查 `.gate-wave.log`。
- **要快**：它在每片门禁里跑，应当是秒级；`timeout_sec` 照常生效。
- **wave 集成检查的测试那一半**：按依赖图只重跑受影响的测试（与增量 final 同一选法），新增失败记 `G16 wave test`；没有可用锚点、估算超过 `gate.wave_test_budget_sec`（缺省 120 秒）、配了分层文件或 `gate.impacted` 时跳过并在时间线写明，不退化成全量；`GATE_PHASE` 对 `gate.test` 环境同样是 `wave`。
- **不做什么**：集成检查不写锚点、不写测试账本。

该节正文必须出现：`` `slice` ``、`GATE_PHASE`、`` `wave` ``、「并行」、「只读」、`.gate-slice-`、`G15`、`G16`、`wave_test_budget_sec`。

第 2 节「`GATE_PHASE` / `GATE_CHANGE`」里若列举了取值，补上新取值并指向新的一节（标题不改）。
