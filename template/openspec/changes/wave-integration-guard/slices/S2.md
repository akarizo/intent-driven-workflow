# S2 · slice-gate.py：wave-check 子命令、record 认 wave 行、ship 读 wave 行

## 做什么

新增 `slice-gate.py wave-check`：每个 wave 合回后的集成检查，跑全部守护与受影响的测试，结论进 `gate-report.md`（切片列 `wave`）与时间线（事件 `wave-check`）。`record --json` 能把它的 JSON 写回分支；`ship` 见到最新的 `wave` 行是红的就判 draft。规则原文见 `specs/wave-check/spec.md` 的前四条 Requirement，决策见 `design.md` D2、D5。

## 依赖的接口

见 `slices/_interfaces.md` 的 S1 节：`_guard_checks(gate)`、`_run_guards(root, change_dir, checks, baseline, phase, log_tag)`。本片以 `phase="wave"`、`log_tag="wave"` 调用。

## 怎么做

TDD：`tests/test_wave_check.py` 的 9 条骨架现在是红的。

### `cmd_wave_check(args)`（参数：`--change-dir`、`--wave`（int，可选）、`--of`（int，可选）、`--fix-base`（可选））

1. `root = toplevel()`，读计划与基线，`change_rel`、`name` 的取法同 `cmd_final`。
2. **`--fix-base`**（给了才做）：
   - `git cat-file -e <sha>^{commit}` 失败、或它不是 HEAD 的祖先（`_is_ancestor`）→ `failed = ["G0 base: --fix-base <sha> 不存在或不是 HEAD 的祖先"]`，跳过守护与测试，直接到第 6 步输出（`guards` 为 `{}`，`tests.mode` 为 `skipped`、`why` 为 `基点校验未通过`）；
   - `files = sorted(git diff --name-only <sha> HEAD)`；其中是本 change 飞行记录的（`<change_rel>/` 下的 `FLIGHT_RECORDS`）→ 每个一条 `G6 flight-record: <路径> 属飞行记录，跨片修复不得提交`；
   - `outside = [f for f in files if not any(glob_match(f, o) for o in _planned_owns(data))]`；
   - `result["fix"] = {"base": sha, "files": files, "outside_owns": outside}`。
3. **先定测试那一半跑不跑**（要在取锁之前知道，锁的方式取决于它）。按下面的顺序，命中即 `mode = "skipped"` 并记 `why`：
   - `_load_tiers(change_dir)[0] is not None` → `分层仓库：受影响测试留给 final`；
   - `gate.get("impacted")` → `gate.impacted 选测留给 final`；
   - 取锚点：与 `final_forecast` 同一套步骤（`_anchor_key` / `_tiers_key` / `_snapshot` / `_scope_extras` / `_inert_drop(…, recon=False)[0]` / `_pick_anchor` / `_hops_cap`），再调 `_full_why(root, False, pick, bl, snap_why, gate=gate, tier_rel=…, decl_rels=…, declared_global=extras["global"], hops_cap=hcap)`；基线带 `deps_unmeasured` 且没有锚点时把 `why` 换成 `依赖图未测（…）：…`（`final_forecast` 里有同一句）。`why` 非空 → 跳过，原因就是它。优先把这段抽成 `final_forecast` 也能用的内部函数；不管怎么抽，`final_forecast` 的返回值一个字都不能变。**不要**走无图退路（`_tests_only_pick`）。
   - `sel = _final_select(root, anchor, delta, extras["blind"])`；
   - 估算：`secs = anchor.get("secs")`；是 dict 时 `est = round(sum(v for n, v in secs.items() if n.split("::", 1)[0] in sel 且 v 是数), 1)`，否则 `est = None`；
   - 预算：`gate.get("wave_test_budget_sec")` 是正数用它，否则 `WAVE_TEST_BUDGET_SEC = 120`；`est is not None and est > budget` → 跳过，`why = "受影响测试约 %s 秒（%d 个文件），超过预算 %s 秒，留给 final"`；
   - `sel` 为空 → `mode = "none"`；否则 `mode = "impacted"`。
4. **取锁**：`flight_lock("exclusive" if mode == "impacted" else "shared", name, "wave %s" % (args.wave or "?"), est 或 _lock_expect_sec(baseline, gate))`。
5. **锁内**：
   - 守护：`gf, guards = _run_guards(root, args.change_dir, _guard_checks(gate), baseline, "wave", "wave")`；
   - `mode == "impacted"` 时：`outcomes, rc, text, timed_out = _pytest_outcomes(root, sel, gate, extra_env=_gate_test_env("wave", args.change_dir))`；计时；
     - `timed_out` → `G16 wave test：重跑受影响测试超时`；
     - 否则 `fails = sorted({n for n, o in outcomes if o in ("FAILED", "ERROR")} - 预存红)`，预存红 = 基线 `test.failed_nodes` ∪ 锚点 `failed`（都按 nodeid）；非空 → `G16 wave test：新增失败 %d 条：%s`；
     - 否则 `rc not in (0, 1, 5) or "ERROR collecting" in text` → `G16 wave test：exit %s` 加 `_tail(text)`（`rc == 1` 而没有新增失败时是预存红，不算）。
   - 放锁。
6. **输出与记录**：
   - `result = {"slice": "wave", "ok": not failed, "commit": HEAD, "failed", "warnings", "summary", "wave": args.wave, "of": args.of, "guards": guards, "tests": {"mode", "why", "files": sel 或 [], "rerun_tests": 重跑到的用例数或 None, "est_sec": est, "sec": 测试墙钟（没跑为 0.0）, "budget_sec": budget}, "lock": hold.info}`（有 `fix` 时带上）；
   - `append_report(args.change_dir, result)`；
   - 时间线：`timeline_record(args.change_dir, "wave-check", _wave_note(result))`；`_wave_note` 单独写成函数（`record` 也用），格式见 `slices/_interfaces.md`：`wave N/M`（缺的用 `?`）· 守护段（没有守护时省略）· 测试段（`测试 12.3s（3 个文件）` 或 `测试跳过（原因）`）· 跨片修复段（有 `fix` 且无 G0 时：`跨片修复 A 个文件（owns 外 B 个）`）· 锁片段（`_lock_note(result.get("lock"))`，JSON 里没有 `lock` 时省略）；各段以 ` · ` 相连，最后空格加 `ok` / `red`；
   - 打印 JSON，退出码 `0 if ok else 1`。
7. argparse 注册子命令 `wave-check`；文件头的子命令清单与 JSON 契约各补一段。

### `cmd_record`

`result.get("slice") == "wave"` 时：时间线事件改记 `wave-check`、备注用 `_wave_note(result)`；其余路径（幂等判断、`append_report`、`record_ceilings`）不变。其它切片的行为不变（仍记 `gate` 事件）。

### `cmd_ship`

在 final 的判定之后加：`w = latest.get("wave")`；`w is not None and not w["ok"]` → `reasons.append("wave 集成检查红：%s（修复后重跑 slice-gate.py wave-check）" % w["failed"])`。这段放在 `if os.path.isfile(plan_path)` 分支里（与切片行、final 行同处）。输出键不变。

### lint

`lint_plan`：`gate.wave_test_budget_sec` 存在时须是正数（非 bool），否则 `gate: gate.wave_test_budget_sec 须是正数`。它不进 `plan_sha`。

## 注意

- 不写锚点、不落账：不要调用 `_anchor_write`、`_ledger_commit`、`_final_rec_write` 之类；`test_wave_check_leaves_anchors_and_ledger_alone` 钉着。
- `test_wave_check_skips_tests_over_budget` 改写了锚点文件的 `secs`（把 `tests/test_a.py::test_a` 记成 500 秒）并在第二次运行前改了工作树里的 `slices.json`（未提交）：计划文件在 change 目录里，不进内容快照，锚点仍然可用。
- `test_wave_check_skips_tests_without_anchor` 的仓库基线带 `deps_unmeasured`：`why` 非空即可，文案不限。
- `test_wave_check_fix_base_lists_files_outside_owns` 的第二次运行是在第一次写出的 `timeline.md` / `gate-report.md` 被提交之后：`SHA..HEAD` 里出现了飞行记录文件。
- 带守护的三条骨架依赖 S1：基线要先记下 `checks.layering.slice`。
- `ship` 的 `report_latest` 已经按切片名取最后一行，`wave` 不需要特殊解析。`tests/test_ship_verdict.py` 里没有 `wave` 行的用例必须不受影响。
- `gate-report.md` 的列是 `| 时间 | 切片 | ok/red | commit | failed |`（`report_latest` 的解析），`append_report` 已经会写。
- `--wave` / `--of` 只进文案；不给时 JSON 里是 `null`。
