## 怎么做

TDD：`tests/test_wave_docs.py` 的 3 条骨架现在是红的。全部是增补，现有句子不删不改（它们被二十多个文档测试按子串钉着）。

### `template/.claude/commands/opsx-apply.md` 与 `template/.claude/skills/openspec-apply-change/SKILL.md`（两份同改）

1. **切片规划 lint 那一步**（运行 `turns` 的那句之后）：再运行 `python3 .claude/hooks/slice-gate.py landed --change-dir openspec/changes/<name>`，stdout 的 JSON（已落地的切片 → 门禁行里的 commit）原样作为 `landed` 传给工作流；首次起飞是 `{}`；报 `invalid choice`（hooks 未升级）就不传。一句话说明用途：补计划后重新起飞时，已落地的切片不再派执行体，评审与集成检查照做。
2. **启动工作流那一步**：args 说明里加「同时传 `landed: <上一步 landed 的输出>`」。
3. **回退路径那一长段**（Workflow 不可用时用 Agent 派发）追加，语义与脚本逐项一致：
   - `landed` 里的切片不派执行体，评审照派；
   - 每个 wave 合回并 `record` 之后，integrator 运行 `python3 .claude/hooks/slice-gate.py wave-check --change-dir <dir> --wave <i> --of <n>`（整个 wave 都已落地时只运行它、不合回），把 JSON 带回；子命令不存在（`invalid choice`）→ 跳过，照常往下；
   - 它是红的 → 当场派一次**跨片修复**（`slice-executor`，`isolation: worktree`，不运行 `start` / `gate`、不受 owns 限制，先做与批量修复相同的基点校验与 `sub-sync`，收尾运行带 `--fix-base <开工时的 HEAD>` 的 `wave-check`）；未返回、抛错或 G0 拒绝重派一次；
   - 修复绿了 → integrator 用 `slice-gate.py merge wavefix<i>=<commit>` 合回、`record --json` 写回、记 `wave-fix` 事件，并为该 commit 派一个评审；
   - 仍红 → 不合回，记 blocked（`wave<i>`）；失败项里有 `G15`（守护红）→ 后面的 wave 全部停下并记 blocked；只有 `G16` → 只停依赖本 wave 切片的下游切片。
   - 「最终都产出同一份 JSON」那一句的字段清单加 `waves`。
4. **收口分解那一步**：「把工作流返回的 `{blocked, blocking, deferred, fix}` 原样写入 `review-findings.json`」改为把 `waves` 也写进去（同一行里要同时出现 `waves` 与 `review-findings.json`）；`ship` 的说明加一句：reasons 里出现「wave 集成检查红」→ 修复后重跑 `slice-gate.py wave-check` 再 `ship`。

### `template/.claude/commands/pr-ship.md`

- 起草正文的那一步加一条：`review-findings.json` 的 `waves` 里带 `fix` 的条目列成「跨片修复」一节（wave 号、修复 commit、改动文件、其中落在所有切片 owns 之外的文件）；没有就不写这一节。这一条的同一行里要同时出现 `waves` 与「跨片修复」。
- 跑 `ship` 的那一步加一句：reasons 出现「wave 集成检查红」→ 修复后在 change worktree 里重跑 `python3 .claude/hooks/slice-gate.py wave-check --change-dir …`，再 `ship`。

### `README.md`

在「成对检查（`gate.checks`）」那一条附近加条目，各一两句：

- **全局守护**：检查可带 `slice` 命令，baseline、每片门禁（`G15 guard`）与每个 wave 合回后都运行；细则见契约文档的「全局守护」一节。
- **wave 集成检查**：`slice-gate.py wave-check`，守护 + 受影响的测试；没有锚点、估算超过 `gate.wave_test_budget_sec`（缺省 120 秒）或配了分层文件时测试那一半跳过并写明原因；红了工作流当场派跨片修复；如实写明：改动波及面大的仓库（例如几乎所有测试都依赖的文件被改）测试那一半会被预算挡下，集成检查只剩守护。
- **owns 上限与 `owns_wide`**：标准档 12 条、大片档 30 条；单条通配展开超过 20 个现存文件要在 `owns_wide` 写理由。
- **重新起飞**：`slice-gate.py landed` 列出已落地的切片，重新起飞时不再派它们的执行体。
