# S3 · slice-gate.py：owns 条数上限随轮次档、宽通配写理由；landed 子命令

## 做什么

两件互不相干、但都落在 `slice-gate.py` 里的事：

1. lint 的 owns 规则：条数上限从固定 12 改为按轮次档（标准档 12、大片档 30）；单条通配展开出多于 20 个现存文件时要在该片的 `owns_wide` 里写理由；通过时把每条通配的展开数打印出来。规则见 `specs/owns-tiers/spec.md`，决策见 `design.md` D6、D7。
2. 新子命令 `landed`：列出已落地的切片，供重新起飞时跳过。规则见 `specs/retakeoff-landed/spec.md` 的第一条 Requirement，决策见 `design.md` D8。

## 怎么做

TDD：`tests/test_owns_tiers.py` 的 4 条与 `tests/test_landed.py` 的 2 条骨架现在是红的。

### owns 规则（`lint_plan` 的切片循环）

- 常量：`OWNS_CAP = {"standard": 12, "large": 30}`（保留 `MAX_OWNS = 12` 作为标准档的值或直接替换，别留两个不同步的数）、`OWNS_WIDE_FILES = 20`。
- 现有的 `turn_root` / `turn_tree` 只在有切片写 `"turns": "standard"` 时才取。改成按需取：有切片写 `standard`、或有切片 owns 多于 12 条、或有切片的 owns 带通配符（`*` `?` `[`）时取；`change_dir` 为 `None` 或不在 git 仓库里 → 不取，下面依赖文件数的判断全部跳过。
- 条数：`n = len(owns)`。`n > 12` 时定档：计划写 `"turns": "large"` → 大片档；否则能数文件且 `_owned_file_count(turn_root, turn_tree, owns) > TURN_LARGE_FILES` → 大片档；否则标准档。`not (1 <= n <= OWNS_CAP[档])` → `owns: %s 的 owns 有 %d 条，%s须在 1–%d 内（标准档 1–12，大片档 1–30；这一片要更多条目先写 "turns": "large"）`。`n <= 12` 的切片不数文件。`n == 0` 仍按原规则报错。
- `owns_wide`（可选）：不是对象 → `owns: %s 的 owns_wide 须是对象（owns 条目 → 理由）`；键不在该片 owns 里 → `owns: %s 的 owns_wide 有多余的键 %s（须是该片的 owns 条目）`；值不是非空字符串 → `owns: %s 的 owns_wide 里 %s 的理由须是非空字符串`。这三条不依赖 git。
- 宽通配（能数文件时）：对每条带通配符的 owns 条目 `o`，`k = _owned_file_count(turn_root, turn_tree, [o])`；记下 `(切片 id, o, k)`。`k > OWNS_WIDE_FILES` 且 `o` 不在 `owns_wide` 里：
  - change 的时间线已有 approve 事件（`_has_approve(change_dir)`）→ 不判红，记一条提示 `owns: %s 的 %s 展开出 %d 个现存文件（> 20），新计划须在 owns_wide 里为它写理由`；
  - 否则 → `errors.append("owns: %s 的 %s 展开出 %d 个现存文件（> 20），须在该片的 owns_wide 里为它写理由")`。
- 打印：`lint_plan` 末尾现有 `if scope_note and not errors: sys.stderr.write(...)`。同样在没有错误时，为每条带通配的条目写一行 `owns: <切片> <条目> → <k> 个文件`，再写上面的提示行。
- 文件头注释与 `tasks.md` 无关（那是 S6 的 schema）；只改 `slice-gate.py` 头部 lint 段的说明。

### `cmd_landed(args)`

1. `data = load_plan(...)`；`lint_plan(data, args.change_dir, run_scope=False)` 有错 → 与 `cmd_turns` 一样 `die`（退出 2）。
2. `root = toplevel(args.change_dir)`；`latest = report_latest(args.change_dir)`；`change_rel = _change_rel(root, args.change_dir)`。
3. 对计划里的每个切片 `s`，全部满足才收进输出 `{s["id"]: row["commit"]}`：
   - `row = latest.get(s["id"])` 存在且 `row["ok"]`；
   - `git rev-parse --verify <commit>^{commit}` 成功（门禁行里是 10 位前缀，能解析即可）且 `_is_ancestor(root, 解析出的 sha, "HEAD")`；
   - `git diff --quiet <sha> -- <change_rel>/slices/<id>.md <change_rel>/specs` 退出 0（对比的是那个 commit 与当前工作树；路径不存在于两边时 git 也返回 0，没问题）；
   - `git show <sha>:<change_rel>/slices.json` 能读出 JSON，其中该片条目去掉 `owns`、`owns_wide` 后与当前计划里该片条目去掉这两个键后相等。读不出或没有该片 → 不算落地。
4. `print(json.dumps(out, ensure_ascii=False))`，退出 0。
5. argparse 注册 `landed`；文件头子命令清单补一行。

## 注意

- `tests/test_turn_tiers.py` 钉着 `turns` 的行为：`"turns": "standard"` 而规模是大片档仍然判红，文案不变。
- 13 条 owns、现存文件 13 个的切片（`test_owns_cap_follows_turn_tier` 的 S1）要判为大片档并通过；同一用例里 S2 是 13 条 owns、2 个现存文件，判标准档超限——错误信息里要同时出现 `S2 的 owns`、`12` 与 `30`，且不能出现 `S1 的 owns`。
- `test_wide_glob_needs_reason`：`lib/*.py` 展开 21 个文件，切片只有这 1 条 owns，按规模是大片档——宽通配规则与档位无关。
- `test_approved_change_not_reddened_by_wide_rule`：`timeline.md` 在计划提交时一起提交了，里面有一行事件列为 `approve`。
- `_owned_file_count` 对每条通配各调一次 `git ls-tree`：只对带通配符的条目调，字面路径不调。计划里通配很多时把 `ls-tree` 的输出缓存在本次 `lint_plan` 调用内。
- `lint_plan` 被 `lint` / `waves` / `turns` / `preflight` / `baseline` 共用，stderr 多出的行不能影响它们的 stdout（仍只有 waves JSON 等）。
- `test_landed_lists_green_merged_slices` 里 S3 的门禁行 commit 是 `ffffffffff`（不在对象库）；`record` 写进 `gate-report.md` 的 commit 列只有前 10 位。
- `landed` 只读，不写任何文件、不记时间线。
- 本片是三个 wave 里最后改 `slice-gate.py` 的一片。
