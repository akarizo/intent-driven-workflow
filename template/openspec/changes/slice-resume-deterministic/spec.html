Why · 01为何而做

afa 的 key-features-keyft 飞行里，切片的「接着干」有四处靠运气（交接文档 F1 / F2 / F3 / F11）：

- 轮次上限不看切片大小。执行体定义里 maxTurns: 40 是常数。回放本机六个仓库的 1124 个执行体转录，取其中带 40 轮上限、能对上计划的 821 个首轮：计划时 owns 展开不超过 8 个现存文件的切片，撞 40 轮或未交回的占 5.5%；超过 8 个的占 28.4%（数据与脚本在 calibration/）。大切片几乎注定要重派，重派又要花十几轮看清现场。 - 重派由 prompt 指挥 git。重派的「第零步」只 cherry-pick 上一轮的最后一个提交，上一轮有两个提交时丢掉前一个；跨工作流续跑时沿用 prompt 回传的旧区间起点，把 change 分支后来的飞行记录提交算进切片，门禁误报「执行体不得提交飞行记录」。 - 撞上限只留一句「agent 未返回」。看不出是哪一档、续跑过几次、半成品在哪。 - 临时 worktree 的东西回不到分支，也没人收。切片的测试留痕写在临时 worktree 里，分支上的 evidence.log 没有任何切片行，评审员按 prompt 去读只能读到空；执行体跑的是包装脚本（命令里没有 pytest 这类字样）时一行都不记，门禁就报「无 evidence.log（hook 未安装或未触发）」，而 hook 其实在工作。合回之后临时 worktree 留在磁盘上，afa 一度积到约 64G。

这四处都能由脚本确定地做掉，不该留给模型临场处理。

What · 02变更范围

  • 接续收进 start：slice-gate.py start <S> --continue <上一轮 commit> 由脚本把上一轮的全部提交接到当前 HEAD（能快进就快进，否则按区间逐个重放），冲突时自己回滚并以 G0 base 退出。工作流的重派 prompt 去掉「第零步 cherry-pick」。
  • 区间起点由脚本算：带 --expect-branch 时，起点恒为 HEAD 与 change 分支的合并基点，不再采用 prompt 回传的 --base。
  • 轮次按切片大小分两档：标准档 40 轮、大片档 80 轮。档位由 slice-gate.py turns 按「owns 展开后在基线 commit 上的现存文件数」算（超过 8 个为大片档），计划里可以用 "turns": "large" 把小片升档，不能把大片降档。工作流按档位选执行体定义文件；大片档是一份只有 frontmatter 加一句指向的薄定义 slice-executor-large.md。审批页的切片表显示档位。
  • 撞上限说清楚：执行体重派后仍未交回时，blocked 理由写明档位与该档上限、本次飞行内已重派一次、半成品快照所在的 ref。
  • 切片留痕写进 git 共用目录：test-evidence.py 在有切片标记时把留痕写到 <git common dir>/flight-evidence/<change>/<切片>.log，任何 Bash 调用都留一个空文件作心跳；除了认运行器名字，还认本片 verify 与 gate.test 里出现的脚本路径。门禁从共用目录读（上一轮在别的 worktree 留下的也算），integrator 记录门禁结论时把本片的行并进分支上的 evidence.log。
  • 合回后回收临时 worktree：slice-gate.py merge 成功合回一片后，把 HEAD 停在该片提交上、且除飞行记录与字节码外没有未提交改动的临时 worktree 移除，并删掉它那条已合入的临时分支。不用强制参数，删不掉就留着并写进 warnings。铁律 6 的措辞同步。
  • 命令文档与同名 skill 的回退路径、README、安装脚本的 agent 清单随之更新。

Specs · 04行为规范 (Gherkin)

slice-continue ADDED

Requirement: start 接上一轮的全部提交

slice-gate.py start <S> SHALL 接受 --continue <commit>，在基点校验之后、子仓填充之前把上一轮属于本片的提交接到当前 HEAD：<commit> 已是 HEAD 的祖先时不做任何事（mode 为 noop）；HEAD 是 <commit> 的祖先时快进到它（mode 为 ff）；否则把 git rev-list --reverse <commit> --not HEAD 列出的提交按原顺序逐个重放（mode 为 pick）。成功时 stdout 的 JSON SHALL 多一个 continued，形如 {"from": <commit>, "mode": "noop" | "ff" | "pick", "applied": <接上的提交数>}。<commit> 不在对象库、区间里有合并提交、或重放冲突时，脚本 MUST 自己撤销已做的重放并回到接续前的 HEAD，MUST NOT 写切片标记，stdout 打印 {"slice", "ok": false, "commit": "", "failed": ["G0 base: 接续 …"], …} 并以 1 退出；冲突时 failed 首项 MUST 点名冲突文件。子仓按接续之后的 gitlink 填充。 Feature: 重派的切片从上一轮停下的地方继续 Rule: 上一轮有几个提交就接几个；接不上就原样退回，不留半截

Scenario: continue-replays-all-previous-commits

  • GIVEN上一轮执行体在基点 T 上提交了两次
  • ANDchange 分支随后多了一个飞行记录提交 R，重派的临时 worktree 从 R 分叉
  • WHEN在该 worktree 里运行 start S1 --continue <第二个提交> --expect-branch <change 分支>
  • THEN退出 0，两个提交按原顺序出现在 R 之上，两处改动的文件都在场
  • AND输出的 continued 为 {"from": <第二个提交>, "mode": "pick", "applied": 2}
  • AND输出与切片标记里的 base 都是 R

Scenario: continue-fast-forwards-descendant

  • GIVEN上一轮执行体在基点 T 上提交了两次，change 分支没有前进
  • AND重派的临时 worktree 从 T 分叉
  • WHEN运行 start S1 --continue <第二个提交> --expect-branch <change 分支>
  • THEN退出 0，HEAD 就是上一轮的第二个提交，没有产生新提交
  • ANDcontinued 的 mode 为 ff、applied 为 2，base 为 T

Scenario: continue-conflict-rolls-back-with-g0

  • GIVEN上一轮改了 src/a.py，change 分支随后合回了对同一文件的不同改动
  • AND重派的临时 worktree 从分支最新提交分叉
  • WHEN运行 start S1 --continue <上一轮的提交> --expect-branch <change 分支>
  • THEN退出 1，JSON 的 ok 为 false、commit 为空，failed 首项以 G0 base 开头并含「接续」与 src/a.py
  • ANDHEAD 回到分叉时的提交，工作树干净，没有切片标记

Scenario: continue-noop-when-already-applied

  • GIVEN上一轮的 worktree 里切片标记还在，HEAD 已含上一轮的全部提交
  • WHEN连续两次运行 start S1 --continue <上一轮的最后一个提交> --expect-branch <change 分支>
  • THEN两次都退出 0，HEAD 不变，continued 为 {"from": …, "mode": "noop", "applied": 0}
  • AND标记里的 base 仍是首轮记下的值

Scenario: continue-populates-submodule-at-new-gitlink

  • GIVEN带 submodule 的仓库，上一轮执行体提交了子仓 s1 与父仓 C1（gitlink 指向 s1）
  • AND重派开了一间子仓尚未填充的临时 worktree
  • WHEN运行 start S1 --continue C1 --expect-branch <change 分支>
  • THEN退出 0，父仓 HEAD 是 C1
  • AND该 worktree 的子仓检出在 s1 上，上一轮的文件在场

Requirement: 门禁区间的起点由脚本按 change 分支算

start 带 --expect-branch <B> 时，写进切片标记与输出的 base SHALL 是 HEAD 与 B 的合并基点（接续完成之后计算）；同时给了 --base 且与之不同的，MUST 以算出的为准。不带 --expect-branch 时 --base 照旧生效、缺省为 HEAD。同片标记已存在时标记 MUST 原样保留。切片门禁据此算出的区间 MUST NOT 包含 change 分支自己的提交。 Feature: 切片的改动范围不受分支上别的提交干扰 Rule: 有 change 分支可对照时，起点不采信调用方回传的旧值

Scenario: base-is-branch-merge-base

  • GIVEN上一轮在旧基点 T 上提交了一次，change 分支此后多了两个只改飞行记录的提交
  • AND重派的临时 worktree 从分支最新提交分叉，并已把上一轮的提交接上
  • WHEN运行 start S1 --base T --expect-branch <change 分支>，再运行 gate S1
  • THENstart 退出 0，base 是分支最新提交，不是 T
  • AND门禁 JSON 的 base 与之相同，failed 里没有 G6 项

Requirement: 工作流的重派经 start 接续

opsx-apply 工作流在上一轮交回了带 commit 的门禁 JSON 而需要重派时，执行体 prompt 里的 start 命令 SHALL 带 --continue <上一轮 commit> 与 --expect-branch，MUST NOT 带 --base，prompt MUST NOT 再有要求执行体手工接提交的「第零步」。prompt SHALL 写明 hooks 未升级时的回退：start 报 unrecognized arguments 时，HEAD 不是该提交就 git cherry-pick 它，再运行不带 --continue 的 start。执行体定义 slice-executor.md SHALL 说明 --continue 由脚本接上一轮的提交、输出里有 continued、start 非 0 退出时原样返回其 JSON。命令文档 opsx-apply.md 与同名 skill 的回退路径 SHALL 用同样的做法描述重派。 Feature: 重派 prompt 不再指挥 git Rule: 接续交给 start；文档与脚本说同一件事

Scenario: workflow-retry-continues-via-start

  • GIVEN某切片首轮门禁红，门禁 JSON 带 commit
  • WHEN工作流重派该切片
  • THEN重派 prompt 里的 start 命令带 --continue <该 commit> 与 --expect-branch，不带 --base
  • ANDprompt 不含「第零步」，只在 hooks 未升级的回退句里提到 cherry-pick 与 unrecognized arguments
  • ANDprompt 仍要求只修上一轮红的门禁项

Scenario: executor-contract-describes-continue

  • GIVEN执行体定义 slice-executor.md
  • WHEN阅读它的开工段与预算条
  • THEN写明重派时 start 带 --continue、输出带 continued，不再有「第零步」
  • AND预算条指向 frontmatter 的上限并点名 slice-executor-large
  • AND--resume-checkpoint、--expect-branch、checkpoint.restored、recovered、G12 的说明仍在

Scenario: apply-docs-mirror-continue-and-tiers

  • GIVEN命令文档 opsx-apply.md 与同名 skill openspec-apply-change/SKILL.md
  • WHEN阅读两份文档的起飞步骤与回退路径
  • THEN两份都写明起飞前运行 slice-gate.py turns --change-dir … 并把结果作为 turns 传给工作流
  • AND回退路径的重派用 start --continue，大片档派 slice-executor-large，全文不含「第零步」
  • AND回退路径写明未返回的 blocked 理由带档位与 refs/flight/ 下的快照位置，--resume-checkpoint 的说明仍在

slice-evidence-shared ADDED

Requirement: 切片的测试留痕写在 git 共用目录

test-evidence.py 在工作树根有切片标记时 SHALL 把留痕写到 <git common dir>/flight-evidence/<change>/<切片>.log（<change> 为标记里 change 目录的目录名），行格式不变：ISO 时间\t切片\tPASS|FAIL\t命令前 120 字符；此时 MUST NOT 写工作树里的 <change>/evidence.log。有标记时任何 Bash 事件都 SHALL 确保该文件存在（没有可记的行时是空文件）。命令被认作测试运行的条件 SHALL 是：命中原有的运行器名字，或命令文本包含本片 verify 或计划 gate.test 里的脚本路径记号（按空白与 ; & | ( ) 引号切开后，含 / 且以 .sh、.py、.js、.mjs、.ts 结尾的记号）；读不到计划时只按运行器名字认。没有切片标记时行为 MUST 不变。hook 任何异常 MUST 静默并以 0 退出。 Feature: 同一仓库的任何 worktree 都读得到切片的留痕 Rule: 留痕按切片分文件放在共用目录；文件在就说明 hook 在工作

slice-worktree-reap ADDED

Requirement: 合回后回收切片临时 worktree

slice-gate.py merge 每成功合回一片 <S>=<sha> 后，SHALL 回收这样的 worktree：不是当前 worktree，且 HEAD 落在这次合并带进来的提交里（git rev-list <sha> --not <合并前的 HEAD>）。回收前它的未提交改动里除三类之外 MUST 为空：change 目录下的飞行记录（timeline.md / gate-report.md / evidence.log）、切片标记、未跟踪的字节码；这三类由脚本丢弃。回收 SHALL 用不带强制参数的 git worktree remove；该 worktree 有自己的分支且分支正指向那个 HEAD 时，随后用 git branch -d 删除它。借出的子仓 worktree SHALL 先归还（在 change 家的子仓里不带强制参数移除），前提是它的 HEAD 已是 change 家子仓 HEAD 的祖先且除字节码外没有未提交改动。输出 JSON 在有回收时 SHALL 多一个 reaped（被回收的路径数组）；没有回收时 MUST NOT 出现这个键。任何一间不满足条件或移除失败时 MUST 原样留下，在 warnings 里写「未回收 <路径>：<原因>」（有未提交改动时点名文件）；回收的成败 MUST NOT 影响 ok、merged、failed 与退出码。HEAD 不在上述提交集合里的 worktree MUST NOT 被触碰。 Feature: 合回的切片不再占着磁盘 Rule: 只收「提交已合回、没有别的未合回内容」的；收不掉就留着并说明

Scenario: merge-reaps-merged-slice-worktrees

  • GIVEN两间切片临时 worktree 各提交了一个文件，各有自己的临时分支
  • AND里面只剩门禁留下的飞行记录改动与未跟踪的字节码
  • WHEN在 change 家运行 merge S1=<提交一> S2=<提交二>
  • THEN退出 0，merged 为 ["S1", "S2"]，reaped 列出这两间的路径
  • AND两间 worktree 的目录与登记都不在了，它们的临时分支也删除了
  • ANDchange 家仍检出 change 分支，两片的文件都已合入

Scenario: merge-keeps-worktree-with-unmerged-work

  • GIVEN切片临时 worktree 提交之后，工作树里还有一个不属于飞行记录的未提交文件
  • WHEN在 change 家运行 merge S1=<提交>
  • THEN合回成功，输出没有 reaped（或为空）

Design · 05技术设计

Context

飞行模式里，一个切片可能跑不止一轮：门禁红重派一次，执行体未交回重派一次，人类修完计划后还会再起飞。「下一轮接着上一轮干」现在由四段各管一截：

| 环节 | 现状（main 1dabeac） | 出过的事 | |---|---|---| | 接上一轮的提交 | 工作流 prompt 的「第零步」：HEAD 不是上一轮 commit 就 git cherry-pick <commit>（opsx-apply.js executorPrompt） | 上一轮两个提交只接到后一个（F2） | | 区间起点 | start --base <上一轮门禁 JSON 的 base>，脚本照单全收（cmd_start） | 分支在两轮之间多了记录提交，旧起点把它们算进切片，报 G6 flight-record（F3） | | 轮次上限 | slice-executor.md frontmatter maxTurns: 40，常数 | 20 个文件、91 个文件的切片各撞四次、两次（F1） | | 临时 worktree 的善后 | 留痕写在临时 worktree 的 change 目录；合回后 worktree 留在磁盘 | 分支上没有切片留痕；磁盘占满（F11） |

约束：

  • Workflow 脚本的 agent() 没有轮次参数（只有 label / phase / schema / model / effort / isolation / agentType），上限只能来自 agent 定义文件的 frontmatter。
  • 自举飞行（useAgentTypes: false）时执行体是默认 subagent，先读定义文件再干活，frontmatter 的 maxTurns 不生效。本仓自己的飞行因此没有轮次上限，这一点本 change 不改。
  • 现行 ADR：DRAFT-measurements-stay-out-of-plan-files（脚本不写计划文件）、DRAFT-gate-evidence-not-self-reported（判据不由被门禁方提供）、DRAFT-post-merge-cleanup-by-tiered-script（铁律 6 的例外要成文，新增本地状态要登记清理规则或写明保留）、DRAFT-submodule-slices-borrow-home-worktree（临时 worktree 的子仓是从 change 家借出的 linked worktree）。

Goals / Non-Goals

Goals:

  • 重派与续跑时，上一轮的全部提交由脚本接上；接不上时脚本自己回滚并给出 G0 JSON。
  • 门禁区间的起点不依赖 prompt 回传的值。
  • 轮次上限随切片大小分档，档位由脚本算，人类在审批页看得到。
  • 撞上限后的 blocked 理由能直接指导下一步。
  • 切片的测试留痕在门禁时读得到（不论是哪一轮、哪间 worktree 留下的），合回后在分支上读得到。
  • 合回后临时 worktree 不再堆积。

Non-Goals:

  • 不取消轮次上限，不做每片一个自定义数字（定义文件只有两份）。
  • 不加「超大切片判红」（见调查二，定不出阈值）。
  • 不改自举模式下执行体没有轮次上限这一点。
  • 不做「重新起飞时首轮自动接上一次飞行的快照」：首轮 start 仍会清掉旧快照（防止把废弃尝试的半成品带进来）。blocked 理由如实写明这一点。
  • 不回收未交回执行体留下的、带未提交改动的临时 worktree（删它要强制参数）。
  • fix 执行体仍用标准档。
  • 不动 gate 的 --base 参数、不动 final / ship / 选测（那是 ship-rerun-hardening 的范围）。
