# S4 · 工作流与 agent 定义：接续、按档位选定义、未交回的理由

## 做什么

让 `opsx-apply` 工作流用上 S1 的 `start --continue`，按 `args.turns` 给每片选执行体定义文件，把未交回的 blocked 理由写清楚；新增薄定义 `slice-executor-large.md`；凡是按 agent 类型名判定的脚本都认新类型。规则原文见 `specs/slice-continue/spec.md` 的第三条 Requirement 与 `specs/turn-tiers/spec.md` 的第三、四、五条，决策见 `design.md` D4、D5、D9。

## 依赖的接口

见 `slices/_interfaces.md` 的 S1 节：

- `slice-gate.py start <S> --change-dir DIR [--expect-branch B] [--continue <commit>] [--resume-checkpoint]`：`--continue` 由脚本接上一轮的全部提交，成功时输出多一个 `continued: {"from", "mode", "applied"}`；接不上以 1 退出并打印 `G0 base: 接续 …` 的 JSON，不写标记。带 `--expect-branch` 时区间起点由脚本算，**不要再传 `--base`**。

`args.turns` 的形状是 `{"S1": "standard", "S2": "large", …}`（由 `slice-gate.py turns` 给出，该子命令在同一 wave 的 S3 里落地；本片只消费这个参数，缺省视为全部 `standard`，不调用子命令）。

## 怎么做

TDD：`tests/test_workflow_resume.py` 的 6 条骨架现在是红的。

### `template/.claude/workflows/opsx-apply.js`

1. 头部注释的 args 清单加 `turns`（可选）。脚本里：`const turns = args.turns || {}`；`const CAPS = { standard: 40, large: 80 }`；`const TIER_NAME = { standard: '标准档', large: '大片档' }`；`const tierOf = (s) => (turns[s] === 'large' ? 'large' : 'standard')`；`const execDef = (s) => (tierOf(s) === 'large' ? 'slice-executor-large' : 'slice-executor')`。
2. 切片执行体（`run`）：`typed('slice-executor')` 换成 `typed(execDef(s))`；`executorPrompt` 里的 `rules('slice-executor')` 换成 `rules(execDef(s))`。Fix 执行体不变（仍是 `slice-executor`）。
3. `startCmd` 的第二个参数从 `base` 改成接续的 commit：给了就拼 ` --continue <commit>`，不再拼 `--base`。
4. `executorPrompt` 的重派分支（`retryOf.commit` 非空）：
   - 删掉「第零步」那一行；
   - start 那一行改为：`第一步运行 \`<startCmd(s, retryOf.commit)>\`（\`--continue\` 由脚本把上一轮的全部提交接到当前 HEAD，输出里的 continued 写明接了几个）。`；
   - 紧跟一句回退：`start 报 unrecognized arguments: --continue（hooks 未升级）→ 运行 \`git rev-parse HEAD\`，不等于 <commit> 就 \`git cherry-pick <commit>\`（冲突则 \`git cherry-pick --abort\` 并返回 failed 为 ["G0 base: cherry-pick <commit> 冲突"] 的 JSON），再运行不带 --continue 的 start。`
   - 「上一轮门禁未过：…只修这些门禁项」保持。
   - 未返回分支（`--resume-checkpoint`）与首轮分支不变。
5. 未交回的 blocked 理由（`if (!r)` 那一行）：
   `执行体未返回（已重派一次）：${TIER_NAME[t]}上限 ${CAPS[t]} 轮；半成品快照在 refs/flight/${changeName}/${s}，重新起飞的首轮会清掉它，要保留先在新 worktree 里 start ${s} --resume-checkpoint`，其中 `t = tierOf(s)`，`changeName = changeDir.split('/').filter(Boolean).pop()`。
6. `GATE` schema 里 `base` 的注释改掉（不再回传给 `--base`；仍保留该字段）。

### `template/.claude/agents/slice-executor.md`

- 开工第 2 条：把「重派时 prompt 会给上一轮的 commit 与 `--base`：按 prompt 的第零步先把 commit 接上（HEAD 不是它则 `git cherry-pick`），再跑带 `--base` 的 `start`；`start` 对同片幂等，重跑不会改写起点」改写为：重派时 prompt 给的 `start` 带 `--continue <上一轮 commit>`，由脚本把上一轮的全部提交接到当前 HEAD（输出的 `continued` 写明方式与个数），区间起点由脚本按 change 分支算；接不上时 `start` 非 0 退出，照下面的规则原样返回。其余句子（`--resume-checkpoint` / `checkpoint.restored` / `--expect-branch` / `G0 submodule` / 「以 3 退出」/ `recovered`）原样保留。
