# S1 · start --continue 与区间起点

## 做什么

给 `template/.claude/hooks/slice-gate.py` 的 `start` 加 `--continue <commit>`：由脚本把上一轮属于本片的提交接到当前 HEAD；带 `--expect-branch` 时把区间起点规范成 HEAD 与 change 分支的合并基点。规则原文见 `specs/slice-continue/spec.md` 的前两条 Requirement，决策见 `design.md` D1、D2。

## 现状（改之前先读）

- `cmd_start`：基点校验（`_base_check`）→ `_sub_sync` → `--resume-checkpoint` 的门禁结论找回（退出 3）→ 同片标记存在则原样返回 → 快照恢复或清理 → 写标记（`base` = `args.base or HEAD`）。
- `_is_ancestor(root, anc, desc)`、`_run_git(root, *args)`（返回 CompletedProcess，不抛）、`git(root, *args)`（非 0 抛 `RuntimeError`）、`_unmerged(root)`（冲突文件清单）、`_first_line(text, default)` 都已有。
- argparse 的 `start` 子命令在 `main()` 末尾。

## 怎么做

TDD：`tests/test_start_continue.py` 的 6 条骨架现在是红的（5 条因 `--continue` 不认识，1 条因 `base` 取了传入的旧值）。

1. argparse：`start` 加 `--continue`，`dest="continue_from"`，help 写清「接上一轮的全部提交」。
2. 新函数 `_continue_from(root, commit)`，返回 `(info, err)`：
   - `git cat-file -e <commit>^{commit}` 失败 → `err = "G0 base: 接续的 commit %s 不存在" % commit[:10]`。
   - `_is_ancestor(root, commit, "HEAD")` → `{"from": commit, "mode": "noop", "applied": 0}`。
   - `_is_ancestor(root, "HEAD", commit)` → 先数 `git rev-list --count HEAD..<commit>`，再 `git merge -q --ff-only <commit>`；`mode: "ff"`，`applied` 为数到的个数。
   - 否则 `revs = git rev-list --reverse <commit> --not HEAD`；其中有合并提交（`git rev-list --merges --count <commit> --not HEAD` 大于 0）→ `err = "G0 base: 接续 %s 的区间含合并提交，无法重放"`。逐个 `git cherry-pick <rev>`；任一失败 → 先取 `_unmerged(root)`，再 `git cherry-pick --abort`（失败忽略）与 `git reset -q --keep <接续前的 HEAD>`，`err = "G0 base: 接续 %s 冲突：%s" % (commit[:10], 冲突文件或 git 首行报错)`。全部成功 → `mode: "pick"`，`applied = len(revs)`。
3. `cmd_start`：在基点校验之后、`_sub_sync` 之前调用它（`args.continue_from` 给了才调）。`err` 非空 → 打印与基点校验失败同形的 JSON（`{"slice", "ok": false, "commit": "", "failed": [err], "warnings": [], "summary": "接续未成功"}`）并 `sys.exit(1)`，不写标记。成功 → 之后所有打印的 JSON（含同片标记已存在的那条早退分支）都并上 `continued`。
4. 起点：写新标记时，`args.expect_branch` 给了 → `base = git merge-base HEAD <branch>`（此时接续已做完）；否则沿用 `args.base or HEAD`。同片标记已存在的分支不改标记。
5. 文件头注释里 `start` 那几行补上 `--continue` 的说明。

## 注意

- 放在 `_sub_sync` 之前是有意的：子仓按接续后的 gitlink 借出（`tests/test_submodule_sync.py::test_retry_after_cherry_pick_populates_new_gitlink` 走的是「先手工 cherry-pick 再 start」，等价）。
- `tests/test_slice_gate.py::test_start_expect_branch_accepts_descendant` 传 `--base T --expect-branch`，HEAD 在 T 之上一个提交，期望 `base == T`：合并基点正是 T，不会坏。`test_start_accepts_base_flag` 不带 `--expect-branch`，`--base` 仍须生效。
- `--resume-checkpoint` 的门禁结论找回分支里有 `git rev-parse HEAD in (rec.base, rec.commit)` 的判断，不要动。
- cherry-pick 需要提交者身份：测试仓库已配 `user.name` / `user.email`，不要在脚本里加 `-c user.*`。
- 不改 `cmd_gate`（它读标记里的 `base`）。不碰 `final` / `ship` / 选测相关函数（在飞的 `ship-rerun-hardening` 在改）。
