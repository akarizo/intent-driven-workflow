# S5 · 临时 worktree 的善后：留痕并回分支、合回后回收

## 做什么

在 `template/.claude/hooks/slice-gate.py` 里做两件事，并同步铁律 6 的措辞：

1. 门禁从共用目录读切片留痕，`record` 把它并进分支上的 `evidence.log`，首轮 `start` 清残留。规则原文见 `specs/slice-evidence-shared/spec.md` 的第二条 Requirement，决策见 `design.md` D6。
2. `merge` 成功合回一片后回收它的临时 worktree。规则原文见 `specs/slice-worktree-reap/spec.md`，决策见 `design.md` D7、D8。

## 依赖的接口

见 `slices/_interfaces.md` 的 S1、S2、S3 节：

- S2（`test-evidence.py`）：有切片标记时留痕在 `<git common dir>/flight-evidence/<change>/<S>.log`，`<change>` 是标记里 change 目录的目录名；文件存在但为空 = hook 在工作而没有可记的行。行格式 `ISO 时间\t切片\tPASS|FAIL\t命令`。
- S1（`cmd_start`）：`args.continue_from`（`--continue`）与 `args.resume_checkpoint`；写新标记的那段在函数末尾。
- 本文件已有：`_pool_dir(root, sub)`（`<git common dir>/<sub>` 的绝对路径）、`evidence_state(change_dir, slice_id)`、`EVIDENCE`、`FLIGHT_RECORDS`、`MARKER`、`is_bytecode(path)`、`_run_git(root, *args)`、`_is_ancestor`、`_gitlinks(root)`、`_sub_ready` / `_sub_git` / `_sub_head`、`_first_line`、`_ckpt_ref` 对 change 名的取法（`os.path.basename(os.path.abspath(change_dir).rstrip(os.sep))`）。

## 怎么做

TDD：`tests/test_evidence_shared_gate.py` 的 4 条与 `tests/test_merge_reap.py` 的 6 条骨架现在是红的。

### 留痕

1. 常量 `EVIDENCE_DIR = "flight-evidence"`、`EVIDENCE_KEEP = 30`。`_evidence_shared(root, change_dir, slice_id)` → 共用目录里该片文件的绝对路径（change 名照 `_ckpt_ref` 的取法）。
2. `evidence_state(change_dir, slice_id, root=None)`：行 = 工作树 `<change_dir>/evidence.log` 里本片的行，后接共用目录文件里本片的行；「存在」= 两个文件至少一个存在。两处都不存在 → `missing_file`；存在而没有本片的行 → `no_rows`；其余判定照旧。`root` 为 `None`（不在 git 仓库或调用方没给）时只看工作树那份，行为与今天相同。
3. `cmd_gate`：调用处传 `root`。`no_rows` 的文案改为 `G5 evidence: hook 在工作，但本片 %s 没跑过测试（先运行本片的 verify 再过门禁）`。在 `append_report` 之前调用 `_evidence_merge(root, change_dir, slice_id)`（见下，但 **不删** 共用目录的文件）。
4. `_evidence_merge(root, change_dir, slice_id, drop=False)`：把共用目录里该片的行追加进 `<change_dir>/evidence.log`，跳过该文件里已经有的行（整行相等），原有内容不动；`drop=True` 时随后删除共用目录里该片的文件。共用文件不存在是空操作；任何 `OSError` 吞掉。
5. `cmd_record`：拿到 `result["slice"]` 之后、`report_has_row` 早退之前，调用 `_evidence_merge(os.getcwd() 所在的 git 顶层, args.change_dir, slice, drop=True)`。
6. `cmd_start`：首轮分支（既没有 `--continue`、也没有 `--resume-checkpoint`、也没有同片标记，即现有的「清掉残留快照」那个 else 分支，再加上 `not args.continue_from`）里删除共用目录里该片的文件，并把 `<git common dir>/flight-evidence/` 下的子目录按修改时间修剪到最近 `EVIDENCE_KEEP` 个。

### 回收

7. `_reap(root, sid, sha, pre, warnings)` → 被回收的路径列表。`pre` 是合并这一片之前的 HEAD。
   - `commits = set(git rev-list <sha> --not <pre>)`。
   - 解析 `git worktree list --porcelain`：跳过当前 worktree（`realpath` 等于 `root` 的）、bare、以及 HEAD 不在 `commits` 里的。
   - 对每一间候选 `wt`：
     1. `git -C wt status --porcelain -z --untracked-files=all` 列出改动。可丢弃的三类：basename 属于 `FLIGHT_RECORDS` 且路径形如 `**/changes/<名>/<文件>`（即倒数第三段是 `changes`）；等于 `MARKER`；未跟踪且 `is_bytecode`。gitlink 路径本身的改动另算（见 2）。其余任何一条 → `warnings.append("未回收 %s：有未提交改动 %s" % (wt, 前 4 个路径))`，跳过这一间。
     2. 对 `wt` 里已填充的 gitlink 路径 P（`_sub_ready(wt, P)`）：change 家对应的子仓是 `root/P`；要求 `_sub_ready(root, P)`、`wt/P` 的 HEAD 是 `root/P` 的 HEAD 的祖先、`wt/P` 除未跟踪字节码外没有改动。满足 → 删掉那些字节码，在 `root/P` 里 `git worktree remove <wt/P>`（不带 `--force`）。不满足或失败 → 「未回收 … ：子仓 P …」，跳过这一间。
     3. 丢掉第 1 步的三类：已跟踪的 `git -C wt checkout -- <路径>`，未跟踪的直接删文件（字节码所在的 `__pycache__` 目录空了一并删）。
     4. `git worktree remove <wt>`（不带 `--force`）。非 0 → `warnings.append("未回收 %s：%s" % (wt, _first_line(stderr)))`，跳过。
     5. 该 worktree 有分支且 `git rev-parse <分支>` 等于它的 HEAD → `git branch -d <分支>`；失败只加一条「未回收分支 …」警告。
     6. 成功 → 记进返回列表。
   - 整个函数包在 `try` 里：任何异常变成一条「未回收 …」警告，不向外抛。
8. `cmd_merge`：每片合并前记下 `pre = git rev-parse HEAD`；该片 `merged.append(sid)` 之后调用 `_reap`。全部结束后，回收列表非空才在输出里加 `"reaped"`。`ok` / `merged` / `failed` / 退出码的计算一行都不改。

### 铁律 6

9. 根 `CLAUDE.md` 第 6 条：在「不删 worktree」之后加括注，例如「不删 worktree（例外：切片临时 worktree 的提交已合回 change 分支、且没有未合回的改动时，由 `slice-gate.py merge` 不带强制参数回收）」；其余文字不动。
10. `template/CLAUDE.md.snippet` 第 6 条的例外里加一句短的，例如「…删（例外：显式跑 `/clean-after-merged` 的 safe 档；已合回的切片临时 worktree 由 `slice-gate.py merge` 回收）」。改完确认文件不超过 8KB（现 6976 字节）。

## 注意

- `tests/test_submodule_merge.py::test_merge_plain_repo_equals_no_ff` 断言输出**整体等于** `{"ok", "merged", "failed", "warnings"}` 四个键：没有回收时不能出现 `reaped`，也不能多出警告。
- `tests/test_slice_gate.py` 的 `test_gate_g5_fails_when_evidence_has_no_rows_for_slice`（只断言 `failed` 里有以 `G5` 开头的项）与 `test_gate_g5_warns_when_hooks_missing`（两处都没有 → 警告、`hooks_missing` 为 true）是现有行为，必须保持绿。
- `tests/test_clean_after_merged_docs.py::test_iron_rule_grants_cleanup_exception` 钉着根那一行里的「不删 worktree」「branch -D」「/clean-after-merged」与 snippet 的 8KB：改措辞时保留。`tests/test_docs_iron_rules.py` 钉着 11 条铁律的关键词（第 6 条是「Git 边界」）。
- 回收只用不带强制参数的 git 命令；除上面列的三类文件外，脚本不得删除或还原别的 worktree 里的任何东西。
- 「形如 `**/changes/<名>/<文件>`」是为了在 `merge` 没有 `--change-dir` 参数的前提下认飞行记录；不要给 `merge` 加参数（工作流与 integrator 的契约不变）。
- `git worktree list --porcelain` 的条目以空行分隔，`worktree <路径>` / `HEAD <sha>` / `branch refs/heads/<名>` / `detached` / `locked …`。**被锁的（有 `locked` 行）在第 1 步之前就跳过**，记「未回收 <路径>：已锁定」，不动它的任何文件（锁着的多半是还在跑的 agent）。
- 带子仓时父仓的 `git status` 会把「子仓里有未跟踪内容」报成 gitlink 路径自身的改动：gitlink 路径的条目不按第 1 步判，交给第 2 步。子仓 worktree 归还后目录会消失；如果 git 因此把该 gitlink 报成删除而拒绝移除父 worktree，就在原处补一个空目录（未填充的 submodule 是干净状态）。
- 路径比较统一用 `os.path.realpath`（macOS 的临时目录有 `/private` 前缀）。
- 不碰 `final` / `ship` / 选测相关函数；不碰 `_final_fresh` 用的 `BOOKKEEPING`。
