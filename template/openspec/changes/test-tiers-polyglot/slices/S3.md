# S3 · 判定器：部件形态下 baseline / final / preflight 逐部件运行

**做什么**：在 `cmd_baseline` / `cmd_final` / `cmd_preflight` 里加部件形态分支：
- 不执行 `gate.test`（驱动命令），逐部件运行单元层、判 G10 / G11、差分、对账；
- 区域在所属部件 root 下运行；
- `tier_sec.parts`。

简写形态与无分层文件的路径不改。语义见 `specs/test-tiers-polyglot` 第五条 Requirement，design D8。

**owns**
- `template/.claude/hooks/slice-gate.py`
- `tests/test_tiers_parts_gate.py`

**依赖 S2 的接口**（见 `slices/_interfaces.md`）：`run_part(top, name, part, probe=True)`、`part_tier_verdict(top, name, part, res, allow)`、`part_tier_verdicts`。
**依赖 S1**：`tiers_is_parts`、`tier_parts`、`tier_adapter_errors`、`tiers_matching`、`parts_of`。
已存在：`_diff_verdict(label, tg, known_failed)`、`tier_seconds`、`_tier_add`、`_tier_note`、`_selected_regions`。

**做法**
1. **TDD**：逐条去掉 `tests/test_tiers_parts_gate.py` 的 `XF` 标记，先红后绿。
2. **共同前置**：部件形态下 `tier_adapter_errors(top, tiers)` 非空时：
   - baseline 与 terrs 同处 `die`；
   - final 记一条 `G2 tiers：…先跑 lint 修好` 失败，并跳过单元层与区域。
3. **baseline**（部件形态分支，替换「全量 `run_test_gate(test_cmd)`」那一段）：
   - 逐部件（按名字排序）`res = run_part(top, P, part)`，`rec = {"exit": rc, "sec": res["sec"], "cmd": unit.cmd}`；
   - `rc != 0` 时：`failed` 非 None → `rec["failed"]` 并警告「部件 P 预存红 n 条…」；否则进 `reasons`：`部件 P 单元层在基线上红（exit N；按退出码判：<why>）`；
   - `part_tier_verdict` 的失败进 `reasons`，警告进 warnings；
   - `bl["test"] = {"exit": 0 或 1, "sec": 各部件之和, "parts": {...}}`，`gate["full_suite_sec"]` 同 `sec`；
   - `bl["tiers"] = {"parts": {P: {"measured": probe 可度量[, "why"]}}}`；
   - 不写锚点（不传 deps，`adeps` 保持 None），verify 不做 junit 推导（驱动命令本就推不出）。
   - 区域：在所属部件 root 下运行（`run_test_gate(rcmd, <top>/<root>)`），其余同简写。
   - `bl["tier_sec"]` 在原有键外加 `parts`：`{P: {"unit": 该部件单元层墙钟（含重跑）, "integration": 该部件区域之和}}`。
4. **final**（部件形态，G7 绿时）：
   - 不取锚点、不走 `gate.impacted`（lint 已禁）；
   - `inc = {"mode": "full", "full_why": "多部件分层：增量未支持（依赖图只认 pytest）"}`；
   - 逐部件：基线 `test.parts.P` 缺失或 `cmd` ≠ 当前 `unit.cmd` → `G2 part P：基线缺记录或命令已变，重跑 baseline`，跳过该部件；否则 `run_part` → `_diff_verdict("part P", res, rec.get("failed"))` → `part_tier_verdict`；
   - 区域：同 baseline，在所属部件 root 下运行；
   - 不写锚点；同树沿用（`_final_reusable`）照旧；
   - `tier_sec`：`tier_seconds(durations, tiers)`（G7 部分），再按部件加上运行墙钟。`parts.P.unit` = G7 里 `parts_of` 归到 P 的单元层用例耗时 + P 的单元层墙钟；`parts.P.integration` = 其区域墙钟。
5. **preflight**：在现有区域核对之后，部件形态下：
   - 基线 `test.parts` 的键集合 ≠ 当前部件集合 → 「基线过期：部件 <差集> …；重跑 baseline」；
   - 某部件 `cmd` ≠ 当前 `unit.cmd` → 「基线过期：部件 P 的单元命令已变；重跑 baseline」。
6. **gate（每片）**：部件形态下 `tier_sec` 也加 `parts`（G7 耗时按 `parts_of` 归属）。

**verify**：`python3 -m pytest -q tests/test_tiers_parts_gate.py tests/test_tiers_gate.py tests/test_tiers_timing.py tests/test_final_tiers.py tests/test_slice_gate_final.py tests/test_slice_gate_baseline_preflight.py tests/test_baseline_incremental.py`

**注意**
- 简写形态的 baseline / final / preflight 输出逐字不变；既有 `test_tiers_*`、`test_final_tiers.py` 是护栏。
- timeline 备注的结论词仍在末尾（`timeline.py` 按末尾取结论）。
- 被测仓库里没有 `test-tiers.py`：门禁一旦执行 `gate.test` 就会红，测试据此断言驱动命令没被执行。
