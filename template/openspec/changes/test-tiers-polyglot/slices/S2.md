# S2 · 判定器：部件运行器与逐部件 G10 / G11

**做什么**：在 `slice-gate.py` 里新增两个函数：
- 部件运行器 `run_part`：在 root 下运行，接 JUnit 契约、探针适配器契约、内置探针的顶层 id；
- 逐部件判定 `part_tier_verdicts`（纯函数）与带重跑的 `part_tier_verdict`。

本片不接线 baseline / final（S3 的事）。语义见 `specs/test-tiers-polyglot` 第三、四条 Requirement，design D2、D5、D6、D8（运行器与 G10 / G11 部分）。

**owns**
- `template/.claude/hooks/slice-gate.py`
- `tests/test_tiers_parts_runner.py`

**依赖 S1 的接口**（见 `slices/_interfaces.md`）：`tier_parts`、`tiers_is_parts`、`TIER_DRIVER_CMD`。
已存在：`run_test_gate(cmd, root, probe=False, deps=False, _plain=False, extra_env=None)`、`_read_probe(path)`、`TIER_PROBE_PLUGIN`、`UNIT_MAX_SEC`、`_drop_inherited`。

**做法**
1. **TDD**：逐条去掉 `tests/test_tiers_parts_runner.py` 的 `XF` 标记，先红后绿。
2. **内置探针顶层 id**：
   - `TIER_PROBE_PLUGIN` 在环境变量 `FLIGHT_TIER_TOP` 存在时，每条用例记录另写 `"top"` = `os.path.relpath(str(item.path 或 item.fspath), FLIGHT_TIER_TOP)`（`/` 分隔）+ `::` + nodeid 里第一个 `::` 之后的部分；
   - `_read_probe` 增加可选参数，按 `top` 合并（缺 `top` 时用 nodeid）；
   - 不设 `FLIGHT_TIER_TOP` 时记录与读取结果和现在逐字相同。
   - logreport 阶段拿不到 item：可在 setup hookwrapper 里按 nodeid 记下 top 映射，teardown 写记录时取用。
3. **`run_part(top, name, part, probe=True) -> dict`**：
   - `cwd = os.path.join(top, part["root"])`，命令 = `part["unit"]["cmd"]`；
   - 建临时目录，`FLIGHT_JUNIT = <tmp>/junit-part.xml`，记下开始时间 t0。
   - **有 `unit.probe`**：
     - 运行 `probe.cmd`（shell，`cwd` 同上），环境 `FLIGHT_UNIT_CMD = unit.cmd`、`FLIGHT_TIER_OUT = <tmp>/tier-probe.jsonl`、`FLIGHT_JUNIT`；
     - 先 `_drop_inherited`，适配器不是 pytest，不注入 PYTEST_ADDOPTS；
     - 结果 rc 取适配器退出码，`failed = None`，`why = "非 pytest 部件按退出码判"`（rc ≠ 0 时）；
     - `probe` 由 `_read_probe` 读，nodeid 补 root 前缀。
   - **无 `unit.probe`**：
     - 调 `run_test_gate(unit.cmd, cwd, probe=probe, extra_env={"FLIGHT_JUNIT": ..., "FLIGHT_TIER_TOP": top})`，保留它的 `failed` / `why` / 回退语义；
     - `probe` 用顶层 id。
     - 注意 `run_test_gate` 现以 `root` 作 cwd；如需区分「运行目录」与「仓库根」，加可选参数，不改既有调用方的行为。
   - **`secs`**（`{顶层 id: 秒}`）：
     - 探针可度量时取探针 `sec`；
     - 否则解析 `$FLIGHT_JUNIT`；
     - 再否则按 `unit.junit`（相对 root 的 glob）找 mtime ≥ t0 的文件逐个解析；
     - 都没有 → `secs = None`，`secs_why` 写原因。
     - junit id 规则：testcase 有 `file` → `<root>/<file>::<name>`（root 为 `.` 不补）；否则 `<部件名>::<classname>::<name>`。同 id 多次出现取最大值。
   - **返回**：`{"rc", "out", "failed", "why", "sec"（墙钟，1 位小数）, "probe", "probe_why", "secs", "secs_why"}`。不记依赖图。
4. **`part_tier_verdicts(name, res, rerun, allow) -> (failed, warnings)`**（纯函数，不做 I/O）：
   - G11：
     - `res["probe"]` 非 None → 每个有 hits 的 id 一条 `G11 impure unit test: 部件 <name>：<id> 碰了<类别>（<样例>）：改成纯函数或移入集成区域`；
     - 为 None → 待合成的 G11 不可度量原因 = `probe_why`。
   - G10：
     - `res["secs"]` 非 None → 候选 = ≥ `UNIT_MAX_SEC`；
     - `rerun`（dict 或 None）里该 id 存在且 < 阈值 → 不确认；否则确认；
     - 确认后：在 `allow` → 警告 `G10 slow unit test 已人工放行：部件 <name>：<id> …（<approved>）`；否则失败 `G10 slow unit test: 部件 <name>：<id> 首跑 x.xs，重跑 …（≥3s）：…`；
     - `secs` 为 None → G10 不可度量原因 = `secs_why`。
   - 两者都不可度量 → 一条警告 `G10/G11 不可度量：部件 <name>：<原因>`；只一者 → `G10 不可度量：部件 <name>：…` 或 `G11 不可度量：部件 <name>：…`。
5. **`part_tier_verdict(top, name, part, res, allow) -> (failed, warnings, extra_sec)`**：
   - 有候选时整部件再 `run_part` 一次，取其 `secs` 作 rerun（拿不到 → None，按确认处理），再调纯函数；
   - 返回重跑耗时，供 S3 计入墙钟。

**verify**：`python3 -m pytest -q tests/test_tiers_parts_runner.py tests/test_tiers_probe.py tests/test_tiers_verdict.py tests/test_tiers_gate.py tests/test_final_guard.py`

**注意**
- 简写形态的 `tier_verdicts` / `_unit_tier_verdict` / `_tier_rerun` 不改。
- 探针插件改动后，`tests/test_tiers_probe.py`、`tests/test_final_guard.py` 必须仍绿（嵌套会话不写记录的语义不变）。
- 只用标准库，兼容 Python 3.8。
