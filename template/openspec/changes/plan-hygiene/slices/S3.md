# S3 · final 预告收进 slice-gate.py；ship 的「final 过期」理由带补跑预告

## 做什么

改 `template/.claude/hooks/slice-gate.py` 与 `template/.claude/hooks/flight-doctor.py`，实现 design D5。规则原文：`specs/ship-rerun-forecast/spec.md`。

## 依赖的接口

- S1 的 `suite_sec(change_dir, data=None)`，见 `_interfaces.md`「S1 提供」。
- 依赖 S2 只因为两片都改 `slice-gate.py`、不能同 wave；不使用 S2 的接口。

## 怎么做

TDD：先确认 `tests/test_ship_forecast.py` 的 3 条骨架是红的，再写实现。

1. **搬判定**：把 `flight-doctor.py` 的 `_final_part(sg, change_dir, data, baseline)` 搬成 `slice-gate.py` 的
   ```python
   def final_forecast(change_dir, data, baseline):
       """final 将怎么跑的预告 → (mode, why)；mode ∈ impacted / full / incremental / unknown。只读，不运行测试。"""
   ```
   - 逻辑与文字原样照搬（`gate.impacted 自己选测` / `多部件分层：部件恒全量` / `gate.test 未配置（final 将探测测试命令）` / `依赖图未测（<kind>）：<why>` / `锚点 <10 位>，Δ N 个文件`），`sg.` 前缀去掉即可；
   - `anchor_max_hops` 直接取 `_scope_extras(change_dir)["anchor_max_hops"]`，原来的 `hasattr` 兼容分支不要了；
   - `_full_why` 的入参与原函数相同（不传 `declared_global` 也保持原样，本片不改预告的判定范围）。
2. **`flight-doctor.py`**：
   - `forecast()` 里 `_final_part(sg, …)` 改为 `sg.final_forecast(change_dir, data, baseline)`，删掉 `_final_part` 与只为它存在的常量 / import（`DEFAULT_MAX_HOPS`、`TIER_FILE`、`CHECKS_FILE` 若再无引用）；
   - `out["final"]["sec"]` 改为 `sg.suite_sec(change_dir, data)`；
   - 文件头注释里「只调用 _interfaces.md「S4 提供」列出的函数」那句按实际更新；恒退出 0 的约定不动。
3. **`cmd_ship`**：判 final 过期的那一支，在 `final 过期：记录 X，HEAD Y` 之后追加：
   - `incremental` → `；补跑将是增量（<why>）`
   - `full` → `；补跑将是全量（<why>）`
   - `impacted` → `；补跑由 gate.impacted 选测`
   - `unknown`，或 `final_forecast` 抛任何异常（含 `SystemExit`）→ 不追加。
   裁决（`ready` / 退出码 / 其余理由）不受影响；`--markdown` 输出与 timeline 的 ship 行自然带上这句。
