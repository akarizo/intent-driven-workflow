## 怎么做

TDD：先确认 `tests/test_runner_statement.py` 的 6 条骨架是红的，再写实现。

1. **常量**：`RUNNER_UNMEASURED = "runner:deps-unmeasured"`，放在 `SCOPE_UNDECLARED` 旁边。
2. **一个判定函数**，lint 与 final 复核共用，例如 `_runner_state(gate, change_dir, phase) -> {"trigger": bool, "pending": bool, "kind": str | None}`：
   - 豁免（两者都为假）：`gate.impacted` 已配；或 `_builtin_by_design(gate, tiers)`。
   - 取 `load_baseline(change_dir)`；「跑完的基线」= 是对象且 `running` 不为真。
   - `phase != "baseline"` 且有跑完的基线：`deps_unmeasured` 是对象 → `trigger`，`kind` 取其 `kind`；否则两者都为假（此时计划里留着的理由按现有规则报「不是本次触发项，删除」/「应删除」）。
   - 其余（没有跑完的基线，或 `phase == "baseline"`）：`pending`。
3. **并入 `_lint_scope`**（三处调用 `_scope_reason_errors` 之前，未声明-建立声明、builtin、cmd 三个分支都要）：
   - `trigger`：报告变为全选；原本未全选 → 触发项只有它；原本已全选 → 追加在后。
   - `pending`：把它并进传给 `_scope_reason_errors` 的 `pending`（builtin 分支已有自己的待定项，合并）。
   - 缺理由的违规文字：现有那句之后追加一段，含未测类别与契约文档路径，例如 `（依赖图未测：plugins-dropped；修法见 .claude/flight-runner-contract.md，或配 gate.impacted）`。只在缺的是这个触发项时追加。
   - 通过时的摘要行照旧；全选摘要里触发项清单会自然带上它。
4. **并入 `_final_scope_guard`**：算出 `full, trig` 之后、与 `approved` 对账之前，`trigger` 为真就追加。`final --full` 的豁免在调用处，不用管。
5. **静态提示**（只提示，不影响退出码）：`pending` 为真、**没有跑完的基线**、`gate.test` 不是 `_plain_test_cmd` 时：
   - 取 `_test_gate_files(root, gate)`（命令里直接写出的仓库文件及其 shell 静态闭包；返回 `None` 或空集就不提示）；
   - 这些文件的文本合起来没有同时出现 `FLIGHT_PYTEST_ARGS` 与 `FLIGHT_PLUGIN_PATH` → 提示一行，以 `runner:` 开头，点名 `gate.test` 里直接写出的脚本路径与这两个变量，并说明「baseline 若测不到依赖图须为 runner:deps-unmeasured 写理由（可预写）」；
   - 打印位置：`lint_plan` 里与 `scope_note` 同处（无 errors 时写 stderr）。`_lint_scope` 的返回值可以把它拼进摘要（多一行），不必改签名。
   - `phase == "baseline"` 不打印。
6. **增量基线沿用状态**，`cmd_baseline`：经旧基线 / 基线池复用（`hit is not None` 且不是锚点路径，即现在 `bl["test"] = {k: ct[k] …}` 那个分支）时，来源 `src` 有 `deps_unmeasured`（对象）就原样带进 `bl`。基线池条目的键清单加上 `deps_unmeasured`。经锚点的分支不带。

## 要跟着改的旧测试（在 owns 里）
