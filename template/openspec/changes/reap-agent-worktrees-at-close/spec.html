Why · 01为何而做

切片执行体的临时 worktree 在飞行结束后大量残留，持续吃磁盘。2026-11-19 只读盘点：afa 有 35 个、约 33G（该仓此前就因磁盘写满导致 verify 失败），stc-foundation 6 个、6.4G，本仓库 23 个。

现有回收只在 slice-gate.py merge 合回那一刻判一次（判据是「HEAD 在本次合入的提交里」）。下面几类都没人收：

- 门禁红后重派留下的旧尝试：--continue 把提交接到新 HEAD 上，SHA 变了； - blocked 的切片、未交回的执行体； - 合回时因故没收掉的。

/clean-after-merged 拿 target（main）判断「是否已合入」，可执行体的提交只合进了 change 分支，所以一律落到 keep。afa 实测 safe 档一个也收不了。

用户要求（2026-11-19）：agent worktree 一旦确认无用，就在释放后立即清理。

意图访谈以四轮审批页代替：docs/flight-routing-config.html v1–v4，在主仓库工作区，未入库。用户 2026-11-19 回复「全按推荐」，其中 Q11-A 定为「作废尝试先归档再删」，Q10-A 定本 change 为四个中的第一个。

What · 02变更范围

  • 新增 slice-gate.py reap --change-dir DIR：飞行收口时回收本次飞行留下的全部执行体临时 worktree。
  • 已落地的（HEAD 在 change 分支历史里）直接删。
  • 作废的尝试，先把提交与未提交改动归档到 refs/flight/<change>/attic/<名>，再删。
  • 归属只认飞行证据（切片标记或本 change 的飞行记录改动），不看目录名。
  • 删除不带 --force。未合入的分支不删。锁定的不碰。
  • 输出 JSON，恒退出 0，并写 timeline 事件 reap。
  • /opsx-apply 收口步骤（命令与 skill 同改）：运行 reap，并打印「回收 N 个 · 释放 X MB · 归档 M 个」。子命令不存在时跳过。
  • merged-cleanup.py 新增两条判据：
  • landed：worktree 的 HEAD 被 merge 进了另一个本地分支（不在该分支的 first-parent 链上）。
  • dead-attempt：worktree 属于已落地 change，提交没进任何其他分支。有自己的分支 → safe；游离 HEAD → manual。
  • 已归档的 change（openspec/changes/archive/<日期>-<名>/）也算已落地。
  • 文档同步：clean-after-merged.md 原因表补 landed / dead-attempt；铁律 6（根 CLAUDE.md 与 template/CLAUDE.md.snippet）写明收口回收与归档；README 同步。
  • 新 ADR：扩展 DRAFT-slice-worktrees-reaped-after-merge 的回收时机与判据。只取代它的「merge 之外的脚本不得删除 worktree」一条，其余在役。
代码：template/.claude/hooks/slice-gate.py（新子命令 reap，复用现有 _reap_one）、template/.claude/hooks/merged-cleanup.py（判据与已落地 change 识别）。文档：template/.claude/commands/opsx-apply.md、template/.claude/skills/openspec-apply-change/SKILL.md、template/.claude/commands/clean-after-merged.md、CLAUDE.md、template/CLAUDE.md.snippet、README.md。ADR：新增 template/openspec/adr/DRAFT-flight-close-reaps-slice-worktrees.md。行为：收口多一步，秒级。/clean-after-merged 的 safe 档会多收执行体 worktree。铁律 6 的例外多一条。依赖：无新依赖，纯标准库 + git。存量：本 change 不在实现里动存量。afa / stc 的 A 类由用户执行 /tmp/worktree-cleanup-{afa,stc}.sh。B 类等本 change 落地、各仓升级后用 /clean-after-merged 处理。

Specs · 04行为规范 (Gherkin)

flight-close-reap ADDED

Requirement: 收口时回收本次飞行留下的已落地临时 worktree

slice-gate.py reap --change-dir <DIR> 在 change 家运行时，SHALL 枚举 git worktree list，跳过主 worktree、change 家自身与 bare，只处理带本 change 飞行证据的 worktree。飞行证据为以下之一： - 切片标记 .openspec-slice 的 change_dir 目录名等于本 change 名； - 未提交改动里有 **/changes/<本 change>/{timeline.md,gate-report.md,evidence.log}。

没有飞行证据的 worktree MUST NOT 被触碰，也 MUST NOT 出现在输出的任何列表里。被锁定的 MUST 原样保留，并在 kept 写明已锁定。HEAD 是 change 家 HEAD 祖先的，SHALL 按合回回收的同一规则回收： - 只丢弃飞行记录、切片标记与未跟踪字节码； - 先归还借出的子仓； - 用不带强制参数的 git worktree remove 删除； - 分支仍指向该 HEAD 时 git branch -d。

Feature: 飞行收口回收 Rule: 只回收带本 change 飞行证据的临时 worktree；HEAD 已在 change 分支历史里的直接回收；锁定的不碰

Scenario: close-reap-removes-landed-slice-worktree

  • GIVENchange 家检出 change 分支，一间临时 worktree 的提交已合进 change 分支
  • AND这间 worktree 里只剩本 change 的飞行记录改动、切片标记与字节码
  • WHEN在 change 家运行 slice-gate.py reap --change-dir <本 change>
  • THEN这间 worktree 的目录与 git 登记都消失，它的分支被删除
  • AND输出的 reaped 列出它，archived 为空，退出码为 0

Scenario: close-reap-ignores-worktrees-without-flight-evidence

  • GIVEN一间 HEAD 在 change 分支历史里、却既没有切片标记也没有本 change 飞行记录改动的 worktree
  • AND一间切片标记指向另一个 change 的 worktree
  • WHEN在 change 家运行 reap
  • THEN两间 worktree 与它们的分支原样保留
  • AND它们不出现在 reaped、archived、kept 任何一个列表里

Scenario: close-reap-skips-locked-worktree

  • GIVEN一间带本 change 飞行记录改动的临时 worktree 被 git worktree lock 锁住
  • WHEN在 change 家运行 reap
  • THEN这间 worktree 原样保留
  • ANDkept 里有它，原因写明已锁定，退出码为 0

Requirement: 作废的尝试先归档再回收

HEAD 不是 change 家 HEAD 祖先的带证据 worktree（作废的尝试），reap SHALL 先写 refs/flight/<change>/attic/<目录名>，再删除目录： - 除飞行记录、切片标记、未跟踪字节码外没有未提交改动时，ref 指向原 HEAD； - 有这类改动时，ref 指向一个以原 HEAD 为唯一父提交、树里含这些改动（含未跟踪、不含被忽略）的新提交。

归档后，已归档的改动由脚本丢弃，再按上一条的规则删除目录。该 worktree 自己的未合入分支 MUST 保留。同名 ref 已存在且指向别的提交时，名字 SHALL 加 -<原 HEAD 前 7 位> 后缀。含自有子仓克隆（不是从 change 家借出）的 worktree MUST 原样保留，并在 kept 写明含自有子仓克隆。任何回收步骤 MUST NOT 使用强制参数或 git branch -D。

Feature: 作废尝试归档 Rule: 先把提交与未提交改动写进 attic ref，再删除目录；未合入的分支保留

Scenario: close-reap-archives-superseded-attempt

  • GIVEN一间临时 worktree 的提交没有进 change 分支（门禁红后重派留下的旧尝试）
  • AND它只剩本 change 的飞行记录改动
  • WHEN在 change 家运行 reap
  • THENrefs/flight/<change>/attic/<目录名> 指向这间 worktree 原来的 HEAD
  • AND目录与 git 登记消失，它自己的分支仍在
  • ANDarchived 列出这条路径与 ref

Scenario: close-reap-archives-uncommitted-work

  • GIVEN一间未交回执行体的临时 worktree 带切片标记，有一处已跟踪源码文件的未提交修改和一个未跟踪的新源码文件
  • WHEN在 change 家运行 reap
  • THENattic ref 指向一个以原 HEAD 为唯一父提交的新提交，这个提交的树里有那处修改和那个新文件，不含切片标记
  • AND目录被删除后，从 attic ref git worktree add 出来的工作树里能读到这两处内容

Scenario: close-reap-keeps-worktree-with-own-submodule-clone

  • GIVEN一间带本 change 飞行记录改动、提交已合进 change 分支的临时 worktree，里面的子仓是它自己初始化的克隆
  • WHEN在 change 家运行 reap
  • THEN这间 worktree 原样保留，子仓内容不动
  • ANDkept 里有它，原因写明含自有子仓克隆，退出码为 0

Requirement: 回收结果可度量

reap MUST 恒以 0 退出，stdout SHALL 是 JSON {ok, reaped, archived, kept, freed_kb, warnings}： - reaped：被删除目录的路径； - archived：{path, ref}； - kept：{path, why}； - freed_kb：被删除目录删除前的磁盘占用之和，整数。

每次运行 SHALL 在本 change 的 timeline.md 追加一条 reap 事件，备注为「回收 N 个 · 释放 X MB · 归档 M 个 · 保留 K 个」，N 为 0 时也写。不在 git 仓库或 change 目录不存在时，SHALL 输出空列表与一条 warning 并以 0 退出。

Feature: 回收留痕 Rule: reap 恒以 0 退出，打印完整 JSON，并在 timeline 追加一条 reap 事件

Scenario: close-reap-reports-and-records-timeline

  • GIVEN本次飞行留下一间已落地的临时 worktree 和一间作废的尝试
  • WHEN在 change 家运行 reap
  • THENstdout 是含 reaped、archived、kept、freed_kb 的 JSON，reaped 两条、archived 一条，freed_kb 大于 0
  • AND本 change 的 timeline.md 末尾追加一条 reap 事件，备注含「回收 2 个」与「归档 1 个」

Requirement: 收口步骤运行回收

/opsx-apply 命令文档与 openspec-apply-change skill 的收口步骤 SHALL 在 flight-doctor.py cost 之后、写入 review-findings.json 之前运行 slice-gate.py reap --change-dir openspec/changes/<name>，原样打印回收一行；报 invalid choice（hooks 未升级）时 SHALL 跳过并照常往下。两份文档 MUST 同改。

Feature: 收口调用 Rule: 命令与 skill 的收口步骤都运行 reap，子命令不存在时跳过

Scenario: apply-close-runs-reap

  • GIVENtemplate/.claude/commands/opsx-apply.md 与 template/.claude/skills/openspec-apply-change/SKILL.md
  • WHEN读它们的收口步骤

  • AND都写明打印回收一行，以及报 invalid choice 时跳过

Requirement: 铁律 6 写明收口回收

根 CLAUDE.md 与 template/CLAUDE.md.snippet 的铁律 6 SHALL 写明飞行收口由 slice-gate.py reap 回收本次飞行的临时 worktree、作废尝试先归档；原有的 slice-gate.py merge 回收、/clean-after-merged 授权、不删 worktree、不带强制参数、branch -D 交人等措辞 MUST 保留；snippet MUST NOT 超过 8KB。

merged-cleanup-agent-worktrees ADDED

Requirement: 已被合进其他分支的临时 worktree 不再因未合入 target 而保留

对 .claude/worktrees/ 下相对 target 为 unmerged 的 worktree，merged-cleanup.py SHALL 检查它的 HEAD 是否被 merge 进了另一个本地分支 B，判据是： - HEAD 在 B 的历史里； - 不在 B 的 first-parent 链上； - B 不是它自己的分支。

Design · 05技术设计

Context

名词：执行体临时 worktree = 飞行里切片执行体、批量修复、wave 跨片修复在运行时开的隔离 worktree（Claude Code 放在 .claude/worktrees/ 下），下文简称「临时 worktree」。change 家 = 本 change 自己的 worktree（.worktrees/<name>/），即运行 reap 的 root。

现状

  • 合回时回收：slice-gate.py 的 _reap(root, sid, sha, pre, warnings)（slice-gate.py:5506）在 merge 每合回一片后，回收 HEAD 落在「本次合入的提交」里的临时 worktree。逐间回收由 _reap_one（slice-gate.py:5463）完成：
  • 只允许三类可丢弃改动：飞行记录、切片标记、字节码；
  • 先归还借出的子仓；
  • 不带 --force 删除；分支用 -d 删。
  • 合并后清理：merged-cleanup.py 判断 worktree 是否已合入只看 target（Ctx.merged，merged-cleanup.py:90）。fresh / unmerged 一律进 keep（merged-cleanup.py:228）。
  • 切片标记：.openspec-slice 是 JSON {slice, change_dir, base, started}，其中 change_dir 是绝对路径（slice-gate.py:4240）。门禁绿时删除标记。门禁在临时 worktree 里会改动 <change>/timeline.md、gate-report.md、evidence.log。

漏网实测（2026-11-19，只读）

| 仓库 | 临时 worktree | 漏网原因 | |---|---|---| | afa | 35 个 · 33.0G | 全部是 11-18 的产物；afa 11-19 才升级到带回收的版本。另有 2 个 change 分支已被删，挂在它们下面的无法再证明已落地 | | stc-foundation | 6 个 · 6.4G | 4 个已在 change 分支里，2 个不在任何分支 | | 本仓库 | 23 个 · 183M | 14 个是回收功能上线前的飞行留下的；8 个是重派留下的旧尝试，各有 1 个提交既不在任何分支里、也找不到 patch 等价；1 个是人工 regate 留下的 |

现有 merged-cleanup.py plan 的结果：afa 的 safe 档收 0 个，保留原因主要是 unmerged（相对 main）与 submodule。

git 行为实测（git 2.54.0，脚本 /tmp/c4_probe/probe*.sh）

| 待删 worktree 里的东西 | git worktree remove（不带 --force） | |---|---| | 被 .gitignore 忽略的文件 | 可删 | | 未初始化的 submodule（空目录） | 可删 | | 已初始化的 submodule（自有克隆） | 拒绝；先 submodule deinit 也照样拒绝，因为 worktrees/<id>/modules 还在 | | 未跟踪文件 / 改动过的已跟踪文件 | 拒绝 |

afa 的 admin/viewer 子仓是从 change 家借出的子仓 worktree（.git 文件指向 …/worktrees/dlib-impl-web-console/modules/admin/viewer/worktrees/viewer），临时 worktree 自己没有 modules 目录。_reap_one 已经会先归还这类子仓。

### 容器视图（ASCII，C4 风格的轻量容器图）

`` ┌────────┐ /opsx-apply ┌──────────────────────────┐ python3 ┌───────────────────────────────┐ │ 人类 │────────────▶│ 主会话 · opsx-apply 收口 │────────▶│ slice-gate.py reap（新） │ └────────┘ └──────────────────────────┘ │ 复用 _reap_one · 归档 attic │ │ │ 打印一行 └──────┬───────────┬────────────┘ │ /clean-after-merged ▼ │ git │ 追加 │ ┌────────────────┐ ▼ ▼ └─────────────────▶│ merged-cleanup │──git──▶ ┌──────────────────────────┐ ┌─────────────┐ │ plan / apply │ │ 仓库 .git │ │ timeline.md │ │ +landed │ │ worktree 登记 · 分支 │ │ reap 事件 │ │ +dead-attempt │ │ refs/flight/<c>/attic/* │ └─────────────┘ └────────────────┘ └────────────┬─────────────┘ ┌────────────┐ slice-gate.py merge ┌─────────────────┐ │ 登记 │ integrator │────────────────────▶│ _reap（已有） │──git────▶▼ └────────────┘ └─────────────────┘ ┌──────────────────────────────┐ │ .claude/worktrees/*（临时） │ └──────────────────────────────┘ ``

  • 三个回收点，一套判据：合回时（已有，只收本片已落地的）→ 收口时（新，收本次飞行的全部）→ /clean-after-merged（存量与漏网）。
  • 只有脚本删除：收口由主会话运行脚本完成。工作流脚本本身不碰文件系统（ADR 已否决在工作流里收尾）。
  • 假设：收口时本次飞行的执行体都已返回（工作流已结束），它们的 worktree 不在使用中。锁定的仍跳过。

### 动态视图：reap --change-dir D

`` for W in git worktree list（跳过主 worktree、change 家自身、bare）: W 锁定 → kept「已锁定」 W 没有本 change 的飞行证据（D2） → 不碰，不出现在输出里 HEAD(W) 是 HEAD(change 家) 的祖先 → _reap_one(W) → reaped 否则（作废尝试） → 归档 attic（D4）→ 丢弃已归档改动 → _reap_one(W) → reaped + archived 任一步失败 → kept「<原因>」，继续下一间 timeline 追加 reap 事件；打印 JSON；exit 0 ``

Goals / Non-Goals

Goals: - 飞行收口时，本次飞行留下的临时 worktree 一间不剩（锁定的和自有子仓克隆的除外，并说明原因）。 - 不丢内容： - 已落地的，提交已在 change 分支上； - 作废的，提交与未提交改动都进 refs/flight/<change>/attic/<名>，可以 git worktree add 找回。 - /clean-after-merged 能收存量：已被合进 change 分支的临时 worktree；已落地 change 的、有自己分支的作废尝试。 - 不新增强制参数，不新增 branch -D。

Non-Goals: - 不处理 change worktree（.worktrees/<name>），仍由 /clean-after-merged 按 target 判。 - 不删未合入的 worktree-wf_* 分支（几乎不占空间；-D 交人）。 - 不清 git 对象（gc 由 git 自理）。 - 不在实现里清理任何仓库的存量（由用户执行脚本或升级后运行 /clean-after-merged）。

Decisions

*否决*

在工作流脚本收尾时清。脚本不碰文件系统，得再派 agent；中途 blocked 的飞行也走不到收尾（原 ADR 已否决）。

*否决*

门禁结束时执行体自删。执行体的 CWD 就在要删的目录里，删了会卡住。

(a) W/.openspec-slice 存在，且其 change_dir 的目录名等于本 change 名；
(b) W 的未提交改动里有 **/changes/<本 change>/{timeline.md, gate-report.md, evidence.log}。
*否决*

按 wf_* 目录名认。名字是运行时的实现细节（原 ADR 已否决）。

*否决*

按「HEAD 从本 change 派生」认。本仓库 worktree.baseRef = head，会话在 change 家里用 EnterWorktree 开的 worktree 同样从 change HEAD 派生，会被误收。

没有可丢弃三类以外的改动 → ref 直接指向 HEAD。
有 → 用临时索引（GIT_INDEX_FILE 指向临时文件，先 read-tree HEAD）把这些路径（含未跟踪、不含被忽略的）写进去，write-tree 后用 commit-tree -p HEAD 做一个提交，ref 指向它。随后丢弃这些改动（已跟踪的 checkout --，未跟踪的删文件），再交给 _reap_one。
同名 ref 已存在且指向别的提交时，名字后加 -<HEAD 前 7 位>。
分支 -d 会因未合入而失败

保留分支，不告警。

生命周期

attic 与 refs/flight/<change>/* 其他快照一样，在 /clean-after-merged 判定该 change 已落地时由 safe 档删除。这与现有快照 ref 的处理一致，也是用户批准的口径（审批页 v4：归档保留到 change 合并为止）。

找回

git worktree add <路径> refs/flight/<change>/attic/<名>。

*否决*

直接删、不归档。未交回执行体的半成品可能是人还想看的，铁律要求不丢未落地内容。

借出的子仓

_reap_one 已处理（先在 change 家子仓里 worktree remove 归还）。

自有子仓克隆

git 不带 --force 必拒（见实测）。保留，kept 写「含自有子仓克隆 <路径>，交 /clean-after-merged」。merged-cleanup 已有带未推送提交防护的 force 处理。

stdout

{"ok": true, "reaped": [路径], "archived": [{"path", "ref"}], "kept": [{"path", "why"}], "freed_kb": N, "warnings": [...]}。

freed_kb 是删除前对被删目录的磁盘占用统计（遍历文件，用 st_blocks × 512，取不到时退回 st_size）。
timeline 追加事件 reap，备注 回收 N 个 · 释放 X MB · 归档 M 个 · 保留 K 个；N 为 0 也写，供度量。
回收是善后，任何异常都只进 kept / warnings，不影响收口结论。
不在 git 仓库或 change 目录不存在时，输出 ok: true 与空列表加一条 warning。
landed
条件

W 的 HEAD 在另一个本地分支 B 的历史里，且不在 B 的 first-parent 链上（即被 merge 进 B，而不是 B 从它派生）。B 不是 W 自己的分支。

结果

不再因相对 target 的 unmerged 进 keep，按现有的 dirty / submodule / locked / outside 规则分档，原因以 landed: 开头并写明 B。

只对 unmerged 生效，fresh 维持 keep（PR #25 评审 HIGH，2026-11-19）

fresh 的 HEAD 在 target 的 first-parent 链上、没有独有提交。某个本地分支预合并 target 后，这个 HEAD 会落进那个分支的历史，但合进去的是 target 的提交，不是 W 的工作。照判会把刚开、未改动的 .claude/worktrees/ 会话目录误收。

实现

for-each-ref --contains <HEAD> refs/heads/ 一次取候选，每个分支的 first-parent 列表缓存一次。

*为什么排除 first-parent*

执行体从 change 分支的 tip 派生，所以 change 分支的 tip 落在执行体分支的 first-parent 链上。按「被包含」判，会把正在飞行的 change 家或同类 worktree 误判为已落地。

dead-attempt
条件

W 未 landed、相对 target 也未合入，但从切片标记或飞行记录改动能认出它属于 change C，且 C 已落地。

已落地 = target 树里有 openspec/changes/C/，或有 openspec/changes/archive/<YYYY-MM-DD>-C/。归档目录的识别同时让已归档 change 的 refs/flight/C/* 进 safe。
结果

W 有自己的分支 → 分支保住提交，按现有规则分档，原因 dead-attempt: C。游离 HEAD → 删除会丢提交，进 manual，原因写明。

为什么只限 .claude/worktrees/

这是看位置不是看名字，与 merged-cleanup 已有的 HOME_DIRS 区分一致。change worktree（.worktrees/）仍只按 target 判，避免把人正在用、刚好干净的 change worktree 收走。

根 CLAUDE.md 与 snippet 的铁律 6 例外加一句

飞行收口由 slice-gate.py reap 回收本次飞行的临时 worktree，作废尝试先归档。现有措辞全部保留（tests/test_merge_reap.py:153 钉住）。

clean-after-merged.md 的原因表补 landed、dead-attempt 两行。
README「切片留痕与临时 worktree 回收」一条同步。

Risks / Trade-offs

[归属证据缺失

门禁绿且没有飞行记录改动的临时 worktree，D2 认不出] → 这类本就是已落地的，合回时的 _reap 已收；漏网的由 /clean-after-merged 的 landed 判据兜底。

[作废尝试的目录被删后，人想现场查看] → attic ref 可随时 git worktree add 找回；ref 保留到该 change 落地。
[收口时仍有执行体在跑（例如人在飞行中途手动收口）] → 锁定的跳过。未锁定却在跑的，其 worktree 的提交和改动都会先归档，不丢内容，但执行体会失去工作目录。opsx-apply 只在工作流返回后才进入收口。
[landed 判据遍历分支有开销] → 一次 for-each-ref --contains 加按分支缓存的 first-parent 列表，规模与分支数线性。
[游离 HEAD 的作废尝试在 merged-cleanup 里进 manual] → 符合「判不准往保守落」；收口时的 reap 已经先归档，正常飞行不会留下这类。

Migration Plan

1. 本 change 落地后，本仓库与下游 install.sh --upgrade 即生效。之后每次飞行收口都会自动回收。 2. 存量： - A 类（已在 change 分支里、只脏在飞行记录），由用户执行 /tmp/worktree-cleanup-{afa,stc}.sh（只读核对后生成，带 HEAD 复核，不带 --force）。 - 其余在升级后运行 /clean-after-merged：landed 与有分支的 dead-attempt 进 safe，游离的进 manual。 3. 回滚：revert 本 change。attic ref 无副作用，可留可删。
