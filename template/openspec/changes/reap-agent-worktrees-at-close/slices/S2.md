# S2 · merged-cleanup.py：认出被合进其他分支的与已落地 change 的作废尝试

## 做什么

`template/.claude/hooks/merged-cleanup.py` 给 `.claude/worktrees/` 下的 worktree 加两条判据。命中后不再因为相对 target 是 `fresh` / `unmerged` 而落进 keep，改按现有的 dirty / submodule / locked / outside 规则分档：

- `landed`：HEAD 被 merge 进另一个本地分支；
- `dead-attempt`：属于已落地 change 的作废尝试。

另外，「已落地 change」的识别要认出归档目录。

规则原文见 `specs/merged-cleanup-agent-worktrees/spec.md` 的前两条 Requirement（共 5 个 scenario），决策见 `design.md` D8。

## owns

- `template/.claude/hooks/merged-cleanup.py`
- `tests/test_merged_cleanup_landed.py`（5 条 strict-xfail 骨架已写好；实现后去掉标记）

## 依赖的接口（本文件已有）

- `Ctx.merged(tip)` → `fresh | ancestor | content | unmerged`；
- `worktree_item(ctx, wt)`：现有分档逻辑，最后由 `state in ("fresh", "unmerged")` 决定 keep；
- `landed_changes(ctx)` 与 `CHANGE_RE`；
- `status_paths(wt)`、`is_flight(p)`、`FLIGHT_RE`；
- `HOME_DIRS`、`under(path, base)`、`real(p)`、`out(cwd, *args)`、`ok(cwd, *args)`、`keep_reason(state, target)`。

## 怎么做（TDD：先跑 verify 看 5 条红）

1. **只对 `.claude/worktrees/` 生效**：`under(path, os.path.join(root, ".claude", "worktrees"))` 为真才做下面两步。`.worktrees/` 下的 change worktree 行为完全不变。
2. **landed**：
   - 在 `Ctx` 里缓存两样东西：
     - `heads = for-each-ref --format=%(refname) refs/heads/`；
     - 每个分支的 first-parent 集合，按需 `rev-list --first-parent <分支>`，算一次就缓存。
   - 对 `state in ("fresh", "unmerged")` 的 W：取 `for-each-ref --contains <HEAD> --format=%(refname:short) refs/heads/`。去掉 W 自己的分支，剩下的分支里取第一个满足「HEAD 不在其 first-parent 集合里」的 B。
   - 命中 → `item["merged"] = "branch"`，`reasons.append("landed: 已合进本地分支 %s" % B)`，不再进 keep。
3. **dead-attempt**（landed 未命中、`state == "unmerged"` 时）：
   1. 认 change：先读 `W/.openspec-slice`，JSON 里 `change_dir` 的目录名就是 change 名；读不到时，看 `status_paths(W)` 里匹配 `FLIGHT_RE` 的路径，用 `CHANGE_RE` 取 change 名。取到多个不同的名字就当作认不出。
   2. 认出 C，且 `C in landed_changes(ctx)`：
      - W 有自己的分支（`wt["branch"]` 非空）→ `reasons.append("dead-attempt: %s 已落地，提交仍在分支 %s" % (C, 分支短名))`，不进 keep；
      - 游离 HEAD → `reasons.append("dead-attempt: %s 已落地，但提交只在该 worktree（游离 HEAD），删除会丢失" % C)`，落 manual。
4. **`landed_changes` 认归档目录**：
   - 归档目录形如 `(?:^|/)openspec/changes/archive/\d{4}-\d{2}-\d{2}-([^/]+)/`，命中的名字计入；
   - 原有的 `CHANGE_RE` 命中名为 `archive` 时不计入。

   这一改动同时让已归档 change 的 `refs/flight/<C>/*` 进 safe（现有逻辑按 `landed_changes` 判）。
5. 分支项（`branch_item`）不改：未合入 target 的 `worktree-wf_*` 分支仍是 keep，`-D` 永远交人。
6. 测试全绿后去掉 5 个 xfail 标记；`tests/test_merged_cleanup.py` 的既有用例必须保持绿。

## 注意

- safe 的语义是「执行后不丢任何未落地内容」（`DRAFT-post-merge-cleanup-by-tiered-script`）。dead-attempt 能进 safe，是因为提交还留在 W 自己的分支上；游离 HEAD 没有这层保障，所以落 manual。
- 不得改动 apply 的执行顺序与授权边界。
