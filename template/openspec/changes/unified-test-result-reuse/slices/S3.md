# S3 · 判定器基线侧：经锚点复用、按部件复用、门禁脚本闭包口径、基线链长上限、timeline 原因

## 做什么

只改 `template/.claude/hooks/slice-gate.py`，实现 design D7、D8、D10、D13 与 D6 的基线部分。规则原文见 `specs/baseline-anchor-reuse/spec.md` 除「cmd_key 归一」「final 链长」「按 nodeid 差分」之外的需求。约束同 S1。

1. **候选**（D7）：`_baseline_candidates` 改为三级——本 change 旧基线 → 锚点 → 基线池。
   - 锚点用 `_anchor_candidates(root, akey, None)`，满足 measured、`hops < K`（K 取 `_scope_extras`）；
   - 多条可用时按 `_delta` 取 |Δ| 最小的；
   - 有测试分层文件或带 `--full` 时仍然没有候选（现状）。
2. **锚点路径**：
   - `_full_triggers`（含 `declared_global`）有触发项 → 跳过，理由进 `reuse_skipped`（理由文字里带全局文件的说法与路径）；
   - 否则用 `_final_select`（含 `blind`）选文件，经 `_pytest_outcomes(..., deps_out=…, extra_env=GATE_PHASE/GATE_CHANGE)` 补跑；
   - 补跑超时、rc 不在 {0, 1, 5}、或有收集错误 → 中止，走全量。
   - 结果按 `_interfaces.md`「S3 提供」写入；verify 全部重跑；写新锚点（`source: "baseline-incremental"`，`hops` = 来源 + 1）。
3. **按部件复用**（D8）：
   - 基线写 `test_ok`；
   - `_try_reuse` 对本 change 旧基线接受 `ok is True or test_ok is True`；跨 change 与池候选仍要求 `ok is True`；
   - 缺 `test_ok` 字段不放宽。
4. **门禁脚本口径**（D10）：本 change 旧基线候选的「测试结论 Δ」去掉不在 gate.test / `gate.pytest` 静态 shell 闭包里的本 change 目录门禁脚本；verify 与 lint / typecheck 的判定仍用完整 Δ。
5. **基线链长**：锚点全部 `hops >= K` → `reuse_skipped` 写 `锚点链已达上限 <K> 代`。
6. **timeline 备注**（D13）：格式见 `_interfaces.md`。

- 旧测试里断言「非测试改动 → 全量」的用例，如果因为现在有了锚点而变成增量，说明它们原本测的是「没有锚点时」的行为：给它们的被测仓库加 `--full` 前置或去掉锚点池，保留原意，不删用例。
- 基线池的入池条件不改。
