# S5 · 文档：运行器契约、propose / apply 指引、选测声明措辞

## 做什么

实现 design D2、D3、D5、D14 中文档侧的部分。规则原文见 `specs/flight-runner-contract/spec.md`「运行器契约文档随模板下发」与 `specs/test-cost-visibility/spec.md`「预告与体检出现在人看得见的地方」中的文档要求。命令与同名 skill 必须同改，措辞一致。

1. **新增 `template/.claude/flight-runner-contract.md`**（项目侧接入的唯一依据）：
   - 包装脚本的转发方法：给出一段 bash 示例，`PYTHONPATH` 以 `$FLIGHT_PLUGIN_PATH` 开头，`eval "args=($FLIGHT_PYTEST_ARGS)"` 后传给 pytest；
   - `GATE_PHASE` / `GATE_CHANGE`；
   - `GATE_TEST_RESULT` 的字段与 `mode` / `inherited` / `complete` 的用法（只要实跑结果的检查看 `mode == "full"`）；
   - 必须有一行同时写明：`FLIGHT_` 与 `GATE_` 前缀的变量每次运行都变，项目缓存键必须剔除，建议白名单；
   - 四个类别名与修法；
   - `gate-scope.json` 的 `global` / `blind` / `anchor_max_hops`；
   - 接入步骤：改包装脚本 → 跑 baseline 确认依赖图测到 → 对账（同一棵树增量与全量逐条一致）→ 声明 global / blind → 检查改读结果文件。
2. **`opsx-propose.md` 与 `openspec-propose/SKILL.md`**：
   - 在生成门禁脚本的指引处加同一句（逐字相同、单独成行），句中同时含 `FLIGHT_PLUGIN_PATH`、`FLIGHT_PYTEST_ARGS`、`$GATE_CHANGE` 与「不写死」：
     > 新写的 gate.test 包装脚本必须转发 `FLIGHT_PLUGIN_PATH` / `FLIGHT_PYTEST_ARGS`，用 `$GATE_CHANGE` 取 change 名，不写死 change 名（见 `.claude/flight-runner-contract.md`）。
   - step 5 基线复用描述改为新规则：旧基线 → 锚点（按依赖图补跑，跨 change 带红只经锚点）→ 基线池；链长上限；红基线按部件复用。
   - 基线报告行之后运行 `python3 .claude/hooks/flight-doctor.py forecast --change-dir openspec/changes/<name>` 并原样转述，写明「只预告，不阻断」。
3. **`opsx-apply.md` 与 `openspec-apply-change/SKILL.md`**：
   - step 3 preflight 之后运行 `flight-doctor.py forecast` 并原样打印，写明「只预告，不阻断」；
   - step 6 `timeline.py report` 之后运行 `flight-doctor.py cost --change-dir openspec/changes/<name>`。
4. **`schema.yaml` 与 `README.md`**：选测声明的措辞改为「恰含 cmd 或 builtin 之一，另可选 global / blind / anchor_max_hops」；README 补一节「运行器契约」，指向契约文档。
