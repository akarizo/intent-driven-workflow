# S1 · 判定器契约层：结果交接、gate.test 环境、运行器契约变量、依赖图未测四分类、锚点 nodes、cmd_key 归一

## 做什么

只改 `template/.claude/hooks/slice-gate.py`，实现 design D1–D4、D9。规则原文见 `specs/gate-test-result-handoff/spec.md` 与 `specs/flight-runner-contract/spec.md` 的前两条需求，以及 `specs/baseline-anchor-reuse/spec.md` 的「cmd_key 归一」。约束：纯标准库、Python 3.9 兼容（禁 `match`、禁 `X | Y` 注解），能通过 compileall。

1. **契约变量**（D3）：`_flight_plugins` 写好插件之后，在 env 里设：
   - `FLIGHT_PLUGIN_PATH`：插件临时目录；
   - `FLIGHT_PYTEST_ARGS`：`-p flight_guard`［`-p flight_deps`］［`-p flight_tier_probe`］`--junitxml=<path>`，用 `" ".join(shlex.quote(x) for x in ...)` 拼。
   - `_plain` 路径不设。
   - 现有的 `PYTEST_ADDOPTS` 与 `PYTHONPATH` 注入不变。
2. **四分类**（D4）：
   - `_read_deps` 与 `run_test_gate` 产出 `deps_kind`，判据见 design D4；
   - 汇总行复用现有的汇总行判定；junit 是否存在看临时目录里的 `junit.xml`；
   - `deps_why` 带修法，前两类点名 `FLIGHT_PLUGIN_PATH`、`FLIGHT_PYTEST_ARGS`、`.claude/flight-runner-contract.md`。
   - 基线记 `deps_unmeasured: {kind, why}`；warning 文字改为 `依赖图未测（<kind>）：<why>`；
   - 锚点记 `deps_kind`。
3. **gate.test 环境**（D2）：
   - baseline 与 final 调 `run_test_gate`、`_pytest_outcomes`、`gate.impacted` 时，经 `extra_env` 传 `GATE_PHASE` / `GATE_CHANGE`；
   - `_pytest_outcomes` 新增 `extra_env` 参数。
4. **锚点 nodes**（D1）：
   - 全量锚点写依赖图插件的逐用例结局 `nodes`（outcome 统一小写）；
   - 增量锚点在 `_anchor_forward` 里同口径替换重跑过的文件；依赖图未测时写 `{}`。
5. **结果交接**（D1）：
   - `run_test_gate` / `_pytest_outcomes` 新增 `keep_junit`；
   - final 在 gate.test 判定之后、跑检查之前写 `.gate-test-result.json`（原子写），字段见 spec；
   - 增量时 `nodes` = 锚点 `nodes` 中未选中文件的条目 ∪ 本次重跑结局，`inherited` = 前者条数，`complete` 的口径见 design D1；
   - 检查环境（`_check_env` 的 final 分支）加 `GATE_TEST_RESULT`；同树沿用时不写、不设；baseline 不设。
6. **cmd_key**（D9）：
   - 对命令里直接写出的仓库内文件加上 `_shell_closure` 的闭包，逐个读内容；
   - 内容按词边界（前后不是 `[A-Za-z0-9_-]`）把 `os.path.basename(change_rel)` 换成 `<change>` 后取 sha1，与归一后的命令文本一起进指纹；
   - 读不到的文件只记路径。

## 注意

- 依赖图插件与 sitecustomize 的行为不变：契约变量只是多出口，旧路径照旧可用。
- `cmd_key` 算法变化会让既有基线、锚点、池条目失配，这是预期行为（design D9 BREAKING）。只为算法变化本身调整旧测试，不放宽其他断言。
