# S4 · propose 命令与 skill 改用工具链

## 做什么

`/opsx-propose` 命令与 `openspec-propose` skill（同改）改用 S1–S3 的工具，补断言按测试文件用 fork 并行。规划期不变式测试改为「派发只允许 fork」。

规则原文见 `specs/propose-fork-assertions/spec.md`（4 个 scenario），决策见 `design.md` D8。

## owns

- `template/.claude/commands/opsx-propose.md`
- `template/.claude/skills/openspec-propose/SKILL.md`
- `tests/test_propose_toolchain.py`（4 条 strict-xfail 骨架已写好）
- `tests/test_routing_docs.py`（`test_planning_docs_carry_no_routing` 里「正文不含 `subagent_type`」一句要放宽为「只允许 fork」）

## 依赖的接口

- **S1** `plan-kit.py instructions --change <name>`、`tasks --change-dir`、`packets --change-dir`；packets 的机械区在 `<!-- plan-kit:begin -->` / `<!-- plan-kit:end -->` 之间，标记之外由主会话写。
- **S2** `plan-scaffold.py scaffold --change-dir`、`gwt --change-dir`；占位标记是 `PLAN-SCAFFOLD-PLACEHOLDER`，模块常量 `PLACEHOLDER`。
- **S3** `slice-gate.py warm --change-dir`（分层仓库或找不到命令时打印「跳过预热」并 exit 0；stdout JSON 的 `test_cmd` 是建议的 `gate.test`）；baseline 会自动等仍在跑的预热；lint 对占位判 `skeleton:` 红；模块常量 `SCAFFOLD_PLACEHOLDER`。

## 怎么做（TDD：先跑 verify，看 4 条 xfail）

两份文档同步修改。工具调用的首次出现顺序必须是：`slice-gate.py warm` → `plan-kit.py instructions` → `plan-kit.py packets` → `plan-scaffold.py scaffold` → `plan-scaffold.py gwt` → `plan-kit.py tasks` → `slice-gate.py lint --change-dir` → `model-routing.py pin`。

注意：现有文档在 step 3 之前可能已经出现 `slice-gate.py lint` 等字样。顺序断言看的是首次出现，所以必要时调整措辞，保证前面的段落不提前出现后面的命令。

### 1. step 2 之后：后台预热

建好 change 目录后立即后台运行 `python3 .claude/hooks/slice-gate.py warm --change-dir openspec/changes/<name>`（例如 Bash 的 `run_in_background`），不等它结束，并说明：
- 它沿用最近一个 change 的 `gate.test`（stdout 的 `test_cmd`）；
- 计划的 `gate.test` 写成同一条命令，正式 baseline 才能复用；
- 分层仓库或无可沿用命令时，它打印「跳过预热」，什么也不做。

### 2. step 3：一次取 instruction

把「并行对每个待建工件跑 `openspec instructions …`」改为运行一次 `python3 .claude/hooks/plan-kit.py instructions --change "<name>"`。

### 3. tasks 阶段，写完 slices.json 之后

1. `plan-kit.py packets --change-dir …`：在每个包的 `<!-- plan-kit:end -->` 之后写接口约定、怎么做、注意事项。机械区不手改，改 slices.json 后重跑。
2. `plan-scaffold.py scaffold --change-dir …`：生成骨架，然后进入补断言段。这一段必须写明：
   - **分组**：按**测试文件**分组；
   - **多于 1 组**：同一条消息里为每组派一个 fork（Agent 工具，`subagent_type: "fork"`）。prompt 写明只改分到的文件：把 `PLAN-SCAFFOLD-PLACEHOLDER` 那行换成真实断言，必要时加 fixture 参数，保留 GWT 注释与 xfail 标记；不碰其他文件；完成后运行 `gwt` 并回报。
   - **回退**：fork 报错或不可用 → 主会话**串行**补完剩下的组；
   - **只有 1 组**：主会话自己写；
   - **路由**：fork 继承主会话，不进路由配置。
3. `plan-scaffold.py gwt --change-dir …` 必须 exit 0。
4. `plan-kit.py tasks --change-dir …` 生成 tasks.md，替换原来「tasks.md 由 slices.json 生成」的手写说明。
5. 保持原有的 `slice-gate.py lint --change-dir …` 与 `model-routing.py pin --change-dir …`。

### 4. `tests/test_routing_docs.py`

`test_planning_docs_carry_no_routing` 里 `"subagent_type" not in t` 改为：正文里每个 `subagent_type` 的取值都是 `fork`。`model: "` 的断言保留。

### 5. 收尾

去掉 4 个 xfail 标记，verify 全绿。
