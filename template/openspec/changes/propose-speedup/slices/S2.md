# S2 · plan-scaffold.py：scaffold / gwt

## 做什么

新建 `template/.claude/hooks/plan-scaffold.py`：
- `scaffold`：按 `scenario_tests` 生成缺失的 strict-xfail 测试函数；
- `gwt`：规划期的 G4 与占位标记自查。

规则原文见 `specs/scenario-scaffold/spec.md`（4 个 scenario），决策见 `design.md` D1、D5、D6。

## owns

- `template/.claude/hooks/plan-scaffold.py`（新建）
- `tests/test_plan_scaffold.py`（4 条 strict-xfail 骨架已写好）

## 接口

```
plan-scaffold.py scaffold --change-dir D   # stdout {"created": [...], "existing": [...], "skipped": [...]}；exit 0 / 2
plan-scaffold.py gwt      --change-dir D   # 逐条打印问题；有问题 exit 1，全部通过 exit 0
```

- **模块常量** `PLACEHOLDER = "PLAN-SCAFFOLD-PLACEHOLDER"`：S3 在 `slice-gate.py` 里定义同值的 `SCAFFOLD_PLACEHOLDER`，S4 的端到端测试断言两者相等。
- **仓库根**：`git -C D rev-parse --show-toplevel` 成功就用它；否则用 `D/../../..`（与 `spec_html.project_root` 同一口径）。测试夹具不是 git 仓库，走后一种。
- **scaffold**：
  - scenario 文本取自 `D/specs/<能力>/spec.md` 的 `#### Scenario: <名>` 块；能力名取 `scenario_tests` 键里 `#` 前的部分；
  - 归属切片：在 `slices[].scenarios` 里找到包含该键的那片，取它的 id 填进 `reason="<id> 未实现"`；
  - 函数已存在的判定：与 G7 相同的正则 `^\s*(?:async\s+)?def\s+<func>\s*\(`；
  - 生成函数的形状见 design D5；AND / BUT 并入它前面那个关键字所在的行，用「；」连接；
  - 新文件：先写模块 docstring「<能力名> 的 scenario 骨架（strict xfail；切片 <S> 实现后去掉标记即解锁）。」，再写 `import pytest`；
  - 已有文件缺 `import pytest`：用 `ast` 找最后一条顶层 import 的结束行，插在它后面；没有 import 就插在 docstring 后面；两者都没有就插在文件开头；
  - 追加的函数之前空两行（PEP 8）；
  - 映射的 scenario 在 specs 里找不到 → exit 2，stderr 点名。
- **gwt**：
  - 按路径加载同目录的 `slice-gate.py`（文件名含连字符，用 `importlib.util.spec_from_file_location`，写法参照 `session-decompose.py` 的 `load_alias_of`），调用 `gwt_violations(root, files)`，只保留点名到映射函数的那几条；
  - 再对每个映射函数（`.py`）检查函数体（AST 取源码段）里有没有 `PLACEHOLDER`，命中就打印 `占位: <path::func> 仍是 scaffold 占位断言`。

## 怎么做（TDD：先跑 verify，看 4 条 xfail）

1. 先写 scaffold，去掉 3 条 scaffold 测试的 xfail 标记，跑绿。
2. 再写 gwt，去掉最后一条的标记，跑绿。
3. 只用标准库，兼容 Python 3.8+；头注释写用途与退出码。

## 注意

- 不改 `slice-gate.py`（S3 并行在改）。gwt 只读取它的 `gwt_violations`，这个函数在 main 上已存在。
- 测试里的 `ast.unparse` 在 3.8 下不可用时有兜底，不必管。
