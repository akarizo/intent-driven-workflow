# S3 · slice-gate.py：warm 预热、baseline 等待预热、lint 判占位

## 做什么

`template/.claude/hooks/slice-gate.py` 做三件事：
- 新增 `warm` 子命令；
- `baseline` 读旧基线前等待仍在跑的预热；
- `lint` 判 scaffold 占位标记。

规则原文见 `specs/baseline-warm/spec.md`（5 个 scenario）与 `specs/propose-fork-assertions/spec.md` 的「未补完的骨架不能通过 lint」，决策见 `design.md` D6、D7。

## owns

- `template/.claude/hooks/slice-gate.py`
- `tests/test_baseline_warm.py`（5 条 strict-xfail 骨架已写好）
- `tests/test_lint_placeholder.py`（规划期已写好，不映射 scenario：1 条 strict-xfail 驱动 lint 红线，1 条护栏已绿；实现后去掉标记）

## 现有接口（本文件内）

- `cmd_baseline(args)`（约第 4874–5277 行）：
  - 开头依次是 `load_plan`、检查形状、分层、`_lint_scope`、`plan_sha`、读旧基线、`_snapshot`、`cmd_key`、写运行标记、`flight_lock`；
  - 然后是候选判定（`nocand = args.full or tiers is not None`）、全量、lint / typecheck、verify、区域、检查、运行期间改动、锚点、账本、池；
  - 最后写 `gate-baseline.json`、记 timeline、打印 JSON。
- `_preflight_running`（约第 5295 行起）：判断运行标记的 pid 是否存活，写法可复用。
- `_tiers_path(change_dir)` / `_load_tiers`：分层文件。
- `lint_plan(data, change_dir, ...)`：错误列表追加在 `errors`。
- `_test_bodies(rel, lines)`：取测试函数体。
- `_shell_closure(root, files)`、`_repo_rel(root, tok)`：命令引用到的文件。

## 怎么做（TDD：先跑 verify，看 5 条 xfail）

### 1. lint 红线（`tests/test_lint_placeholder.py` 已有 xfail 用例，先看它红）

- 模块常量 `SCAFFOLD_PLACEHOLDER = "PLAN-SCAFFOLD-PLACEHOLDER"`。
- `lint_plan` 在 `change_dir is not None` 时，对每个 `.py` 的 `scenario_tests` 目标读文件、取函数体，含该常量 → `errors.append("skeleton: %s 仍是 scaffold 占位断言，补真实断言后再 lint" % target)`。
- 文件或函数不存在时跳过（那是 G7 的事）。
- 仓库根取 `_git_top(change_dir)`，取不到就跳过。

### 2. warm 子命令

`warm --change-dir D [--cmd CMD]`，按 design D7 的顺序定命令：
- `--cmd`；
- 分层文件存在 → 打印 `跳过预热：分层仓库的 baseline 恒走全量`，exit 0；
- `<D 的上一级>` 下、除 `archive` 与 D 自己之外，`slices.json` mtime 最新、且 `gate.test` 非空的 change；
- 都没有 → 打印 `跳过预热：没有可沿用的 gate.test`，exit 0。

**沿用包装脚本**：
- 对来源命令切词，取 `_repo_rel` 落在 `<来源 change 目录>/` 下的文件，加上它们的 `_shell_closure` 里同样落在来源目录下的文件；
- 复制到 D 的同一相对位置，已存在就不覆盖，保留可执行位；
- 命令文本里把来源 change 目录的仓库相对路径替换成 D 的；
- 来源计划带 `gate.pytest` 时一并沿用。

**运行**：
- 把 `cmd_baseline` 的主体抽成 `_run_baseline(change_dir, data, full, warm=False)`，`cmd_baseline` 读计划后调用它；
- warm 传入 `data = {"gate": {"test": cmd[, "pytest": …]}, "slices": []}`、`full=True`、`warm=True`。

**warm=True 时与 baseline 的差别**：
- 跳过 `_lint_scope` 复核与检查（没有 checks）；
- 运行标记与结果都带 `"warm": true`；
- `plan_sha` 写 null，并跳过「运行期间 gate / verify 被修改」那一项，因为 D 里还没有 `slices.json`；
- 时间线事件名为 `warm`；
- 其余照常：快照、指纹、锁、全量、运行期间改动、锚点、账本、池。

**退出码**：按 ok。stdout 打印结果 JSON，带 `test_cmd`。

### 3. baseline 等待预热

在 `cmd_baseline` 读旧基线之前（运行标记被覆盖之前）：
- 如果 `gate-baseline.json` 是 `{"running": true, "warm": true, "pid": …}` 且 pid 存活 → 往 stderr 打印一次 `等待预热结束（pid …）`，每 2 秒复查一次；
- 直到文件不再是运行标记，或进程已不在，然后继续原流程。

复用规则一个字不改。

### 4. 头注释与收尾

- 文件头注释的子命令清单补 `warm`，并在 `baseline` 一段补「先等仍在跑的预热」。
- 去掉 5 个 xfail 标记，verify 全绿。

## 注意

- `test_baseline_waits_for_running_warm` 会在预热跑的时候写入未提交的计划文件。计划工件与 change 目录里不在 gate.test 闭包内的脚本不进快照差异，这正是现有规则，不要为了这条测试放宽运行期间改动检测。
- 改 `cmd_baseline` 时保持既有 baseline 测试全绿（verify 已包含主要的几组）。
