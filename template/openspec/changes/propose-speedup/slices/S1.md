# S1 · plan-kit.py：instructions / tasks / packets

## 做什么

新建 `template/.claude/hooks/plan-kit.py`，提供三个零 token 子命令。规则原文见 `specs/plan-kit-commands/spec.md`（6 个 scenario），决策见 `design.md` 的 D1–D4。

## owns

- `template/.claude/hooks/plan-kit.py`（新建）
- `tests/test_plan_kit.py`（6 条 strict-xfail 骨架已写好，实现后去掉标记）

## 接口

```
plan-kit.py instructions --change <name> [--all]   # 在当前目录调用 openspec CLI
plan-kit.py tasks    --change-dir D
plan-kit.py packets  --change-dir D
```

- **instructions**：
  - 先 `openspec status --change <name> --json`，取 `artifacts[]`（`id` / `outputPath` / `status`）；
  - 对每个 `status != "done"` 的工件（带 `--all` 时全部），运行 `openspec instructions <id> --change <name> --json`，读 `instruction` / `template` / `rules`（rules 是列表，可能为空）；
  - 每个工件打印一节：`## <id> → <outputPath>`，下面依次是 `### instruction`、`### template`（放进 markdown 代码块）、`### rules`（为空就省略）；
  - 任一次子进程非 0，或 JSON 解析失败 → exit 2，stderr 写 `openspec <参数…> 失败：<子进程 stderr 末行>`。
- **tasks**：格式见 design D3，逐字与 `template/openspec/schemas/intent-driven/templates/tasks.md` 一致：
  - 文件头注释行是 `<!-- 本文件由 slices.json 生成，不要手写编辑；改动请改 slices.json 后重新生成。 -->`；
  - 接着空一行、`## 切片`、再空一行，然后每片一行；
  - 旧文件里 `- [x] <id> ` 开头的行 → 该 id 保持勾选。
- **packets**：标记、区内结构与「已存在 / 无标记」的处理见 design D4。
  - 依赖切片一行：`- \`S1\` · <标题> · \`slices/S1.md\``；
  - scenario 小节标题：`### <能力>#<scenario> → \`<path::func>\``。下面原样列出该 scenario 在 `specs/<能力>/spec.md` 中 `#### Scenario: <名>` 之后、下一个 `####` / `###` / `##` 之前，所有以 `- **GIVEN|WHEN|THEN|AND|BUT**` 开头的行；
  - spec 里找不到该 scenario → 写一行「（specs 中未找到）」，不报错；
  - 写文件统一用 UTF-8、`\n` 换行，末尾一个换行。

## 怎么做（TDD：先跑 verify，看 6 条 xfail）

1. 头注释写用途、子命令与退出码，风格参照 `model-routing.py`。只用标准库，兼容 Python 3.8+。
2. 逐个子命令实现，每完成一个就去掉对应测试的 xfail 标记，跑绿。
3. `openspec` 不在 PATH 时，同样 exit 2，并写明命令找不到。
