# S4 · 安装器与 README（摘自原仓 #35 #36 #38 #55 + 本仓新增）

**做什么**：安装器缺省从本仓下载并带上原仓的安装器修复与 Mod 版退场提示；README 写明本仓的安装方式与两个版本的关系。语义见 `specs/installer-edition/spec.md`。

**owns**
- `install.sh`
- `README.md`
- `tests/test_install.py`

**做法**
1. `install.sh` 以 v2.0 为底：
   - `REPO_URL` 缺省改为 `https://github.com/akarizo/intent-driven-workflow`，文件头与 `--help` 里的仓库名同步；`IDT_BRANCH` 缺省仍为 `main`；
   - pipe 段换成原仓 `f7df55f` 的终版：先按分支、再按 tag 下载归档，落盘后解压，交给归档自带的 `install.sh`（本地模式），退出码透传；`--help` 的 `IDT_BRANCH` 说明为「分支或 tag」（#38）；
   - `copy_tree` 的 preserve 支持空格分隔多个名字；复制 `.claude/` 时保留 `preferences.md` 与 `settings.json`；`merge_settings` 补模板 settings 里缺失的顶层键（#35 #36）；
   - `openspec/` 只按清单下发种子与 `schemas/`，结尾列出疑似旧版误拷的本库开发工件（#55）；
   - 新增：目标 settings 的 `enabledPlugins["flight@intent-driven"]` 为 true 时醒目提示，并打印 `claude plugin uninstall flight@intent-driven -s project` 与 `claude plugin marketplace remove intent-driven --scope project`，不代执行；目标里有 `.claude/hooks/ledger.py`、`.claude/hooks/plan_fp.py` 时列出并提示可手动删除；
   - **不带**：flight 插件安装、`RETIRED` 退役 hook 注册移除、退役文件清单（`opsx-apply.js` 等）、「已迁入插件」清单。
2. `README.md` 以 v2.0 为底：标题与安装 / 更新命令里的仓库名改为本仓；新增「### 安装指定版本」（本仓 tag 表 stable-v1.0 / stable-v2.0；pipe 写法用本仓 main 的 install.sh 加 `IDT_BRANCH`；clone 写法用 `--branch`；不支持用 `--upgrade` 降级）；新增「## 与 Mod 版的关系」（原仓 `akarizo/intent-driven-claude-code`、从 Mod 版切换的步骤与两条卸载命令）。
3. 去掉 `tests/test_install.py` 里 15 条 `workflow-edition S4` 的 xfail 标记。

**已在基底成立的 scenario**（不带标记，改完须仍绿）：`installer-edition#upgrade-reregisters-v2-hooks`、`installer-edition#upgrade-keeps-user-seed-edits`。
