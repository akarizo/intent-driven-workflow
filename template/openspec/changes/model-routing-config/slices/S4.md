# S4 · spec_html.py：审批面板显示钉住的模型路由

## 做什么

`template/.claude/hooks/spec_html.py` 的飞行区块，在「切片」表之前加一个「模型路由」小节：
- `slices.json` 有 `routing` → 输出表格，flight 组与 ship 组的每个键各一行（键 · 模型 · effort），表头注明来源；
- 没有 `routing` → 输出提示：「未钉住模型路由：起飞会被拒绝，先运行 `python3 .claude/hooks/model-routing.py pin --change-dir <change>`」。

规则原文见 `specs/spec-html-routing/spec.md`（2 个 scenario），决策见 `design.md` D3。

## owns

- `template/.claude/hooks/spec_html.py`
- `tests/test_spec_html_routing.py`（2 条 strict-xfail 骨架已写好）

## 现有接口（本文件内）

- `render_flight(change_dir)`：第 704–767 行，读 `slices.json`，拼「切片」「Scenario 状态」「飞行记录」等表；可沿用 `esc()` / `inline_md()`，以及 `flight-table` 的 class。

## 怎么做（TDD：先跑 verify，看 2 条 xfail）

1. 新增 `render_routing(data)`，返回 HTML 字符串：
   - 表头 `<h3>模型路由</h3>`；
   - 每行的第一格是 `<td class="mono">flight.executor</td>` 这样的完整 `组.键`，后面依次是模型与 effort；
   - 来源写在表格上方的一句说明里，取 `routing.source`；
   - 只渲染 `flight` 与 `ship` 两组，按 `executor, executor-large, fixer, reviewer, integrator, reviewer, followup` 的顺序；缺的键跳过。
2. `render_flight` 在返回串的最前面拼上 `render_routing(data)`。
3. 去掉 2 个 xfail 标记；`tests/test_spec_html*.py` 的既有用例保持绿（它们的夹具没有 routing，所以页面会多出提示，不影响原有断言）。
