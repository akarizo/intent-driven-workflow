# S5 · 命令与 skill：各派发点从路由配置取值

## 做什么

把执行层的每个派发点都改为从 `model-routing.py` 取 model 与 effort，删掉 `<main>`、`--model=` 与写死的 sonnet。propose 在 tasks 阶段运行 pin。新增规划期不变式测试。

规则原文见 `specs/routing-docs/spec.md`（3 条 Requirement、4 个 scenario），决策见 `design.md` D3、D7、D8、D9。命令与同名 skill 必须同改（本仓库开发纪律）。

## owns

- `template/.claude/commands/opsx-apply.md` + `template/.claude/skills/openspec-apply-change/SKILL.md`
- `template/.claude/commands/opsx-propose.md` + `template/.claude/skills/openspec-propose/SKILL.md`
- `template/.claude/commands/pr-ship.md`
- `template/.claude/commands/opsx-archive.md` + `template/.claude/skills/openspec-archive-change/SKILL.md`
- `template/.claude/commands/claudemd-standardize.md`
- `template/.claude/commands/opsx-bulk-apply.md` + `template/.claude/skills/openspec-bulk-apply-change/SKILL.md`
- `template/.claude/skills/legacy/openspec-subagent-apply-change/SKILL.md`
- `tests/test_routing_docs.py`（4 条 strict-xfail 骨架已写好）
- `tests/test_template_docs.py`（钉住旧措辞的用例需同步，见下）

## 依赖的接口

- **S1** `model-routing.py`：`resolve --change-dir` → `{"models", "efforts"}`（5 个角色）；`pin --change-dir`；`get <组.键> [--change-dir]` → `{"model", "effort", "source"}`；exit 3 = 未 pin 或环境覆盖；模块常量 `PLANNING_GROUPS`。
- **S2** 工作流：`args.models` / `args.efforts` 接受 5 个角色（executor / executor-large / fixer / reviewer / integrator）。
- **S3** `session-decompose.py`：`--expect-models '<JSON>' --expect-efforts '<JSON>' --turns '<turns JSON>'`。

## 怎么做（TDD：先跑 verify，看 4 条 xfail）

### 1. apply（命令与 skill 同改）

**路由表**改为 5 行：

| 角色 | 键 |
|---|---|
| slice-executor | `flight.executor` |
| slice-executor-large | `flight.executor-large` |
| 批量修复与 wave 跨片修复 | `flight.fixer` |
| code-reviewer | `flight.reviewer` |
| integrator | `flight.integrator` |

取值来自 `slices.json.routing`，即规划期钉住、人类批准时看到的那份。

**删除**：`--model=` 旗标说明、`session-model.py` 的判定步骤，以及全部 `<main>`。

**step 2（lint / preflight 之后）**新增：
- 运行 `python3 .claude/hooks/model-routing.py resolve --change-dir openspec/changes/<name>`；
- exit 非 0 → 停下，把 stderr 原样报告（未 pin：给出 pin 命令，pin 后要人类重新批准；环境覆盖：说明要先 unset 哪个变量）；
- 绿了就运行 `model-routing.py show --change-dir …`，把路由表原样打印（「起飞只打印」）。

**step 3**：`.flight` 的字段改为 `{"started", "approval", "models", "efforts", "source"}`，`source` 取 `routing.source`；删除 `raw`。

**step 4**：
- Workflow args 的 `models` / `efforts` 直接用 resolve 的输出；
- 回退路径：每个 Agent 派发显式传 `model` 与 `effort`，取 resolve 的值。执行体用 `flight.executor`，大片档用 `flight.executor-large`，fix 与跨片修复用 `flight.fixer`，评审用 `flight.reviewer`，integrator 用 `flight.integrator`。
- 把「Agent 工具没有 effort 参数，effort 由 agent frontmatter 决定」改为：「Agent 派发带 `effort`（取自 model-routing resolve）；Agent 工具不支持 effort 参数的旧版本由 agent frontmatter 决定，回退路径收口不对账 effort」。

**step 5**：`session-decompose.py` 加 `--expect-efforts '<.flight 里的 efforts>' --turns '<step 2 turns 的输出>'`，不符同样按铁律 11 追加 HIGH。

**Guardrails**：把 `<main>` 那条改为「路由取自 `slices.json.routing`，经 `model-routing.py resolve` 读取；未 pin 或环境覆盖即停飞」。

### 2. propose（命令与 skill 同改）

tasks 阶段 `slice-gate.py lint` 绿之后：
- 运行 `python3 .claude/hooks/model-routing.py pin --change-dir openspec/changes/<name>`；
- 说明：pin 把 flight 与 ship 的路由钉进 `slices.json.routing`，spec.html 会显示它，人类批准即确认；之后改路由要重新 pin，并重新批准。

不得新增任何 `subagent_type`、`model: "` 或 frontmatter 的 `model` / `effort`（规划期不变式）。

### 3. pr-ship

- **step 8 的 code-reviewer 派发**：先运行 `python3 .claude/hooks/model-routing.py get ship.reviewer --change-dir openspec/changes/<name>`（没有 change 时去掉 `--change-dir`），再按它的 `model` / `effort` 派发；
- **复核**：用 `ship.followup`；
- 删除 `session-model.py` 与 `<main>`。

### 4. archive（命令与 skill 同改）

sync 派发：`model: "sonnet"` → 先 `get archive.sync --change-dir …`，再按结果带 `model` / `effort`。

### 5. claudemd-standardize

证据调查子 agent：`model: sonnet` → `get claudemd.evidence`，按结果派发。

### 6. bulk-apply（命令与 skill 同改）

每个子 agent 派发前 `get bulk.apply`，显式带 `model` / `effort`（补上漏写的 model）。

### 7. legacy 逐 task 模式

- 4a 实现：`get flight.executor --change-dir …`；
- 修复：`get flight.fixer --change-dir …`；
- 评审（三处）：`get flight.reviewer --change-dir …`；
- 每处都显式带 `model` / `effort`，删除 `<main>` / `session-model.py`。
