# S2 · opsx-apply.js：按 5 个角色派发

## 做什么

`template/.claude/workflows/opsx-apply.js` 从 3 个角色扩到 5 个：
- 大片档执行体用 `executor-large`；
- 批量修复与 wave 跨片修复用 `fixer`；
- 新角色缺省取 `executor` 的值；
- effort 不在允许集合内时抛错。

规则原文见 `specs/flight-role-routing/spec.md`（4 个 scenario），决策见 `design.md` D5。

## owns

- `template/.claude/workflows/opsx-apply.js`
- `tests/test_workflow_routing_roles.py`（4 条 strict-xfail 骨架已写好）
- `tests/test_agents_workflow.py`（钉住旧写法的 `test_workflow_routes_models_explicitly` 需同步）

## 现有接口（本文件内）

- `models` / `efforts` 在第 49–55 行定义；`execDef(s)` 按 `tierOf(s)` 选 agent 定义。
- 执行体派发在 `exec` 附近（`model: models.executor, effort: efforts.executor`）。
- `fix:w<i>` 在 wave 跨片修复处派发；`fix` / `fix:retry` 在批量修复处派发。
- 返回值是 `{ change, models, efforts, ... }`。

## 怎么做（TDD：先跑 verify，看 4 条 xfail）

1. 定义并校验：
   ```js
   const EFFORTS = ['low', 'medium', 'high', 'xhigh', 'max']
   const ROLES = ['executor', 'executor-large', 'fixer', 'reviewer', 'integrator']
   ```
   - `models`：executor / reviewer / integrator 仍然必填，缺则抛错（保留原错误措辞的意思）；`models['executor-large']` 与 `models.fixer` 缺省取 `models.executor`。
   - `efforts`：沿用缺省 `{executor: 'high', reviewer: 'high', integrator: 'low'}` 合并 args；`executor-large` / `fixer` 缺省取 `efforts.executor`。
   - 校验每个角色的 effort ∈ `EFFORTS`，否则 `throw new Error(...)`，信息含角色名与 `EFFORTS.join(' / ')`。校验必须在任何 `agent(` 调用之前。
2. 执行体派发：用 `const execRole = (s) => (tierOf(s) === 'large' ? 'executor-large' : 'executor')`，派发写成 `model: models[execRole(s)], effort: efforts[execRole(s)]`。
3. 三处修复派发（`fix:w<i>`、`fix` 与它们的 retry）改为 `model: models.fixer, effort: efforts.fixer`。
4. 路由日志打印 5 个角色；返回值的 `models` / `efforts` 为补全后的 5 角色对象。
5. 同步 `tests/test_agents_workflow.py::test_workflow_routes_models_explicitly`：
   - 正则放宽为 `model:\s*models[.\[]` / `effort:\s*efforts[.\[]`；
   - 仍要求每个 `agent(` 调用都带 model 与 effort；
   - 改为断言出现 `models.fixer`。
6. 去掉 4 个 xfail 标记，verify 全绿。

## 注意

- 不用时间戳与随机数，脚本不碰文件系统（原有约束）。
- `flight_args()` 的 3 角色夹具不要改：它就是「旧调用兼容」的回归保护。
