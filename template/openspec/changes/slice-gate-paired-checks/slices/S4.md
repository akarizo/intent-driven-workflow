# S4 · 文档：gate.checks 的配置、时机与契约

**做什么**：把检查写进规划 instruction、propose / verify 命令与同名 skill、README。语义见 `specs/gate-paired-checks` 最后一条 Requirement。只改文档，不改判定器。

**owns**
- `template/openspec/schemas/intent-driven/schema.yaml`
- `template/.claude/commands/opsx-propose.md`
- `template/.claude/skills/openspec-propose/SKILL.md`
- `template/.claude/commands/opsx-verify.md`
- `template/.claude/skills/openspec-verify-change/SKILL.md`
- `README.md`
- `tests/test_gate_checks_docs.py`

**做法**
1. 去掉 `tests/test_gate_checks_docs.py` 的 xfail 标记，先红后绿。
2. **schema.yaml** 的 tasks instruction 第 1 点（`gate.test` 那段之后）加一段：
   - `gate.checks`（可选）：仓库自定义的成对检查，每项 `{name, baseline, final, timeout_sec}`；baseline 跑 `baseline`、final 跑 `final`，只看退出码；
   - 仓库有 openspec 根目录下的 `gate-checks.json` 时，把其中每个检查抄进 `gate.checks`，或在 `gate.checks_skip` 写明理由（由 `slice-gate.py lint` 校验）。
3. **opsx-propose.md 与 openspec-propose/SKILL.md** 第 5 步（基线门禁）加同一行：配置了 `gate.checks` 时 baseline 在 verify 之后运行每个检查的 `baseline`，任一红即基线红（照红处理）；代码树没变时按与 lint 相同的条件沿用。两份文本逐字一致。
4. **opsx-verify.md 与 openspec-verify-change/SKILL.md** 第 2 步（跑门禁 final）加同一行：配置了 `gate.checks` 时，final 在全量之后运行每个检查的 `final`，红记 `G9 check <name>`，完整输出在 `$GATE_CHECK_DIR/.gate-final.log`。两份文本逐字一致；不增减提到的 hook 脚本名（`test_command_skill_sync` 比对它）。
5. **README.md** 机械门禁表之后加一段「成对检查（`gate.checks`）」：何时跑、只看退出码、四个环境变量 `GATE_PHASE` / `GATE_CHANGE` / `GATE_BASE_COMMIT` / `GATE_CHECK_DIR` 的含义、共用目录位置、`timeout_sec`、仓库默认检查 `gate-checks.json` 与 `checks_skip`；表格的 `final` 行补「+ 检查 final（G9）」。

**verify**：`python3 -m pytest -q tests/test_gate_checks_docs.py tests/test_template_docs.py tests/test_docs_iron_rules.py tests/test_baseline_incremental_docs.py`

**注意**
- 改完 schema 后跑 `cd template && openspec schema validate intent-driven`，须绿。
- 文档禁日文假名 / 韩文谚文。
- 不改其他命令或 skill。
