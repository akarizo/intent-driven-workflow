# S2 · `/clean-after-merged` 命令、铁律 6 例外、git-discipline、README / WORKFLOW_zh / install.sh

## 做什么

把 S1 的脚本包装成命令，写明授权边界与回退，并同步全部文档。本片同时负责把 S3 的语义（自动录入、step 2b）写进 README。规则原文见 `specs/clean-after-merged-command/spec.md`，决策见 `design.md` D8、D9。

依赖的接口以 S1 / S3 为准：
- **S1**：
  - `merged-cleanup.py plan [--target T] [--remote R] [--fetch] [--markdown]` → JSON `{ok, target, target_ref, sync, items, manual, warnings}`，或 markdown（safe / manual / keep 三段）；
  - `merged-cleanup.py apply [--target T] [--remote R] [--no-fetch]` → JSON `{ok, done, failed, manual, kept}`；
  - 退出码 0 = 无失败，1 = 有失败，2 = 拒绝运行（不在主 worktree）。
- **S3**：`/pr-ship` 新增 step 2b「记忆层沉淀（自动，不问询）」；`/claudemd-commit` 改为自动录入，较大差异才对齐。

## 怎么做

1. **新建 `template/.claude/commands/clean-after-merged.md`**：
   - frontmatter 写 `description`，说明 PR 合并后清理 worktree、分支和飞行快照；safe 档自动执行，`manual` 档交你。
   - **Input**：可选 target branch，缺省为远端默认分支，再缺省为 `main`。例如 `/clean-after-merged develop`。
   - **Steps**：
     1. **定位主 worktree 根**：`git rev-parse --path-format=absolute --git-common-dir` 的父目录，之后所有命令都在这里运行。当前会话 CWD 若在某个 worktree 里，先切到主仓库根；禁止 `cd` 进待删的 worktree。
     2. **展示**：`python3 .claude/hooks/merged-cleanup.py plan --fetch --markdown [--target <T>]`，原样展示。
     3. **执行**：`python3 .claude/hooks/merged-cleanup.py apply [--target <T>]`。它会依次执行 `fetch --prune`、`--ff-only` 同步、删除 safe 档 worktree（带或不带 `--force` 由脚本判定）、`worktree prune`、删除已落地 change 的 `refs/flight/*`、`branch -d`。
     4. **汇报**：打印 `done` / `failed`。`manual` 原样放进一个 ```` ```bash ```` 代码块交用户执行，并按原因标记逐条加一行中文说明：
        - `content` → squash 合并，需 `-D`；
        - `unpushed-submodule` → 先推送子仓；
        - `dirty` → 先看清改动；
        - `locked` → 确认没有运行中的 agent；
        - `outside` → 仓库目录外的 worktree；
        - 远端分支 → `push --delete`。
     5. **验证**：`git worktree list`、`git branch --list 'worktree-*'`。
   - **退出码 2**（拒绝运行）：说明原因并停下。
   - **`**回退（merged-cleanup.py 不可用时）**` 段**：标题必须以 `**回退` 开头。只做两件安全的事：`git fetch --prune <R>`；当前在 T 上时 `git merge --ff-only <R>/<T>`。然后输出 `git worktree list --porcelain` 与 `git branch --list 'worktree-*'`，附人工判据：
     - 先同步 T 再 `-d`；
     - `-d` 报 not fully merged 时，先判断是否 squash，再决定是否 `-D`；
     - 含子仓的 worktree 先确认子仓提交已推送。

     本段写明「不自动删除任何东西」。
   - **`**Guardrails**` 段**（标题原样）写明以下几条：
     - 只执行脚本判定的 safe 档；
     - 不执行 `git branch -D`、`git push --delete`、`manual` 档的任何命令，也不 `git worktree unlock`；
     - 不 `cd` 进待删的 worktree；
     - 不归档（`/opsx-archive` 另行触发）；
     - 显式运行本命令 = 授权 safe 档（铁律 6 例外），越出 safe 档仍需单独授权。
   - **「与已有命令的配合」**：`/pr-ship`（送出）→ 人类合并 → `/clean-after-merged` → 可选 `/opsx-archive`。
2. **根 `CLAUDE.md` 铁律 6**：在该行末尾补一句：
   > 显式跑 `/clean-after-merged` = 授权其 safe 档（ff 同步 target · 删已合并 worktree · `branch -d`）；`branch -D` / `push --delete` 永远交人。

   该行仍须含「不删 worktree」。
3. **`template/CLAUDE.md.snippet` 铁律 6**：改为：

   snippet 不得超过 8KB。
4. **`template/.claude/skills/openspec-git-discipline/SKILL.md`**：
   - **Worktree Isolation 节「建 worktree 是工作区准备」一条**：「仍是破坏性收尾，一律交用户授权」后补「（例外：显式运行 `/clean-after-merged` 时其 safe 档已获授权）」。
   - **「清理只在主仓库根」一条**：改为首选 `/clean-after-merged`。它调用 `merged-cleanup.py` 判定每项是否已合并、是否需要 `--force`、`-d` 还是 `-D`，并先 `--ff-only` 同步 target。保留原来的三步顺序作为手工路径，保留「禁 cd 进 worktree 后再删自身」。行首仍为 `- **清理只在主仓库根**`。

   - **Submodule 小节**：加一条——含已填充子仓的 worktree 删除需 `--force`；子仓库本体在 `.git/worktrees/<id>/modules/` 下，随 worktree 一起删除，所以未推送的子仓提交会丢失，`/clean-after-merged` 会把这类判为 `manual`。
