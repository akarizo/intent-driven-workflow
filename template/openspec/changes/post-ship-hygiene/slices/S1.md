# S1 · 判定脚本 `merged-cleanup.py`：plan / apply

## 做什么

新增 `template/.claude/hooks/merged-cleanup.py`，零 token 判定合并后的清理项，并执行 `safe` 档。规则原文见 `specs/merged-cleanup-plan/spec.md`，决策见 `design.md` D1–D8。纯标准库实现，Python 3.9 兼容（本机 `python3` 是 3.9，禁用 `match` 语句与 `X | Y` 类型注解），可 compileall。

## 接口（S2 依赖，按此实现）

```
python3 .claude/hooks/merged-cleanup.py plan  [--target T] [--remote R] [--fetch] [--markdown]
python3 .claude/hooks/merged-cleanup.py apply [--target T] [--remote R] [--no-fetch]
```

- **`--remote`**：缺省 `origin`。
- **`--target`**：缺省值按顺序取：
  1. `refs/remotes/<R>/HEAD` 的符号目标去掉前缀，例如 `main`；
  2. 取不到则用 `main`。
- **`target_ref`**：`refs/remotes/<R>/<T>` 存在则用它，否则用 `refs/heads/<T>`；两者都没有 → exit 2，`reasons: ["no-target: …"]`。
- **plan 输出**：JSON 写到 stdout，形状：
  ```json
  {"ok": true, "target": "main", "target_ref": "refs/remotes/origin/main",
   "sync": {"from": "<sha>", "to": "<sha>", "command": "git merge --ff-only origin/main"},
   "items": [{"kind": "worktree", "name": ".worktrees/a", "merged": "ancestor", "tier": "safe", "force": false,
              "reasons": [], "dirty": [], "command": "git worktree remove .worktrees/a"}],
   "manual": ["git branch -D worktree-s"], "warnings": []}
  ```
  不需要同步时 `sync` 为 `null`。
- **`--markdown`**：只打印 markdown，分三段：
  - 「将自动执行（safe）」；
  - 「交你执行（manual）」，放在 ```` ```bash ```` 代码块里，每行一条命令，原样输出；
  - 「保留（keep）」，用表格列出原因。
- **apply 输出**：JSON 写到 stdout：`{"ok": bool, "done": [cmd], "failed": [{"command": cmd, "error": str}], "manual": [cmd], "kept": [name]}`。
- **退出码**：
  - 0：plan 正常，或 apply 无失败；
  - 1：apply 有失败项；
  - 2：拒绝运行。
- **拒绝运行**：
  - 不在 git 仓库，或 `git rev-parse --git-dir` 与 `--git-common-dir` 的绝对路径不同（在 linked worktree 里）→ stdout `{"ok": false, "reasons": ["not-main-worktree: …"]}`，exit 2，不做任何改动；
  - 以上判定以 cwd 所在仓库为准；
  - 主 worktree 根取 `--git-common-dir` 的父目录。所有 git 调用都以它为 cwd。
- **`command` 字段**：给人看，由 `shlex.quote` 拼接。执行时一律用参数列表（`subprocess.run([...])`），不经 shell。

### 字段取值

| kind | name | merged | command |
|---|---|---|---|
| worktree | 相对主仓根的 posix 路径（在根之下时），否则绝对 realpath | ancestor / content / fresh / unmerged / -（prunable） | `git worktree remove [--force] <name>`；locked 时前缀 `git worktree unlock <name> && `；prunable 时为 `git worktree prune` |
| branch | `worktree-x` | 同上 | `git branch -d <b>` 或 `git branch -D <b>` |
| remote | `<R>/worktree-x` | ancestor / content | `git push <R> --delete worktree-x` |
| ref | `refs/flight/<change>/<S>` | landed | `git update-ref -d <ref>` |

`reasons` 的每条以稳定标记开头，后跟「: 」和中文说明。可用的标记有：`flight-records`、`submodule`、`unpushed-submodule`、`dirty`、`locked`、`outside`、`prunable`、`content`、`reference`、`fresh`、`unmerged`。

## 怎么做

1. **列 worktree**：解析 `git worktree list --porcelain`，读取 `worktree` / `HEAD` / `branch` / `detached` / `locked [<reason>]` / `prunable` 字段。第一项是主 worktree，跳过。
2. **合并状态**（D2）。设 tip 为 worktree 的 HEAD 或分支 tip，`fp` 为 `git rev-list --first-parent <target_ref>` 的集合（只算一次），按顺序判定：
   - `tip ∈ fp` → `fresh`；
   - `git merge-base --is-ancestor tip target_ref` → `ancestor`；
   - `git merge-tree --write-tree <target_ref> <tip>` 退出 0，且 stdout 第一行等于 `git rev-parse <target_ref>^{tree}` → `content`；
   - 其余 → `unmerged`。

   `fresh` / `unmerged` 一律判 `keep`，并在 reasons 写对应标记。
3. **未提交改动**（D4）：
   - 用 `git -C W status --porcelain=v1 -z --ignore-submodules=none --untracked-files=all` 列出改动；按 `-z` 规则解析，重命名项多一个 NUL 段。
   - **飞行记录**：路径为 `.openspec-slice`，或匹配 `(^|.*/)openspec/changes/[^/]+/(timeline\.md|gate-report\.md|evidence\.log)$`。
   - **只有飞行记录** → `force`，原因 `flight-records: <文件,…>`。
   - **有其他改动** → `manual`、`force`，`dirty` 列出全部改动路径，原因 `dirty: …`。子仓 gitlink 路径本身出现在 status 里也算其他改动。
4. **子仓**（D5）：
   - **找出已填充的子仓**：`git -C W ls-files -s` 中模式为 `160000` 的路径 P，且 `W/P/.git` 存在。有任何一个 → `force`，原因 `submodule: <P,…>`。
   - **判定子仓库是否随 W 删除**：`common = realpath(git -C W/P rev-parse --path-format=absolute --git-common-dir)`，`own = realpath(git -C W rev-parse --path-format=absolute --git-dir)`。common 以 `own + os.sep` 开头，或以 `realpath(W) + os.sep` 开头 → 会随 W 一起删除。
   - **会随 W 删除时**：tips 取 `git -C W/P rev-parse HEAD`，加上 `git -C W/P for-each-ref --format=%(objectname) refs/heads refs/flight-sub`。每个 tip 须满足下面任一条件：
     - `<root>/P/.git` 存在，且 `git -C <root>/P cat-file -e <tip>^{commit}` 成功；
     - `git -C W/P for-each-ref --contains <tip> --format=%(refname) refs/remotes` 输出非空。

     任一 tip 不满足 → `manual`，原因 `unpushed-submodule: <P> <tip 前 10 位> 只存在于该 worktree 的子仓库，删除会丢失；先推送子仓（或在主 checkout 里 fetch 它）`。
   - **不会随 W 删除时**：把 common 记入该项内部字段 `prune_subs`。这个字段不必输出到 JSON，apply 用。
5. **lock / 目录外 / prunable**：
   - `locked` → `manual`，原因 `locked: <原因>`；
   - 路径不在 `<root>/.worktrees/` 或 `<root>/.claude/worktrees/` 下（用 realpath 比较）→ `manual`，原因 `outside: …`；
   - `prunable` → `safe`，`command` 为 `git worktree prune`，不再做其他判定。
6. **档位合成**（worktree）：
   - `fresh` / `unmerged` → `keep`；
   - 否则命中任一 manual 条件（dirty / unpushed-submodule / locked / outside）→ `manual`；
   - 否则 → `safe`。

   `force` 为真的条件：有任何未提交改动，或有已填充子仓。
7. **分支**：列出 `refs/heads/worktree-*`，排除主 worktree 当前检出的分支。
   - **分支被 worktree 检出时，跟随该 worktree 的档位**：
     - worktree 为 keep → 分支 keep；
     - worktree 为 manual → 分支 manual，命令按下面规则计算，排在 worktree 命令之后；
     - worktree 为 safe → 按下面规则计算。
   - **规则**：
     - `fresh` / `unmerged` → `keep`；
     - `content` → `manual`，`git branch -D`，原因 `content: merge-tree 结果与 <T> 树相同（squash 等方式合入）`；
     - `ancestor` → 计算参照点（D3）：`git for-each-ref --format=%(upstream) refs/heads/<b>` 非空，且 `git rev-parse --verify -q <upstream>` 成功 → 参照点为 upstream；否则为有效 HEAD。
       - tip 是参照点的祖先 → `safe`，`git branch -d`；
       - 否则 → `manual`，`git branch -D`，原因 `reference: …`。
   - **有效 HEAD**：计划了 sync 时取 `target_ref` 的 SHA，否则取 HEAD。
8. **sync**（D3）：同时满足以下条件时计划 sync，`command` 为 `git merge --ff-only <R>/<T>`；target_ref 是本地分支时就写 `<T>`：
   - 主 worktree 当前分支为 `refs/heads/<T>`；
   - HEAD ≠ target_ref；
   - HEAD 是 target_ref 的祖先；
   - `git status --porcelain --untracked-files=no --ignore-submodules=all` 为空。

   当前不在 T、已分叉、有改动这三种情况，各写一条 `warnings`。
9. **远端**：只在 target_ref 是 remote-tracking ref 时列出 `refs/remotes/<R>/worktree-*`。其中 `ancestor` / `content` 的 → `manual`，`git push <R> --delete <b>`；其余不列。
10. **快照 ref**（D7）：
    - 用 `git ls-tree -r --name-only <target_ref>` 收集 `(^|/)openspec/changes/<c>/` 中的 c；
    - 遍历 `git for-each-ref --format=%(refname) refs/flight/`，取出 `refs/flight/<c>/...` 的 c；
    - c 已落地 → `landed`、`safe`；否则不列。
11. **顶层 `manual`**：按 worktree → branch → remote 的顺序收集所有 manual 项的 command。
12. **apply 执行顺序**（D6）：
    1. 未带 `--no-fetch` 时 `git fetch --prune <R>`，失败记入 failed，继续往下；
    2. 计算 plan；有 sync 时执行 `git merge --ff-only`，然后重算 plan；
    3. 删除 safe 档 worktree：先 `.claude/worktrees/` 下的，再其余的。每删一个，对它的 `prune_subs` 跑 `git --git-dir=<c> worktree prune`；
    4. `git worktree prune`；
    5. 删除 safe 档 ref；
    6. 删除 safe 档 branch。

    每个成功执行的命令把它的 command 串追加到 `done`，fetch 记为 `git fetch --prune <R>`。单项失败不中断。`manual` 照抄 plan 的结果；`kept` 列出 keep 项的 name。
