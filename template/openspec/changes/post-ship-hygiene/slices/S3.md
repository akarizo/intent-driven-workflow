# S3 · `/pr-ship` step 2b 记忆层沉淀 + `/claudemd-commit` 自动录入与 E 类

## 做什么

把知识沉淀接进 `/pr-ship`，同时把 `/claudemd-commit` 从逐条确认改为自动录入，只有较大差异的条目才对齐，并新增有上限的 E 类「反复错误」。规则原文见 `specs/ship-memory-sedimentation/spec.md`，决策见 `design.md` D10–D12。本片只改文档，不改脚本。

## 怎么做

1. **`template/.claude/commands/claudemd-commit.md`**：
   - **frontmatter `description`**：改为写明「自动识别与录入，较大差异才对齐」。
   - **step 3「生成候选」**：
     - 标题与小注的「三类，没有第四类」改为四类：A / B / D / E。
     - 在 D 类之后新增一条，格式与 A / B / D 相同，以 `- **E. 反复错误**：` 开头。正文写明以下五点：
       1. 同一错误本轮**至少 2 次**；
       2. 每次都有**证据**指针，可以是 `gate-report.md` / `timeline.md` 的门禁红记录、`review-findings.json` 的 `blocked` / `fixed` 条目、fix commit 的 SHA，或本会话用户原话纠正；
       3. 只出现 1 次，或给不出证据的 → 进 backlog；
       4. Q4 ✓ → 进 backlog，立项实现测试 / lint / hook 防线，常驻层只留一行带 backlog 指针的**过渡**条目，防线落地后由 B 类改成防线索引；
       5. Q4 ✗ → 按 §12b 分流表定载体。
     - 原「⚠ 不再有 C 类」小注保留，并补一句：E 类不是 C 类的回归，上界是证据数，C 类维持废除（2026-08-25）。
   - **step 4 / step 5**：不改。四问与预算中性照旧适用于 E 类。
   - **step 6**：标题改为 `### 6. 自动录入 + 较大差异对齐`。正文写明三件事：
     - **自动录入**：通过四问与预算闸的新增条目（A / D / E），以及不丢含义的迁移（指针化、分流到 rules / skill），直接写入，并在第 8 步报告里逐条列出。
     - **较大差异**：命中以下任一条：①「删除或反转」既有条目的含义（含 B 类与为预算而删掉知识的减法）；② 与既有条目或在役 ADR 同题异令（「矛盾」）；③ 改动「铁律」或「核心约束」段；④ 写到仓库外的全局 `~/.claude/CLAUDE.md`。单独运行本命令时，这类条目用 **AskUserQuestion** 逐条对齐，减法项与加法项成对展示。
     - **被 `/pr-ship` 调用时**（自动模式）：较大差异条目**不落盘**，作为「需与你对齐」清单返回给调用方。
   - **step 8 报告**：增加「自动录入」「需与你对齐（未落盘）」两张小表，E 类条目附证据指针。
   - **Guardrails**：
     - 「没有 C 类」一条改为「C 类维持废除；E 类须至少 2 次且有证据」；
     - 增加「较大差异必须对齐，不得自动落盘」。
2. **`template/.claude/commands/pr-ship.md`**：
   - **新增 step 2b**：插在 step 2（梳理本轮变更范围）之后、step 3 之前，标题行为 `2b. **记忆层沉淀（自动，不问询）**`。正文写明以下各项：
     - 按 `/claudemd-commit` 的自动模式运行，base = `origin/<target>`。
     - 巡视三处来源：
       - ① 本会话**对话**，含 compact 摘要。用户给过的规则、纠正、偏好归 D 类，纠正同时是 E 类的证据；
       - ② 分支 diff，归 A / B 类；
       - ③ 飞行记录与评审：`openspec/changes/<name>/timeline.md`、`gate-report.md`、`review-findings.json`，以及 `git log` 中的 `fix:` commit，作为 E 类证据。
     - 产出写成独立 commit：`docs(memory): 沉淀本轮知识（+N / −M）`。写完跑 `python3 .claude/hooks/claudemd-lint.py` 与 `python3 .claude/hooks/memory-lint.py`，须全绿；红了当场减，减完再提交。没有可沉淀的条目时，不产生 commit，在 Output Summary 记「无」。
     - 飞行模式（`slices.json` 存在）下，沉淀 commit 之后重跑 `python3 .claude/hooks/slice-gate.py final --change-dir openspec/changes/<name>`。原因：ship 裁决只容忍 final 之后出现记账文件，CLAUDE.md 不在其列。
     - 较大差异条目不落盘，交给 step 6 写进 PR 正文。
     - ⚠ 2b 正文里不要出现 `数字. **` 形式的有序粗体列表，测试按 `3. **` 定位 step 3。也不要出现 `AskUserQuestion` 字样。
   - **step 6 正文**：追加两段，写法与「## 切片评审（未自动修的 MEDIUM/LOW）」那段并列：
     - 「## 记忆层沉淀」：逐条列出载体、路径、动作和一行证据；
     - 「## 记忆层：需与你对齐」：列出较大差异条目，说明它们未落盘，等你在 PR review 时裁决。
   - **step 11**：在给出 merge 命令之后，加一句「合并后在主仓库根运行 `/clean-after-merged` 清理 worktree 与分支」。
   - **Output Summary**：增加一行 `**记忆层沉淀**: +N / −M（需对齐 K 条）`。
   - **「与已有命令的配合」表与「典型使用顺序」**：`/claudemd-commit` 改为「已由 step 2b 内置，单独运行用于 PR 之外的场合」；顺序表去掉独立的 claudemd-commit 一步，并在第 4 步之后加「合并后 `/clean-after-merged`」。
3. **`template/.claude/claudemd-standard.md` §13 合约表**：`/claudemd-commit` 那一行的「模式」列改为「增量 + **预算中性**；**自动录入**，较大差异才对齐（`/pr-ship` step 2b 内置调用）」。该行仍以 `` | `/claudemd-commit` `` 开头，保持唯一。其余段落不改。
