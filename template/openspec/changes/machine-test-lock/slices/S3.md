# S3 · slice-gate.py 持锁、lock 留痕、争抢时 G10 降级

## 做什么

给 `slice-gate.py` 的三个测量命令加取锁 / 放锁的调用点，把锁信息写进输出 JSON 与时间线备注；放弃等待后跑出来的那一次，把 G10 慢单测从失败降为警告。规则原文见 `specs/machine-test-lock/spec.md` 的「门禁各命令按方式持锁」「争抢时时间类判定降为警告」与「时间线记录排队、负载与收口各项耗时」的 `timeline-records-wait-and-load`；决策见 `design.md` D3、D5、D6、D7、D8。

锁逻辑不写在这里：只调用 S1 的 `flight-lock.py`。判定逻辑（差分、G7、G11、锚点、复用）一行不改。

## 依赖的接口（S1 提供，design D7）

- `acquire(mode, change="", label="", expect_sec=None)` → 持有对象，`.info`（`mode` / `state` / `waited` / `why` / `load` / `cores`）、`.release()`（幂等，填 `load[1]`）；不抛异常。
- `note(info)` → 时间线锁片段（`排队 12.3s` / `排队 600.0s 后放弃（…）` / `重入` / `未加锁（…）`，取得到负载时接 ` · 负载 起→止/核数`）。

## 怎么做

TDD：`tests/test_gate_lock.py` 的 7 条骨架现在是红的（strict xfail）。其中两条各跑一次带 3.1 秒睡眠用例的 baseline，整份文件约需 30–40 秒。

1. **加载函数**（本片**提供**给 S5）：
   ```python
   def flight_lock(mode, change="", label="", expect_sec=None):
       """按路径加载同目录的 flight-lock.py 并 acquire；文件缺失、加载失败或意外抛错 →
       返回 state = unavailable 的替身（有 .info 与空的 .release()）。"""
   ```
   - 加载方式同 `flight-doctor.py` 的 `load_gate`（`importlib.util.spec_from_file_location`），模块对象缓存在模块级变量里。
   - 替身的 `info`：`{"mode": mode, "state": "unavailable", "waited": 0.0, "why": <原因>, "load": None, "cores": None}`。
   - 另给一个 `_lock_note(info)`：能加载到模块就调它的 `note(info)`，否则自己按同一格式拼「未加锁（原因）」。
2. **`expect_sec`**（design D5）：本 change `gate-baseline.json` 的 `test.sec`；`cmd_baseline` 用覆盖前读到的旧基线 `old`；读不到再退 `gate.get("full_suite_sec")`；都没有传 `None`。
3. **`cmd_baseline`**（独占，标签 `baseline`，`change` = change 目录名）：
   - 取锁点：写完运行标记之后、复用候选判定之前（design D3）；
   - 放锁点：检查全部结束之后、结束快照 `_snapshot` 之前；
   - `bl["lock"] = hold.info`（放锁之后赋值，`load[1]` 才有值）；它会随 `bl` 写进 `gate-baseline.json` 并出现在 stdout 的 JSON 里；入池与锚点只挑固定键，不要把它加进去；
   - 时间线：现有三种备注的末尾各接 `；` + `_lock_note(info)`。
4. **`cmd_final`**（独占，标签 `final`）：
   - 同树沿用分支不取锁、输出与备注不变；
   - 取锁点：`scenario_status`（G7 实跑）之前；放锁点：检查（`_final_checks`）结束之后、组装 `result` 之前；
   - `result["lock"] = hold.info`；
   - 时间线：`final_note` 现在是 `[inc_note] [tier_note] 结论`。在结论词之前插入锁片段：与它前面的分层片段用 ` · ` 连接，前面只有「全量（…）/ 增量（…）」时用一个空格连接，结论词前一个空格。例：`增量（锚点 …） 排队 0.0s · 负载 1.2→1.4/8 ok`、`全量（…） 单元 1.0s · 集成 0.0s · 排队 0.0s ok`。
     （S5 会在同一位置再插「测试」「检查」片段，把拼接写成「片段列表 → join」便于它接着加。）
5. **`cmd_gate`**（共享，标签 `gate <S>`）：
   - 取锁点：`run_cmd(sl["verify"], root)` 之前；放锁点：`scenario_status` 之后；
   - `result["lock"] = hold.info`；
   - 时间线：`gate_note` 之后、结论词之前按同样规则插锁片段，备注仍以切片 id 开头。`cmd_record`（integrator 写回）不动。
6. **G10 降级**（design D6）：新增纯函数，例如
   ```python
   def _time_verdicts(failed, warnings, lock_info):
       """lock_info["state"] == "timeout" 时，把以 "G10 slow unit test" 开头的失败项挪进 warnings，
       原文保留并在末尾加「（排队放弃后未持锁，时间类判定降为警告：<why>）」；其他状态原样返回。"""
   ```
   在取得 G10 / G11 结论的每一处调用后再并入 `reasons` / `failed`：
   - `cmd_baseline` 的 `_unit_tier_verdict`（约 4063 行）；
   - `cmd_final` 增量与全量两处 `_unit_tier_verdict`（约 3786、3819 行）；
   - 部件形态 `_baseline_parts` / `_final_parts` 里的 `part_tier_verdict`（给这两个函数加一个 `lock_info=None` 参数传进去）。
   `tier_verdicts` / `part_tier_verdicts` 这两个纯函数本身不改（有既有测试直接调用）。
7. **不做**：不改 `_final_checks` 的返回值、不加 `sec` 字段、不碰 `test-tiers.py`（都在 S5）；不改 `opsx-apply.js` 与 `cmd_record`。

## 附带修复：持有者文件防 pid 复用（首飞评审 MEDIUM，2026-11-18）

问题：`flight-lock.py` 的 `_holders_raw` 只用 `os.kill(pid, 0)` 判断持有者在世。持有者被强杀后，它留下的 `holders/<pid>.json` 若 pid 被无关进程复用，文件永远清不掉；其 `since` 最早、排第一，之后任何争锁的排队方都会判它超过上限而立刻放弃、以 `timeout` 不加锁运行。

修法（只此一处，其余锁逻辑不动）：`_acquire` 以**独占**方式拿到 `main.lock` 之后、`_write_holder` 之前，删掉 `holders/` 下除本进程以外的所有 `.json`——此刻 flock 保证不存在别的合法持有者。删除失败静默忽略（不抛异常的约定不变）；共享方式不做这一步。

TDD：先在 `tests/test_flight_lock.py` 加一条普通用例（不挂 scenario，Given/When/Then 中文注释）：Given 测试自己起一个无关的在世子进程（如 `sleep 30`，用例结束时杀掉），锁目录 `holders/` 下有一份 pid 为该子进程、`since` 很早的假持有者文件 · When 以独占方式 acquire 再 release · Then 该假文件已不存在、`holders()` 为空。（MUST NOT 用测试进程自己的 pid：acquire 会写同名持有者文件把它覆盖，测不出清理。）先看它红，再改实现。
