# S1 · flight-lock.py：全机读写锁 + 测试套件隔离

## 做什么

新增 `template/.claude/hooks/flight-lock.py`：一把用户级目录下的读写文件锁，模块接口给门禁用，`run` / `status` 两个子命令给人和测试用。再让 `tests/conftest.py` 把整个测试套件的锁目录指到会话临时目录。规则原文见 `specs/machine-test-lock/spec.md` 前三条 Requirement，决策见 `design.md` D1、D2、D4、D5、D7、D9。

本片不碰 `slice-gate.py`。

## 依赖的接口

无（与 S2 并行）。本片**提供**的接口被 S3 / S4 / S5 使用，必须与 design D7 一致：

| 接口 | 约定 |
|---|---|
| `acquire(mode, change="", label="", expect_sec=None)` | `mode` 为 `"exclusive"` / `"shared"`；返回持有对象；**不抛异常** |
| 持有对象 `.info` | `{"mode", "state", "waited", "why", "load", "cores"}`；`state` ∈ `held` / `nested` / `off` / `unavailable` / `timeout`；`waited` 保留 1 位小数；`why` 恒为字符串；`load` 为 `[起, 止]` 或 `None`；`cores` 为整数或 `None` |
| 持有对象 `.release()` | 幂等；填 `load[1]` |
| `holders()` | 在世持有者列表，每项 `{"pid", "mode", "change", "label", "started", "held_sec", "cap_sec"}`，持有最久的在前 |
| `note(info)` | 时间线锁片段，格式见 design D8 的表 |
| `lock_dir()` | 当前生效的锁目录 |

## 怎么做

TDD：`tests/test_flight_lock.py` 的 9 条骨架现在是红的（strict xfail），逐条解锁。`tests/lock_helpers.py` 是这些用例的同步工具（开始文件 / 放行文件 / stderr 排队提示），已写好；发现它有错可以改（在 owns 内），但它被 S3 / S4 / S5 的测试只读共用，接口不要变。

1. **锁目录**：`FLIGHT_LOCK_DIR`，缺省 `~/.claude/flight-lock`。内含 `gate.lock`、`main.lock`、`holders/<pid>.json`。目录不存在就建；建不了 / 不可写 → `state = unavailable`，`why` 写原因。
2. **取锁顺序**（design D1）：
   - 共享：取 `gate.lock`（独占）→ 取 `main.lock`（共享）→ 放 `gate.lock`；
   - 独占：取 `gate.lock`（独占）并一直握着 → 取 `main.lock`（独占）→ 放 `gate.lock`。
   - 两个文件用 `os.open` 打开（缺省不可继承），不要把描述符传给子进程。
3. **轮询**（design D2）：`flock(fd, … | LOCK_NB)`；失败后睡 0.2 秒起、逐步加到 1 秒。第一次失败**立刻**往 stderr 打印并 flush：
   `flight-lock: 排队中（独占|共享），等 <change> · <标签> · pid <pid> · 已持有 <N>s`
   之后每 30 秒一行。「等谁」取 `holders()` 里持有最久的一项；读不到时写「（持有者信息尚未写入）」。
4. **持有者文件**：拿到主锁后原子写 `holders/<pid>.json`（临时文件 + `os.replace`）：`pid`、`mode`、`change`、`label`、`started`（ISO）、`since`（epoch）、`cap_sec`。`release()` 时删除。`holders()` 用 `os.kill(pid, 0)` 判在世，顺手删掉死进程留下的文件。
5. **持有上限 `cap_sec`**（design D5）：`FLIGHT_LOCK_MAX_HOLD_SEC`（浮点）> `max(300, 3 × expect_sec)` > `1800`。
6. **放弃等待**：每次轮询后，持有最久的在世持有者 `held_sec > cap_sec` → `state = timeout`，`why = "<change> · <标签> 已持有 N 秒，超过上限 M 秒"`，`waited` 记已等秒数，关掉自己打开的锁文件后返回。读不到任何持有者信息且自己已等超过自己的 `cap_sec` → 同样放弃。
7. **重入**（design D4）：拿到锁后设 `os.environ["FLIGHT_LOCK_HELD"] = "<mode>:<pid>:<锁目录 realpath>"`，`release()` 时恢复原值。请求锁时环境里已有标记且第三段等于当前锁目录的 realpath → `state = nested`，不取锁。
8. **关闭与回退**：`FLIGHT_LOCK=off`（不分大小写）→ `state = off`；`import fcntl` 失败 → `unavailable`；`acquire` 内部任何异常 → `unavailable`，`why` 带异常文字。这几种都不取锁、不写持有者文件、不设重入标记。
9. **负载**：`os.getloadavg()[0]` 保留 1 位小数；取不到（`AttributeError` / `OSError`）→ `load = None`。`cores = os.cpu_count()`。
10. **CLI**：
    - `run <exclusive|shared> [--change NAME] [--label TEXT] [--expect-sec N] -- CMD [ARG…]`：取锁 → `subprocess.call(CMD 的 argv)`（不经 shell）→ 放锁 → stderr 末行 `flight-lock: <info 的 JSON，ensure_ascii=False>` → 以 CMD 的退出码退出；CMD 起不来 → 127。
      ⚠ 自己在 `--` 处切开 `sys.argv`，`--` 之前的交给 argparse；不要用 `argparse.REMAINDER`（它会把位置参数之后的 `--label` 一并吞进命令）。
    - `status [--json]`：`{"dir", "enabled", "holders"}`；恒退出 0。
11. **`tests/conftest.py`**（design D9）：在模块顶层（导入时）建一个 `tempfile.mkdtemp(prefix="flight-lock-test-")`，写进 `os.environ["FLIGHT_LOCK_DIR"]`，`atexit` 删除；同时 `os.environ.pop` 掉 `FLIGHT_LOCK` 与 `FLIGHT_LOCK_MAX_HOLD_SEC`。其余内容不动。

设计期用一份一次性原型验证过：除 conftest 那一条外的 8 条用例可以稳定通过（连跑 3 遍，每遍约 2.5 秒）。原型不在仓库里，按上面的规则自己写。
