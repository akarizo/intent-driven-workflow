# S5 · final 的测试与检查秒数；test-tiers.py 持独占锁

## 做什么

两件事：

1. `slice-gate.py final` 留下 gate.test 与每项检查的秒数——输出 JSON 的 `sec` 与时间线备注的「测试」「检查」片段。
2. `test-tiers.py run` / `probe` 整个运行期间持独占锁。

规则原文见 `specs/machine-test-lock/spec.md` 的 `final-note-records-test-and-check-seconds` 与 `test-tiers-run-and-probe-hold-exclusive-lock`；决策见 `design.md` D3、D8。

## 依赖的接口（S3 提供，在 slice-gate.py 里）

- `flight_lock(mode, change="", label="", expect_sec=None)` → 持有对象（`.info`、`.release()`）；加载不到 `flight-lock.py` 时返回 `state = unavailable` 的替身，不抛。
- `cmd_final` 里结论词之前的备注片段已由 S3 写成「片段列表 → join」，本片往列表里加两项。

## 怎么做

TDD：`tests/test_gate_cost_note.py` 的 2 条骨架现在是红的。

### final 的秒数

1. **`sec.test`**：`cmd_final` 的测试分支（`gate.impacted` / 内建增量 / 全量三选一）开始前已有 `t0 = time.time()`。三个分支各自跑完后记 `test_sec = round(time.time() - t0, 1)`（不含其后的区域运行）。没进这三个分支（G7 红、scope 复核未过 `sfail`、部件形态、没有测试命令）→ `None`。
2. **`sec.checks`**：`_final_checks` 现在丢掉 `_run_check` 返回的秒数（`rc, out, _, timed_out`）。给它加一个可选的输出参数（如 `secs=None`，是 dict 时写入 `{检查名: 秒}`），**返回值不变**（仍是 failed 列表）。只记实际运行了的检查（基线缺记录而跳过的不记）。
3. **输出**：`result["sec"] = {"test": test_sec, "checks": {…}}`；没运行任何检查时 `checks` 为 `{}`。
4. **时间线**：在锁片段**之前**加入
   - `测试 %.1fs`（`test_sec` 不为 `None` 时）；
   - `检查 a 3.1s / b 2.4s`（`checks` 非空时，按 `gate.checks` 的顺序，` / ` 分隔）。
   最终形如：`全量（没有可用锚点） 单元 1.0s · 集成 0.0s · 测试 524.3s · 检查 ratchet 3.1s / linkage 2.4s · 排队 212.0s · 负载 2.9→17.8/18 ok`。
   同树沿用的备注不变。结论词仍在末尾。
5. baseline 不动（它的检查秒数已经记在 `gate-baseline.json`）。

### test-tiers.py

6. `cmd_run` 与 `cmd_probe`：进入后 `hold = sg.flight_lock("exclusive", label="test-tiers run" / "test-tiers probe")`，用 `try / finally` 保证 `hold.release()`。`change` 留空；`expect_sec` 传 `None`。
   - `fail()` 走的是 `sys.exit`，`finally` 会执行；取锁放在参数与分层文件校验**之后**（校验失败不该排队）。
   - `canary`、`check`、`allow-slow`、`render` 不取锁。
7. 文件头注释的 `run unit` / `probe` 两条各补一句「整个运行期间持全机测试锁（独占）」。

## 解锁

去掉 `tests/test_gate_cost_note.py` 2 条用例的 `@PENDING`，`PENDING` 不再使用时连同定义一起删除。MUST NOT 改断言与函数名。verify 里其余测试不在本片 owns 内，必须保持全绿（含 S3 的 `tests/test_gate_lock.py`：备注里的锁片段与结论词位置不能被本片挪动）。
