# S2 · flight-doctor.py cost 读新备注

## 做什么

让 `flight-doctor.py cost` 读懂时间线备注里的三种新片段（格式由 design D8 定，S3 / S5 负责写出）：final 的「测试 Xs」、baseline 与 final 的「排队 Xs」。规则原文见 `specs/machine-test-lock/spec.md` 的「成本归因与体检读得到排队和收口耗时」，决策见 `design.md` D8 的「解析」。

本片只做解析与汇总，不依赖任何其他切片：用例直接喂时间线文本。

## 依赖的接口

无（与 S1 并行）。要解析的备注形如：

```
baseline  exit 0, 500.0s ok；全量：<原因>；排队 12.5s · 负载 2.9→17.8/18
final     全量（没有可用锚点） 测试 524.3s · 检查 ratchet 3.1s / linkage 2.4s · 排队 212.0s · 负载 2.9→17.8/18 ok
final     增量（锚点 abcdef0123，重跑 2 个文件 / 沿用 10 个用例） 测试 8.0s · 排队 0.0s ok
```

放弃等待时的片段是 `排队 600.0s 后放弃（…）`，同样按「排队 Xs」计入。

## 怎么做

TDD：`tests/test_flight_doctor_cost_lock.py` 的 1 条骨架现在是红的。

1. `parse_note` 现有返回值不变。在 `cost()` 里对每条 baseline / final 备注另外取：
   - `测试 ([\d.]+)s` → 该次 final 的秒数；
   - `排队 ([\d.]+)s` → 排队秒数（没有则 0）。
2. 汇总：
   - 全量 final：秒数取「测试」片段（没有则沿用现状的 `None` → 0），计入 `out["final"]["full_sec"]` 与该条 `full_runs` 项的 `sec`；
   - baseline 的秒数来源不变（`exit N, Xs`）；
   - 新增顶层 `out["wait_sec"] = {"baseline": 秒, "final": 秒}`，各保留 1 位小数。
   - ⚠ `out["baseline"]` 与 `out["final"]` 两个对象**不加键**：`tests/test_flight_doctor.py` 对 `baseline` 做整体相等断言。
3. `cost_text`：每个事件那一行末尾接 ` · 排队 %.1f 秒`，其余文字不动。例：`  final：全量 1 次（524.3 秒）· 增量 1 次 · 排队 212.0 秒`。
4. 文件头注释里 `cost` 的说明补一句。恒退出 0 的约定不变。
5. 顺手提供一个纯函数（S4 要用）：`note_costs(note) -> {"test": 秒 | None, "wait": 秒 | None, "checks": {名: 秒}}`，其中「检查」片段按 design D8 的写法解析：取 `检查 ` 之后到下一个 ` · `、或到末尾结论词之前的文字，按 ` / ` 拆开，每段最后一个空格之后是 `<秒>s`、之前是检查名。`cost()` 用它取 `test` 与 `wait`。

## 解锁

去掉 `tests/test_flight_doctor_cost_lock.py` 用例的 `@PENDING`，`PENDING` 不再使用时连同定义与 `import pytest` 一起删除。MUST NOT 改断言与函数名。verify 里的 `tests/test_flight_doctor.py`、`tests/test_flight_doctor_surfaces.py` 不在本片 owns 内，必须保持全绿——它们就是「旧时间线结果不变」的护栏。
