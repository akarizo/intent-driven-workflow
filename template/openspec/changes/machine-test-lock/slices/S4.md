# S4 · flight-doctor.py doctor 的 [checks] 与 [lock]

## 做什么

`flight-doctor.py doctor` 在现有四节（`[runner]` `[anchors]` `[gate.test]` `[declare]`）之后新增两节：`[checks]` 点名「耗时接近测试耗时」的检查，`[lock]` 列出全机测试锁当前的持有者。规则原文见 `specs/machine-test-lock/spec.md` 的「成本归因与体检读得到排队和收口耗时」后两条 scenario，决策见 `design.md` D10。

只读、只报告、恒退出 0。

## 依赖的接口

- **S1**（`flight-lock.py`，design D7）：`holders()` → `[{"pid", "mode", "change", "label", "started", "held_sec", "cap_sec"}]`；`lock_dir()`。按路径加载（与本文件的 `load_gate` 同法），加载失败在 `[lock]` 里写原因，不抛。
- **S2**（本文件内）：`note_costs(note) -> {"test", "wait", "checks"}`。

## 怎么做

TDD：`tests/test_flight_doctor_lock.py` 的 2 条骨架现在是红的。

1. **`[checks]`**：
   - 对每个在途 change（`_changes`），读 `timeline.md`，取**最近一条** `note_costs(note)["test"]` 不为空的 final 备注；
   - 其中某项检查的秒数 ≥ 10 且 ≥ `test` 的一半 → 输出一行：
     `  <change>：检查 <名> <秒> 秒，接近测试 <秒> 秒 → 疑似检查在重跑测试，改读 $GATE_TEST_RESULT（见 .claude/flight-runner-contract.md 第 3 节）`
   - 没有任何命中 → `  无：最近的 final 里没有耗时接近测试的检查`。
   - 只点名命中的检查；没命中的检查名不要出现在这一节里。
   - 阈值写成模块常量（10 秒、0.5），是草案。
2. **`[lock]`**：
   - 第一行 `  锁目录：<lock_dir()>`；
   - `FLIGHT_LOCK=off`（不分大小写）→ `  已关闭（FLIGHT_LOCK=off）`，不再列持有者；
   - 有持有者 → 每个一行：`  <独占|共享> · <change> · <标签> · pid <pid> · 已持有 <秒> 秒`；
   - 没有 → `  空闲`；
   - `flight-lock.py` 加载不了 → `  flight-lock.py 加载失败：<原因>`。
3. `doctor()` 里按 `[runner]` → `[anchors]` → `[gate.test]` → `[declare]` → `[checks]` → `[lock]` 的顺序拼接；文件头注释的 `doctor` 一行补上两节的名字。

## 解锁

去掉 `tests/test_flight_doctor_lock.py` 2 条用例的 `@PENDING`，`PENDING` 不再使用时连同定义与 `import pytest` 一起删除。MUST NOT 改断言与函数名。verify 里其余测试不在本片 owns 内，必须保持全绿。
