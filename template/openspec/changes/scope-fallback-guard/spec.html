Why · 01为何而做

工作流自己写的分类元数据一改动，选测逻辑就把整个文件当成「基础设施」，范围退回全量，而且没有任何人在计划期看得到。

- afa 实测（2026-11-02，change cpdb-lru-position）：propose 期按 ADR 把 3 个真实库测试登记为集成用例，改了 executor/tests/tiering_registry.json（+23 行，全是新文件的条目）。该文件在 afa 选测的 INFRA_PATTERNS 里，888 条登记集成用例（240 个文件）全选，baseline 跑了 474.7 秒；只拿掉登记表，受影响的集成文件只有 3 个。final 还会再全选一次。 - 模板自身同类缺陷（临时仓库实证）：baseline 之后只在 test-tiers.json 的 slow_allow 加一条（等同 apply 期跑 allow-slow），或只给某区域的 covers 加一个 glob，final 都退回全量（full_why 为「没有可用锚点」）；不碰分层文件的对照组走增量。原因是锚点按整个分层文件的 blob 哈希过滤（slice-gate.py:3967、:3982），且 GLOBAL_FILES 含 test-tiers.json（:3977）。

模板改不到项目自己的选测代码，但能做两件事：把自己的分层文件改成按条目判定；给项目自带选测定一个范围报告契约，让「退化为全选」在计划期就被机械发现、由人类看着放行。用户决策（2026-11-02，决策页 openspec/superpower/2026-11-02-scope-fallback-guard-decisions.html，6 题全取推荐）。

What · 02变更范围

  • A · 分层文件按条目参与增量 final（简写形态）：
  • 锚点的分层指纹只由单元层（unit.paths / unit.cmd）算出；单元层变了照旧全量；
  • 已选区域的条目变了 → 该区域本次必跑；未选区域的改动不影响 final；
  • slow_allow 按用例 id 比对，新增或删除的条目所在测试文件并入重跑、G10 按新名单重判；
  • Δ 里的分层文件本身不再命中两条全量条件（全局文件、未被用例触及的非 Python 文件）；
  • 锚点额外记录各区域条目指纹与 slow_allow 清单。部件形态 final 恒全量，不变。
  • B · 项目自带选测的范围报告契约（计划期表态）：
  • 计划可写 gate.scope，或仓库在 openspec 根放 gate-scope.json（{"cmd": "..."}）作默认；
  • lint 与 preflight 实跑选测命令（waves 不跑，超时 300 秒），库经 GATE_SCOPE_OUT 给出文件路径，命令写入 {"full", "triggers", "count"}；
  • 报告全选时，计划须在 gate.scope_full_reason 为每个触发项写理由，键与本次触发项必须完全一致；
  • 选测命令失败（非 0 / 超时 / 报告不合法）即 lint 红；
  • spec.html 显示选测命令、来源与「触发项 → 理由」表；
  • 两个新字段不进 plan_sha。
  • 文档：schema tasks instruction、/opsx-propose 与同名 skill、/opsx-verify 与同名 skill、/test-tiers 的「放行慢单测」、README。
代码：template/.claude/hooks/slice-gate.py（锚点写入、_tiers_key、GLOBAL_FILES、final 增量选择、lint / preflight 的选测范围核对）、template/.claude/hooks/spec_html.py（选测范围小节）。文档：template/openspec/schemas/intent-driven/schema.yaml、template/.claude/commands/{opsx-propose,opsx-verify,test-tiers}.md、template/.claude/skills/{openspec-propose,openspec-verify-change}/SKILL.md、README.md。ADR：新增两份 DRAFT；其一 supersede DRAFT-final-incremental-by-dependency-anchor 决策 4 中「分层文件」一项（原文件不改）。兼容：锚点格式变化，升级后各仓库第一次 final 全量一次；未配分层、未配选测命令的仓库行为不变。不在范围：afa 侧 tiering_select.py 的登记表按条目差分、afa 输出范围报告的子命令（afa 自己的 change）；gate.impacted 在 final 的退化；baseline / final 侧的范围记录。

Specs · 04行为规范 (Gherkin)

gate-scope-report ADDED

Requirement: 选测命令的声明与运行契约

计划 MAY 在 gate.scope 写选测范围命令（非空字符串，只算范围、不跑测试）；仓库 MAY 在 openspec 根放 gate-scope.json，内容是只含 cmd（非空字符串）的对象。有效的选测命令 = gate.scope（若有），否则 gate-scope.json 的 cmd（若有）。gate.scope 不是非空字符串、gate.scope_full_reason 不是「键 → 非空字符串」的对象、gate-scope.json 无法解析或字段不对时，slice-gate.py lint SHALL 退出非 0，违规行以 scope: 开头并点名对象。

有有效选测命令时，slice-gate.py lint 与 slice-gate.py preflight SHALL 实跑它一次；slice-gate.py waves SHALL NOT 运行它。运行契约：

- 在 git 顶层目录运行，超时 300 秒； - 环境变量 GATE_SCOPE_OUT 指向库准备的临时文件路径； - 命令往该文件写一个 JSON 对象，只含 full（布尔，必填）、triggers（字符串数组，必填；full 为真时非空，每项非空）、count（可选，非负整数）。

命令退出非 0、超时、没写出文件、文件不是合法 JSON 或形状不符时，lint / preflight SHALL 退出非 0，违规行以 scope: 开头并写明原因（退出码、超时、缺文件，或哪个字段不合法）。

核对通过时，lint SHALL 在 stderr 打印一行以 scope: 开头的摘要（是否全选、count、全选时的触发项）；stdout 的 waves JSON 不变。

gate.scope 与 gate.scope_full_reason SHALL NOT 计入 plan_sha。

Requirement: 选测退化为全选时计划须逐项表态

有效选测命令报告 full 为真时，计划 SHALL 在 gate.scope_full_reason（对象：触发项 → 非空理由）为每个触发项写理由，键集合 SHALL 与本次 triggers 完全相等。下列情形 lint / preflight SHALL 退出非 0，违规行以 scope: 开头：

- 缺键 → 点名缺理由的触发项，并提示在 gate.scope_full_reason 写理由或修选测； - 多出的键（不是本次触发项）→ 点名该键； - full 为假而 gate.scope_full_reason 非空 → 点名每个键，提示删除； - 没有有效选测命令却写了 gate.scope_full_reason → 点名 gate.scope_full_reason。

tier-file-incremental ADDED

Requirement: 分层文件按条目参与增量 final

配置了合法的简写形态 test-tiers.json 时，final 的增量判定 SHALL 把分层文件拆成三块与锚点比对，不再把整个文件当作一个指纹或全局文件：

- 单元层（unit 的 paths 与 cmd）：锚点的分层指纹 SHALL 只由单元层算出；与当前单元层不同的锚点不可用（没有可用锚点 → 全量，full_why 照旧为「没有可用锚点」）； - 区域：已选区域（gate.integration）的条目（paths / covers / cmd）与锚点记录不同、或锚点没有该区域的记录时，该区域本次 SHALL 运行（不进 regions_skipped）；未选区域的增、删、改 SHALL NOT 影响 final； - slow_allow：按用例 id 与锚点记录的清单比较；新增或删除的条目，其用例所在测试文件存在且落在 unit.paths 时，SHALL 并入本次重跑，G10 按当前名单判定；只改理由或批准文字不算变化。

Δ 里的分层文件本身 SHALL NOT 命中「Δ 含全局文件」或「Δ 含未被任何用例触及的非 Python 文件」两条全量条件。

每次写锚点（baseline 全量、final 全量与增量）SHALL 同时记录各区域条目的指纹与 slow_allow 的用例 id 清单。

配置了 gate.impacted 时，同样 SHALL NOT 因分层文件里单元层以外的改动退回全量。已选区域的命令改动仍按现有规则判红（「基线缺记录或命令已变，重跑 baseline」）。部件形态的 final 恒全量，不变。

Design · 05技术设计

Context

  • 现状（main 471aa98，template/.claude/hooks/slice-gate.py）：
  • 锚点过滤：_anchor_candidates（:3967）要求锚点的 tiers_key 与当前相等；_tiers_key（:3982）是整个 test-tiers.json 的 blob 哈希。baseline（:3463）与 final（:3176）写锚点时都带它。
  • 全局文件：GLOBAL_FILES（:3977）含 TIER_FILE；_full_why（:4106）里 Δ 命中全局文件即全量，gate.impacted 路径同样检查；另有「Δ 含锚点时已存在、未被任何用例触及的非 Python 文件 → 全量」一条，test-tiers.json 也会命中它。
  • 同树沿用与 gate.impacted 锚点：_final_fps（:4010）的 tiers 指纹也取 _tiers_key；_impacted_anchor（:4076）比对它。
  • 分层增量（:3066）：选中文件按 unit.paths 挂探针；已选区域只在「选中文件落在区域 paths / 锚点没测过 / Δ 命中 covers」时运行。
  • lint：lint_plan（:1939）只做形状与仓库默认检查的核对，不运行命令（部件形态的 list 选择器除外）；cmd_lint 同时服务 lint 与 waves（:4391）；cmd_preflight（:3530）先调 lint_plan。
  • 审批页：spec_html.py 的 render_flight（:480）渲染切片、scenario 与飞行记录，不渲染 gate 字段。
  • 实证（2026-11-02，临时仓库，用 tests/test_final_tiers.py 的 tiers_repo）：baseline 后只加一条 slow_allow、或只给区域 covers 加 glob，再改一行源码 → final {"mode": "full", "full_why": "没有可用锚点"}；对照组走增量（重跑 1 个文件、沿用 2 个用例、区域跳过）。
  • afa 实证：见 proposal。afa 的选测（tools/testgate + executor/tests/tiering_select.py）是项目自己的代码。
  • 用户决策（2026-11-02，6 题全取推荐）：Q1 三块分别比对；Q2 $GATE_SCOPE_OUT 文件；Q3 {触发项: 理由} 键须与触发项一致；Q4 仓库级 gate-scope.json；Q5 lint 与 preflight 跑、waves 不跑、300 秒；Q6 失败即红。
  • 约束：
  • 铁律 9：判据由脚本取得——触发项来自选测命令的输出，lint 核对键，不靠模型转述；
  • 铁律 10：未配分层、未配选测命令时行为不变；
  • 在役 ADR DRAFT-final-incremental-by-dependency-anchor 决策 4 写明「分层文件变动 → 全量」：本 change 由新 ADR 只 supersede 这一项（D1–D4），原文件不改；
  • 在役 ADR DRAFT-gate-evidence-not-self-reported：新门禁先回答「判据从哪来、谁能伪造」（D10）。

C4 组件视图（plain Mermaid，沿用先例）：

  • 边界：A 全在 slice-gate.py 的锚点与 final 里；B 横跨 lint / preflight（判定）与 spec_html.py（展示），选测命令属于项目，模板只定契约、核对格式与表态。
  • 假设：选测命令能在 300 秒内只算范围不跑测试（afa 量级：收集 10698 个用例 9.5 秒）。
  • 不确定：选测命令报告的真伪模板无法核验（见 D10、Risks）。

Goals / Non-Goals

Goals: - apply 期改 slow_allow、改或新增区域不再让 final 退回全量；单元层改动仍全量。 - 项目自带选测退化为全选时，在 propose 的 lint 就被发现，并由人类在 spec.html 看着触发项与理由放行。 - 仓库声明一次选测命令，之后每个 change 都受保护，不靠模型记得。

Non-Goals: - 修 afa 的 tiering_select.py，或为 afa 写范围报告子命令（afa 自己的 change）。 - gate.impacted 在 final 的退化、baseline / final 侧的范围记录。 - 部件形态（final 恒全量，不变）。 - 兼容旧格式锚点（升级后第一次 final 全量一次）。

Decisions

_tiers_key 对简写形态改为单元层的规范 JSON（json.dumps(unit, sort_keys=True, ensure_ascii=False)）的 sha1；部件形态仍取整文件 blob 哈希（其 final 恒全量，不受影响）；无分层 → None，不变。
锚点过滤、_final_fps.tiers、_impacted_anchor 都经它，自动换成新口径。分层文件新增或删除时，一方为 None，锚点照旧不可用。
否决

继续用整文件哈希、只给 slow_allow 开白名单（Q1 的 B）——区域改动仍全量。

有分层（简写形态）时，baseline 全量、final 全量与增量写的锚点都带 tiers_detail

{"regions": {区域名: 条目规范 JSON 的 sha1}, "slow_allow": [用例 id，排序]}。

增量 final 的新锚点按当前分层文件写 tiers_detail（本次已按当前名单判过选中文件）。
区域

run_regions 在现有三条件外再加一条——已选区域 R 当前条目指纹 ≠ 锚点 tiers_detail.regions[R]（锚点缺该项也算）。未选区域不进 run_regions，与现在相同。

放行

当前 slow_allow 键集合与锚点 slow_allow 清单的对称差 → 取 :: 前的文件，存在且落在 unit.paths 的并入选中集合（随后与其它选中文件一样挂探针、判 G10）。理由 / 批准文字不参与比较。

锚点缺 tiers_detail（理论上只有旧锚点，而旧锚点已被 D1 过滤掉）→ 区域按「缺记录」全跑、放行清单视为空，均偏保守。
GLOBAL_FILES 去掉 TIER_FILE；_full_why 的「未被任何用例触及的非 Python 文件」一条跳过 openspec 根的分层文件路径（由 cmd_final 算出仓库相对路径传入）。
安全性

单元层变化由 D1 拦（没有可用锚点 → 全量）；区域与放行由 D3 处理；其它目录下同名文件按普通非 Python 文件处理。

有效命令 = gate.scope（非空字符串）否则 <openspec 根>/gate-scope.json 的 cmd（文件只许 cmd 一个字段）。
运行

cwd = git 顶层，subprocess.run(cmd, shell=True, timeout=SCOPE_TIMEOUT)，SCOPE_TIMEOUT = 300（常量，不可配置）；环境变量 GATE_SCOPE_OUT 指向临时目录里的 scope.json，运行后读它。

报告形状

对象，只含 full（bool）、triggers（str 数组；full 为真时非空、每项非空）、count（可选，非负 int，bool 不算）。

失败（非 0、超时、无文件、非 JSON、形状不符）→ scope: 违规，写明退出码 / 超时 / 缺文件 / 哪个字段（Q6 失败即拦，与 afa ScopeError「算不出就抛错、不静默退回全量」同一取向）。
否决

stdout 最后一行 JSON（日志会挤掉它，Q2 的 B）。

lint_plan(data, change_dir=None, run_scope=False)

形状校验（gate.scope、gate.scope_full_reason、gate-scope.json）在有 change_dir 时恒做；实跑只在 run_scope=True 时。

cmd_lint 传 run_scope=(args.cmd == "lint")，waves 不跑；cmd_preflight 传 True（起飞前的机械关口，模型跳过 lint 也躲不过）。
核对通过时 lint_plan 往 stderr 打一行摘要，如 scope: 选测范围未全选（12 条） / scope: 选测范围全选（触发 a.json、b.py），已逐项写理由；stdout 的 waves JSON 不变。
gate.scope_full_reason

对象，键 → 非空字符串。核对：full 为真 → 键集合须等于 triggers（缺键点名缺的触发项并提示写理由或修选测；多键点名多出的）；full 为假 → 每个键都点名、提示删除；没有有效选测命令却写了它 → 违规。

与 checks_skip、integration_skip 同一「逐项表态」模式；触发项由命令给出，spec.html 显示的是机械事实。
否决

一段自由文字（Q3 的 B，看不到触发项、无法核对过期）。

render_flight 在切片表之后加「选测范围」小节

选测命令原文与来源（「计划 gate.scope」/「仓库默认 gate-scope.json」），有 gate.scope_full_reason 时渲染「触发项 → 理由」表。只读文件，不运行命令。

两个字段不影响 baseline 的测试结论；改理由不应让基线过期。plan_sha 不取未列出的 gate 键，代码无需改动，用 guard scenario 锁住。
触发项与 full 来自仓库内的选测命令（gate.scope 显示在 spec.html；gate-scope.json 在仓库里，PR diff 可见），lint 只核对计划的表态是否与之吻合。
模型能改的是计划里的 gate.scope

换成一个永远报 full: false 的命令可以绕过——但命令原文显示在审批页，人类批准前可见；仓库默认则只能经 PR 修改。

选测命令报告失真（实际全选却报 false）模板看不出，这是「项目自带选测」的固有边界，记入 Risks。

Risks / Trade-offs

[lint 变慢

配了选测命令的仓库，每次 lint / preflight 多跑一次] → 只在 lint 与 preflight 跑，waves 不跑；300 秒上限。

[选测命令报告失真] → 模板无法核验；靠命令在仓库内可审、审批页显示命令原文。
[区域 paths 改动只让该区域重跑，不追究被移出区域的文件] → 单元层 paths 未变时这些文件不会悄悄进单元层；不属于任何层的文件由切片门禁 G12 与 /test-tiers check 拦。
[放行清单只按用例 id 比较] → 理由文字变化不影响判定结果，不重跑是正确的。
[锚点格式变化，升级后第一次 final 全量一次] → 一次性代价；之后恢复增量。

Migration Plan

  • 模板升级后，已有仓库的锚点因 D1 指纹口径变化全部不可用，第一次 final 全量并写入新锚点，之后自动增量；无需人工操作。
  • 想要 B 保护的仓库：实现一个只算范围的选测命令（遵守 D5 契约），在 openspec 根写 gate-scope.json。之后的 propose 若选测退化为全选，lint 会红并点名触发项。
  • afa 跟进（afa 自己的 change，不在本 change）：① tiering_select 的登记表按条目差分；② testgate 增加输出 D5 报告的子命令并写 gate-scope.json。
  • 回退：A 回退即恢复整文件哈希与 GLOBAL_FILES；B 是可选契约，删除 gate-scope.json / gate.scope 即回到现状（铁律 10）。
