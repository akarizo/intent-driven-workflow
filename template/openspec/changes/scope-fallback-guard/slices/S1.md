# S1 · 判定器：分层文件按条目参与增量 final

**做什么**：落实 design D1–D4。简写形态的分层指纹只取单元层；锚点记录区域条目指纹与 `slow_allow` 清单；final 内建增量按块收窄；Δ 里的分层文件不再触发全量。部件形态行为不变。

**owns**
- `template/.claude/hooks/slice-gate.py`
- `tests/test_tier_file_incremental.py`

**要点**（行号以 main `471aa98` 为准）
- `_tiers_key`（`:3982`）：简写形态 → 单元层规范 JSON（`json.dumps(tiers["unit"], sort_keys=True, ensure_ascii=False)`）的 sha1；部件形态保持整文件 blob 哈希；`tiers is None` → `None`。调用方（`_anchor_candidates` 过滤、`_final_fps`、baseline / final 写锚点）不用改签名。
- 新增一个纯函数算 `tiers_detail`（简写形态）：`{"regions": {名: 条目规范 JSON 的 sha1}, "slow_allow": sorted(键)}`；部件形态或无分层 → `None`。
- 写锚点：baseline（`:3463` 附近）与 final（`:3176` 附近）的锚点条目都加 `tiers_detail`。
- final 内建增量（`:3066` 起）：
  - 选中集合并入「当前 `slow_allow` 键 ⊕ 锚点 `slow_allow` 清单」里用例所在、存在且命中 `unit.paths` 的文件；
  - `run_regions` 再加条件：已选区域当前条目指纹 ≠ 锚点 `tiers_detail.regions` 里的值（缺也算）。
- `GLOBAL_FILES`（`:3977`）去掉 `TIER_FILE`；`_full_why`（`:4106`）的「未被任何用例触及的非 Python 文件」一条跳过 openspec 根分层文件的仓库相对路径（`cmd_final` 用 `_tiers_path(args.change_dir)` 算出后传入）。
- 不改：同树沿用的判定方式、区域命令变更判红、部件形态 final 恒全量。

**依赖切片接口**：无。
