## scenario

### baseline-full-suite-sec#anchor-carries-full-suite-sec → `tests/test_baseline_full_sec.py::test_anchor_carries_full_suite_sec`

- **GIVEN** change c 跑过一次全量 baseline
- **WHEN** 读取锚点池里最新的锚点
- **THEN** 它的 `full_suite_sec` 是数值，等于 c 的 `gate-baseline.json` 里的 `full_suite_sec`

### baseline-full-suite-sec#final-anchor-keeps-full-suite-sec → `tests/test_baseline_full_sec.py::test_final_anchor_keeps_full_suite_sec`

- **GIVEN** change c 跑过一次全量 baseline，记下的全量耗时为 T；之后提交了非测试文件 `src/a.py` 的改动
- **WHEN** 对 c 运行 final，读取锚点池里最新的锚点；再运行 `final --full`，再读一次
- **THEN** 第一次 final 走增量，最新锚点的 `full_suite_sec` 等于 T
- **AND** `final --full` 之后，最新锚点的 `full_suite_sec` 是大于 0 的数值

### baseline-full-suite-sec#anchor-baseline-inherits-full-suite-sec → `tests/test_baseline_full_sec.py::test_anchor_baseline_inherits_full_suite_sec`

- **GIVEN** change other 跑过全量 baseline，全量耗时为 T；change c 与 other 的 `gate.test` 相同，c 还没有基线
- **WHEN** 对 c 运行 baseline
- **THEN** c 的基线经锚点走增量，来源是 other
- **AND** c 的 `full_suite_sec` 等于 T

### baseline-full-suite-sec#own-reuse-keeps-inherited-full-suite-sec → `tests/test_baseline_full_sec.py::test_own_reuse_keeps_inherited_full_suite_sec`

- **GIVEN** change c 的基线经 other 的锚点走增量，`full_suite_sec` 等于 other 的全量耗时 T
- **AND** 之后只提交了测试文件的改动
- **WHEN** 再对 c 运行 baseline
- **THEN** c 的基线复用本 change 旧基线（增量）
- **AND** `full_suite_sec` 仍等于 T，不等于本次或上次的 `test.sec`

### baseline-full-suite-sec#legacy-anchor-leaves-full-suite-sec-unknown → `tests/test_baseline_full_sec.py::test_legacy_anchor_leaves_full_suite_sec_unknown`

- **GIVEN** change other 跑过全量 baseline，锚点池里的锚点都去掉了 `full_suite_sec`（模拟旧版本写的锚点）；change c 还没有基线
- **WHEN** 对 c 运行 baseline，之后只提交测试文件的改动，再运行一次 baseline
- **THEN** 两次 c 的基线都是增量，`full_suite_sec` 都为空

### warm-source-selection#warm-picks-latest-committed-change → `tests/test_warm_source.py::test_warm_picks_latest_committed_change`

## 怎么做（TDD：先跑 verify，看 8 条 xfail）

行号以 main `9b2f62f` 为准，动手前用 `grep -n` 重新定位。

### 1. 锚点条目带 `full_suite_sec`（design D1）

- **全量 baseline**：`_run_baseline` 里 `hit is None and not parts` 那段 `_anchor_write(root, {...})`（约 5260 行），在条目里加 `"full_suite_sec": full_sec`（就是本次写进基线的全量墙钟）。
- **增量路径**：`_anchor_forward`（约 6981 行）的返回 dict 加 `"full_suite_sec": _num(old.get("full_suite_sec"))`。增量 baseline（`apart`）和增量 final 都经它构造，一处覆盖两条路径。
- **全量 final**：`anchor_part = {... "source": "final-full" ...}`（约 4737 行）加 `"full_suite_sec"`，值为本次 `run_test_gate` 的墙钟。在调用前后自己计时，`round(…, 1)`；不要复用分支外的 `t0`，它包含了前面的准备步骤。

### 2. 增量 baseline 的取值顺序（design D2）

改 `_run_baseline` 结尾的「全量耗时记在基线里」段（约 5207–5214 行）：

```python
if hit is not None:
    full_sec = last_sec
    if full_sec is None and hit.get("source") == "anchor":
        full_sec = _num((src.get("pick") or [{}])[0].get("full_suite_sec"))
    elif full_sec is None:
        full_sec = _num(src.get("full_suite_sec"))
        if full_sec is None and src.get("mode") != "incremental":  # 池条目没有 mode，都是全量
            full_sec = _num((src.get("test") or {}).get("sec"))
```

同步更新该段上方的中文注释。

### 3. `_warm_source`（design D3）

- **排序键**：改成 `(提交时间, 名字)`，取最大的那个。
  - 从没提交过的记为 `-1`。
  - git 调用失败时全部记为 `-1`，退化为按名字排序，不抛错。
- **取提交时间只调一次 git**：
  - 在 git 顶层运行 `git log --format=%ct --name-only -- <changes 根相对 git 顶层的路径>/*/slices.json`。
  - 输出由两种行交替组成：一行时间戳，后面跟若干路径行。逐行解析，每个路径只记第一次出现时的时间。
  - 拿到的路径相对 git 顶层，要和候选目录换算到同一口径再比较。
- **docstring 同步**：不再出现 mtime。
