Why · 01为何而做

收口阶段的 final 在依赖图没接通的仓库里几乎每次都是全量（方案页 docs/flight-fixes-and-test-governance.html 第 02b 节，本 change 是其中的 C1b）：

- 为什么会重跑：slice-gate.py ship 只认对齐 HEAD 的 final，final 之后只容忍记账文件。/pr-ship 自己还会产生两类提交——记忆沉淀（改 CLAUDE.md）与评审修复——所以命令文档规定这两处之后各重跑一次 final（template/.claude/commands/pr-ship.md step 2b 与收尾复裁）。 - 为什么是全量：重跑走增量还是全量，只取决于上一次 final 留下的锚点有没有测到依赖图。没测到就是「没有可用锚点」。 - 实测（各 change 时间线里 apply-done 之后的 final 行，2026-11-18 只读统计）：afa 收口阶段全量 49 次，原因全部是「没有可用锚点」；本仓 2 次，都在 incremental-final 这个 change 自己。本仓近期收口的重跑都是「增量，重跑 0–4 个文件」。

机制按设计在工作，出问题的是它的退路：一个只改了 CLAUDE.md 的提交、或只改了一个测试文件的修复提交，在没有依赖图的仓库里会换来一整遍全量，一次收口至少两遍。模板不该要求「先有完整依赖图」才能认出这两种最便宜的情形。

另外，基线复用把 .claude/skills/…、CLAUDE.md、迁移脚本这类与测试无关的改动一律算「有非测试文件改动」而退回全量（交接 T4）。仓库没有办法告诉门禁「这些路径不影响测试结论」。

C1 plan-hygiene（已合入）让「依赖图未测」必须表态；本 change 给表态之后仍然没有依赖图的仓库两条便宜的路，并让有依赖图的仓库也能少一次无意义的重跑。决策来自方案页与 2026-11-18 的对话，没有另开 grill-me 访谈。

What · 02变更范围

  • gate-scope.json 新增可选字段 inert（template/.claude/hooks/slice-gate.py）：仓库相对路径 glob 的字符串数组，含义是「这些路径的改动不影响测试结论」。不做任何缺省，由仓库自己声明。
  • 生效处与记账文件同等看待：ship 的新鲜度；final 的同树沿用与取锚点时的 Δ；baseline 的复用判定（本 change 旧基线 / 基线池路径，以及经锚点路径）。
  • 永不按 inert 处理的路径：测试路径、全局文件、global 命中的路径、changes/ 下的路径、三份声明文件（gate-scope.json / gate-checks.json / test-tiers.json）。
  • 起飞前检查（preflight）的「基线过期」判定、lint / typecheck 结论的沿用条件不看 inert（见 design D2）。
  • inert 的静态核对与依赖图对账（slice-gate.py 的选测复核、flight-doctor.py doctor）：
  • glob 匹配到已跟踪的测试路径、全局文件或 global 路径 → lint / preflight 判红并点名。
  • 有测到依赖图的锚点、且某个测试文件依赖了匹配 inert 的路径 → lint / preflight 判红，点名路径与测试文件。
  • final 运行时遇到这种矛盾，按依赖图处理（照常重跑）并给警告。
  • doctor 的 [declare] 一节列出 inert 的值与矛盾；没有测到依赖图的锚点时注明无法对账。
  • final 的无图退路（slice-gate.py 的 cmd_final 与 final_forecast）：没有可用锚点、也没配 gate.impacted 时，若本 change 上一次绿 final 之后的 Δ（去掉记账文件与 inert）只含 test_*.py，只重跑这些测试文件，其余沿用上次绿 final 的结论。
  • 结果里 incremental.source 为 tests-only；时间线备注以「增量（无图」开头；GATE_TEST_RESULT 的 mode 新增取值 tests-only。
  • 不适用时仍全量；因为上次绿 final 之后有非测试文件改动而不适用时，全量原因点名这些文件，成本预告与 ship 的「final 过期」理由事先说明。
  • 这条路不写锚点。
  • /pr-ship 先裁决再重跑（template/.claude/commands/pr-ship.md）：记忆沉淀提交之后先跑 slice-gate.py ship；reasons 里没有 final 过期 就不重跑 final。评审修复之后的重跑规则不变。
  • 文档：flight-runner-contract.md（inert 一行、边界与对账、结果文件 mode 的新取值、接入步骤）、opsx-propose.md 与同名 skill、schema 的 tasks instruction、README.md 的可选字段清单。
  • 不做：
  • 不给 inert 任何缺省值，也不按文件类型推断（本仓就有读 CLAUDE.md 与文档的测试）。
  • 不改 gate.impacted 路径的 Δ（仓库自己的选测自己负责）。
  • 无图退路不处理配了测试分层文件的仓库，也不处理增量重跑无法等价复现 gate.test 的仓库（没配 gate.pytest 的包装脚本）。
  • 不动全机测试闸与 final 耗时进时间线（C2）、切片接续与留痕（C3）、wave 集成检查（C4）。
  • C1 留下的「内建声明下的非 pytest 运行器与部件形态豁免表态」维持现状。
代码：template/.claude/hooks/slice-gate.py、template/.claude/hooks/flight-doctor.py。文档：template/.claude/commands/pr-ship.md、template/.claude/flight-runner-contract.md、template/.claude/commands/opsx-propose.md、template/.claude/skills/openspec-propose/SKILL.md、template/openspec/schemas/intent-driven/schema.yaml、README.md。ADR：新增 DRAFT-inert-paths-declared-and-reconciled.md、DRAFT-final-tests-only-rerun-without-graph.md（后者修订 DRAFT-final-incremental-by-dependency-anchor 决策 4 的「没有可用锚点即全量」，原文不改）。测试：新增 5 个测试文件（20 条 scenario 骨架 + 1 条既有行为守卫）。在一次性副本上按 design 做了原型并跑全量：没有旧测试受波及。契约：GATE_TEST_RESULT 的 mode 多一个取值 tests-only。按契约只认 mode == "full" 的检查不受影响；枚举了全部取值的检查需要补一支。下游：已安装的仓库 ./install.sh --upgrade 后行为不变，直到在 gate-scope.json 里写了 inert，或出现「上次绿 final 之后只改了测试文件」的重跑。与在途 change 的交叠：C2 machine-test-lock（未合入）也改 cmd_final 的时间线备注与 flight-doctor.py，后合入的一方在预合并时要解冲突。

Capabilities · 03能力清单

New

inert-paths：仓库声明改动不影响测试结论的路径；三处生效、五类路径永不生效；静态核对与依赖图对账；doctor 列出声明与矛盾。

New

tests-only-final：没有可用锚点时，上次绿 final 之后只改了测试文件的 final 只重跑这些文件；预告、时间线、结果交接认得这个模式。

New

ship-rerun-decision：只改 CLAUDE.md 的提交在三种配置下的收口行为；/pr-ship 先裁决再决定是否重跑 final。

Modified

无。template/openspec/specs/ 不存在，现有行为的规格都还在各自的 change 目录里；本 change 的增量全部以 ADDED 写在上面三个新 capability 里。

Specs · 04行为规范 (Gherkin)

inert-paths ADDED

Requirement: gate-scope.json 可声明 inert 路径

<openspec 根>/gate-scope.json SHALL 接受可选字段 inert：仓库相对路径 glob 的字符串数组，含义是「这些路径的改动不影响测试结论」。模板 MUST NOT 给它任何缺省值。形状不合法时 lint 与 preflight SHALL 判红并点名字段。 Feature: 仓库自己说哪些路径与测试无关 Rule: 不声明就不生效

Scenario: inert-shape-checked

  • GIVENgate-scope.json 的 inert 写成了字符串而不是数组
  • WHEN运行 slice-gate.py lint
  • THEN退出码非 0
  • ANDstderr 含「inert 须是字符串数组」

Requirement: inert 路径在三处与记账文件同等看待

匹配 inert 的路径 SHALL 在以下三处不计入改动：ship 判 final 是否过期；final 的同树沿用与取锚点时的 Δ；baseline 的复用判定（本 change 旧基线、基线池、经锚点）。起飞前检查的「基线过期」判定与 lint / typecheck 结论的沿用条件 MUST NOT 受 inert 影响。 Feature: 与测试无关的改动不触发重跑 Rule: 只放宽测试结论的复用，不放宽其他判定

Scenario: final-reuses-same-tree-across-inert-change

  • GIVEN仓库声明 inert 为 ["CLAUDE.md"]，final 已绿
  • AND之后只提交了 CLAUDE.md 的改动
  • WHEN再运行 slice-gate.py final
  • THEN结果 incremental.mode 为 reused，摘要含「同树沿用」

Scenario: baseline-reuse-ignores-inert-change

  • GIVEN依赖图测不到的仓库（包装脚本丢掉插件参数，计划已为此表态），声明 inert 为 ["docs/**"]
  • ANDbaseline 跑过一次全量，之后只提交了 docs/notes.md 的改动
  • WHEN重跑 slice-gate.py baseline
  • THEN基线 mode 为 incremental，incremental.source 为 own，rerun_files 为空

Scenario: anchor-delta-drops-inert-path

  • GIVEN仓库声明 inert 为 ["assets/**"]，基线测到了依赖图，没有任何用例读 assets/logo.bin
  • ANDbaseline 之后只提交了 assets/logo.bin 的改动
  • WHEN运行 slice-gate.py final
  • THEN结果 incremental.mode 为 incremental，rerun 为空

Requirement: 五类路径永不按 inert 处理

以下路径即使匹配 inert 的 glob，也 MUST 照常计入改动：测试路径；全局文件；global 命中的路径；changes/ 下的路径；gate-scope.json、gate-checks.json、test-tiers.json。 Feature: 声明写宽了也不漏测 Rule: 测试与门禁自身的输入不能被声明成无关

Scenario: inert-never-covers-test-files-added-later

  • GIVEN仓库声明 inert 为 ["extras/**"]，声明时该目录下只有说明文件，final 已绿
  • AND之后提交了新的测试文件 extras/test_new.py
  • WHEN运行 slice-gate.py ship
  • THENreasons 里有一条含「final 过期」

Requirement: inert 与依赖图矛盾时依赖图优先

final 取到测到依赖图的锚点时，被任一测试文件依赖的路径 MUST NOT 按 inert 处理：依赖它的测试文件照常重跑，并 SHALL 给出一条警告，点名该路径与依赖它的测试文件。 Feature: 实测胜过声明 Rule: 声明错了不会让该重跑的测试被跳过

Scenario: graph-wins-when-inert-contradicts

  • GIVEN基线测到 tests/test_b.py 读 data/b.json
  • AND之后才把 data/** 声明成 inert，并提交了 data/b.json 的改动
  • WHEN运行 slice-gate.py final
  • THEN结果 incremental.mode 为 incremental，rerun 含 tests/test_b.py
  • ANDwarnings 里有一条同时含 inert、data/b.json 与 tests/test_b.py

Requirement: lint 与 preflight 核对 inert 声明

选测复核（lint、preflight、baseline 开跑前）SHALL 对 inert 做两项核对，任一不过即判红： - glob 匹配到已跟踪的测试路径、全局文件或 global 命中的路径 → 点名 glob、路径与类别； - 锚点池里有与本计划同命令指纹、同分层指纹且测到依赖图的锚点时，取最新一条对账：有测试文件依赖了匹配 inert 的路径 → 点名路径与测试文件。 没有这样的锚点时 MUST NOT 因对账判红。 Feature: 起飞前发现写错的声明 Rule: 能机械判定的矛盾不留到运行时

Scenario: lint-rejects-inert-matching-test-or-global-files

  • GIVENinert 写了 ["tests/**", "*.ini"]
  • WHEN运行 slice-gate.py lint
  • THEN退出码非 0
  • AND有一条违规同时含 tests/**、tests/test_a.py 与「测试路径」
  • AND有一条违规同时含 *.ini、pytest.ini 与「全局文件」

Scenario: lint-reconciles-inert-with-dependency-graph

  • GIVEN基线测到 tests/test_b.py 读 data/b.json
  • AND之后把 data/** 声明成 inert
  • WHEN分别运行 slice-gate.py lint 与 slice-gate.py preflight
  • THEN两者退出码都非 0
  • AND各有一条违规同时含 data/b.json 与 tests/test_b.py

Scenario: inert-consistent-with-graph-passes-lint

  • GIVEN基线测到了依赖图，没有任何用例触及 scripts/helper.sh
  • AND之后把 scripts/** 声明成 inert
  • WHEN运行 slice-gate.py lint
  • THEN退出码为 0

Requirement: doctor 列出 inert 声明与对账结果

flight-doctor.py doctor 的 [declare] 一节 SHALL 列出 inert 的值；声明了 inert 时另列出它与锚点池里各条测到依赖图的锚点的矛盾（路径与测试文件）；没有这样的锚点时 SHALL 注明无法对账。flight-doctor.py MUST 仍恒退出 0。 Feature: 体检看得见声明对不对 Rule: 只读，不阻断

Scenario: doctor-lists-inert-and-conflicts

  • GIVEN仓库声明了 inert，锚点池为空
  • WHEN运行 flight-doctor.py doctor
  • THEN退出码为 0，输出里有一行含 inert 与「无法对账」
  • AND基线测到 tests/test_b.py 读 data/b.json、再把 data/ 声明成 inert 后重跑，输出里有一行含 data/，另有一行同时含「矛盾」、data/b.json 与 tests/test_b.py

Requirement: 文档写明 inert 与无图退路

flight-runner-contract.md SHALL 在可选字段表里列出 inert 并写明对账、永不按 inert 处理的路径、依赖图未测时无法对账；结果文件 mode 的取值 SHALL 列出 tests-only；接入步骤 SHALL 提到 inert。opsx-propose.md、同名 skill、schema 的 tasks instruction 与 README.md 的可选字段清单 SHALL 含 inert。 Feature: 接入的唯一依据是契约文档 Rule: 命令与同名 skill 同改

Scenario: docs-describe-inert-and-tests-only

  • GIVEN本 change 合入后的模板
  • WHEN读运行器契约、propose 命令与同名 skill、schema、README
  • THEN契约的可选字段表有以 inert 开头的一行且含「对账」
  • AND契约含「无法对账」与「永不」，结果文件 mode 一行含 tests-only，「接入步骤」一节含 inert
  • AND其余四处都含 inert

ship-rerun-decision ADDED

Requirement: 只改 CLAUDE.md 的提交不该换来一遍全量，除非别无依据

final 绿之后只提交了 CLAUDE.md 的改动时，收口行为 SHALL 按仓库的配置分三种： - 依赖图已测、没有声明 inert：ship 判 final 过期，重跑 final 走增量、重跑 0 个文件（既有行为，由守卫测试钉住）； - 声明了 inert 且含该文件：ship 仍判 final 新鲜，不需要重跑； - 依赖图未测、也没有声明：重跑 final 走全量，全量原因 SHALL 点名该文件，成本预告与 ship 的「final 过期」理由 SHALL 事先说明这次是全量并点名该文件。 Feature: 记忆沉淀提交之后的收口 Rule: 能不跑就不跑，要全量就事先说清为什么

Scenario: claude-md-commit-with-inert-keeps-ship-fresh

  • GIVEN仓库声明 inert 为 ["CLAUDE.md"]，final 已绿
  • AND之后只提交了 CLAUDE.md 的改动
  • WHEN运行 slice-gate.py ship
  • THENreasons 里没有含「过期」的条目

Scenario: claude-md-commit-without-graph-or-inert-runs-full-and-names-file

  • GIVEN依赖图测不到、也没有声明 inert 的仓库，final 已绿
  • AND之后只提交了 CLAUDE.md 的改动
  • WHEN依次运行 flight-doctor.py forecast --json、slice-gate.py ship、slice-gate.py final
  • THEN预告的 final.mode 为 full，final.why 含 CLAUDE.md
  • ANDship 有一条理由同时含「final 过期」「补跑将是全量」与 CLAUDE.md
  • ANDfinal 的 incremental.mode 为 full，full_why 含 CLAUDE.md

Requirement: /pr-ship 先裁决再决定是否重跑 final

/pr-ship 在记忆沉淀提交之后 SHALL 先运行 slice-gate.py ship：reasons 里没有 final 过期 时 MUST NOT 重跑 final；有时才重跑。要不要重跑 MUST 由 ship 的输出决定，模型不自行判断。评审修复之后的重跑规则不变。 Feature: 重跑由脚本裁决 Rule: 零 token 优先

Scenario: pr-ship-asks-ship-before-rerunning-final

  • GIVEN本 change 合入后的 template/.claude/commands/pr-ship.md
  • WHEN读 step 2b（记忆层沉淀）
  • THENslice-gate.py ship 出现在 slice-gate.py final 之前
  • AND写明 reasons 含 final 过期 才重跑，否则「不重跑 final」
  • AND不再有「沉淀 commit 之后重跑：」这句无条件说法

tests-only-final ADDED

Requirement: 没有可用锚点时，只改了测试文件的 final 只重跑这些文件

slice-gate.py final 在没有可用锚点、没配 gate.impacted、不是 --full 时，若以下条件全部成立，SHALL 只重跑改动的测试文件，其余用例沿用本 change 上一次绿 final 的结论： - 本 change 有一次绿 final，它的 gate.test / gate.pytest 指纹与分层指纹同当前； - 其后的 Δ 去掉记账文件与按 inert 生效的路径后，只含文件名匹配 test_*.py 的路径，且都不命中 global； - 改动的测试文件不含基线的预存红； - 没有测试分层文件；增量重跑能等价复现 gate.test（直接的 pytest 调用，或配了 gate.pytest）。

blind 命中的测试文件 SHALL 一并重跑。锚点链到上限（anchor_max_hops）而没有可用锚点时 MUST NOT 走这条路。任一条件不成立时 SHALL 照常全量。这条路 MUST NOT 写锚点。 Feature: 没有依赖图也认得出最便宜的重跑 Rule: 安全级别与 baseline「只改了测试文件就复用」相同

Scenario: tests-only-rerun-after-green-final

  • GIVEN依赖图测不到的仓库（包装脚本丢掉插件参数，计划已表态，配了 gate.pytest），final 已绿
  • AND之后只提交了 tests/test_a.py 的改动
  • WHEN运行 slice-gate.py final
  • THEN退出码为 0，incremental.mode 为 incremental，incremental.source 为 tests-only，rerun 恰为 ["tests/test_a.py"]
  • AND时间线最后一条 final 备注以「增量（无图」开头、以 ok 结尾
  • AND另一个没配 gate.pytest 的同样仓库做同样的改动后，final 的 incremental.mode 为 full

Scenario: tests-only-refused-when-source-changed

  • GIVEN同样的仓库，final 已绿
  • AND之后提交了 src/a.py 的改动
  • WHEN运行 slice-gate.py final
  • THENincremental.mode 为 full
  • ANDfull_why 同时含「没有可用锚点」与 src/a.py

Requirement: 重跑红即 final 红

无图退路重跑的测试文件里有失败或错误的用例时，final SHALL 判红并逐条点名，MUST NOT 退回全量；重跑超时或异常退出同样判红。 Feature: 红就是红 Rule: 不用一遍全量去确认一个已经看见的失败

Scenario: tests-only-red-when-rerun-fails

  • GIVEN同样的仓库，final 已绿
  • AND之后提交的 tests/test_a.py 里有一条会失败的新用例 test_a_again
  • WHEN运行 slice-gate.py final
  • THEN退出码为 1，incremental.source 为 tests-only
  • ANDfailed 里有一条以 G2 test 开头、含「新增失败」与 tests/test_a.py::test_a_again

Requirement: 结果交接标明 tests-only

走无图退路时，交给检查的结果文件（GATE_TEST_RESULT）mode SHALL 为 tests-only，nodes 与 inherited 为 null，complete 为假，failed_nodes 为本次重跑里失败的用例；检查的 GATE_FINAL_MODE 为 incremental。 Feature: 检查知道这份结果有多完整 Rule: 没有逐用例记录就不假装有

Scenario: tests-only-result-handoff-marks-mode

  • GIVEN同样的仓库，计划配了一项把 GATE_TEST_RESULT 复制到仓库外的检查，final 已绿
  • AND之后只提交了 tests/test_a.py 的改动
  • WHEN运行 slice-gate.py final

Context

现状（行号指 template/.claude/hooks/，main ef52807，即 C1 plan-hygiene 合入之后）：

  • ship 的新鲜度只容忍记账文件：_final_fresh（slice-gate.py:5766）取 final 行的 commit 与 HEAD 的文件名之差，全部是 changes/<任一 change>/ 下的记账文件才算新鲜。

  • final 走增量的唯一入口是测到依赖图的锚点：_pick_anchor（:5295）只取 measured 为真的锚点；取不到时 _full_triggers 给出 final:no-anchor，_full_why 说「没有可用锚点」（:5398），全量。
  • baseline 有一条不靠依赖图的复用路，final 没有：_try_reuse（:5650）在 Δ 只含 test_*.py 时复用上次全量结论、只补跑这些文件；Δ 里有别的文件就报「有非测试文件改动」。
  • 每次实跑的 final 都留一份记录：<git common dir>/flight-final/<change>.json（_final_rec_write，:5237），含 commit、快照、指纹与结果；红的记录带着最近一次绿的树（_last_green，:5257）。gate.impacted 已经拿它当锚点用（_impacted_anchor，:5267）。

  • 预告函数只有一个：final_forecast（:5777），flight-doctor.py forecast 与 ship 的「final 过期」理由都调它。
  • /pr-ship 无条件重跑：step 2b 写的是「沉淀 commit 之后重跑 final」（commands/pr-ship.md:50）。

实测（2026-11-18，各 change 时间线里 apply-done 之后的 final 行）：afa 收口阶段全量 49 次，原因全部是「没有可用锚点」；本仓 2 次，都在增量功能自己的那个 change。

用户决策（2026-11-18，方案页 docs/flight-fixes-and-test-governance.html 第 02b 节与对话）：收口全量属于需要加固的结构性问题；inert 不做缺省、与依赖图对账；final 补一条无图退路；/pr-ship 先裁决再重跑。

  • DRAFT-baseline-reuse-by-content-fingerprint（只改测试文件才复用）与 DRAFT-baseline-reuse-via-dependency-anchor：D2 在两条路上各去掉 inert 路径，判据本身不变。
  • DRAFT-gate-test-result-handoff-and-runner-contract 决策 1（结果文件写明 mode / inherited / complete，由检查自己决定）：D6 在它之内加一个 mode 取值。

Goals / Non-Goals

Goals：

  • 只改了与测试无关的路径（记忆文件、文档等）时，ship 不判 final 过期，final 与 baseline 不因它重跑。
  • 声明写错时，能机械发现的在起飞前发现；运行时不因声明跳过依赖图认定该重跑的测试。
  • 没有依赖图的仓库，上次绿 final 之后只改了测试文件时，final 只重跑这些文件。
  • 仍然要全量时，事先说清原因，点名文件。
  • /pr-ship 的重跑由 ship 的输出决定。

Non-Goals：

  • 不给 inert 缺省值，不按扩展名推断。
  • 不放宽起飞前检查的「基线过期」与 lint / typecheck 结论的沿用条件。
  • 不改 gate.impacted 路径。
  • 不为无图退路写锚点、不让它支持测试分层。
  • 不改 C1 的表态制与它的豁免范围。
  • 不动全机测试闸与时间线耗时格式（C2）。

Risks / Trade-offs

[inert 声明错了、仓库又没有依赖图 → 改动不触发重跑，漏测] → 不做缺省；五类路径永不生效；契约文档写明这种仓库里声明只能靠人审；final --full 随时可用。
[对账用池里最新的锚点，它可能来自别的分支，依赖略有出入] → 只会多报矛盾（偏严），不会少跑；矛盾的修法是改声明或改测试，两者都是显式动作。
[无图退路沿用的结论来自更早的 final，中间如果有人绕过门禁改了环境] → 与 baseline 旧基线复用同一假设；指纹（命令、gate.pytest、分层）变了就不沿用；--full 可用。
[被别的测试文件 import 的 test_*.py 改了，只重跑它自己] → baseline 的旧基线复用已有同样的盲区并被接受；conftest.py 是全局文件，不走这条路。
[GATE_TEST_RESULT.mode 多一个取值，枚举了全部取值的检查会走到缺省分支] → 契约文档列出新取值；proposal 标明。
[C2 machine-test-lock 未合入，也改 cmd_final 的备注与 flight-doctor.py] → 本 change 对备注只加一个分支；后合入的一方在预合并时解冲突，两边的测试各自钉着自己的格式。
[/pr-ship 文档改成有条件重跑，模型看漏条件直接跳过重跑] → ship 之后建 PR 前还会再裁一次（step 6），final 过期必然被判 draft，不会带着过期的 final 开出 ready 的 PR。
