# S3 · final 的无图退路（tests-only）；预告与全量原因

## 做什么

只改 `template/.claude/hooks/slice-gate.py`，实现 design D5、D6、D7。规则原文：`specs/tests-only-final/spec.md` 全部，与 `specs/ship-rerun-decision/spec.md` 第一条里「依赖图未测、也没有声明」的那个 scenario。

本片不改 `flight-doctor.py`：`forecast` 已经调 `final_forecast`；`cost` 按备注开头的「增量」归类，新备注自然被认成增量。

## 依赖的接口

- S1 的 `_inert_drop`（`cmd_final` 里已有的 `idrop`），见 `_interfaces.md`「S1 提供」。
- 依赖 S2 只因为两片都改 `slice-gate.py`、不能同 wave；不使用 S2 的接口。

## 怎么做

TDD：先确认 `tests/test_final_tests_only.py` 的 7 条骨架是红的（另有 1 条不带标记的既有行为守卫，一直是绿的），再写实现。

1. **判定函数**（D5），`cmd_final` 与 `final_forecast` 共用：
   ```python
   TESTS_ONLY = "tests-only"

   def _tests_only_pick(root, change_dir, data, rec, baseline, cur_snap, head, fps, tiers, drop):
       """无图退路 → ((green, Δ, 要重跑的测试文件) | None, 不适用且值得说明的原因 | None)。"""
   ```
   按序判，任一不成立返回 `(None, None)`，除非下面写了原因：
   - `tiers is None`、`cur_snap is not None`、`_unreproducible_why(root, gate)` 为空；
   - `green = _last_green(rec)` 是带 `snapshot` 的 dict；它的 `fps.cmd.test` / `fps.cmd.pytest` / `fps.tiers` 与当前 `fps` 相同；
   - `delta = _delta(root, green, cur_snap, head, change_rel, True)` 不为 `None`；`kept = drop(delta)`；
   - `kept` 里文件名不匹配 `test_*.py`、或命中 `global` 的路径非空 → `(None, "上次绿 final <10 位> 后有非测试文件改动：<至多 8 个，逗号分隔>")`；
   - 基线的 `test.failed`（按模块名，与 `_try_reuse` 同一比法）或 `test.failed_nodes`（按文件）落在 `kept` 的测试文件里 → `(None, "上次绿 final <10 位> 后改动的测试文件有预存红：<用例>")`；
   - 通过 → 重跑集合 = `kept` 里现存的文件 ∪ `blind` 命中的已跟踪测试文件（排序）；返回 `((dict(green, change=<change 名>), delta, files), None)`。
2. **`cmd_final`**（在 `_full_why` 之后、开跑前复核之前）：
   - 条件：`why` 非空、`pick is None`、`hcap is None`、不是 `--full`、没配 `gate.impacted`；传给判定函数的计划用 `dict(data, gate=rgate)`。
   - 适用 → `why = None`，`final_ctx = {"mode": "incremental", "delta": Δ, "anchor": <绿 final 的 commit>}`；
   - 不适用且有原因 → `why = "<why>；<原因>"`。
   - 运行分支加在 `if sfail:` 之后、`gate.impacted` 分支之前：
     - 重跑集合非空时 `_pytest_outcomes(root, files, rgate, extra_env=genv, keep_junit=rjunit)`，不挂依赖图与探针；
     - 超时 → `G2 test：重跑改动的测试文件超时`；有失败 / 错误 → `G2 test：新增失败 N 条：<nodeid 逗号分隔>`；其余异常（`rc` 不在 0 / 5，或输出含 `ERROR collecting`）→ `G2 test：重跑改动的测试文件 exit <rc>` 加输出末尾；
     - `inc = {"mode": "incremental", "source": "tests-only", "anchor": {"change", "commit"}, "delta": len(Δ), "rerun": files, "rerun_tests": 用例数, "inherited_tests": None}`；
     - `tres = {"mode": "tests-only", "inherited": None, "fails": fails}`；`anchor_part` 保持 `None`（不写锚点），`_write_test_result` 现有逻辑会给出 `nodes: null`、`complete: false`，不用改它。
   - 摘要与时间线备注在 `inc["mode"] == "incremental"` 那一支之前加一支（`inherited_tests` 是 `None`，不能落进原来的 `%d`）：文字见 design D6 的表。
3. **`final_forecast`**（D7）：
   - 取锚点处已由 S1 传了 `drop`；这里另取 `hcap = _hops_cap(root, akey, tkey, pick, hops)`；
   - 在「依赖图未测」那句改写之后：`why` 非空、`pick is None`、快照取到了、`hcap is None` → 调判定函数（`rec = _final_rec_read(root, name)`，`fps = _final_fps(root, change_rel, data, tiers)`）；适用 → 返回 `("incremental", "无图：上次绿 final <10 位>，只重跑 N 个测试文件")`；不适用且有原因 → `why` 后追加同一句。
   - `_rerun_forecast`（`ship` 的理由后缀）不用改。
4. **文字约束**：全量原因里不要出现「增量」两个字（`flight-doctor.py` 的 `parse_note` 按先出现的词判模式）；不适用原因固定用「有非测试文件改动」这几个字（`cost` 的归类表按它归到「可避免」）。
