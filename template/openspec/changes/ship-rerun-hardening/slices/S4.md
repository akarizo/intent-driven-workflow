# S4 · 文档：pr-ship 先裁决再重跑；契约与规划指引写明 inert 与 tests-only

## 做什么

只改文档，实现 design D4 与各决策的文档部分。规则原文：`specs/ship-rerun-decision/spec.md` 的「/pr-ship 先裁决再决定是否重跑 final」，与 `specs/inert-paths/spec.md` 的「文档写明 inert 与无图退路」。

本片不碰任何 `.py` 源码（`tests/test_ship_rerun_docs.py` 除外）。

## 依赖的接口

无（wave 1，与 S1 并行，owns 不相交）。文档里提到的 `slice-gate.py ship` 早已存在；`inert` 与 `tests-only` 由 S1–S3 落地，文档先于它们合回没有执行上的影响（飞行中没有人按这些文字操作）。

## 怎么做

TDD：先确认 `tests/test_ship_rerun_docs.py` 的 2 条骨架是红的，再改文档。

1. **`template/.claude/commands/pr-ship.md` step 2b**：把
   > 飞行模式（`slices.json` 存在）下，沉淀 commit 之后重跑：…`slice-gate.py final`… 原因：ship 裁决只容忍 final 之后出现记账文件，CLAUDE.md 不在其列。

   换成「先裁决、再决定要不要重跑」：
   - 先给 `python3 .claude/hooks/slice-gate.py ship --change-dir openspec/changes/<name>`；
   - reasons 里没有 `final 过期` → 不重跑 final（原文须含「不重跑 final」这几个字），并说明两种会出现这种结果的情形：沉淀只动了记账文件，或仓库在 `gate-scope.json` 的 `inert` 里声明了这些路径；
   - reasons 里有 `final 过期` → 重跑 `python3 .claude/hooks/slice-gate.py final --change-dir openspec/changes/<name>`，并说明理由后面的补跑预告已经写明这次是增量还是全量；
   - 末尾一句：要不要重跑由 `ship` 的输出决定，模型不自行判断。
   - 不要再出现「沉淀 commit 之后重跑：」这句。step 2b 里 `slice-gate.py ship` 必须出现在 `slice-gate.py final` 之前。
   - 收尾复裁（step 10 之后那段「有修复 commit 时先重跑 final」）不改。pr-ship 没有同名 skill。
2. **`template/.claude/flight-runner-contract.md`**：
   - 第 3 节结果文件字段表：`mode` 一行改为 `` `full` / `incremental` / `impacted` / `tests-only` ``；在「用法」里补一句 `tests-only` 的含义：没有依赖图、只重跑了上次绿 final 之后改动的测试文件，`nodes` 与 `inherited` 为 `null`、`complete` 为假。
   - 第 6 节可选字段表：加一行，行首必须是 `` | `inert` | ``，作用一栏含「对账」二字：这些路径的改动不影响测试结论——ship 的新鲜度、final 的同树沿用与 Δ、baseline 的复用判定都不计它们；依赖图测到时与它对账，矛盾即判红。
   - 表后加一小段「`inert` 的边界」，三点：
     - 永不按 `inert` 处理的五类路径（原文须含「永不」）；glob 匹配到已跟踪的测试路径、全局文件或 `global` 路径时 lint 判红；
     - 依赖图测到时对账：lint / preflight 判红并点名；final 运行时仍按依赖图重跑并警告；
     - 依赖图没测到时无法对账（原文须含「无法对账」），声明只能靠人在 PR 里审；起飞前的「基线过期」判定与 lint / typecheck 结论的沿用不看 `inert`。
   - 第 7 节接入步骤：第 4 步标题改为「声明 global / blind / inert」，补一句哪类路径写进 `inert`（与测试无关、却会让 final 过期或退回全量的：记忆文件、文档、迁移脚本）。
3. **可选字段清单四处**（只加 `inert`，别的字不动）：
   - `template/.claude/commands/opsx-propose.md` 与 `template/.claude/skills/openspec-propose/SKILL.md`：同一句里的 `` 另可选 `global` / `blind` / `anchor_max_hops` `` 改为 `` 另可选 `global` / `blind` / `inert` / `anchor_max_hops` ``——两处必须同文（命令与同名 skill 同改）。
   - `template/openspec/schemas/intent-driven/schema.yaml` 的 tasks instruction：`另可选 global / blind / anchor_max_hops——` 加上 `inert`，并在后面逐项解释的地方补一句 `inert`（仓库相对路径 glob 数组，改动不影响测试结论的路径，依赖图测到时与它对账）。改完跑 `cd template && openspec schema validate intent-driven` 确认仍绿。
   - `README.md` 「选测范围声明（契约 v2）」那一条：`另可选 global / blind / anchor_max_hops` 加上 `inert`。
