# S2 · inert 的静态核对与依赖图对账；doctor 列出声明与矛盾

## 做什么

改 `template/.claude/hooks/slice-gate.py` 与 `template/.claude/hooks/flight-doctor.py`，实现 design D3 里「起飞前判红」与 `doctor` 两部分。规则原文：`specs/inert-paths/spec.md` 的「lint 与 preflight 核对 inert 声明」「doctor 列出 inert 声明与对账结果」两条 Requirement。

本片不做：无图退路与预告（S3）；文档（S4）。

## 依赖的接口

S1 的 `_never_inert` / `_inert_ctx` / `_inert_paths` / `_recon_anchor`，见 `_interfaces.md`「S1 提供」。

## 怎么做

TDD：先确认 `tests/test_inert_reconcile.py` 的 4 条骨架是红的，再写实现。

1. **`slice-gate.py`**：新增
   ```python
   def _lint_inert(gate, change_dir):
       """inert 声明的两项核对 → 违规列表（都以 "scope: " 开头）。没声明、或不在 git 仓库里 → []。"""
   ```
   - git 顶层用 `_git_top(os.path.dirname(_scope_decl_path(change_dir)))`（与内建提供方同一取法）；已跟踪路径用 `git ls-files -z`，取不到 → `[]`。
   - **静态核对**：逐条 glob，匹配到的已跟踪路径里 `_never_inert` 类别属于「测试路径」「全局文件」「声明的 global」的 → 一条违规：
     `scope: gate-scope.json 的 inert <glob> 匹配到不能声明为无关的路径：<路径>（<类别>）、…`，至多列 5 个，多了加「等 N 个」。「changes 根下」与「声明文件」不判红。
   - **对账**：`anchor = _recon_anchor(top, change_dir, {"gate": gate})`；有锚点时对全部已跟踪路径调 `_inert_paths(top, tracked, ctx, anchor)`，每条矛盾一条违规（至多 8 条）：
     `scope: inert 声明与依赖图矛盾：<路径> 被测试文件 <文件> 依赖（锚点 <change>@<10 位>）；从 inert 去掉它，或让该测试不再依赖它`。
   - **接入**：`_lint_scope` 里，形状与提供方声明的错误都没有、且 `run_scope` 为真时，先调 `_lint_inert`；有违规就直接返回它们（不再按提供方核对）。lint、preflight、baseline 开跑前都经过这里，不用另外接。
2. **`flight-doctor.py`**：
   - `DECLARE_KEYS` 加 `"inert"`（`blind` 之后）。
   - `doctor_declare` 在列完各字段后追加对账行：
     - 没声明 `inert` → 不加；
     - 取不到 git 顶层或 `slice-gate.py` 加载失败 → `  inert：无法对账（…）`；
     - 锚点池里没有 `measured` 为真的条目 → `  inert：没有测到依赖图的锚点，无法对账`；
     - 否则逐条锚点（由新到旧）调 `sg._inert_paths`，同一路径只列一次：`  inert 与依赖图矛盾：<路径> 被测试文件 <文件> 依赖（锚点 <change>@<10 位>）`；一条矛盾都没有 → `  inert：与 N 条锚点的依赖图无矛盾`。
   - `sg._inert_ctx` 要一个 change 目录来定位 openspec 根：传 `<openspec 根>/changes/_`（不必存在，只用来取上两级目录）。
   - 恒退出 0 的约定不动；读锚点池的方式照 `doctor_anchors`。
   - 文件头注释里 `doctor` 一行的说明按实际更新。
