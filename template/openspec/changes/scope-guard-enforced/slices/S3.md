# S3 · 运行期守卫：baseline / final 开跑前复核、理由以 approve 提交为准、--full 豁免

## 做什么

baseline 与 final 在运行任何测试之前，按 lint 的同一套规则复核选测范围：未表态的全选不跑、判红。批准后再改理由无效。规则原文见 `specs/scope-runtime-guard/spec.md`，决策见 `design.md` D8–D10、D14。

## 怎么做（`template/.claude/hooks/slice-gate.py`，签名见 `_interfaces.md`）

1. **baseline**（D8）：在 `cmd_baseline` 现有形状校验之后、写运行标记（现 `:3416`）之前，调用 `_lint_scope(gate, args.change_dir, True, data, "baseline")`。有 errors 时：
   - `die("选测范围复核未过（baseline 不运行）：\n  - " + "\n  - ".join(errors))`；
   - 不写运行标记，不碰现有 `gate-baseline.json`；
   - 违规原文（含「触发项 … 缺理由」「未声明选测范围」）须出现在输出里。
2. **approve 绑定**（D10）：新增 `_approved_reasons(root, change_dir)`。
   - 找提交：`git log -G "\tapprove\t" --format=%H -n 1 -- <change_rel>/timeline.md`，用 subprocess 参数列表传入真实制表符；
   - 读 `git show <sha>:<change_rel>/slices.json`，取 `gate.scope_full_reason`，缺省 `{}`；
   - 找不到提交 → `None`；任一 git 调用失败 → 视同找不到。
3. **final 复核**（D9）：在 `cmd_final` 算出 `why` / `pick` 之后、进入任何运行测试的分支（`gate.impacted`、增量、全量）之前插入复核。`--full` 时整段跳过。
   - **approve 绑定**：`approved = _approved_reasons(…)`；为 `None` 时取当前计划的理由。当前理由 ≠ approved（键或文字）→ 失败 `G2 scope：gate.scope_full_reason 在批准后被修改（批准时 …；当前 …）`。
   - **提供方**：`_scope_provider(gate, change_dir)`。
     - **未声明**：不是本 change 建立声明 → `G2 scope：未声明选测范围 …`；
     - **builtin**：`why` 非空 → 用与 `_full_why` 同一组参数调 `_full_triggers`，不在 approved 键里的触发项 → `G2 scope：final 将全量（触发 …），未在计划期表态：在 propose 期写理由并重新批准，或修复后重跑`；
     - **cmd**：`_run_scope(cmd, root, _planned_owns(data), change_rel)`，失败或报告全选且有未批准触发项 → 同上措辞（点名触发项）。
   - **不通过时**：
     - 把失败写进 `failed`；
     - 跳过测试运行，不写锚点；
     - final JSON 照常输出，`ok` 为 false，带 `"scope": {"kind", "full", "triggers", "unapproved"}`；
     - gate-report / final 记录按红处理。
   - **通过时**行为与现在完全相同。
4. **解锁**：去掉 `tests/test_scope_runtime_guard.py` 5 条 xfail（3 条护栏本来就没有标记），删掉不再使用的 `PENDING`。MUST NOT 改断言与函数名。
