# S1 · 契约 v2：声明形态与提供方解析、未声明判红、builtin 误用、PLANNED / CHANGE、scope-seed、审批页、测试基座

## 做什么

把「选测提供方」从可选改为必有，并给提供方补上计划上下文。规则原文见 `specs/scope-provider-contract/spec.md`，决策见 `design.md` D1–D4、D11–D13。本片**不做**以下几项：
- 内建预测（S2）；
- final / baseline 的复核（S3）；
- 安装器与文档（S4）。

## 怎么做

1. **`template/.claude/hooks/slice-gate.py`**（签名见 `_interfaces.md`）
   - **声明形态**：`_scope_default` 换成 `_scope_provider(gate, change_dir)`。`gate-scope.json` 恰含 `cmd`（非空串）或 `builtin`（`true`）之一，违规措辞：
     - `cmd 与 builtin 只能取其一`；
     - `builtin 须为 true`；
     - `有未知字段 <名>`。
   - **gate.test 识别**：`_plain_test_cmd(cmd)` 满足任一条即可识别：
     - `_pytest_head` 非 None；
     - 解释器名以 `python` 开头 + `…/test-tiers.py` + `run unit`；
     - 去空白后 ∈ {`npm test`, `go test ./...`, `cargo test`}。
   - **契约 v2 环境变量**：`_run_scope` 另设 `GATE_SCOPE_PLANNED`（与 `scope.json` 同一临时目录下的 `planned.txt`）和 `GATE_SCOPE_CHANGE`（change 目录相对 git 顶层，`/` 分隔）。
   - **`_lint_scope(gate, change_dir, run_scope, data, phase)`**：
     - 形状校验恒做。
     - `run_scope` 为真时：
       - **未声明**：`_establishes_decl` 为真 → 报告 `{"full": True, "triggers": [SCOPE_UNDECLARED]}`，交给表态核对，通过时摘要 `scope: 未声明选测范围，本 change 建立仓库选测声明（已写理由）`；否则判红，措辞见 design D2，须同时提到 `builtin` 与 `cmd`。
       - **builtin**：`_plain_test_cmd(gate.test)` 为假 → 判红，措辞含「认不出」与 `cmd`。为真 → 调 `_builtin_report(root, change_dir, data, phase)`（本片给最小实现：恒不全选），通过时摘要含「模板内建」，例如 `scope: 模板内建选测（builtin）：final 预测未全选`。
       - **cmd**：沿用现行实跑与核对，环境加上两个新变量。
     - 删掉旧规则「没有选测命令却写了理由 → 删除」，「未声明」规则已覆盖它。
   - **`_scope_reason_errors(report, reasons, pending=())`**：新增 `pending` 参数，其中的键不算多余（本片调用方传空）。
   - **`lint_plan(…, phase="lint")`**：`cmd_preflight` 传 `phase="preflight"`；`waves` 与 `run_scope=False` 的直接调用不判未声明。
   - **新子命令 `scope-seed --openspec-root DIR`**（spec「声明判定可供安装器调用」）：
     - 递归收集 `DIR/changes/**/slices.json`；读不出的计为认不出；
     - 恒退出 0；
     - stdout 首行含「已种」/「未种」/「保留已有声明」；「未种」时列最多 3 个例子，并给出接入 `{"cmd": …}` 的指引（含 `gate-scope.json` 字样）；
     - 写文件内容为 `{"builtin": true}` 加换行。
2. **`template/.claude/hooks/spec_html.py`**：`render_scope` 恒输出「选测范围」小节（design D13），用一份与 D1 同口径的只读解析，不 import slice-gate：
   - cmd：命令原文 +「计划 gate.scope」或「仓库声明 gate-scope.json」；
   - builtin：「模板内建（builtin）」+ 来源；
   - 未声明：`<p class="placeholder">未声明选测范围</p>`，owns 匹配声明文件时加注「本 change 建立仓库选测声明」。
   - 有理由时照旧输出表格。
3. **测试基座**（design D12）：
   - **`tests/conftest.py`**：`git_repo` 在初始提交前写 `openspec/gate-scope.json` = `{"cmd": "printf '{\"full\": false, \"triggers\": []}' > \"$GATE_SCOPE_OUT\""}`，并在 docstring 写明用途。
   - **不用 `git_repo`、直接跑 lint 的用例**：`tests/test_slice_gate.py` 6 条、`tests/test_tiers_plan.py` 8 条、`tests/test_gate_checks_lint.py` 6 条，改为带 `{"builtin": true}`。推荐做法：
     - `write_plan` 在 change 目录的上一级名为 `changes`、且其上一级没有 `gate-scope.json` 时补写 builtin；
     - 不走 `write_plan` 的在各自 helper 里补；
     - ⚠ 不得往 change 目录不在 `<根>/changes/` 下的位置写（例如 `tests/test_slice_gate_baseline_preflight.py::test_lint_requires_gate_test` 用的 `tmp_path / "c"`，其上两级是共享的 pytest 临时根）。
   - **`tests/test_gate_scope_lint.py`**：按 v2 语义调整 `_repo` 与 `test_reason_without_scope_command_is_red`。未声明（删掉基座声明）+ 写了理由 → 判红，断言「未声明选测范围」；其余用例语义不变。
   - **`tests/test_spec_html_scope.py`**：`test_spec_html_shows_repo_default_scope` 的「仓库默认」改为「仓库声明」。
4. **解锁**：
   - 去掉 `tests/test_scope_contract_v2.py` 7 条与 `tests/test_spec_html_scope.py::test_spec_html_shows_provider_state` 的 xfail 标记；
   - `PENDING` / `PENDING_S1` 定义若不再使用一并删除；
   - MUST NOT 改断言与函数名。
