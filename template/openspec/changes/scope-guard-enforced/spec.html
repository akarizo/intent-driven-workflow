Why · 01为何而做

装上模板的仓库仍然可能没人知情地跑全量。2026-11-07 afa change export-xlsx-aparam-override 的 baseline 跑了 683.8 s，原因是门禁范围算成了 11343 条（单元 9416 + 集成 1927），集成层全选；直到 baseline 跑完才有人发现。S2、S3 计划改 executor/bin/*，所以 final 还会再全选一次。

起因是 afa 自己的选测器退化，但模板有 5 个断点，才让它变成「没人知情」。这 5 个断点对任何新装或升级的仓库都成立：

1. 安装器不种选测声明：install.sh:382 只种 .gitignore、config.yaml 和三个 .gitkeep，新装与 --upgrade 之后都没有 gate-scope.json。 2. 没有声明时 lint 静默跳过：slice-gate.py:1566 在没有命令时直接 return errors, None。afa 这次 lint 是绿的，审批页上什么也没有。 3. 契约看不到切片计划改的文件：slice-gate.py:1511 只给选测命令传 GATE_SCOPE_OUT。计划期只看得到 propose 时的 diff（骨架 + 登记表），看不到 owns 里将改的 bin。 4. baseline / final 开跑前不复核范围：slice-gate.py:3416 写完运行标记就直接跑 gate.test。lint 被跳过或计划后改，baseline 照样全量。 5. 模板内建增量自己也会退回全量：_full_why 有一条「Δ 含依赖图没见过的非 Python 文件 → 全量」（slice-gate.py:4294-4306）。bash 子进程 source 的文件测不到，工作流自己的声明文件（gate-scope.json、.claude/**）也会被算进去。这与 afa 的 executor/bin/* 是同一类错误。

用户要求（2026-11-07）：新装与升级都必须不再犯这个错误，目标是可靠的模板工作流。决策页 template/openspec/superpower/2026-11-07-scope-guard-enforced-decisions.html 共 Q1–Q9，用户全取推荐（grill-me 以该决策页完成）。

What · 02变更范围

  • 契约 v2：每个仓库必有选测提供方（BREAKING：「没有声明 → 静默跳过」改为「没有声明 → 红」）。
  • 提供方按优先级解析：计划 gate.scope > <openspec 根>/gate-scope.json > 未声明。
  • gate-scope.json 新增 {"builtin": true}（模板内建）一种形态，与 {"cmd": "..."} 二选一。
  • 未声明 → lint / preflight / baseline / final 红。唯一例外是本 change 自己建立声明（owns 含 gate-scope.json）：这时须为伪触发项 scope:undeclared 写理由，审批页标出。
  • builtin 配上认不出的 gate.test（不是 pytest、test-tiers 驱动或探测出的标准命令）→ 红，提示改用 cmd 提供方。
  • 计划文件交给提供方：新增 GATE_SCOPE_PLANNED（各片 owns 的并集，一行一条，glob 原样）和 GATE_SCOPE_CHANGE（change 目录的仓库相对路径）。计划期报告因此能覆盖 final 会改的文件。
  • 内建提供方（slice-gate.py 内置，不起子进程）：预测模板内建增量 final 会不会退回全量，包括全局文件、依赖图没见过的非 Python 文件、gate.test 无法等价复现、没有可用锚点。lint 用锚点池里最新的锚点预测；preflight 用刚跑完的基线锚点精确预测。非 pytest 运行器和部件形态的 final 本来就恒全量，属于设计边界：只注明，不要求写理由。
  • 运行期守卫：
  • baseline 开跑前复核范围：未表态的全选不跑 gate.test，基线红，不写运行标记。
  • final 开跑前复核：内建看 _full_why，cmd 重跑提供方。未表态 → 不跑测试，final 红。--full 是显式要求，豁免。
  • 理由以 approve 提交里的 gate.scope_full_reason 为准，批准后再改 → 红。
  • 内建精度：
  • 工作流声明文件（<openspec 根>/gate-scope.json、<openspec 根>/gate-checks.json、git 顶层 .claude/**）不再触发「依赖图没见过的非 Python 文件」这条全量规则。
  • 实测依赖里的 shell 脚本做静态闭包：source / . / 字面路径、$(dirname "${BASH_SOURCE[0]}") 及由它赋值的变量、文件名含变量时取整个目录的同后缀文件。闭包结果计入依赖，用于增量选中和全量判定。
  • 安装器：
  • 新装和 --upgrade 缺声明时都调用 slice-gate.py scope-seed。没有历史 change，或历史 gate.test 全部可识别 → 种 {"builtin": true}；否则不种，并在安装摘要醒目提示接入 cmd 提供方。
  • 已有声明不动，只打印出来。
  • 不新增参数、不交互（遵守 DRAFT-installer-versioned-with-template 决策 2）。
  • 文档：schema、/opsx-propose、/opsx-apply、/opsx-verify 及各自同名 skill、README 同步契约 v2。本仓库自己声明 template/openspec/gate-scope.json = {"builtin": true}。
  • 不变：gate.scope / gate.scope_full_reason 仍不进 plan_sha；报告形状 {full, triggers, count?}、300 秒上限、失败即红都不变；gate.impacted、部件形态 final 的判定不变。

Specs · 04行为规范 (Gherkin)

builtin-scope-precision ADDED

Requirement: 内建提供方在计划期预测 final 是否退化

Rule: 模板内建提供方的报告 SHALL 针对预测的 final Δ：tracked 文件中匹配任一切片 owns glob 的那些。报告的触发项取以下各条命中的全部，full = 有触发项。

- 全局文件：预测 Δ 里的全局文件（与增量 final 同一清单），触发项是该文件路径。 - 无法等价复现：gate.test 无法被增量 final 等价复现（pytest 之后带白名单外选项，且 gate.pytest 没配或没覆盖）时，触发项是 final:gate-test-unreproducible。 - 依赖图没见过的文件：预测 Δ 里现存的、依赖图（含 shell 静态闭包）没见过的文件，触发项是该文件路径。排除以下几类： - 测试文件； - .py 文件，与 final 一样只警告； - 文档； - 工作流声明文件。 - 锚点： - lint 用锚点池里命令指纹与分层指纹都匹配的最新锚点； - preflight 用当前树能取到的锚点，通常就是刚跑完的基线锚点； - lint 或 baseline 取不到锚点时，不报这一类触发项，而是把预测 Δ 里现存的、上述排除项以外的非 Python 文件列为待定。为待定项预写的理由不算多余；摘要注明「final 精确预测在 preflight」； - preflight 取不到锚点时，触发项是 final:no-anchor。 - 库外：不在 git 仓库里时，只做 gate.test 识别与全局文件检查。全局文件检查按 owns 条目的文件名判定；这种情况不会出现在真实仓库里。 - 基线缺逐用例记录：preflight 时基线有失败、但缺 failed_nodes，触发项是 final:baseline-missing-failed-nodes。

gate.test 不是 pytest（npm test、go test ./...、cargo test），或分层文件是部件形态时，final 恒全量属于设计边界：报告不全选，摘要注明「final 恒全量（设计边界）」。

Requirement: shell 静态闭包计入依赖

Rule: 一个测试文件的实测依赖里有 shell 脚本时（后缀 .sh / .bash，或首行 #! 指向 sh、bash、zsh、dash），库 SHALL 静态解析这些脚本，把解析到的仓库文件并入该测试文件的依赖。并入的结果既用于增量选中，也用于「依赖图没见过」判定。

解析规则： - 跳过注释行； - $(dirname "${BASH_SOURCE[0]}")、$(dirname "$0")、${BASH_SOURCE%/*}、${0%/*}（含引号变体）视为脚本所在目录； - 被赋予这些形式（含 $(cd … && pwd) 包裹）的变量，其引用 $V / ${V} 同样视为脚本所在目录； - 路径记号先按脚本所在目录解析，再按 git 顶层解析，只保留存在的仓库文件； - 文件名含未解析的 $、但目录能解析时，取该目录下同后缀的全部文件； - 新到达的 shell 脚本递归解析。

解析不到的引用不补依赖，现行规则照旧生效，即仍判全量。

scope-provider-contract ADDED

Requirement: 每个仓库必有选测提供方

Rule: 库 SHALL 按优先级解析选测提供方，取第一个存在的：计划 gate.scope（非空字符串，cmd 提供方，来源「计划 gate.scope」）> <openspec 根>/gate-scope.json（来源「仓库声明 gate-scope.json」）> 未声明。

gate-scope.json SHALL 是对象，并且恰含以下两个字段之一： - cmd（非空字符串）→ cmd 提供方； - builtin（只能是 true）→ 模板内建提供方。

两个都有、builtin 不是 true、或带其它字段时，slice-gate.py lint SHALL 退出非 0，违规行以 scope: 开头并点名问题。

未声明时，slice-gate.py lint、preflight、baseline、final SHALL 判红，提示写 {"builtin": true} 或 {"cmd": ...}。唯一例外是本 change 自己建立声明（任一切片 owns 的某条 glob 匹配 <openspec 根>/gate-scope.json 的仓库相对路径）：这时视为报告全选，触发项为伪触发项 scope:undeclared，gate.scope_full_reason SHALL 为它写理由；写了即通过，摘要点名「本 change 建立仓库选测声明」。slice-gate.py waves 不做这项核对。

Requirement: builtin 声明只用于普通测试命令

Rule: gate-scope.json 是 {"builtin": true} 时，模板内建提供方 SHALL 在进程内给出报告，不起子进程。

gate.test SHALL 是可识别的普通测试命令，即满足以下任一条： - 能切出 pytest 前缀（与增量 final 的识别同一口径）； - 是 test-tiers 驱动 python3 <路径>/test-tiers.py run unit； - 等于测试命令探测的产出之一：npm test、go test ./...、cargo test。

否则 lint SHALL 判红，提示自带选测的仓库改用 {"cmd": ...}。核对通过时，lint 的 stderr 摘要行 SHALL 写明「模板内建」。

Goals: - I1：每个 change 在 lint、preflight 都有一份范围报告，覆盖 baseline 与 final，包括计划要改的文件。 - I2：全选必须逐个触发项写理由，显示在审批页；「未声明」本身就红，不再静默。 - I3：baseline 与 final 开跑前机械复核，未表态的全选不跑、判红；批准后改理由无效。 - I4：工作流声明文件不会单独导致全量；被 source 的 shell 文件按依赖选中，不再触发全量。 - I5：新装与升级都由安装器种好声明；种不了的，醒目提示，并由 lint 兜底。

[预测与实际不一致] → owns 是写入上限，预测偏保守；preflight 用新鲜锚点再算一次；final 复核兜底，真不一致时停下判红，不先付出全量的代价。
