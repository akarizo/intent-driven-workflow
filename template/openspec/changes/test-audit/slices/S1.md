# S1 · test-ledger.py：全量超线清单 violations()

## 做什么

给 `template/.claude/hooks/test-ledger.py` 加一个纯函数 `violations(ledger, budgets, scope_of, allow=None)`，返回账本里**全部**超线用例。规则原文见 `specs/test-audit/spec.md` 的「账本里的超线用例清单」，取舍见 `design.md` D4。

`budget()` 只给门禁要的那几条（每类至多 5 条、只判 `m == 1`、不判单元层单条），体检要全量，所以另开一个函数；但线的取法必须是同一处代码。

## 怎么做

TDD：`tests/test_audit_core.py` 的 4 条骨架现在是红的（`AttributeError: … has no attribute 'violations'`）。

1. 在预算那一段（`budget()` 附近）抽一个小函数，例如 `_case_line(spec, a) -> (线 | None, "allow" | "budget")`：
   - `a`（`allow_view` 里的一条）存在且 `not a.get("expired")` → `(a.get("limit"), "allow")`；
   - 否则 → `(spec.get("case_sec"), "budget")`。
2. `budget()` 里现在的三行
   ```python
   case_sec, a = spec.get("case_sec"), amap.get(cid)
   via_allow = bool(a) and not a.get("expired")
   line = a.get("limit") if via_allow else case_sec
   ```
   改成经 `_case_line` 取 `line` 与 `via_allow`（`via_allow = by == "allow"`）。`case_sec` 这个局部变量后面还在用，保留。**返回值与每一条文本都不许变**：`tests/test_budget_core.py` 的 11 条是守卫。
3. `violations`：
   - `form = ledger.get("id_form") or "nodeid"`；`form == "junit"` 时把 `allow` 的键用 `_to_junit` 换算（与 `budget()` 里的 `amap` 同一写法）；
   - 遍历 `ledger["cases"]`：`s = c.get("s")`、`sc = scope_of(cid, c.get("t"))`；`s is None` 或 `sc not in budgets` → 跳过；**不看 `m`**；
   - `line, by = _case_line(budgets[sc], amap.get(cid))`；`line is None` → 跳过；
   - 超线：`budgets[sc]["kind"] == "unit" and by == "budget"` 时 `s >= line`，其余 `s > line`；
   - 命中 → `{"case": cid, "scope": sc, "kind": budgets[sc]["kind"], "sec": s, "line": line, "by": by}`；
   - 按 `(-sec, case)` 排序返回。不截断。
4. 文件头注释里补一句 `violations` 的用途（体检用的全量清单）。

## 注意

- 纯函数：不读文件、不取时间、不 import 新模块。
- 单元层的 `>=` 是为了与 G10 一致（`slow_candidates` 用的是 `>= case_sec`）；带有效放行时比的是放行上限，用 `>`（与 `_slow_verdict` 的 `took > v["limit"]` 一致）。
- 骨架复用 `tests/test_budget_core.py` 里的 `allowed` / `budgets` / `case` / `ledger` / `scope_of`，不要改那个文件。
