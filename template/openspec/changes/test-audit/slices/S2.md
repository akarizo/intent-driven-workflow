# S2 · test-tiers.py audit：数据来源、归层与十个不合规类别

## 做什么

给 `template/.claude/hooks/test-tiers.py` 加只读子命令 `audit` 的主体：读分层文件、测试文件清单、一份测量（账本 ∪ 探针结果），按当前工作树重新归层，列出十个不合规类别，输出 JSON，有不合规项退出 1。规则原文见 `specs/test-audit/spec.md` 的「体检的数据来源与归层」「体检的不合规类别」，取舍见 `design.md` D2–D5。

未判、退出码 3、文本明细、筛选与前后对比是 S3 的事；本片先把 JSON 骨架与不合规类别做对。

## 依赖的接口

见 `slices/_interfaces.md`。

- S1 `test-ledger.py`：`violations(ledger, budgets, scope_of, allow)`；另用现有的 `budget()`（取 `totals` 与 `allow`）、`load` / `ledger_dir` / `PHASES` / `_file_of` / `_to_junit` / `NO_SEC_RATIO`。按 `_load("test-ledger")` 加载（同文件里加载 `slice-gate` 的写法）。
- `slice-gate.py`（已加载为 `sg`）：`tier_budgets` / `budget_scope_of` / `allow_view` / `tiers_matching(path, tiers, top)` / `tiers_is_parts` / `TEST_FILE_RE` / `TIER_TEST_NAME_RE` / `is_canary` / `parts_of` / `now_iso` / `git` / `toplevel` / `UNIT_MAX_SEC`。

## 怎么做

TDD：`tests/test_audit_scan.py` 的 9 条骨架现在是红的（`invalid choice: 'audit'`）。

1. **常量 `AUDIT_RULES`**：16 个类别一次定全（含 S3 才产出的提示与 `unjudged`），形状与每类的 `rule` / `level` / `fix` 见 `_interfaces.md` 与 spec 的表。S7 的对账测试会拿它对文档。
2. **把 `check` 的判据抽成一个函数**，返回结构化结果，例如 `(恰落一层的测试文件 {路径: 层}, [(路径, 文本)])`：
   - 简写形态：`TEST_FILE_RE` 命中的文件按 `tiers_matching` 判，文本就是现在的「未归层：…」「匹配多层：…（…）」；
   - 部件形态：沿用 `check_parts` 的判据与文本（「不属于任何部件：…」「属于多个部件：…」等）；
   - `cmd_check` 改为调用它，**打印与退出码一字不变**（`tests/test_tiers_cli.py`、`tests/test_tiers_parts_cli.py` 是守卫）。
3. **参数**（本片先接这些；`--scope` / `--category` / `--top` / `--compare` / `--plan` 的解析可以先加上，行为留给 S3）：`--openspec-root`、`--change-dir`、`--ledger`、`--no-ledger`、`--probe`（`action="append"`）、`--json`、`--out`。
4. **选账本**：`--no-ledger` → 无；`--ledger PATH` → 读它（不是含 `cases` 的对象 → `fail`，退出 2）；`--change-dir DIR` → 目录不存在 `fail`，否则依次 `load(top, <目录名>, "final")`、`"baseline"`；都没给 → 遍历 `ledger_dir(top)` 下每个子目录的两份文件，取 `at` 最大的；取不到 → 无。
5. **没有分层文件**：`items` 只放一条 `no-tiers`（文本含 `/test-tiers`），`form = "none"`，`scopes = {}`，不再往下。分层文件存在但不合法 → 沿用 `load_tiers` 的 `fail`（退出 2）。
6. **用例表**（`{用例 id: {"s", "t", "hits", "file"}}`）：
   - 账本的每条用例：`nodeid` 形式取 `::` 之前作文件，`junit` 形式用 `_file_of(cid, form, top)`；
     - 文件存在 → 层 = `(tiers_matching(文件, tiers, top) or [None])[0]`；
     - 像路径（含 `/` 或带扩展名）但不存在 → 丢弃，`source.dropped += 1`；
     - 定不出文件 → 层取账本里记的 `t`，`file = None`；
     - `hits = None`（账本不知道触碰）。
   - 每份探针结果的 `tests`：键在账本是 `junit` 形式时用 `_to_junit` 换算；同样按文件重新归层；`s = sec`、`hits = rec["hits"]`（可能是空字典）；覆盖账本里的同名条目。探针结果不是含 `tests` 的对象 → `fail`。
7. **判定**（都不新造判据）：
   - `budgets = sg.tier_budgets(tiers)`、`scope_of = sg.budget_scope_of(tiers)`、`aview = sg.allow_view(tiers.get("slow_allow") or {})`；
   - 把用例表包成账本形状 `like = {"cases": {cid: {"s", "t", "m": 1}}, "id_form": form, "complete": True, "mode": "full"}`；
   - `violations(like, budgets, scope_of, aview)` → `kind == "unit"` 记 `unit-slow`，否则 `region-slow`；条目带 `sec` / `line` / `scope` / `case` / `file`；
   - `b = budget(like, None, budgets, scope_of, aview, "baseline")` → `totals` 填 `scopes`（另算 `p50` / `p95` / `max`，最近秩即可），`over` 为真的范围记 `total-over`（文本写出合计与预算）；`rep["allow"] = b["allow"]`；
   - `layering`：第 2 步返回的每个问题一条，键是文件路径，文本原样；
   - `no-case-limit`：`budgets` 里 `kind == "region"` 且 `case_sec is None` 的范围；
   - 放行（遍历 `aview`，每条只归最靠前的一类）：
     1. 键的首段像路径、不是部件名、且文件不存在 → `allow-stale`；
     2. `expired` → `allow-expired`；
     3. `limit` 或 `expires` 为空 → `allow-unbounded`（文本写缺哪个）；
     4. 否则 `soon` → `allow-soon`（提示，本片就做）；
   - 探针相关（给了 `--probe` 才判）：用例表里 `hits` 非空且所在范围 `kind == "unit"` → `unit-impure`（文本带第一类触碰的样例）；区域文件里有 `hits == {}` 且耗时低于单元层线的用例 → 每个文件一条 `pure-in-region`（提示）；没给探针 → 一条 `purity-unchecked`（提示）。
8. **结论与输出**（本片的最小版）：`counts` 按级别与类别数；有 `violation` → `verdict = "violations"`、退出 1；否则 `"compliant"`、退出 0（S3 会在两者之间插进 `unjudged` / 3）。`--json` 打印一个 JSON 对象；`--out` 写同一个对象；不带 `--json` 时至少打印首行与结论行（S3 补全文本）。
9. `main` 里注册子解析器与 handler；文件头的子命令说明与退出码说明各补 `audit`。

## 注意

- 体检**不取全机测试锁**（不跑测试），也不写分层文件、不写账本。
- 部件形态：`budget_scope_of` 返回的单元层范围名是 `<部件>/unit`；`tiers_matching` 在部件形态下要传 `top`。骨架 `test_audit_works_for_parts_form` 用的是只有一个 pytest 部件、没有区域的分层文件。
- 账本夹具写在 `<仓库>/.git/flight-ledger/c/final.json`，用例文件由夹具建好（`missing` 里的故意不建）。
- `test_audit_without_tiers_file_points_to_test_tiers` 断言 `items` **恰好一条**：没有分层文件时不要再附加提示或未判。
- `test_audit_flags_allow_entries` 里快到期的那条断言「只有 `allow-soon` 一条」：它 5.0 秒、放行上限 10 秒，既不超线也不算「已不需要」。
- 行数不少，但都是把现成函数接起来；propose 期在一次性副本上按上面的步骤写过原型，9 条骨架与相邻的 `test_tiers_cli` / `test_tiers_parts_cli` / `test_budget_core` 等 39 条都绿。
