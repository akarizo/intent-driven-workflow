# S3 · test-tiers.py audit：未判、结论、筛选与前后对比

## 做什么

在 S2 的 `audit` 上补齐：两类还没做的提示、三种「未判」、三态结论与退出码 3、完整的文本输出、按范围 / 类别 / 最慢 N 条筛选、`--compare` 与 `--plan`。规则原文见 `specs/test-audit/spec.md` 的「体检的提示、未判与结论」「体检的输出与筛选」「体检前后对比」，取舍见 `design.md` D5、D9。

## 依赖的接口

S2 已有：用例表、`budgets` / `scope_of` / `aview`、`b = budget(...)` 的 `totals`、恰落一层的测试文件清单、`AUDIT_RULES`（16 类已定全）、JSON 骨架。见 `slices/_interfaces.md`。

## 怎么做

TDD：`tests/test_audit_verdict.py` 的 4 条与 `tests/test_audit_compare.py` 的 4 条骨架现在是红的。

1. **提示补两类**：
   - `allow-unneeded`：未过期、有上限有期限的放行，对应用例在用例表里有耗时，且已回到线内（单元层 `s < case_sec`，区域 `s <= case_sec`）→ 一条提示，键是放行的键；
   - `gwt-missing`：对恰落一层的 Python 测试文件调 `sg.gwt_violations(top, 文件清单)`，条数大于 0 时出一条，带 `"count": N`，键为空串。只计数。
2. **未判**：
   - 既没有账本也没有探针 → `unjudged:no-measure`，并且不再出按范围的未判；
   - 来源账本 `complete` 为假或 `mode == "impacted"` → `unjudged:ledger`；
   - 按范围：恰落一层的测试文件里，没有任何用例表条目落在它上面的 → 归到它的范围（`scope_of(路径 + "::x", 层)`）；某范围有这样的文件 → `unjudged:scope:<范围>`，文本带个数与一个例子路径；另外该范围 `no_sec / cases > NO_SEC_RATIO` 也记未判；
   - 范围里有 `file is None` 的用例（定不出文件）→ 该范围不做「文件没有测量」这一项；
   - 未判的范围（以及有 `unjudged:ledger` 时的全部范围）**不出 `total-over`**；单条超线照常。
3. **结论与退出码**：`violations`（1）> `unjudged`（3）> `compliant`（0）。
4. **筛选**（顺序：范围 → 类别 → 计数与结论 → 截断）：
   - `--scope`（可重复）：只留 `scope` 在其中的条目，`scopes` 也只留这些范围；没有 `scope` 的条目（`layering`、`gwt-missing` 等）在给了 `--scope` 时不出现；
   - `--category`（可重复）：只留该类别；
   - `counts`、`verdict`、退出码按此时的条目算；
   - `--top N`：每个类别至多留前 N 条。排序：级别（不合规 → 未判 → 提示）、类别、耗时由大到小、id。
5. **文本输出**（不带 `--json`）：
   - 首行 `测试体检：不合规 N 条 · 提示 N 条 · 未判 N 项`；
   - 一行测量来源（change · 阶段 · commit 前 10 位 · 时间 · 模式；探针 N 份；丢弃 N 条）或「没有测量」；
   - 每个类别一个小节（标题带类别名、中文名、条数、规则号），每条一行；
   - 每个范围一行（用例数、合计、单条上限、总量预算、p50 / p95 / 最慢）；
   - 末行恰为 `结论：合规` / `结论：不合规` / `结论：判不全`。
6. **`--compare` 与 `--plan`**：
   - `--plan` 没有 `--compare` → `fail`（退出 2）；`--compare` 的文件读不了、不是含 `items` 数组的对象 → 退出 2（`read_json` 的失败本来就是 2）；
   - `was` = 之前那份里 `level == "violation"` 的 id；`now` = 这一次筛选后、截断前的不合规 id；
   - `compare = {"before": {"at", "head"}, "resolved": 排序后的 was − now, "remaining": was ∩ now, "new": now − was, "targets": 目标数, "targets_remaining": 目标 ∩ now}`；
   - 目标 = 整改稿 `items` 里 `action != "keep"` 且 id 在 `was` 里的条目；
   - 退出码改为：`new` 或 `targets_remaining` 非空 → 1；否则有未判项 → 3；否则 0；
   - 文本多一行 `前后对比：已解决 N 条 · 仍在 N 条 · 新增 N 条`，新增与未解决的目标逐条列出；这时末行改为 `结论：整改达标` / `结论：整改未达标` / `结论：未能确认（有未判项）`。
7. 文件头的 `audit` 说明补全参数与退出码（含带 `--compare` 时的含义）。
