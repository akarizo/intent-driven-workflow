# S5 · test-audit.py verify：整改护栏

## 做什么

给 `template/.claude/hooks/test-audit.py` 加 `verify`：命令内的整改做完之后，对着工作树相对 `--base` 的 git 改动核对四条护栏。规则原文见 `specs/test-audit/spec.md` 的「整改护栏」，取舍见 `design.md` D8。

## 依赖的接口

S4 已建好文件骨架（`_load`、`fail`、`read_json`、`main`、`ACTIONS`）。整改稿形状见 `slices/_interfaces.md`。

- `slice-gate.py`（`sg`）：`toplevel` / `git(root, *args)`（失败抛 `RuntimeError`）/ `TIER_FILE` / `TIER_TEST_NAME_RE` / `glob_match(path, pattern)` / `_load_tiers_file(path)` / `_tiers_at(root, commit, 分层文件绝对路径)`（当时没有或不合法 → `None`）/ `_tier_regions(tiers)`（`{区域名: (部件, 区域)}`，简写与部件形态都可用）/ `tier_budgets(tiers)`。
- `test-ledger.py`（同法按路径加载）：`budget_changes(old_budgets, new_budgets, old_allow, new_allow) -> [str]`。文本形如 `hooks 总量预算 100s → 200s（放宽）`、`放行新增 <键>（上限 … · 到期 …）`、`放行移除 <键>`、`放行改动 <键>：…`。

## 怎么做

TDD：`tests/test_audit_verify.py` 的 5 条骨架现在是红的（没有 `verify` 子命令）。

`verify --plan P --base COMMIT [--openspec-root DIR] [--json]`：

1. **输入**：读整改稿（读不了 → 退出 2）；`git cat-file -e <base>^{commit}` 不成立 → `fail`「--base … 不是本仓库的 commit」（退出 2）。
2. **改动清单**：`git diff --name-only --no-renames <base>`（工作树对基线，含已暂存与未暂存）并上 `git ls-files --others --exclude-standard`。用 `--no-renames`，搬动的文件新旧两个路径都在清单里。
3. **逐个路径归类**（顺序即优先级）：
   1. 就是分层文件 → 记 `changed.tiers = True`，不参与下面几项；
   2. 在 openspec 根之下 → 跳过（工作流自己的记账，如 `.mini-active`、审批页）；
   3. `sg.TIER_TEST_NAME_RE` 命中 → 测试文件；
   4. 命中任一区域 `covers`（基线与当前两版分层文件的区域都算）→ 违反「改了被测代码：<路径>」；
   5. 命中稿的 `support` 任一 glob → 记进 `changed.support`；
   6. 其余 → 违反「稿外的改动：<路径>」。
   - 第 4 步排在第 5 步之前：`support` 不能豁免被测代码。
4. **用例与断言不变**（测试文件里的 `.py`）：
   - 基线一侧的内容用 `git show <base>:<路径>`（当时没有 → 空），当前一侧读工作树（文件已删 → 空）；
   - 每一侧 `ast.parse` 后收集测试函数：模块顶层与 `Test*` 类里名字以 `test` 开头的函数（含 `async def`），名字记作 `函数名` 或 `类名.函数名`；
   - 每个函数的签名 = (参数化装饰器的 `ast.dump` 排序元组, 断言的 `ast.dump` 排序元组)；参数化装饰器 = `ast.dump` 里含 `parametrize` 的装饰器；断言 = `ast.Assert`，以及调用名（`Attribute.attr` 或 `Name.id`）以 `assert` 开头或等于 `raises` / `warns` 的 `ast.Call`；
   - 把所有改动的测试文件两侧各并成 `{名字: [签名…]}` 后比较：
     - 一侧条数多 → 「用例消失：<名字>」或「用例新增：<名字>」；
     - 条数相同但签名不同 → 参数化那一半不同记「参数化有改动：<名字>」，断言那一半不同记「断言有改动：<名字>」（两半都不同就两条）；
   - 任一侧 `SyntaxError` → 该路径进 `unchecked`，不参与比较；
   - 非 `.py` 的测试文件 → 进 `unchecked`。
5. **分层文件的改动与稿一致**：
   - `old = sg._tiers_at(top, base, 分层文件路径)`，`new = sg._load_tiers_file(路径)[0]`；任一为 `None` 时把它当空（预算 `{}`、放行 `{}`）；
   - `budget_changes = tl.budget_changes(tier_budgets(old), tier_budgets(new), old 的 slow_allow, new 的 slow_allow)`，恒输出；
   - 稿里各去向的键：`{id.split(":", 1)[1] for id, x in items if x["action"] == 去向}`；
   - 逐范围调 `budget_changes({范围: 旧}, {范围: 新}, {}, {})`：含「放宽」的行，而该范围不在 `budget` 去向的键里 → 违反「稿外的预算放宽：<那一行>」；
   - 逐放行键调 `budget_changes({}, {}, {键: 旧} 或 {}, {键: 新} 或 {})`：有行时，键被删掉需在 `drop-allow` 的键里，新增或改动需在 `allow` 的键里；否则违反「稿外的放行改动：<那一行>」。
6. **输出**：`--json` → `{"ok": 没有违反, "violations": [...], "unchecked": [路径…], "changed": {"tests": 测试文件数, "support": [...], "tiers": bool}, "budget_changes": [...]}`；否则逐行打印违反、未核对（行里写「未核对」）、预算与放行变动，末行「护栏通过」或「护栏未过」。退出码 0 / 1。

## 注意

- `test_verify_flags_source_changes`：`src/a.py` 命中区域 `hooks` 的 `covers`（`src/**`），稿的 `support` 也写了 `src/**`——仍然要报「改了被测代码」；`tests/conftest.py` 不是测试文件（内置命名不认它），靠 `support` 放行并出现在 `changed.support`。
- `test_verify_flags_unplanned_budget_and_allow_changes` 断言第一次的 `violations` **恰好 3 条**：一条预算放宽（行里有「放宽」与 `hooks`）、一条放行新增、一条放行移除；第二次稿里用 `total-over:hooks` / `unit-slow:<键>` / `allow-stale:<键>` 三个条目分别对上。
- `test_verify_passes_pure_moves`：`changed.tests` 为 2（原文件被改、新文件未跟踪）。
- `test_verify_lists_non_python_files_as_unchecked`：`unchecked` 是路径数组；新增的 `web/a.test.ts` 是测试文件（内置命名认 `*.test.*`）。
- 兼容 Python 3.8：`ast.dump` 缺省不带行号，直接比字符串即可；不要用 `ast.unparse`。
- 不跑任何测试，不取锁。复测由命令文档里的复核步骤（`probe` + `audit --compare --plan`）承担。
- propose 期的原型按上面的步骤实现，5 条骨架在一次性副本上全绿。
