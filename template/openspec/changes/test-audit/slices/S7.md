## 怎么做

TDD：`tests/test_audit_docs.py` 的 3 条骨架现在是红的。

1. **`template/.claude/commands/test-audit.md`**（命令本身即逻辑，**无同名 skill**；写法照 `test-tiers.md`）：
   - frontmatter：`description:` 一行，例如「体检测试套件离合规标准多远，并把不合规项改到合规：体检 → 整改稿 → 审批页等人类批准 → 按轨道处置 → 复核」；
   - 开头两三句：它管什么（从有分层文件到合规）、不管什么（建层走 `/test-tiers`）、判据在哪（契约文档「测试套件合规标准」一节）；
   - **Steps**：
     1. **体检并存档**：`python3 .claude/hooks/test-tiers.py audit --out <存档路径>`；说明四个退出码；没有分层文件 → 停下，让人先跑 `/test-tiers`；有「未判」→ 先取测量（任一在途 change 跑过 baseline 即有账本；或 `python3 .claude/hooks/test-tiers.py probe --cmd "<该层命令>" --json <文件>` 后带 `--probe` 重新体检）；大仓库用 `--scope` / `--category` / `--top N` 取一批；
     2. **起草整改稿**（JSON，形状见契约文档与本文件里的例子）：每条不合规项从它的 `fix` 里选一个去向或 `keep`（写理由）；搬与拆写 `dest`；要改分层文件时给出 `tiers`；随迁的非测试文件（`conftest.py`、`__init__.py`、测试数据）写进 `support`；依据是体检条目、探针证据与被测模块，不凭文件名猜；
     3. **渲染审批页并停下**：`python3 .claude/hooks/test-audit.py render --audit <存档> --plan <整改稿> --out openspec/superpower/<YYYY-MM-DD>-test-audit-plan.html`；退出 1 → 按 stderr 改稿重渲；退出 0 → 打印审批页的绝对路径，**停下等人类批准**，未获批准不进入下一步；
     4. **按轨道处置**：
        - 命令内执行（`move` / `split` / `retier` / `budget` / `drop-allow`）：先 `/opsx-mini "测试整改：只搬 / 拆测试与改分层文件，不改被测代码与断言; 范围: <测试目录>, openspec/test-tiers.json"`；记下此刻的 `git rev-parse HEAD` 作基线；整文件用 `git mv`，拆用例时原样剪切、保留 GWT 注释，**不改断言**；
        - 交人放行（`allow`）：不代写；请人类在对话里写明放行哪个用例及理由，再运行 `python3 .claude/hooks/test-tiers.py allow-slow <nodeid> --reason … --limit-sec … --expires …`（判据见 `test-tiers.md`「放行慢单测」）；
        - 转 change（`speedup` / `purify` / `delete`）：不在本命令里动手；把这些条目（id、现状、建议方向）整理成清单交给人，由人发 `/opsx-propose`；那个 change 的验收可以直接用第 5 步的对比命令；
     5. **复核**（全部满足才算完成）：
        - `python3 .claude/hooks/test-audit.py verify --plan <整改稿> --base <第 4 步记下的 commit>` 退出 0；「未核对」的文件逐个请人看 diff；
        - `python3 .claude/hooks/test-tiers.py check` 退出 0；
        - 对动过的层重新取测量：`python3 .claude/hooks/test-tiers.py probe --cmd "<该层命令>" --json <文件>`（它持全机测试锁；部件形态带 `--root` / `--adapter`）；
        - `python3 .claude/hooks/test-tiers.py audit --probe <文件> --compare <第 1 步的存档> --plan <整改稿>`：退出 0 = 本轮目标都已解决且没有新增；1 = 有目标没解决或改出了新的不合规；3 = 未能确认（还有没量到的范围）；
     6. **收尾**：`/opsx-mini --done`；汇报已解决 / 仍在 / 转 change 的条数与清单；**不代 commit**，由人类提交。
   - 文末两小节：「三条轨道」一张表（去向 → 轨道 → 谁来做）；「不做的事」（不改被测代码、不改断言、不删用例、不代写放行、不代 commit）。
   - 骨架按子串断言正文里有：`test-tiers.py audit`、`--out`、`test-audit.py render`、`test-audit.py verify`、`--compare`、`--plan`、`test-tiers.py probe`、`allow-slow`、`/opsx-mini`、`/opsx-propose`、「等人类批准」「不改断言」「不代 commit」「无同名 skill」。
2. **`README.md`**：
   - 两处「17 个 slash 命令」改成「18 个 slash 命令」（目录树注释一处、二级标题一处）；
