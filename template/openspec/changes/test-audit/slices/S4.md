# S4 · test-audit.py render：整改稿校验与审批页

## 做什么

新建 `template/.claude/hooks/test-audit.py`，先做 `render`：读体检 JSON 与整改稿，逐条校验，按去向归轨道，写单文件审批页。规则原文见 `specs/test-audit/spec.md` 的「整改稿审批页」，取舍见 `design.md` D6、D7。

`verify` 是 S5 的事；本片把文件骨架（按路径加载、`fail`、`read_json`、`main`）搭好，S5 往里加一个子命令。

## 依赖的接口

没有切片依赖。输入的体检 JSON 形状见 `slices/_interfaces.md`（本片只用 `items` 里每条的 `id` / `category` / `level` / `fix` / `sec` / `line`），骨架里是手写的夹具，不需要 `test-tiers.py audit` 已经存在。

`slice-gate.py`（按路径加载，写法照抄 `test-tiers.py` 开头的 `_load`）：`toplevel` / `TIER_FILE` / `_load_tiers_file(path)` / `tiers_matching(path, tiers, top)` / `tier_budgets(tiers)`。

## 怎么做

TDD：`tests/test_audit_render.py` 的 4 条骨架现在是红的（脚本文件不存在）。

1. **文件头**：注释写明两个子命令、退出码（0 无问题 / 通过；1 有问题 / 有违反；2 输入读不了），「兼容 Python 3.8+，只用标准库」。
2. **常量 `ACTIONS`**（去向 → 轨道），十个去向，见 `_interfaces.md`。S7 的对账测试会拿它对文档。
3. **`render --audit A --plan P --out H [--openspec-root DIR]`**：
   - 读两个 JSON；体检须是含 `items` 数组的对象、整改稿须是对象，否则 `fail`（退出 2）；
   - **目标分层文件**：稿里有 `tiers` → 写到临时文件后用 `sg._load_tiers_file` 校验（不合法 → 记一条问题「稿里的分层文件不合法：…」）；没有 → 读现行分层文件（`--openspec-root` 或 `<顶层>/openspec`），可能为 `None`；
   - **逐条校验**（稿的 `items`，按 id 排序；每个问题一行，行里带条目 id）：
     | 情形 | 问题文本要点 |
     |---|---|
     | id 不在体检结果里 | 「稿里的条目不在体检结果里」 |
     | `action` 不是已知去向，或不是 `keep` 且不在该条目的 `fix` 里 | 「去向 X 不适用于 <类别>（可选：…）」 |
     | `keep` 没写 `note` | 「保留须写理由」 |
     | `move` / `split` 没写 `dest` | 「缺目标」 |
     | `dest` 按目标分层文件命中 0 层 / 多层 | 「落点 … 未归层」/「落点 … 匹配多层（…）」 |
     | `unit-slow` / `unit-impure` 的 `dest` 命中 `unit` | 「落点 … 仍在单元层」 |
     | `pure-in-region` 的 `dest` 没命中 `unit` | 「落点 … 不在单元层」 |
     | `budget` 而稿里没有 `tiers` | 「去向 budget 须在稿里给出 tiers」 |
     | `no-case-limit` 的区域在稿的 `tiers` 里仍没有 `case_sec` | 「…仍没有 case_sec」 |
   - **轨道计数**：去向合法的条目按 `ACTIONS[action]` 计入 `mechanical` / `human` / `change` / `keep`；`unplanned` = 体检里 `level == "violation"` 而不在稿里的条目数；
   - **审批页**（单文件、内联样式，形态照 `test-tiers.py` 的 `PAGE`）：标题「测试整改稿审批」；问题清单；一行轨道汇总，文本形如 `命令内执行 N 条 · 交人放行 N 条 · 转 change N 条 · 保留 N 条 · 未安排 N 条`；明细表每条一行（勾选框 `<input type="checkbox" checked>`、条目 id、类别、现状「秒 / 线」、去向、目标、轨道、备注）；批注框；「导出 Markdown」「复制」两个按钮，导出文本里每条带勾选结果；所有来自输入的文本经 `html.escape`；
   - 问题逐条写 stderr；stdout 打印一行 JSON `{"tracks": {...}, "problems": N, "out": 路径}`；有问题退出 1（页面照写），否则 0。
4. `main`：`argparse` 子命令 `render`；`if __name__ == "__main__": sys.exit(main())`。

## 注意

- `test_render_checks_move_destinations` 按行断言 stderr：点名的那一行里要同时有条目 id 与「仍在单元层」/「未归层」；没问题的那条 id 不能出现在 stderr 的任何一行里。
- `test_render_lists_unplanned_violations` 断言页面里有「未安排 2 条」这几个字（中间有空格），stdout 的 `tracks.unplanned` 为 2。
- `test_render_writes_approval_page_with_tracks` 断言页面里 `type="checkbox"` 至少出现 4 次、有「导出 Markdown」。
- 模型不逐字写 HTML 的意思是页面由本脚本生成；脚本里的模板字符串照常写。
- 不要从 `test-tiers.py` import：它在加载时会连带加载 `takeoff-gate.py`，本脚本用不上。
- propose 期的原型按上面的步骤实现，4 条骨架在一次性副本上全绿。
