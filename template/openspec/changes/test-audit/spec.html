Why · 01为何而做

test-ledger（C5a）让每次门禁留下逐用例耗时，tier-budgets（C5b）给每层立了线与放行期限。但这些只在飞行经过时才判，而且只判「这次变更有没有让它更坏」：

- 存量没人问。集成层的老债在门禁里只警告，放行到期前没人看，区域没写上限就一直不设线。标准立了，没有一条命令能回答「现在整个套件离标准差多少」。 - 体检是一次性的手工活。2026-11-18 那次 afa 测试体检用了 15 个临时脚本，数字对了一轮才出报告，下一次还得重来。 - 「改到合规」没有路。/test-tiers 只管第一次划分。之后发现单元层混进了慢用例、区域里有该下沉的纯用例、放行过期，怎么改、谁能改、改完怎么证明没改坏，都没有约定。

2026-11-18 用户在方案页 docs/flight-fixes-and-test-governance.html 第 04 节末尾（C6）提出：「提供一个命令能够自检当前不合规的用例然后变成我们要求的标准设计」。本 change 是该页最后一项，范围与取舍来自方案页与主会话的拆分指令，没有另开 grill-me 访谈；与方案页不一样的地方、需要人类拍板的地方都列在下面与 design 的 Open Questions。

What · 02变更范围

  • 标准有明文：运行器契约新增一节「测试套件合规标准」——八条规则 R1–R8，每条的判据、数据来源、不合规时的类别名与可选去向。体检按它判，整改以它为目标。
  • 体检（test-tiers.py audit，零 token，只读）：
  • 读分层文件、测试文件清单与一份测量（本机最新的测试账本，可叠加 test-tiers.py probe --json 的结果），不跑测试；
  • 列出十类不合规项：没有分层文件、归层有问题、单元层不纯、单元层超线、区域没写单条上限、集成区域超线、层总量超预算、放行指向的文件已不存在、放行已过期、放行缺上限或期限；
  • 另列五类提示（不影响结论）与「未判」（没有测量、测量不全的范围）；
  • 文本或 JSON 输出；可按范围、按类别、按最慢 N 条取子集；--out 存档；
  • 退出码：0 合规，1 有不合规项，3 没有不合规项但有判不了的范围，2 输入不可用。
  • 前后对比（test-tiers.py audit --compare <之前的存档> [--plan <整改稿>]）：已解决 / 仍在 / 新增；整改稿里排进本轮的目标没解决或出现新增即失败。
  • 整改稿审批页（test-audit.py render）：模型逐条提去向，脚本校验（去向是否适用、落点是否恰落一层、是否仍在原层）并按去向归到三条轨道，写出带勾选框与导出按钮的单文件 HTML，停下等人类批准。
  • 整改护栏（test-audit.py verify）：命令内的整改做完后，脚本对着 git 改动核对四条——没动被测代码与稿外文件、用例与断言没变（Python 测试文件按语法树比）、分层文件里预算与放行的改动都在稿里、核对不了的文件如实列出。
  • 命令 /test-audit（命令本身即逻辑，无同名 skill）：体检存档 → 起草整改稿 → 渲染审批页并停下 → 按轨道处置 → 复核。slash 命令数从 17 变 18。
  • 整改分三条轨道（design D6、ADR 草案 DRAFT-test-remediation-tracks）：
  • 命令内执行：只搬、只拆、只改分层文件、只删失效放行。沿用 /test-tiers 的做法——/opsx-mini 留痕、审批页、人类批准，再加护栏脚本；
  • 交人放行：放行与补上限、期限只能由人类原话经 test-tiers.py allow-slow 写入，命令不代写；
  • 转 change：要改用例实现的（提速、改纯、删用例）不在命令内动手，整理成清单交 /opsx-propose 另立 change，走起飞批准与独立评审。
  • test-ledger.py 新增纯函数 violations()：返回账本里全部超线用例。budget() 只给门禁要的那几条明细（每类至多 5 条、只判本次实测、不判单元层单条），体检要的是全量；线的取法抽成一处，两个函数共用，budget() 的结论与文本不变。
  • 体检不止挂在 test-tiers.py 上。体检子命令 audit 仍在 test-tiers.py（方案页如此）；整改稿渲染与护栏放进新文件 test-audit.py。理由：test-tiers.py 管划分，已 505 行；两个文件的切片可以并行。
  • 体检不跑测试，也不做「每条整改后独占锁下复测」这一步的调度。复测用现成的 test-tiers.py probe（它本来就持独占锁），结果经 --probe 喂回体检，由 --compare --plan 判目标是否解决。
  • 「每个集成区域都要写单条上限」进了标准（R5）。方案页的分层文件原型里区域预算是可选的；但用户的要求是「每一层的用例每一条的执行时间都进行限制」，没写上限的区域在体检里记不合规，去向是写预算。门禁行为不变（没写仍然不判）。
  • 集成层老债与区域总量超预算在体检里是不合规，在门禁里仍只警告。体检问的是「离标准多远」，门禁问的是「这次变更有没有变坏」。
  • 删除用例不在命令内做。方案页写的是「审批页里人类勾了删除才能删」；改为一律转 change，命令内的护栏因此可以简单地要求「用例集合不变」。
  • 多出「未判」一档与退出码 3。方案页只有「有违规退出 1」；没有测量时说「合规」是假话。
  • 不替仓库决定用例该删、该拆还是该提速：体检只列可选去向，选哪个由整改稿与人定。
  • 不给预算定数：体检打印每个范围的 p50 / p95 / 最慢，数字由仓库自己写。
  • 缺 Given / When / Then 注释只计数，不进整改（方案页的假设）。
  • 不把体检接进门禁：C4 合入后可以把它声明成带 slice 的检查，那是仓库自己的选择，本 change 不依赖 C4。
  • 非 Python 测试文件的断言与用例数不核对，只列进「未核对」交人。
  • flight-doctor.py doctor 不加提示行（C4 正在改同一文件）。

Specs · 04行为规范 (Gherkin)

test-audit ADDED

Requirement: 账本里的超线用例清单

test-ledger.py SHALL 提供纯函数 violations(ledger, budgets, scope_of, allow=None)，返回账本里全部超线用例的清单，每条为 {"case": 用例 id, "scope": 范围, "kind": "unit" | "region", "sec": 秒, "line": 线, "by": "budget" | "allow"}，按耗时由大到小、再按用例 id 排序。判定对象是账本里有耗时（s 不为 null）、所在范围在 budgets 里的每一条用例，实测（m=1）与沿用（m=0）都判。线的取法 MUST 与 budget() 相同：用例有未过期的放行 → 线取放行的 limit，by 为 allow，limit 为空则该用例不设线；否则线取范围的 case_sec，by 为 budget，case_sec 为空则不判。超线的含义：单元层范围在没有有效放行时为「耗时不小于线」（与 G10 相同），其余情形为「耗时大于线」。账本 id_form 为 junit 时 allow 的键 SHALL 按 budget() 的同一规则换算后匹配。budget() 的返回与文本 MUST 保持不变。函数不读文件、不取时间。 Feature: 体检要的是全部不合规用例，不是门禁那几条明细 Rule: 线的取法只有一处，体检与门禁读同一个结论

Requirement: 体检的数据来源与归层

test-tiers.py audit SHALL 只读地体检当前工作树：读 openspec 根的分层文件、git 跟踪与未忽略的测试文件、一份测量（测试账本与探针结果），不运行任何测试、不改任何文件（--out 指定的输出文件除外）。账本的选取：--ledger PATH 指定的文件 > --change-dir DIR 对应 change 的收口账本（没有则基线账本）> 本机 <git common dir>/flight-ledger/ 下 at 最新的一份；--no-ledger 时不读账本。--probe PATH（可重复）读 test-tiers.py probe --json 的结果，其中的用例覆盖账本里同一用例的耗时并带上触碰记录；账本是 junit 形式时探针用例 SHALL 按同一换算规则并入。用例的层 SHALL 按当前分层文件由用例所在文件重新归层；定不出文件的用例保留账本里记的层；所在文件已不存在的用例 SHALL 丢弃并计入 source.dropped。分层文件不存在时 SHALL 只报一条 no-tiers 并说明先跑 /test-tiers；分层文件不合法、--ledger / --probe / --change-dir 读不了时 SHALL 以退出码 2 结束并说明原因。简写形态与部件形态 SHALL 都可用：部件形态的文件归属沿用 check 的判据，单元层范围名为 <部件>/unit。 Feature: 随时能问一句「现在哪些用例不合规」 Rule: 体检不跑测试，读最近一次测量；测量与工作树对不上的部分如实丢弃

Requirement: 体检的不合规类别

test-tiers.py audit SHALL 按下列类别列出不合规项（level 为 violation），每条带稳定的 id（<类别>:<键>）、category、rule、scope（没有则为 null）、text 与可选的去向 fix；类别、规则号、级别与可选去向 SHALL 以模块常量 AUDIT_RULES 为单一出处：

| 类别 | 规则 | 判据 | 键 | 可选去向 | |---|---|---|---|---| | no-tiers | R1 | 没有分层文件 | 空 | 无（先跑 /test-tiers） | | layering | R2 | 测试文件未归层、匹配多层、不属于任何部件或属于多个部件（与 check 同一判据） | 文件路径 | move / retier | | unit-impure | R3 | 探针记录里单元层用例有触碰 | 用例 id | purify / move / split | | unit-slow | R4 | 单元层用例超线（violations 的结论） | 用例 id | speedup / move / allow | | no-case-limit | R5 | 集成区域没写 budget.case_sec | 区域名 | budget | | region-slow | R6 | 集成区域用例超线（violations 的结论） | 用例 id | speedup / allow / delete | | total-over | R7 | 写了 total_sec 的范围合计超预算（单元层与区域都算不合规） | 范围名 | speedup / delete / budget | | allow-stale | R8 | 放行条目的键指向的测试文件已不存在 | 放行的键 | drop-allow | | allow-expired | R8 | 放行已过期 | 放行的键 | allow / speedup / move / drop-allow | | allow-unbounded | R8 | 未过期的放行缺 limit_sec 或缺 expires | 放行的键 | allow / drop-allow |

一条放行只归入上面最靠前的一个放行类别。总量的判定沿用 budget() 的结论与它的「未判」条件。 Feature: 不合规项按类别点名，每类都有明确的出路 Rule: 判据都是机械的；集成层的老债在体检里就是不合规，不因门禁只警告而隐身

  • 判定：slice-gate.py 的 tier_budgets / budget_scope_of / allow_view 把分层文件摊成预算范围与放行视图；test-ledger.py 的 budget() 判集成层单条（G13）与层总量（G14）。tier-budgets 的 design D14 把这组函数留作体检的接口。
  • budget() 当体检用有三处不够（读代码确认）：每类明细只返回前 5 条（TOP_N）；集成层单条只判本次实测（m == 1）；单元层单条它不判（G10 由探针在运行时判）。体检要的是「全部超线用例」，所以需要一个返回全量清单的函数；总量与放行的汇总可以直接用 budget()。
  • 整改没有任何机制。/test-tiers 的第 6、7 步（搬文件、复核）是它自己的一次性流程，护栏只有文档里的一句「不改被测代码，也不改断言」。

先例：/test-tiers 用 /opsx-mini 留痕 + 审批页 + 人类批准来搬测试文件，没有走 change。它是本设计「命令内执行」轨道的依据。

在役 ADR（约束本设计）：

  • DRAFT-test-tiers-unit-baseline-by-audit-probe：两层、按路径归层、纯度与耗时由探针判、放行要人类原话。体检不新造判据，纯度只认探针记录。
  • DRAFT-time-budgets-ratchet-on-ledger：预算写在分层文件、放行有边界、集成层棘轮。本设计不改门禁的处置，只在门禁之外多一个「离标准多远」的读数。
  • DRAFT-test-ledger-outside-repo-follows-anchors：账本在 git common dir、不入库、只报告。体检读它，不写它。
  • DRAFT-machine-wide-test-lock：跑测试要取锁。体检不跑测试，不取锁；复测用的 probe 已经持独占锁。
  • DRAFT-gate-evidence-not-self-reported：结论由脚本给。整改护栏由脚本对着 git 改动核对。
  • DRAFT-measurements-stay-out-of-plan-files：测量不进计划文件。体检存档写到调用方指定的路径（建议临时目录或 openspec/superpower/），不写计划文件。

Goals / Non-Goals

Goals:

  • 合规标准写成文档里的规则表，脚本常量与它一一对应。
  • 一条只读命令随时回答「哪些用例、哪些层、哪些放行不合规」，可进 CI。
  • 整改有固定流程：稿子先给人批；能机械做的命令内做完并由脚本核对；要判断的交给正式的 change。
  • 大仓库能分批：按范围、按类别、按最慢 N 条取子集；复核只看本轮目标。
  • 简写形态与部件形态都能体检。

Non-Goals:

  • 不改任何门禁判定（G10–G14 的处置原样）。
  • 不替仓库选去向、不替仓库定预算数字。
  • 不跑测试、不新造测量手段。
  • 不核对非 Python 测试文件的断言。
  • 不做没有分层文件时的建层——那是 /test-tiers。

Decisions

类别名、规则号、级别、可选去向在 test-tiers.py 里是一个常量 AUDIT_RULES；去向与轨道在 test-audit.py 里是 ACTIONS。一条测试对着文档逐项查（scenario standard-doc-matches-script-constants），改一边不改另一边会红。
为什么放契约文档

第 9、10 节（账本、预算）已经在那里，标准是它们的收口；放命令文档里的话，不跑 /test-audit 的人（比如只在 CI 里跑体检）看不到判据。

R5 是本设计加的（方案页的原型里区域预算可选）。用户的要求是每一层每一条都有限制；没写上限的区域在门禁里照旧不判，但在体检里点名，去向只有「写预算」。这是需要人类拍板的一处，见 Open Questions。
备选

标准只写在脚本的常量与 --help 里——被否：主会话的指令明确要求不让标准只存在于脚本里。

输入

分层文件、git ls-files（已跟踪与未忽略）、一份账本、零到多份探针结果。

账本的选取

--ledger PATH > --change-dir 对应 change 的 final（没有则 baseline）> 本机 flight-ledger/ 下 at 最新的一份；--no-ledger 不读。

探针结果覆盖账本里同一用例的耗时，并带来触碰记录。它是「人特意刚量的」，比账本新。
为什么不自己跑
跑全量集成层在 afa 是一小时量级，体检就不再是「随时可跑」；
取测量的手段已经有两个（飞行落账、probe），再造一个要重新处理锁、部件、适配器；
不跑测试的命令可以放心放进 CI 与 hook。
代价

本机没有账本的仓库第一次体检只能判 R1 / R2 / R5 / R8，时间类规则记「未判」，要先跑一次 baseline 或 probe。命令文档写明这一步。

备选

audit --measure 自己跑各层并落一份体检账本——被否，理由如上；真有需要可以后加，输入口（--ledger）已经留好。

账本里记的层是落账那一刻的；体检时分层文件可能已经改了、文件可能已经搬了。所以每条用例按「所在文件 + 当前分层文件」重新归层（tiers_matching 取第一个）。
用例所在文件

nodeid 形式取 :: 之前；junit 形式用 test-ledger.py 的 _file_of。

文件存在 → 用它归层；
像路径（含 / 或带扩展名）但文件不存在 → 丢弃，计入 source.dropped；
定不出文件（适配器部件的 <部件名>::classname::name）→ 保留账本里记的层。
搬过的用例在旧账本里是旧 id

旧 id 被丢弃，新路径没有测量。这正是下面「未判」要抓的情形，也是复核必须重新取测量的原因。

原型验证

audit-recomputes-layer-and-drops-missing-files 与部件形态的骨架都在一次性副本上跑通。

violations(ledger, budgets, scope_of, allow) 对账本里每条有耗时、范围在预算里的用例判一次，实测与沿用都判，不截断。
budget() 里取线的那三行换成调用同一个小函数；返回值与文本不变，tests/test_budget_core.py 全绿作守卫。
总量与放行汇总仍取自 budget(like, None, budgets, scope_of, allow, "baseline") 的 totals 与 allow，不另算。
为什么不改 budget() 让它返回全量

它的返回进 final 输出 JSON 与 PR 正文，明细有上限是 test-ledger design D8 的决定；体检另开一个函数互不牵连。

为什么要「未判」

没有账本时，时间类规则一条都判不了；说「合规」是假话，说「不合规」也不对。单列一档，退出码 3，CI 可以自己决定 3 算不算过。

某范围「有测试文件没有测量」怎么认

check 认的、恰落一层的测试文件里，没有任何一条用例落在它上面的。范围里有定不出文件的用例时不做这一项（分不清），不误报。

未判的范围不出 total-over，已量到的单条超线照常列——少报总量不会冤枉人，漏报单条才会。
纯度不算未判

有分层文件的仓库每次 baseline 都由 G11 判纯度；体检没带探针时只留一条提示「纯度未在体检里核对」，不把退出码推到 3。否则每次不带 --probe 的体检都是 3，这个码就没用了。

体检比门禁严的两处

集成层老债（G13 只警告）与区域总量超预算（G14 只警告）在体检里都是不合规。门禁回答「这次变更有没有变坏」，体检回答「离标准多远」。

缺 GWT 只计数

直接调 slice-gate.py 的 gwt_violations，只取条数。

与铁律 1 的关系
命令内执行的五种去向都不改用例的行为

文件换地方、分层文件改几行。它与 /test-tiers 是同一性质，先例是 mini 留痕，本设计沿用，并补上先例没有的脚本护栏（D8）。

要改用例实现的三种去向会改变「测试在测什么」，属于中级以上变更。命令不动手，产出一份清单（条目 id、现状、建议方向），由人发 /opsx-propose。那个 change 的验收可以直接用体检

test-tiers.py audit --change-dir <该 change> --compare <清单对应的存档> --plan <清单> 退出 0。

放行是「人类承担这条慢用例」，模型不能代写，这条规则已有（test-tiers.md「放行慢单测」），本设计不动。
为什么不全走 change

搬一个文件也要五工件、起飞、评审，成本与风险不成比例；而且 /test-tiers 的第一次划分（搬几百个文件）都没走 change，之后搬一个反而要走，说不通。

为什么不全在命令内

提速要改 fixture、缩样本、换实现，最容易把断言悄悄改弱；这类改动需要评审员看 diff，也需要 TDD 留痕，命令内的护栏给不了。

删除为什么不在命令内

方案页原写「审批页里人类勾了才删」。但勾选发生在浏览器里，脚本验证不了；而删用例是减覆盖。归到转 change 之后，命令内的护栏可以是一条简单的不变式：用例集合不变。

这一分法是需要人类拍板的一处，见 Open Questions。
render 校验的都是机械判据

条目是否在体检结果里、去向是否在该条目的 fix 里、keep 是否写了理由、搬与拆的落点是否恰落一层且方向对（单元层的问题不能搬回单元层）、写预算是否真给了数。

轨道由去向查 ACTIONS 得到，模型不自己分。
审批页沿用 test-tiers.py render 的形态（单文件、内联样式、批注框、导出 Markdown / 复制），每条多一个勾选框；导出的文本里带每条的勾选结果，人贴回对话即批准意见。
稿可以只覆盖一部分不合规项。没排进稿的在页面上数成「未安排 N 条」，不算问题——分批整改是常态。
support

搬测试往往要跟着搬 conftest.py、__init__.py、测试数据。这些不是测试文件，护栏默认会判「稿外的改动」；写进 support 后放行，并且显示在审批页上给人看。

测试文件（内置命名）、分层文件、openspec 根之下的文件 → 允许；
命中任一区域 covers（基线与当前两版分层文件都算）→ 「改了被测代码」，support 不能豁免；
命中 support → 允许并列出；
其余 →「稿外的改动」。
每个测试函数的签名 = 类名.函数名 + 参数化装饰器 + 断言集合；
断言 = assert 语句、名字以 assert 开头的调用（unittest 风格）、pytest.raises / pytest.warns；
基线一侧与当前一侧各收一个多重集比较

按名字计，跨文件移动不算改动；

消失、新增、断言有改动、参数化有改动，各自点名。
方案页的第四条护栏「每条整改后在独占锁下复测

绿，且达标」不在 verify 里，由复核步骤承担：对受影响的层跑 test-tiers.py probe --json（它持独占锁，失败会非 0），再 test-tiers.py audit --probe … --compare … --plan …。

为什么用函数名而不是文件名对齐

整改的主要动作就是换文件；按文件比，每次搬动都是「全删全增」。

代价

同名函数在不同文件里各有一条时，按多重集比仍然成立，但报错时只能说名字，说不出是哪个文件的那一条。

备选

用 pytest --collect-only 比前后用例 id——被否：要跑两遍收集（基线一侧还得检出），而且搬文件之后 id 本来就全变了。

条目 id = <类别>:<键>，键是用例 id、文件路径、范围名或放行的键，跨两次体检稳定。
--compare 只比不合规项

已解决 / 仍在 / 新增。

--plan 把稿里去向不是 keep 的条目当本轮目标。退出码

有新增或目标未解决 → 1；否则有未判项 → 3；否则 0。

没排进本轮的老债仍在，不算失败。否则 afa 这样的仓库永远过不了复核。
搬过的用例

旧 id 消失（已解决）；如果到了新地方仍然超线，会以新 id 出现（新增）→ 退出 1。这是对的：整改把问题换了个地方。

有未判项时不说达标

目标「不在不合规项里」可能只是因为搬过去之后没量。退出 3，文本写「未能确认」。

只报告」）。

/test-tiers 的文档加一行

建层之后的例行体检与整改走 /test-audit。两条命令的分工：/test-tiers 从无到有，/test-audit 从有到合规。

afa 现状（没有模板的分层文件，用自带的登记表）

体检会一直是 no-tiers，直到它迁到模板的分层文件。这是 afa 自己在体检报告第五节里列为待定的事，本 change 不替它决定。

test-tiers.py audit

与 check 同文件，直接复用 load_tiers / check_parts / read_json；check 的判据抽成一个返回结构化结果的函数，check 与 audit 共用，check 的输出与退出码不变。

test-audit.py（新）

test-tiers.py 管划分与体检（都是「读分层文件下结论」）；整改稿与护栏是另一件事（读 git 改动、渲染页面）。拆开之后两条切片链可以并行。

备选

Risks / Trade-offs

[体检读的是「最近一次」测量，可能来自别的分支的 change] → 输出第二行写明来源（change、阶段、commit、时间、模式）；对不上的用例被丢弃并计数，没测量的文件进「未判」。要准就带 --change-dir 或先 probe。
[单元层超线只凭一次测量，没有 G10 那样的重跑确认] → 体检是报告，不判红任何飞行；tier-budgets 的校准数据里单元层 9710 条只有 3 条时超时不超。整改前的复测（probe）会再量一次。
[junit 形式的账本从 classname 反推文件是有损的] → 推不出的用例保留账本里记的层，所在范围不做「文件没有测量」的判断，不误报。
[护栏的断言比较只懂 Python] → 其他语言列进「未核对」。部件形态的仓库（Go、JVM）搬测试时这一条要靠人看 diff，命令文档写明。
[support 可以被用来放行任意文件] → 它显示在审批页上、由人批；被测代码（covers）无论如何不能进。没有写 covers 的仓库这道硬线不存在，只剩「稿外的改动」这一层。
[审批页上的勾选不被脚本验证] → 与 /test-tiers 的审批页同样是软约束；硬约束在 verify（改了什么）与 allow-slow（谁放行的）。
[R5 让所有没写上限的区域一夜之间「不合规」] → 只影响体检的读数，不影响任何门禁；去向明确（写预算），体检同时打印该区域的 p50 / p95 / 最慢供人定数。
[与在飞的 wave-integration-guard（C4）同改 flight-runner-contract.md 与 README.md] → 两边都在契约文档末尾加一节，后合入的预合并时保留两节、顺延节号；本 change 的测试按标题「测试套件合规标准」找这一节。README 本 change 改两处计数与命令表，C4 改的是飞行机制的条目，不重叠。C4 改的 slice-gate.py、flight-doctor.py、spec_html.py、工作流与 agent 定义本 change 都不碰。
[命令计数被两个旧测试钉住] → tests/test_tiers_docs.py、tests/test_clean_after_merged_docs.py 并入文档切片 S7 的 owns。
