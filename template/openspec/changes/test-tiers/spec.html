Why · 01为何而做

飞行流程的 baseline 与 final 每次都跑 gate.test 全量，没有「单元 / 集成」之分。本仓实测（2026-10-28，main a20e532，Python 3.9.6 / pytest 8.4.2，审计钩子探针逐用例记录）：

- 323 个用例里 312 个碰了真实文件或起了子进程，按「纯函数」口径只有 11 个是单元测试； - 全量 84s，其中约 70s 来自 slice-gate 系列的子进程 + 临时仓库测试； - 最慢单个用例 2.44s，目前没有 ≥3s 的单测，但没有任何机制防止它出现。

用户要求（2026-10-28）：

1. 测试分单元测试（纯函数、不碰真实文件，基线就是它）与集成测试（其余全部，只在判断确实影响到真实文件时，按模块 / package / library 分区域发起）；提供一个命令快速重划分；设计新用例时先按这个划分定层。 2. 每个单元测试必须 <3s，一旦超线需要人工审核放行。 3. （同日追加）每次跑门禁都要分别报告单元层耗时与集成层耗时。

用户决策（2026-10-28，决策页 template/openspec/superpower/2026-10-28-test-tiers-decisions.html 逐项选择，代替 grill-me 访谈；5 项全取推荐）：

- Q1 粒度：文件级，按路径归层；混合文件拆开。跨语言通用，区域天然对应目录 / package。 - Q2 放行：脚本核验人类原话后才写放行名单，判据复用 takeoff-gate 的「人类消息」口径。 - Q3 纯度：门禁机械强制——baseline / final 跑单元层时注入探针，碰真实文件即红。 - Q4 范围：本 change 只交付机制；本仓自己的 323 个测试留给下一个 change，用新命令重划分。 - Q5 计时：含 setup + call + teardown；超线者单独重跑一次仍 ≥3s 才判红。 - 「不得<3s」按笔误处理：每个单测必须 <3s，≥3s 触发放行流程（决策页已列明此解读，用户未反对）。

What · 02变更范围

  • 仓库级分层文件 openspec/test-tiers.json（openspec 根，与 gate-checks.json 同级）：
  • unit：paths（路径 glob）+ cmd（单元层运行命令）；
  • regions：每个区域 paths / covers（它守护的源码 glob）/ cmd；
  • slow_allow：经人工放行的慢单测，{nodeid: {reason, approved}}。
  • 计划：slices.json 的 gate 新增 integration（本 change 要跑的区域名）与 integration_skip（{区域: 理由}）。
  • lint（前缀 tiers:）：分层文件形状；gate.test 必须等于 unit.cmd（基线就是单元层）；区域选择合法；covers 与任一切片 owns 相交的区域必须选上或写理由；每个 scenario 测试文件必须落在单元层或已选区域的 paths 内。
  • 探针：baseline / final 跑单元层时经 PYTEST_ADDOPTS 注入临时 pytest 插件，逐用例记「碰了文件 / 子进程 / 网络」与 setup+call+teardown 耗时；插件加载失败时去掉探针重跑，判为不可度量。
  • 新失败编号：
  • G10 慢单测：≥3s 且单独重跑仍 ≥3s、不在 slow_allow → 红；在 slow_allow → 警告；
  • G11 单测不纯：单元层用例碰了真实文件 / 子进程 / 网络 → 红；
  • G12 测试未归层：切片改动的测试文件不在单元层或已选区域的 paths 内 → 切片门禁红；
  • 区域差分沿用 G2：G2 region <name>。
  • baseline：配置了分层时只跑单元层（带探针）与已选区域；不走增量复用；区域失败按 junit 记基线；G10 / G11 红即基线红。
  • final：G7 绿时，单元层差分 + G10 + G11，再逐个已选区域按基线差分。
  • preflight：已选区域的命令与基线记录不符 → 基线过期。
  • 分层耗时报告：配置了分层时，gate / baseline / final 的输出带 tier_sec（unit / integration / 各区域秒数），并写进 summary 与 timeline 备注，飞行记录逐行可见；G7 按用例耗时归层，单元层与区域运行按墙钟计。
  • 新命令 /test-tiers 与脚本 .claude/hooks/test-tiers.py：
  • probe：实跑一次，逐用例给出层级证据与耗时，按文件汇总「单元 / 集成 / 混合」；
  • render：把探针结果与划分稿渲染成带导出按钮的审批页；
  • check：每个测试文件恰好归一层；
  • allow-slow：核验最新一条人类消息含该用例名与放行词后，写入 slow_allow。
  • 文档：schema tasks instruction、opsx-propose / opsx-verify 命令与同名 skill、TDD skill（写测试前先定层）、slice-executor、README、install.sh 提示、CLAUDE.md.snippet。
template/.claude/hooks/slice-gate.py：分层文件读取与形状校验、lint_plan 的 tiers: 规则、plan_sha 在有 gate.integration 时追加区域名；run_test_gate 可选注入探针；cmd_gate 加 G12；cmd_baseline / cmd_final / cmd_preflight 接入单元层探针、G10 / G11 与区域差分；G7 插件可选记录逐用例耗时；cmd_gate / cmd_baseline / cmd_final 输出 tier_sec。新增 template/.claude/hooks/test-tiers.py（导入 slice-gate 与 takeoff-gate 的函数，不改它们的 CLI）。新增 template/.claude/commands/test-tiers.md（命令本身即逻辑，无同名 skill，同 /opsx-mini、/pr-ship）。文档：schema.yaml、opsx-propose / opsx-verify 命令与同名 skill、test-driven-development/SKILL.md、agents/slice-executor.md、README.md、install.sh（命令数提示）、CLAUDE.md.snippet。测试：新增 tests/test_tiers_plan.py、tests/test_tiers_probe.py、tests/test_tiers_verdict.py、tests/test_tiers_gate.py、tests/test_tiers_cli.py、tests/test_tiers_docs.py、tests/test_tiers_timing.py；既有测试不改。ADR：新增 DRAFT-test-tiers-unit-baseline-by-audit-probe；DRAFT-test-gate-baseline-diff、DRAFT-baseline-reuse-by-content-fingerprint、DRAFT-gate-evidence-not-self-reported 继续有效，不 supersede（关系见 design D12）。兼容：没有 openspec/test-tiers.json 的仓库，lint / gate / baseline / final / preflight 的行为与输出不变，plan_sha 不变，gate-baseline.json 不出现 tiers / regions / tier_sec 键。已知边界：探针只认 pytest；非 pytest runner 的 G10 / G11 降级为警告；os.stat / os.path.exists 不触发审计事件，只做存在性判断的用例测不出；C 扩展绕过 Python 层直接做的 I/O 也测不出；未选区域在本 change 内不跑；靠 lint 逼出「选上或写理由」与计划审批兜住；本仓自己的测试本 change 不重划分（Q4），本仓不放 test-tiers.json，本 change 的 gate.test 仍是全量。

Specs · 04行为规范 (Gherkin)

test-tiers ADDED

Requirement: 分层文件与计划里的区域选择由 lint 校验

仓库级分层文件 test-tiers.json SHALL 从 openspec 根目录读取，openspec 根目录 = change 目录的上两级（<change_dir>/../..，与 gate-checks.json 同一解析）。

文件存在时，slice-gate.py lint（preflight 内的同一份计划校验也一样）SHALL 在下面任一条不满足时退出非 0，stderr 每条违规以 tiers: 开头并点名对象：

- 文件可读、是合法 JSON、顶层是对象，否则只报一行并点名该文件； - 顶层只含 unit、regions、slow_allow，且必有 unit； - unit 只含 paths 与 cmd：paths 是非空数组、每项去掉首尾空白后非空；cmd 是非空字符串； - regions 是对象；区域名匹配 ^[a-z0-9-]+$；每个区域只含 paths、covers、cmd，paths 同上，covers 是数组（可以为空）、每项非空，cmd 是非空字符串； - slow_allow 是对象；每项只含 reason 与 approved，都是非空字符串； - gate.test 去掉首尾空白后等于 unit.cmd 去掉首尾空白后（基线就是单元层）； - gate.integration 缺省，或是数组、每项是 regions 里的区域名、不重复； - gate.integration_skip 缺省，或是对象、每个键是 regions 里的区域名、理由去掉首尾空白后非空、键不同时出现在 gate.integration； - 区域的 covers 里任一 glob 与任一切片 owns 里任一 glob 相交（与同 wave owns 重叠同一判定）时，该区域 SHALL 出现在 gate.integration 或 gate.integration_skip； - scenario_tests 指向的每个测试文件路径 SHALL 匹配 unit.paths，或匹配某个已选区域（gate.integration 里的区域）的 paths。

文件不存在时上面各条都不触发；但计划里出现 gate.integration 或 gate.integration_skip 时，lint SHALL 报一行以 tiers: 开头、指出缺少分层文件。

plan_sha SHALL 只在 gate.integration 是非空数组时把它追加进哈希内容；其余情况结果与本 change 之前相同。

Requirement: 单元层运行时用探针逐用例记录触碰与耗时

slice-gate 以探针方式运行单元层（gate.test）时 SHALL：

- 经 PYTEST_ADDOPTS 追加 -p flight_tier_probe；插件文件写进临时目录并把该目录加进 PYTHONPATH，不写进被测仓库； - 对每个用例记录耗时 = setup、call、teardown 三个阶段耗时之和； - 对每个用例记录在这三个阶段内发生的审计事件，归为三类，每类保留第一条样例： - 文件：open、os.mkdir、os.remove、os.rename、os.rmdir、os.chmod、os.truncate、os.utime、os.symlink、os.link、os.listdir、os.scandir、os.walk、glob.glob、shutil.copyfile、shutil.copytree、shutil.move、shutil.rmtree、shutil.copymode、shutil.copystat； - 子进程：subprocess.Popen、os.system、os.exec、os.spawn、os.posix_spawn、os.fork； - 网络：socket.connect、socket.bind、urllib.Request； - 不计入：发生在 import 机制（importlib._bootstrap*、zipimport）或 pytest 断言重写读源文件期间的事件；三个阶段之外（如失败报告生成）的事件； - 插件加载失败（输出含 Error importing plugin "flight_tier_probe"）时，去掉探针把单元层重跑一次；本次结果判「不可度量」并写明原因，失败用例差分照常用重跑的结果； - 输出里没有探针的开跑记录（如 gate.test 不是 pytest）时判「不可度量」。

Requirement: 单元层的慢单测（G10）与不纯（G11）判定

对一次单元层运行的逐用例记录，slice-gate SHALL：

- 把耗时 ≥ 3 秒的用例当作候选，在同一次 pytest 调用里单独重跑这些候选一次；重跑耗时仍 ≥ 3 秒，或重跑没有取得它的耗时，即确认超线； - 确认超线且不在 slow_allow 里的用例，各给一条失败 G10 slow unit test: <nodeid> …，写明首跑与重跑耗时及处理方式（提速、移入集成区域、或经 test-tiers.py allow-slow 由人类放行）； - 确认超线但在 slow_allow 里的用例，各给一条警告，带放行记录； - 有任何触碰记录的用例，各给一条失败 G11 impure unit test: <nodeid> …，写明触碰类别与样例； - 本次运行不可度量时，只给一条警告 G10/G11 不可度量：<原因>，不判红。

Requirement: baseline、final、preflight 按分层运行

分层文件存在时，baseline、final、preflight SHALL 按下面的方式运行：

- baseline SHALL： - 分层文件或区域选择不合法时停下，不写运行标记、不碰现有 gate-baseline.json； - 不走增量复用（与 --full 相同）； - 以探针方式运行 gate.test（即单元层），按上一条 Requirement 判 G10 / G11，任一失败即基线红；在 gate-baseline.json 记 tiers：{"measured": true}，或 {"measured": false, "why": <原因>}； - 在每片 verify 之后、gate.checks 之前，逐个运行 gate.integration 里区域的 cmd，按 junit 记 regions.<区域名> = {exit, sec, cmd[, failed]}：可度量的红记预存红并警告，不可度量的红即基线红； - 不运行未选区域。 - final SHALL 在 G7 绿时：单元层按基线差分并判 G10 / G11；再逐个已选区域——基线没有它的记录、或记录的 cmd 与分层文件当前命令不同时，失败 G2 region <区域名>：基线缺记录或命令已变，重跑 baseline；否则按它的基线失败逐条差分，新增失败记 G2 region <区域名>: …。G7 红时不跑单元层与区域并给警告（与现状一致）。 - preflight SHALL 在已选区域缺基线记录、或记录的 cmd 与分层文件当前命令不同时报「基线过期」。

分层文件不存在时，baseline / final / preflight / gate 的行为与输出不变：不注入探针，gate-baseline.json 没有 tiers 与 regions 键。

Goals / Non-Goals

Goals: - 单元层 = 基线：飞行的 baseline / final 只跑单元层与本 change 选中的区域。 - 「纯函数」与「<3 秒」两条单元层定义由脚本逐用例判定，不靠自报。 - 区域发起靠判断，但判断必须显式写进计划、随飞行计划审批；漏表态由 lint 拦下。 - 新用例先定层：scenario 测试的位置由 lint 管，切片里的其他测试文件由 G12 管。 - 慢单测的人工放行有人类原话证据。 - 一条命令完成重划分：实测分类 → 审批页 → 搬家 → 复核。 - 每次门禁（gate / baseline / final）分别报告单元层与集成层耗时，进飞行记录（铁律 8）。 - 未配置分层文件时行为、输出、plan_sha 与本 change 之前一致。

Non-Goals: - 不改写测试逻辑（把「经子进程测纯逻辑」的集成测试重写成单元测试）。 - 集成区域不设耗时上限。 - 不支持非 pytest runner 的探针（只降级）。 - 未选区域不兜底全跑。 - 本 change 不重划分本仓自己的测试，本仓不放分层文件（Q4）。

它出现在失败编号文本与 gate-baseline.json 键里，限制字符集免去转义问题。

unit.cmd 与 gate.test 必须相同

「基线就是单元层」由 lint 机械保证；gate.test 已在 plan_sha 里，单元层命令改了基线自然过期。

否决

只在 slices.json 写 gate.test、分层文件不写单元命令——lint 无从判断 gate.test 是否只跑单元层，全量会悄悄继续当基线。

否决

pytest marker 分层（Q1 否决）——只适用 Python，区域要靠多个 marker 组合。

形状

gate.integration = [NAME, …]，gate.integration_skip = {NAME: 理由}；与 gate.checks / checks_skip 同一模式。

表态规则

区域 covers 与任一切片 owns 相交（globs_intersect）→ 必须选上或写理由。这是「你或用户判断」的机械化：判断由模型写、人在 spec.html 里批，漏写由 lint 拦。

只写区域名，不抄命令

命令只在分层文件里有一份；plan_sha 只追加区域名（D9），命令改动由 preflight / final 与基线记录对账。

否决

按 covers 自动选区域——用户要求「判断确实影响到真实文件时」才发起，covers 相交只是信号，可能只改了注释。

否决

final 兜底全跑所有区域——违背用户「仅在……时有区域地发起」；漏网风险靠表态规则与审批兜住。

lint

scenario_tests 指向的文件必须匹配 unit.paths 或已选区域的 paths。tasks 阶段写骨架时就得先定层。

G12（cmd_gate，接在 G4 之后）

本切片区间改动、仍存在、文件名符合测试文件命名的文件，路径必须落在单元层或已选区域；用测试文件命名（TEST_FILE_RE）而不是 is_test_path，免得 conftest.py、测试数据文件被误判。

为什么要 G12

执行体额外写的测试若落在任何层之外，baseline 与 final 都不会跑它——这是静默失败。

否决

G12 放进 final——执行体在自己的切片里就能挪文件修好，放 final 要多一轮修复。

注入

run_test_gate(cmd, root, probe=False) 新增参数；probe=True 时插件源 TIER_PROBE_PLUGIN 写进与 junit 相同的临时目录，PYTHONPATH 前置该目录，PYTEST_ADDOPTS 追加 -p flight_tier_probe，FLIGHT_TIER_OUT 指向临时 jsonl。与 G7 插件同法。

窗口

用 hookwrapper 包住 pytest_runtest_setup / call / teardown，只在这三段内记录；失败报告生成（读源码拼 traceback）不在窗口内。

事件表

见 spec 第三条 Requirement；按事件名集合先过滤，命中才查调用栈，控制开销。

排除

调用栈上有 importlib._bootstrap*、zipimport 或 _pytest.assertion.rewrite 帧时不计——实测 import 会触发 open 与 os.mkdir。

耗时

pytest_runtest_logreport 的 report.duration 三段相加（Q5）。

输出

会话开始写一行开跑记录；每个用例 teardown 后写一行 {nodeid, sec, hits}；写之前先关窗口，免得记到插件自己。

xdist

主进程与 worker 都可能写同一 nodeid；读取时按 nodeid 合并，耗时取最大、触碰取并集。追加写、每行一条，不依赖单进程。

回退

输出含 Error importing plugin "flight_tier_probe"（实测退出码 1，与用例失败同码）→ 去掉探针重跑一次，probe=None、probe_why 写明「探针插件加载失败（包装命令覆写了 PYTHONPATH？）」；差分用重跑结果。没有开跑记录 → probe=None、「没有探针输出（不是 pytest？）」。

返回

res["probe"] = {nodeid: {"sec": float, "hits": {"文件"|"子进程"|"网络": 样例}}} | None，res["probe_why"]。

否决

把插件放进 hooks 目录直接加 PYTHONPATH——hooks 目录里有 timeline.py 等可导入模块，会遮住被测仓库的同名模块。

否决

解析 --durations 输出取耗时——拿不到触碰信息，还要第二套解析。

阈值

常量 UNIT_MAX_SEC = 3.0，不可配置（用户定的规则，不给环境变量开口，见 D12）。

候选与确认

耗时 ≥ 3.0 为候选；用 G7 同款前缀（_g7_runner(gate)）在同一次 pytest 调用里带探针重跑全部候选（--rootdir 为 toplevel）；重跑 ≥ 3.0 或重跑没有该 nodeid 的记录（如 cd 子目录跑导致 nodeid 不同）→ 确认。fail-closed。

纯函数判定

tier_verdicts(probe, probe_why, rerun, allow) → (failed, warnings)，不做 I/O；候选列表由 slow_candidates(probe) 给出，重跑由调用方做。判定逻辑因此能用纯函数单测覆盖，不必每个场景真睡 3 秒。

放行

nodeid 在 slow_allow → 警告，带 approved；否则失败。

否决

一次超线即红（Q5 否决）——切片并行时负载抖动会让飞行误停。

否决

每个候选单独起一次 pytest——候选通常很少，同一调用足够，省进程启动。

任何触碰 → 失败，写明类别与第一条样例。
不可度量 → 一条警告 `G10/G11 不可度量

<原因>`，不判红（与「非 pytest 按退出码判」同一降级口径）。

已知盲区

os.stat 类不触发事件；C 扩展直接做的 I/O 不经审计钩子。写进文档与 ADR。

否决

静态扫描测试源码找 open / subprocess（Q3 选了门禁强制实测）——间接调用看不见，误报也多。

先校验后动作

分层文件或区域选择不合法 → die，不写运行标记，与 gate.checks 形状校验同位置。

不走增量

配置了分层时 _baseline_candidates(..., full=True)。单元层按定义每个用例 <3 秒，复用机器省不了多少；而复用会跳过探针，G10 / G11 无从判。lint / typecheck 的沿用依赖复用命中，随之不沿用。

次序

单元层（原全量位置，带探针，判 G10 / G11，失败进 reasons）→ lint / typecheck → 每片 verify → 已选区域 → gate.checks → 运行期间改动判定。区域放在 verify 之后，与 checks 同属「更贵、按需」的一段。

区域记录

regions.NAME = {exit, sec, cmd[, failed]}；可度量的红记 failed 并警告；不可度量的红进 reasons。区域每次实跑，不沿用。

tiers 记录

{"measured": true} 或 {"measured": false, "why": …}，供 timeline 与人看。

verify 推导（_derive_verify）照旧

单元层是直接 pytest 调用时，落在单元层里的 verify 仍可由它的 junit 推导；区域测试的 verify 照跑。

入池不变

池只按 cmd_key 匹配，分层仓库的单元命令与他人不同，不会误用；不改池逻辑。

次序

G7 → lint / typecheck → G7 绿时：单元层（探针 + 差分 + G10 + G11）→ 已选区域逐个差分 → gate.checks（G9）。

差分复用

把 full_suite_verdict 的差分部分抽成 _diff_verdict(label, tg, known_failed)；单元层用 test 标签（文本与现状一致），区域用 region NAME。

区域记录核对

基线没有 regions.NAME，或记录 cmd ≠ 分层文件当前 cmd → G2 region NAME：基线缺记录或命令已变，重跑 baseline，不跑该区域。

G7 红时沿用现有警告「G2 全量未跑」，单元层与区域都不跑。
plan_sha 在 gate.integration 非空时追加 ["integration", 区域名列表]；其余情况结果不变（兼容旧基线）。
preflight 紧接 plan_sha 校验之后（早于基线 commit 祖先校验与按内容判过期）

分层文件存在且有已选区域时，逐个核对基线 regions.NAME.cmd 与分层文件当前命令，缺记录或不符 → 「基线过期：区域 NAME …；重跑 baseline」。放在内容判过期之前，是为了让人看到具体是哪个区域的命令变了，而不只是「test-tiers.json 有改动」。

分层文件本身的其他改动（paths、covers、slow_allow）不让基线过期

它们不改变基线跑了什么；首次起飞前的内容差异判定（ADR 复用）仍会把它当代码树改动。

为什么取最新一条

门禁红后飞行停下，人回复放行，模型随即运行 allow-slow；取最新一条避免拿很久以前的一句话当证据。

写入

approved = "<ISO 时间> · <摘要 ≤40 字>"；保留分层文件其余键，ensure_ascii=False、缩进 2。

谁能绕过

直接编辑 JSON 可以绕过脚本。飞行中执行体改分层文件会被 G6 所有权拦下（文件在 change 目录外，不在任何 owns 里时）；飞行外的改动出现在 PR diff 里。与起飞批准的信任模型相同。

命令即逻辑

Python 字符串模板生成单文件 HTML（不依赖外网），导出按钮下载 Markdown（含划分摘要与人类批注框）。模型不逐字写 HTML。

判据

单元层

为什么 G7 用用例耗时、层运行用墙钟

G7 一次 pytest 调用混跑两层，墙钟无法拆分；层运行各自独立，墙钟才是真实成本（含收集与启动）。两者相加即「本次门禁花在该层上的秒数」，口径写进 spec。

为什么不计 verify / lint / checks

verify 是混层的切片命令，拆分需要再注入耗时插件，收益低；lint / checks 不属于任何测试层。

输出位置

结果 JSON 的 tier_sec（baseline 同时写进 gate-baseline.json）；summary 末尾追加；timeline 备注把「单元 X.Xs · 集成 Y.Ys」插在结论词之前——timeline.py 的切片号与 ok / red 解析不受影响，飞行记录逐行打印即可见，timeline.py 不改。

未配置分层时

切片
