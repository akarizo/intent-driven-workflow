# S2 · grill-me 维护术语表，schema 引用术语表

## 做什么

- `grill-me` 新增「术语表」一节：开场先读、对照用词、定下即写、默认分支先问、准入与格式。
- schema 的 proposal 与 specs 两个 instruction 各加一段，要求按术语表用词。
- `README.md` 的 `grill-me` 一行补一句。

规则原文见 `specs/domain-glossary/spec.md` 前两条 Requirement，决策见 `design.md` D2、D3、D6。本片只改文档，不改脚本。

## 依赖的接口

无（与 S1 并行）。格式以 design D2 为准，S1 的 `spec_html.py` 按同一格式解析，两边措辞必须一致：词条行 `**规范词**：定义`，可选紧跟一行 `避用：别名、别名`。

## 怎么做

⚠ **措辞禁区**（旧测试钉住了这些，违反即红）：

- `schema.yaml` 的 `- id: proposal` / `- id: specs` / `- id: design` / `- id: tasks` / `apply:` 这些行是测试切段的锚点，不能改、不能挪；
- design、adr、tasks 三段（`- id: design` 起到文件末尾）里**不得**出现 `glossary` 字样；
- `grill-me/SKILL.md` 原有 4 句英文一字不动。

1. **`template/.claude/skills/grill-me/SKILL.md`**：在原文末尾新增一节 `## 术语表`（标题必须是这四个字），内容按 design D3，须包含下列原词（测试按字面断言）：
   - 「`openspec/glossary.md`」与「不存在」：开场先读；文件不存在不新建，第一个术语定下时再建。
   - 「冲突」「避用词」「含糊」「规范词」：用户用词与表里定义冲突、或用了某词条的避用词时当场指出；用词含糊时提出规范词，作为一个问题来问（仍附推荐答案）。
   - 用户描述的行为与代码矛盾时先指出再问。
   - 「当场写入」：用户回答后术语就算定下，当场写入，不攒到最后。
   - 「默认分支」「main」「待写词条」：`git branch --show-current` 是仓库默认分支（如 `main`）时不写文件，访谈末尾列出待写词条，问过再写。
   - 「本项目特有」「实现细节」：只收本项目特有的概念，通用编程概念不收；只写定义，不写实现细节，不当草稿本。
   - 格式：一个缩进代码块或围栏代码块给出 design D2 的样例，再用一条说明写出「每个词条一行 `**规范词**：定义`，可选紧跟一行 `避用：`，别名用 `、` 分隔」（反引号照写，测试断言 `` `**规范词**：定义` `` 与 `` `避用：` ``），并注明 `spec_html.py` 按这个格式解析、审批面板据此列出工件里的避用词。
2. **`template/openspec/schemas/intent-driven/schema.yaml`**：
   - **proposal instruction**：在第 29–30 行「…Research existing specs before filling this in. Each capability listed here will need a corresponding spec file.」这段之后、「Durable architectural decisions…」之前，空一行插入一段（同样缩进 6 格，保持 folded scalar）：说明 `<repo>/openspec/glossary.md` 存在时先读，用每个词条的规范词（粗体那个），不用它 `避用：` 行列出的别名；新术语在 `grill-me` 访谈里定下并写回。
   - **specs instruction**：在第 101–102 行「- Do not create `.feature` files for this artifact. …」这一条之后追加一条同级 bullet：requirement 与 scenario 文字必须用 `<repo>/openspec/glossary.md` 的规范词，不用 `避用：` 行列出的别名；spec.html 会列出命中。
   - 改完跑 `cd template && openspec schema validate intent-driven`，必须绿（gate.checks 的 `schema-validate` 在 final 还会复跑）。
3. **`README.md` 第 518 行**（`| \`grill-me\` |` 那一行）：在「…压力测试方案时使用」之后补「；访谈时对照并维护术语表 `openspec/glossary.md`（规范词 + 避用词），spec.html 列出工件里的避用词」，来源括注保留在行尾。
