# S2 · 文档写明 `/goal` 持续授权：propose 收尾不硬交接、apply step 0、铁律 7、README / WORKFLOW_zh

## 做什么

让文档与 S1 的门禁口径一致。规则原文见 `specs/goal-takeoff-authorization/spec.md` 第三条 Requirement，决策见 `design.md` D6–D7。

- **propose 收尾**：先用脚本判断会话 goal 是否生效，生效就不硬交接。
- **其余文档**：apply step 0、铁律 7、README / WORKFLOW_zh 各补一句。

命令与同名 skill 必须同改，措辞一致，只是「本命令」与「本 skill」的区别。本片只改文档，不改脚本。

## 依赖的接口（来自 S1）

`python3 .claude/hooks/takeoff-gate.py --change-dir openspec/changes/<name>`：

- `exit 0`：stdout 一行 `<ISO 时间> · <摘要>`。会话 goal 生效时，摘要以 `/goal` 开头，豁免新鲜度。
- `exit 3`：无批准，或批准已过期。

## 怎么做

⚠ **措辞禁区**（旧测试钉住了这些，违反即红）：

- 新增文字里不要出现 `数字. **` 形式的有序粗体行，测试靠 `6. **收尾**`、`0. **批准自检`、`1. **选 change**` 定位步骤；
- 不要出现「即视为批准」；
- apply step 0 里不要出现 `AskUserQuestion`；
- 原有的「本命令到此结束」「本 skill 到此结束」「绝对路径」「spec.html」「takeoff-gate」全部保留。

1. **`template/.claude/commands/opsx-propose.md`**：
   - **开头摘要句**：在「然后硬交接给人类：本命令到此结束，起飞由人类自己发出 `/opsx-apply`（…）」之后，补一句「会话 `/goal` 生效时除外：由 `takeoff-gate.py` 判定后不交接，等 baseline 报告后直接起飞」。

       - 把计划工件单独 commit（artifacts-only commit）。

       - 走哪条分支由脚本判定，模型不自行判断 goal 状态。
