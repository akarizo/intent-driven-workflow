# S3 · test-tiers.py allow-slow：放行时写上限与期限

## 做什么

给 `template/.claude/hooks/test-tiers.py` 的 `allow-slow` 加两个可选参数 `--limit-sec` 与 `--expires`。规则原文见 `specs/tier-budgets/spec.md` 的「放行命令可写上限与期限」；取舍见 `design.md` D11。

人类放行证据的判据（只认最新一条人类消息、须同时含函数名与放行词）一字不改。

## 依赖的接口

S2 已让 `slice-gate.py` 的形状校验接受 `slow_allow` 条目里的 `limit_sec`（大于 0 的数）与 `expires`（`YYYY-MM-DD`）。本片写出的文件要过这道校验——`allow-slow` 自己下次运行时就会先 `load_tiers`。

## 怎么做

TDD：`tests/test_budget_allow_cli.py` 的 2 条骨架现在是红的。

1. `main` 里给 `allow-slow` 的子解析器加：
   - `--limit-sec`（`type=float`）；
   - `--expires`（字符串）。
2. `cmd_allow_slow`：在读转录**之前**校验参数，不合法 → `fail(原因)`（退出码 2，不写文件）：
   - `--limit-sec` 给了且不大于 0 → 文本含「须大于 0」；
   - `--expires` 给了但 `datetime.date.fromisoformat` 解析不了（或不是 `YYYY-MM-DD` 的形状）→ 文本含「不是真实日期」；
   - `--expires` 早于今天（UTC 日期）→ 文本含「早于今天」；等于今天可以。
   - 骨架断言三次的 stderr 依次含「大于 0」「日期」「早于今天」。
3. 证据成立后写条目：`{"reason", "approved"}` 之外，给了 `--limit-sec` 就加 `"limit_sec"`，给了 `--expires` 就加 `"expires"`。
   - `limit_sec` 是整数值时写成整数（`90.0` → `90`）：骨架断言 `allow[BIG]["limit_sec"] == 90`，整数与浮点相等都能过，但写成整数分层文件更干净。
4. 两个参数都没给：照常写入、退出 0，并往 **stderr** 打一行：`提示：这条放行没有上限也没有到期日（可加 --limit-sec / --expires）`。stdout 仍只打印那一行 JSON。
5. 文件头的子命令说明把 `allow-slow` 那一条改成带上两个可选参数，退出码说明里 2 的情形补上「--limit-sec / --expires 不合法」。

## 注意

- `fail()` 的缺省退出码就是 2。
- 不要给 `--expires` 设缺省值（design D11）。
- 骨架第一条在放行之后跑了一次 `test-tiers.py check`，要求退出 0：写出的文件必须仍然合法（被测仓库里没有测试文件，check 本身不会点名）。
- `tests/test_tiers_cli.py::test_allow_slow_requires_latest_human_message` 钉着不带新参数时的行为（退出码、`reason`、`approved`），必须保持全绿；它没有断言 stderr。

## 解锁

去掉 `tests/test_budget_allow_cli.py` 2 个用例的 `@PENDING`，`PENDING` 不再使用时连同定义与 `import pytest` 一起删除。MUST NOT 改断言与函数名。verify 里其余文件不在本片 owns 内，必须保持全绿。
