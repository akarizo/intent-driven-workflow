# S1 · test-ledger.py：预算判定、预算变更比较、报告的预算段

## 做什么

在 `template/.claude/hooks/test-ledger.py` 里加两个纯函数 `budget` 与 `budget_changes`，让 `render` 认对账结果里的 `budget`，并把对账里两个噪声项（「变慢」与「某层耗时上涨」的建议行）改成不对区域用例计数。规则原文见 `specs/tier-budgets/spec.md` 的三条 Requirement：「集成层单条上限按棘轮判」「层总量预算按账本里逐用例耗时之和判」「预算结论进测试变更，预算与放行的改动可见」；取舍见 `design.md` D3、D5、D7、D8。

签名与返回形状见 `slices/_interfaces.md` 的 S1 一节，**照那里的键名写**，S4 / S5 与骨架都按它取值。

## 怎么做

TDD：`tests/test_budget_core.py` 的 11 条骨架现在是红的。

1. **`budget(final, base, budgets, scope_of, allow=None, phase="final")`**
   - 给 `final["cases"]` 的每条用例算范围：`scope_of(用例 id, c.get("t"))`；范围不在 `budgets` 里的用例不参与任何判定。
   - **id 对齐**：`base` 与 `final` 的 `id_form` 不同时，照 `delta()` 现有的做法把 nodeid 那一份用 `_to_junit` 换成 junit 形式再比。`allow` 的键是 nodeid：`final` 是 junit 形式时把键换算后再查。
   - **集成层单条**（范围 `kind == "region"`）：
     - 只看 `m == 1` 且 `s` 不是 `None` 的用例；
     - 线：该用例有放行且 `expired` 为假 → `limit`（为 `None` 表示不设线）；否则范围的 `case_sec`（为 `None` 表示不判）；
     - 用例耗时超过区域的 `case_sec` 但没超过放行的线 → 计入 `allowed_n`，另出一条警告 `G13 已放行：<id> <秒>s（<approved>）`；
     - `s > 线` 时分类：
       - `phase == "baseline"` → 老债；
       - `phase == "final"` 且 `base` 为 `None` 或 `base.get("complete") is False` → 不分类，整份结果 `judged = False`、`why` 写原因（「基线账本不在本机」/「基线账本不完整」），按范围各出一条警告 `G13 未判：<why>（集成层超线只警告）：区域 <范围> 有 <n> 条超线，最慢 <id> <秒>s`；
       - 用例不在 `base` 里 → `new`，`failed` 加一条：
         `G13 slow integration test: <id> <秒>s（区域 <范围> 单条上限 <线>s，本 change 新增）：提速、拆小，或由人类放行（test-tiers.py allow-slow --limit-sec）`；线来自放行时把「单条上限」换成「放行上限」；
       - 在 `base` 里且 `base` 的耗时不是 `None` 并大于区域的 `case_sec` → `debt`；
       - 其余（在 `base` 里）→ `cross`。
     - 警告按范围聚合，各一条：
       - `G13 老债：区域 <范围> 有 <n> 条用例基线时已超线（单条上限 <线>s，未判红）：最慢 <id> <秒>s`
       - `G13 本次量到超线：区域 <范围> 有 <n> 条用例基线时未超线（单次测量不足以区分噪声，未判红）：<id> <秒>s`
   - **层总量**（`budgets` 里每个范围都进 `totals`）：
     - `cases` / `sec` / `no_sec` 统计该范围在 `final` 里的全部用例（实测与沿用都算，`s` 为 `None` 的不计入 `sec`）；`sec` 保留 1 位小数；
     - `top`：耗时最大的至多 3 条 `[id, 秒]`；
     - `added_sec`：不在 `base` 里的用例耗时之和（保留 1 位）；`base` 不可用（`None` 或不完整）或 `phase == "baseline"` → `None`；
     - `total_sec` 为 `None` → `over = None`，不出警告；
     - 否则若 `final.get("complete") is False`，或 `cases > 0 and no_sec / cases > NO_SEC_RATIO` → `over = None`，出一条 `G14 未判：<范围> 的账本不完整` 或 `G14 未判：<范围> 有 <no_sec> 条用例无耗时（共 <cases> 条）`；
     - 否则 `over = sec > total_sec`。超了：
       - `kind == "unit"` → `failed` 加 `G14 tier budget: <标签> 合计 <sec>s，超过总量预算 <total_sec>s：最慢 <id> <秒>s、…`；标签：范围 `unit` → 「单元层」，范围 `<部件>/unit` → 「部件 <部件> 的单元层」；
       - `kind == "region"` → `warnings` 加 `G14 区域 <范围> 合计 <sec>s，超过总量预算 <total_sec>s（只警告）：本 change 新增 <added_sec>s；最慢 <id> <秒>s、…`；`added_sec` 为 `None` 时省掉「本 change 新增…；」这一段。
   - **放行名单概况** `allow`：对整份 `allow`（不只本次超线的）统计 `total`、`expired`（用例 id 列表，按原键）、`soon`（`[id, expires]`）、`unlimited`（未过期且 `limit` 为 `None` 的条数）。`allow` 为 `None` → 全 0 / 空。
   - 秒数的写法：用例与合计用 `%.1f`；线与预算用 `%g`（`30.0` 写成 `30`，`0.4` 写成 `0.4`）。骨架按子串断言 `42.0`、`15.0`、`130.0`、`新增 12.0s`、`10`、`100`。
   - 明细清单（`new` / `debt` / `cross`）各至多 `TOP_N` 条，按耗时由大到小；`*_n` 是总数。
2. **`budget_changes(old_budgets, new_budgets, old_allow, new_allow)`** → 文本行：
   - 范围取两边的并集（排序）；缺的一边按 `case_sec` / `total_sec` 都是 `None` 处理；
   - 数值不同才出一行：`<范围> 单条上限 <旧> → <新>（放宽|收紧）` / `<范围> 总量预算 <旧> → <新>（放宽|收紧）`；数值写 `%gs`，`None` 写「未设」；新值为 `None` 或更大 → 放宽，否则收紧；
   - 放行：只在新版里的 → `放行新增 <id>（上限 <x>s · 到期 <日期>）`，没有的写「无上限」「不过期」；只在旧版里的 → `放行移除 <id>`；两版都有且 `limit_sec` 或 `expires` 不同 → `放行改动 <id>：上限 <旧> → <新>；到期 <旧> → <新>`（只写变了的那一半）；`reason` / `approved` 的变化不算；
   - 没有变动 → `[]`。
3. **`render(d)`**：`d.get("budget")` 为真时，在现有全部输出之后追加（没有内容的行不出）：
   - `new` 里每条一行：`- 新增超线：<id> <秒>s（<范围> 上限 <线>s）`（骨架要求「新增超线」与用例 id 在同一行）；`new_n` 多于明细条数时再加一行 `- 新增超线另有 <n> 条`；
   - `- 老债 <n> 条 · 本次量到超线 <n> 条（未判红）`（两个数都是 0 时不出）；
   - 每个 `budget` 不是 `None` 的范围一行：`- 预算 <范围>：<sec>s / <budget>s`，`over` 为真时加「（超预算）」，为 `None` 时加「（未判）」，`added_sec` 不是 `None` 且大于 0 时加「 · 本 change 新增 <x>s」；
   - `- 放行：共 <n> 条 · 已过期 <n> 条（<id>、…）· 14 天内到期 <n> 条 · 无上限 <n> 条`（`total` 为 0 时不出）；
   - `changes` 非空 → `- 预算变更：` 加逐条 `  - <行>`；
   - `judged` 为假 → `- 集成层单条未判：<why>`。
   - 骨架断言 `"\n".join(带预算段的行).startswith(不带预算段的输出)`：只能往后追加，不能改前面任何一行。
4. **两个噪声项收窄**：
   - `delta()`：计「变慢」时跳过层为区域的用例，即 `c.get("t")` 不是 `None` 且不等于 `UNIT_TIER` 的；单元层与未分层（`t` 为 `None`）照旧。
   - `advice()` 规则 2（某层耗时上涨）：只对 `UNIT_TIER` 与 `NO_TIER` 两个层给出。
   - 阈值常数不动。`tests/test_ledger_delta.py` 现有 6 条必须保持全绿（它们的「变慢」用的是未分层与单元层用例）。
5. 文件头的模块接口注释补上这两个函数。
