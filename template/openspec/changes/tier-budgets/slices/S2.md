# S2 · slice-gate.py：分层文件的预算形状、范围摊平、单元层 G10 的线与放行边界

## 做什么

让 `template/.claude/hooks/slice-gate.py` 认识分层文件里的 `budget` 与放行条目的 `limit_sec` / `expires`，提供三个供后续切片与 C6 使用的函数（`tier_budgets` / `budget_scope_of` / `allow_view`），并让单元层 G10 用预算里的线、认放行的上限与期限。规则原文见 `specs/tier-budgets/spec.md` 的「分层文件可声明时间预算与放行期限」「单元层单条上限取预算，放行带上限与期限」；取舍见 `design.md` D1、D2。

没写新字段的分层文件，行为与文本一个字都不能变。

## 提供的接口

见 `slices/_interfaces.md` 的 S2 一节。

## 怎么做

TDD：`tests/test_budget_shape.py` 的 9 条骨架现在是红的。

1. **形状校验**（`_load_tiers_file` / `_parts_shape` / `_tier_shape`）：
   - 四处字段白名单各加 `"budget"`：简写形态的 `unit`、区域；部件形态的 `unit`、区域。
   - 新函数校验 `budget`（在 `_tier_shape` 里调用，标签沿用它的 `label`）：
     - 必须是对象 → 否则 `tiers: <label> 的 budget 须是对象（case_sec / total_sec）`；
     - 未知字段 → `tiers: <label> 的 budget 有未知字段 <k, …>`；
     - `case_sec` / `total_sec` 写了就必须是大于 0 的数（`bool` 不算）→ 否则 `tiers: <label> 的 budget.<字段> 须是大于 0 的数`。
   - 骨架按子串断言：`tiers:` 开头、含 `unit` 或 `区域 hooks`（部件形态含 `部件 py` 与 `区域 api`——现有 label 已经是「部件 py 的区域 api」）、含字段名（`case_sec` / `total_sec` / `max`）。
   - `slow_allow` 条目的字段白名单加 `limit_sec`、`expires`：
     - `limit_sec` 写了须是大于 0 的数 → 否则 `tiers: slow_allow 的 <nid> 的 limit_sec 须是大于 0 的数`；
     - `expires` 写了须能被 `datetime.date.fromisoformat` 解析且形如 `YYYY-MM-DD` → 否则 `tiers: slow_allow 的 <nid> 的 expires 须是 YYYY-MM-DD 的真实日期`。
   - 现有的错误文本（「须是对象（reason / approved）」等）不改。
2. **`tier_budgets(tiers)`**：遍历 `tier_parts(tiers)`（简写形态是单个部件 `main`）：
   - 简写形态：范围 `unit`；部件形态：范围 `<部件名>/unit`，`part` = 部件名；
   - 各区域：范围 = 区域名，`part` 同上；
   - 值 `{"kind", "case_sec", "total_sec", "part"}`；单元层 `case_sec` 缺省 `UNIT_MAX_SEC`。
3. **`budget_scope_of(tiers)`** → 函数 `(用例 id, 层)`：
   - 层为 `None` → `None`；层不等于 `"unit"` → 原样返回；
   - 简写形态 → `"unit"`；
   - 部件形态：id 里第一个 `::` 之前那段若恰等于某个部件名 → 该部件；否则把它当顶层路径，取 `root` 是其前缀（`root + "/"`）的部件里 `root` 最长的，`root` 为 `.` 的部件兜底；定不出 → `None`；返回 `<部件>/unit`。
4. **`allow_view(allow, today=None)`**：见接口。`today` 缺省 `datetime.datetime.now(datetime.timezone.utc).date()`。`expires` 解析不了的条目按没有期限处理（形状错由 lint 管）。
5. **`tier_verdicts` / `slow_candidates` / `part_tier_verdicts`** 加 `case_sec`（缺省 `UNIT_MAX_SEC`）与 `today`（缺省 `None`）：
   - 候选与确认都用 `case_sec` 比；
   - 失败文本里的 `（≥3s）` 改成 `（≥%ss）` 并用 `%g` 填线——线是 3.0 时文本仍然是 `≥3s`（旧测试钉着），1.0 时是 `≥1s`，0.1 时是 `≥0.1s`；
   - 确认了的用例在 `allow` 里时，用 `allow_view({nid: allow[nid]}, today)[nid]` 判：
     - `expired` → 失败：`G10 slow unit test: <nid> 首跑 <x>s，重跑 <y>（≥<线>s）：放行已于 <expires> 到期，重新放行（test-tiers.py allow-slow）、提速或移入集成区域`；
     - `limit` 不是 `None` 且确认耗时（有重跑取 `min(首跑, 重跑)`，否则首跑）大于它 → 失败：`G10 slow unit test: <nid> 首跑 <x>s，重跑 <y>：超过放行上限 <limit>s，提速或重新放行（test-tiers.py allow-slow --limit-sec）`；
     - 否则 → 现有的放行警告原文；`soon` 为真时在末尾加 `，放行将于 <expires> 到期`。
   - 部件版文本照旧带「部件 <name>：」。
   - 三个失败文本都以 `G10 slow unit test` 开头（`_time_verdicts` 靠这个前缀降级）。
6. **接线**（让线真的生效）：
   - `_unit_tier_verdict(root, gate, tg, allow, case_sec=UNIT_MAX_SEC)`：把 `case_sec` 传给 `slow_candidates` 与 `tier_verdicts`；
   - `cmd_baseline` 一处、`cmd_final` 两处调用 `_unit_tier_verdict` 的地方传入 `tier_budgets(tiers)["unit"]["case_sec"]`；
   - `part_tier_verdict(top, name, part, res, allow)`：线取 `(part["unit"].get("budget") or {}).get("case_sec") or UNIT_MAX_SEC`，候选筛选与 `part_tier_verdicts` 都用它。
   - `_tier_rerun` 不用动（它只负责重跑给定的 nodeid）。
7. 文件头注释里 baseline / final 关于 G10 的说明各补半句「线取分层文件的 `unit.budget.case_sec`，缺省 3 秒」。

## 注意

- 旧调用方式必须照常工作：`tests/test_tiers_verdict.py` 以四个位置参数调用 `tier_verdicts`；`tests/test_tiers_parts_runner.py` 以四个位置参数调用 `part_tier_verdicts`。
- `tests/test_tiers_plan.py` / `tests/test_tiers_parts_plan.py` 钉着未知字段的报错（字段 `cover`、`extra`）：白名单只加 `budget`，别的不放开。
- 分层指纹（`_tiers_key` / `_tiers_detail`）不动：`budget` 写在 `unit` 条目里会改变指纹，这是设计（design「在役 ADR」一节）。
- `test_unit_case_budget_applies_in_baseline` 是端到端的：单元层用例睡 0.3 秒、线 0.1 秒，baseline 要红在 G10 且文本含 `≥0.1s`。它同时验证第 6 步的接线。
- 本片不做预算判定的接入（G13 / G14），那是 S4。
