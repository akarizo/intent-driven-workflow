在 `template/.claude/hooks/test-ledger.py` 里加对账：拿 final 账本对基线账本，得出「测试变更」，并提供时间线片段、Markdown 渲染、建议行与 `delta` 子命令。规则原文见 `specs/test-ledger/spec.md` 的「final 账本与基线账本对账得出测试变更」，决策见 `design.md` D7、D8、D11。

全部只报告：本片不产生任何判红，也不碰 `slice-gate.py`。

## 依赖的接口

## 怎么做

TDD：`tests/test_ledger_delta.py` 的 5 条骨架现在是红的。

1. 常量（都标「草案」）：`SLOW_RATIO = 2.0`、`SLOW_MIN_SEC = 0.5`、`TIER_GROWTH_RATIO = 0.2`、`TIER_GROWTH_MIN_SEC = 5.0`、`NO_SEC_RATIO = 0.1`、`TOP_N = 5`。
2. `delta(base, final, rerun_files=None, root=None) -> (dict | None, str | None)`：
   - `base is None` → `(None, "基线账本不在本机（或基线早于测试账本）")`；
   - `base["id_form"] != final["id_form"]` → 把 `nodeid` 形式的那一份换算成 `junit` 形式再往下对（复用 S1 里 nodeid → `classname::name` 的那个换算函数；换算后重名的并成一条，后者覆盖前者）；此时判「文件是否存在 / 是否在 `rerun_files` 里」按 junit 形式求文件；
   - **新增**：在 final 不在 base。
   - **删除**：在 base 不在 final，且满足其一——`final["mode"]` 是 `full` 或 `parts`；`root` 给了且该用例的文件在 `root` 下不存在；该文件在 `rerun_files` 里。
   - 其余在 base 不在 final 的计入 `unknown`。
   - **变慢**：两边都有，`final` 里 `m == 1`，两边 `s` 都不是 `None`，`final.s >= base.s * SLOW_RATIO` 且 `final.s - base.s >= SLOW_MIN_SEC`。
   - 返回的 dict：
     ```
     commit, base_commit, mode（final 的 mode）,
     added, removed, unknown,
     slower_n, slower: [[id, 前, 后], …]（按变慢的秒数由大到小，至多 TOP_N 条）,
     added_sec（新增用例耗时之和，1 位小数，None 不计）,
     top_added: [[id, 秒, 层], …]（按耗时由大到小，None 排最后，至多 TOP_N 条）,
     inherited（final 里 m == 0 的条数）, no_sec（final 里 s 为 None 的条数）, cases（final 的用例数）,
     complete（final 的 complete）,
     tiers: {层: {"before": [条数, 秒], "after": [条数, 秒]}}（层取两边的并集，没有层的归 "-"，秒 1 位小数）,
     advice: advice(这份结果)
     ```
   - 为了让 `advice` 的规则 1 算得出来，结果里另带 `added_by_tier: {层: 秒}`（新增用例按层的耗时之和）。
3. `advice(d) -> [str]`（固定规则，零 token；都不满足返回 `[]`）：
   1. `added_by_tier` 里非 `unit`、非 `-` 的层耗时之和 > `unit` 的 → 一行「新增耗时主要在集成层（集成 X.Xs · 单元 Y.Ys）：最慢 <top_added 里第一条非 unit 用例的 id> Z.Zs」；
   2. 对每个层：`after 秒 - before 秒 >= TIER_GROWTH_MIN_SEC` 且 `after 秒 >= before 秒 * (1 + TIER_GROWTH_RATIO)` → 一行「<层> 层耗时 A.As → B.Bs」，后面接该层在 `top_added` / `slower` 里出现的至多 3 条用例 id；
   3. `cases > 0` 且 `no_sec / cases > NO_SEC_RATIO` → 一行「N 条用例无耗时（沿用自没有账本的锚点，或 junit 缺 time）：跑一次全量即可补齐」。
4. `segment(d) -> str`：`"用例 +%d/-%d（新增 %.1fs）" % (added, removed, added_sec)`。`parse_segment(note) -> {"added", "removed", "added_sec"} | None`：用正则 `用例 \+(\d+)/-(\d+)（新增 ([\d.]+)s）` 在整条备注里找。片段里不得出现 ` · `、「测试」「检查」「排队」。
5. `render(d) -> str`（Markdown，脚本生成，不经模型）：
   ```
   ## 测试变更

   - 新增 A 条（+X.Xs）· 删除 R 条 · 变慢 S 条[ · 未重测 U 条]
   - 沿用未实测 I 条 · 无耗时 N 条[ · 账本不完整]
   - 各层：<层> a 条 X.Xs → b 条 Y.Ys；…
   - 最慢新增：
     - <id> X.Xs（<层>）        ← 至多 TOP_N 条；没有新增就不出这一组
   - 变慢：
     - <id> X.Xs → Y.Ys          ← 至多 TOP_N 条；没有就不出这一组
   - 建议：<advice 的每一行>     ← 没有就不出
   ```
   第一行必须恰为 `## 测试变更`。
6. CLI：`delta --change-dir DIR [--markdown|--json]`：读 `load(root, change, "delta")`；缺省与 `--markdown` 打印 `render`，`--json` 打印原样；退出码 0 有 / 1 没有（打印含「没有对账结果」的一行）/ 2 `DIR` 不可用。文件头注释补上这个子命令。
