# S4 · slice-gate.py baseline 落账

## 做什么

让 `slice-gate.py baseline` 在写锚点之前把观测合成基线账本并存盘：`gate-baseline.json` 多一段 `ledger` 摘要，本次写出的锚点带 `secs`。账本出任何问题都只留一条警告。规则原文见 `specs/test-ledger/spec.md` 的「baseline 写基线账本，锚点带上逐用例耗时」，决策见 `design.md` D1、D4、D6、D9、D10。

## 依赖的接口

见 `slices/_interfaces.md` 的 S1、S2 两节：

- S1 `test-ledger.py`：`build(meta, observations, universe=None, source=None, rerun_files=None, root=None, tier_of=None)`、`from_anchor(anchor)`、`secs_of(ledger)`、`summary(ledger)`、`save(root, change, name, obj)`、`load(root, change, name)`。
- S2 `slice-gate.py`：`ledger_observations()`；`run_test_gate` / `_pytest_outcomes` / `run_part` 已经在上报。

## 怎么做

TDD：`tests/test_ledger_baseline.py` 的 5 条骨架现在是红的。

1. **加载**（照 `_load_flight_lock` 的写法，放在它旁边）：`_ledger_mod()` 按路径加载同目录的 `test-ledger.py`，缓存结果；文件缺失、加载失败 → 返回一个字符串（原因）。
2. **落账函数**（S5 也用，签名定在这里）：
   ```python
   def _ledger_commit(root, name, meta, tiers, universe=None, source=None, rerun_files=None):
       """→ (账本 | None, 警告 | None)。meta = {"commit", "phase", "mode", "lock"}；内部补上 change 与 at。
       整体包在 try 里：模块不可用或任何异常 → (None, "测试账本未写：<原因>")。"""
   ```
   - `tier_of`：`tiers` 不为 `None` 时用 `lambda f: (tiers_matching(f, tiers, root) or [None])[0]`，否则 `None`；
   - `build(meta, ledger_observations(), universe, source, rerun_files, root, tier_of)` → `save(root, name, meta["phase"], 账本)` → 返回账本。
   - 再加两个小工具：`_ledger_secs(led)`——账本存在且 `id_form == "nodeid"` 时返回 `secs_of(led)`，否则 `None`；`_ledger_source(root, change, commit)`——`load(root, change, "baseline")` 读到且其 `commit == commit` 时返回它，否则 `None`（模块不可用也返回 `None`）。
3. **`cmd_baseline` 的落账点**：紧挨着写锚点的那个分支（`if hit is None and not parts:` … `elif apart is not None:`）**之前**。按现有变量分四种情形：

   | 情形 | 判别 | `mode` | `universe` | `source` | `rerun_files` |
   |---|---|---|---|---|---|
   | 全量 | `hit is None and not parts` | `full` | `adeps` 不为 `None` 时取 `_nodes_lower(adeps["nodes"])`，否则 `None` | `None` | `None` |
   | 经锚点 | `apart is not None` | `incremental` | `apart["nodes"]`（为空 dict 时传 `None`） | `from_anchor(src["pick"][0])` | `hit["rerun_files"]` |
   | 复用旧基线 / 基线池 | `hit is not None and apart is None` | `incremental` | `None` | `_ledger_source(root, src.get("change"), src.get("commit"))` | `hit["rerun_files"]` |
   | 部件形态 | `parts` | — | — | — | — |

   - **部件形态本片不落账**（它的 scenario 在 S5，由 S5 加上）。
   - `meta["commit"] = bl["commit"]`，`meta["lock"]` 取本次锁的状态（`hold.info.get("state")`）。
   - 「复用旧基线」时来源就是本 change 即将被覆盖的那份 `baseline.json`：`_ledger_source` 的读取发生在 `save` 之前，顺序天然正确，不要调换。
   - 返回的警告追加进 `warnings`；账本存在时 `bl["ledger"] = summary(账本)`。
   - 基线红（`reasons` 非空）也照常落账。
4. **锚点带 `secs`**：
   - 全量那处 `_anchor_write({...})` 的字典加 `"secs": _ledger_secs(led) if measured else None`；
   - 经锚点那处 `dict(apart, …)` 加 `secs=_ledger_secs(led)`。
   - 其余字段与写入条件不变。字典字面量旁加一行 `# ceiling: secs 让锚点文件变大，选锚点变慢时挪到旁路文件 -> 把 secs 存到 flight-ledger/ 下按锚点文件名对应的文件`。
5. `gate-baseline.json` 的其它键、时间线备注、退出码都不动。文件头注释里 `baseline` 的说明补一句「写基线账本（见 test-ledger.py），`ledger` 为摘要」。

## 注意

- `tests/test_ledger_baseline.py::test_reused_baseline_keeps_source_ledger` 走的是「依赖图未测 + 复用旧基线」：第一次全量的观测是 junit 形式，第二次补跑经 `_pytest_outcomes`（nodeid 形式），靠 S1 的 `build` 在来源是 junit 形式时把 nodeid 观测换算并入。本片只要把来源账本原样传进去。
- `test_ledger_failure_does_not_fail_baseline` 用一份不含 `test-ledger.py` 的 hooks 副本：此时 `bl` 不得有 `ledger` 键，锚点的 `secs` 为 `None`，`warnings` 里那条必须以「测试账本未写」开头。
- 观测表里会混有被拒绝的复用候选的补跑结果，这是预期的（design D3）：同一棵树上的实测都算数。

## 解锁

去掉 `tests/test_ledger_baseline.py` 五个用例的 `@PENDING`，`PENDING` 不再使用时连同定义与 `import pytest` 一起删除。MUST NOT 改断言与函数名。verify 里其余文件不在本片 owns 内，必须保持全绿（原型上已确认 `bl["ledger"]` 与锚点的 `secs` 不会让它们变红）。
