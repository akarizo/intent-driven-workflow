# S2 · 判定器：基线池与跨 change 复用

**做什么**：把全绿的全量写进 git common dir 下的基线池，`baseline` 从池里取候选，实现跨 change 复用。语义见 `specs/baseline-incremental-reuse`（跨 change 复用全量一节）与 design D5。

**owns**
- `template/.claude/hooks/slice-gate.py`
- `tests/test_baseline_pool.py`

**参考实现**：原仓 `855b834` 的 `POOL_DIR`、`POOL_KEEP`、`_pool_dir`、`_pool_order`、`_pool_read`、`_pool_write`、`_pool_candidates`，以及 `cmd_baseline` 末尾的写池分支。取法见 `slices/S1.md`。

**做法**
1. 逐条去掉 `tests/test_baseline_pool.py` 里 6 条 S2 xfail 标记，先红后绿（TDD）。
2. 移入池相关常量与函数，并按本仓改写：
   - **入池条件**：`mode == "full"`、`ok`、`test.exit == 0`、`cmd_key` 非空。后两条是本仓新增：带预存红的全量跨 change 用不上，指纹为空的匹配不到。
   - **条目字段**：`change`、`commit`、`at`、`ok`、`cmd_key`、`snapshot`、`byproducts`、`test`（比原仓多 `byproducts`，供跨 change 的 Δ 排除对方副产物）。
   - **清理**：按 at 保留最新 30 条；同时删除 `.tmp-` 开头、mtime 早于一小时的文件，遇 `FileNotFoundError` 忽略。
   - **写池失败**（含池路径是普通文件）：返回警告「基线池写入失败（不影响本次基线）：…」，追加进 `warnings`。
   - **读池**：坏 JSON 跳过；池不可读（不存在 / 不是目录）返回 `[]`。
3. `_baseline_candidates`（S1 定义）在本 change 旧基线之后追加 `_pool_candidates(root, key)`（`--full` 时不取，最多 10 条，按 at 由新到旧）。
4. 池候选中 `change` 等于本 change 的，按同一 change 计 Δ（`same_change=True`）；verify 的「上一次」只取本 change 的 `gate-baseline.json`（`src is own`）。跨 change 时全部重跑。
5. 跨 change 且 `test.exit != 0` 的拒绝分支已在 S1 写好；入池收紧后它主要防御旧池条目。

**依赖切片的接口**（来自 S1）
- `_baseline_candidates(root, old, key, name, full)`、`_try_reuse(..., rerun_cache) -> (hit, reason, abort)`、`_delta(...)`、`_snapshot(...)`、`cmd_key(...)`；
- `cmd_baseline` 中 `bl` 的字段：`change`、`mode`、`snapshot`、`cmd_key`、`byproducts`、`test`。

**verify**：`python3 -m pytest -q tests/test_baseline_pool.py tests/test_baseline_incremental.py`

**注意**
- 写池先 `tempfile.mkstemp(dir=池目录, prefix=".tmp-", suffix=".json")` 再 `os.replace`。
- `compileall` 绿；只用标准库。
- 不改 `tests/test_baseline_incremental.py`（S1 所有）。
