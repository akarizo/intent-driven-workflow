# S1 · 判定器：内容指纹、同一 change 增量、preflight 按内容判过期（摘自原仓 #65，按本仓改写）

**做什么**：在 `slice-gate.py` 里落地以下能力，语义见 `specs/baseline-incremental-reuse` 与 design D1–D4、D6–D9、D12：
- 基线内容指纹；
- 同一 change 的增量复用；
- verify 按需重跑；
- preflight 按内容判过期，以 `timeline.md` 的 `approve` 事件为起飞判据；
- 运行期改动判定：副产物登记、软链、排除其他 change 目录；
- 补跑去重、`reuse_skipped`、git 失败不留半成品；
- timeline 增量行；
- `--full`。

不做：基线池与跨 change 候选（S2）、lint / typecheck 沿用与 verify 推导（S3）。

**owns**
- `template/.claude/hooks/slice-gate.py`
- `tests/test_baseline_incremental.py`
- `tests/test_slice_gate.py`
- `tests/test_slice_gate_baseline_preflight.py`
- `tests/test_slice_gate_final.py`

**参考实现**：原仓 `akarizo/intent-driven-claude-code` 的 `855b834`（#65）。

原仓 #65 之前的 `cmd_baseline` 与本仓逐行相同，差异可直接对照移植。

**做法**
1. 先去掉 `tests/test_baseline_incremental.py` 里一条 xfail 标记，看它红，再写实现（TDD）。逐条进行，19 条 S1 标记全部去掉。4 条护栏原本就不带标记，改完须仍绿。
2. 从 855b834 移入：
   - 常量 `PLAN_FILES`、`PLAN_DIRS`、`LS_TREE_BATCH`；
   - 函数 `_change_rel`、`_plan_file`、`_ignored`、`_git_raw`、`_hash_paths`、`_snapshot`、`_blobs_at`、`_repo_rel`、`cmd_key`、`_delta`、`_try_reuse`、`_verify_paths`、`_verify_rerun`；
   - `cmd_baseline` 与 `cmd_preflight` 的改动；`main()` 里 baseline 的 `--full`；
   - 文件头注释。

   **不移**：`_has_takeoff`（读账本）、`_pool_*` 与 `_pool_candidates`（S2）。
3. 按本仓改写：
   - **起飞判据**：新增 `_has_approve(change_dir)`：读本 change 的 `timeline.md`，任一行按 `\t` 切分后第 2 列等于 `approve` → True；文件不存在或读不出 → False。preflight 在基线有 `snapshot` 且 `not _has_approve(...)` 时按内容判（design D8）。
   - **软链**（D1）：`_snapshot` 对 `os.path.islink(full)` 的路径，用 `os.readlink` 取链接文本，经 `git hash-object --stdin`（stdin 为链接文本，不加换行）取 blob。其余普通文件照旧批量 `--stdin-paths`。
   - **副产物**（D1、D6）：
     - 基线记 `byproducts`（排好序的列表）；
     - 运行期比对前，先去掉 `<changes 根>` 下非本 change 的路径；
     - 判红：开始就存在、已跟踪或是测试文件的被改路径；
     - 只警告并登记：上一次基线（`old`，`--full` 时也要读）`byproducts` 里的非测试路径被改写，或新出现的非测试文件；
     - 上一次的 `byproducts` 里仍在 s1 中的路径继续保留；
     - `_delta` 不计候选 `byproducts` 中在候选 commit 与当前 HEAD 都未跟踪的路径。
   - **跨 change 全绿**（D3）：`_try_reuse` 里候选 `change` 与本 change 不同且 `test.exit != 0` → 不复用，理由含「预存红」。S1 时还没有跨 change 候选，S2 接入池后才会走到这一分支。
   - **补跑去重**（D3）：`cmd_baseline` 建 `rerun_cache = {}` 传给 `_try_reuse`。
     - 键：`tuple(sorted((路径, 当前 blob) …))`，取 Δ 中现存的测试文件；
     - 值：`(ok, 理由, sec)`；
     - `_try_reuse` 返回 `(hit | None, 理由, abort)`；补跑红、超时或退出码不是 0 / 5 时 `abort=True`，候选循环 `break` 直接走全量。
   - **候选列表**：写成独立函数 `_baseline_candidates(root, old, key, name, full)`，S1 只返回本 change 旧基线（有 `snapshot` 且非运行标记）。S2 在此追加池候选。
   - **reuse_skipped**（D9）：走全量且判过候选时，记至多 5 条 `{change, commit（前 12 位）, reason}`，写进 `gate-baseline.json`（随 stdout JSON 一并输出）。
   - **git 失败**（D12）：
     - 开跑前的 `_snapshot` / `cmd_key` 抛 `RuntimeError` → `die("内容快照失败：…")`，不写运行标记；
     - 候选 `_delta` 失败 → 该候选作废，进 `reuse_skipped`；
     - 结束快照失败 → 红基线，原因「基线结束时内容快照失败：…；重跑 baseline」；
     - preflight 里 `_snapshot` / `_delta` 抛错 → `die("基线内容比对失败：…；重跑 baseline")`。
   - **timeline 行**（D9）：本仓由 `cmd_baseline` 直接 `timeline_record`。
     - 增量：`增量（复用 <from.change> 的全量 exit e, s秒；补跑 n 个测试文件 t秒） ok|red`；
     - 全量：保持 `exit e, s秒 ok|red`（`exit` 取 `bl["test"]["exit"]`）。
4. `tests/test_slice_gate.py::test_baseline_writes_gate_baseline` 对 verify 的完全相等断言放宽为只比每片 `exit`。其余既有用例若只因新增字段或副产物警告而失效，按原语义做最小放宽；不得改变它们断言的行为。

**给后续切片的接口**（S2 / S3 依赖，签名保持）
- `_snapshot(root, change_rel) -> {路径: blob | None}`
- `cmd_key(root, change_rel, cmd) -> str | None`
- `_delta(root, cand, cur_snap, head, change_rel, same_change) -> [路径] | None`（S3 会加关键字参数 `strict=False`）
- `_try_reuse(root, change_dir, data, cand, cur_snap, key, rerun_cache) -> (hit | None, reason, abort)`
- `_baseline_candidates(root, old, key, name, full) -> [候选 dict]`（候选带 `change`）
- `cmd_baseline` 里的 `hit` / `src` / `own` 变量语义同原仓：`src is own` 表示候选是本 change 旧基线

**依赖切片的接口**：无。
