# S4 · 文档：propose 基线步骤与 README

**做什么**：`opsx-propose` 命令与同名 skill 第 5 步（基线门禁）写明以下内容；README 补一条。语义见 `specs/baseline-incremental-reuse`（记录与文档一节）。
- 增量条件；
- 跨 change 只复用全绿；
- verify 推导与 lint / typecheck 沿用；
- 改完计划重跑；
- `--full`；
- 增量的一行报告格式。

**owns**
- `template/.claude/commands/opsx-propose.md`
- `template/.claude/skills/openspec-propose/SKILL.md`
- `README.md`
- `tests/test_baseline_incremental_docs.py`

**做法**
1. 去掉 `tests/test_baseline_incremental_docs.py` 的 xfail 标记，看它红（TDD）。
2. 两份文件的第 5 步，在「baseline 运行期间改计划文件不会被覆盖……」那段之后、「baseline 结束（后台通知）时只报告一行」之前插入下面这段（两份逐字相同）：

   ```
      脚本自己判断跑全量还是**增量**，并跳过重复的运行：
      - 自上次基线以来代码树只有 `test_*.py` 变了（计划工件不计）、这些文件不含上次全量的预存红、且补跑这些文件不红 → 复用上次的全量结论，只补跑这些测试文件；verify 只重跑受影响的片；
      - **跨 change** 复用：同一仓库其他 change 跑过的全绿全量（没有预存红），命令指纹相同、代码树之差只有测试文件时同样复用；基线池在 git common dir 下；
      - 代码树完全没变、命令也没变时，lint / typecheck 沿用上次结论；
      - 全量是直接的 pytest 调用时，只跑若干测试文件的 verify 从全量的 junit 推导，不再单独运行。
      **改完计划后重跑 `slice-gate.py baseline`**，由脚本判全量或增量；模型不自行判断要不要重跑，preflight 会按内容判基线是否过期。
      `--full` 强制全量：仓外环境（数据仓、解释器）变了、被 source 的门禁脚本改了，或 lint 扫描本 change 计划工件目录时用。
   ```
3. 两份文件「退出 0 →」那一行改成：`- 退出 0 → 「基线绿（全量 N 秒；预存红 k 条）」或「基线绿（增量：复用 <change> 的全量，补跑 n 个测试文件 t 秒；预存红 k 条）」；`
4. README「**机械门禁**」表格之后加一段：`**基线增量复用**：改完计划后重跑 \`slice-gate.py baseline\` 时，只改了测试文件就复用上次全量、只补跑变了的测试文件；同仓全绿的全量跨 change 复用；代码树没变时 lint / typecheck 沿用；verify 能从全量 junit 推导时不再单独跑；\`--full\` 强制全量。`

**依赖切片的接口**：无（同 wave 的 S1 实现判定器；本片只写文档，行为以 spec 为准）。

**verify**：`python3 -m pytest -q tests/test_baseline_incremental_docs.py tests/test_template_docs.py tests/test_docs_iron_rules.py`

**注意**
- 命令与同名 skill 同改，提到的 hook 脚本集合必须一致（`test_command_skill_sync`）。
- 第 5 步原有的「后台」「报告一行」「preflight … 拒绝」「gate-baseline.json」「停下报告」「verify … 绿」等字样保留（`test_template_docs.py` 校验）。
- 不写日文假名 / 韩文谚文。
