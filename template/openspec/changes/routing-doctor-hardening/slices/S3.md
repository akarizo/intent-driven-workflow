## 怎么做

- **`model-routing.py`**（design D4）：
  - 新增 `DESC = {"组.键": "<一句话>"}`，文本照 design D4 的表逐字写；新增 `COMMENT`（顶层 `$comment` 的字符串），内容按 D4 写明：每个「组.键」是一个派发用途 · model 只写模型名（列 `MODELS`）· effort 取 `EFFORTS` · 删掉某键 = 走内建默认 · desc 只作说明 · 改 `cleanup.runner` 后在仓库根运行 `python3 .claude/hooks/model-routing.py frontmatter`；
  - `validate()`：顶层键 `$comment` 跳过（值须是字符串，否则报「$comment：必须是字符串」）；`check_value()`：有 `desc` 时须是字符串；
  - 新增子命令 `init [--openspec DIR]`，按 D4 的三态表实现；写出 `json.dumps(cfg, ensure_ascii=False, indent=2) + "\n"`，组 / 键顺序按 `REGISTRY`，`$comment` 放第一个；补全已有文件时保留已有键的原顺序，缺的追加；
  - 文件头用法注释加 `init` 一行；
  - 加一条一致性：`set(DESC) == set(BUILTIN)`（可在模块加载处 assert，或在测试里校验）。
- **`template/openspec/model-routing.json`**：在 `template/` 下运行 `python3 .claude/hooks/model-routing.py init --openspec openspec` 补全，提交结果；`flight.executor` 两档必须仍是 opus · medium。
- **`install.sh`**（design D5）：在「fork 命令路由」块之前加「路由配置」块：
  - 有 python3：`python3 "$TARGET/.claude/hooks/model-routing.py" init --openspec "$TARGET/openspec"`，成功 `log_info` 它的输出，失败 `log_err` 原样输出 + 一行「修好 openspec/model-routing.json 后在目标仓库根重跑：python3 .claude/hooks/model-routing.py init」，不改退出码；
  - 无 python3：`log_info` 提示装好后运行 `init`；
  - 第 521 行一带的收尾说明「缺省内建默认，仓库可写 openspec/model-routing.json 覆盖」改为「安装时种下 openspec/model-routing.json（11 键全写、每键带 desc），直接改值」。
- **`README.md`** 模型路由一节：「文件缺失或缺键走内建默认」之后补一句「安装与升级时 `model-routing.py init` 种下完整文件（11 键、每键带 `desc`），只补缺、不改已有值；内建默认以后变了，已写进文件的值不跟着变」。
