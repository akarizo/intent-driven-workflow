- `flight-doctor.py doctor` 恒 exit 0；新段名 `[routing]`，排在 `[tests]` 之后。

## 怎么做

1. **model-routing.py**（design D4）
   - `FRONTMATTER_RE` 改为 `re.compile(r"^---(\r?\n)(.*?)\r?\n---(\r?\n|\Z)", re.S)`：group 1 = 文件换行风格 `eol`，group 2 = 块内，group 3 = 收尾 `---` 后的换行（可能为空）。
   - `render_frontmatter`：块内按 `eol` 切分（`m.group(2).split(eol)`），拼接写成 `"---" + eol + eol.join(out) + eol + "---" + m.group(3) + text[m.end():]`。其余逻辑（只认 `context: fork`、缺字段时补在块尾）不变。
   - `cmd_frontmatter`：读用 `path.read_bytes().decode("utf-8")`，写用 `path.write_bytes(new.encode("utf-8"))`；`new == text` 时不写（现状）。
   - 文件头退出码段补一行：`exit 1  frontmatter --check 发现漂移（逐条点名「文件：字段 期望 x 实际 y」）`。
2. **flight-doctor.py**（design D3）
   - 新增 `doctor_routing(openspec_root)`：`subprocess.run([sys.executable, os.path.join(HOOKS_DIR, "model-routing.py"), "frontmatter", "--check", "--openspec", openspec_root], capture_output=True, text=True, timeout=60)`。
     - 返回 0 → `["[routing]", "  " + stdout 首行]`；
     - 返回 1 → `["[routing]"] + ["  " + l for l in stdout 非空行] + ["  修法：在仓库根运行 python3 .claude/hooks/model-routing.py frontmatter"]`；
     - 其他 / 抛异常（`OSError`、`subprocess.TimeoutExpired`）→ `["[routing]", "  不可用：" + stderr 首行或异常文字]`。
   - `doctor()` 末尾 `out += doctor_routing(openspec_root)`；文件头 CLI 说明的段列表补 `[routing]`，并加一行说明它调用 `model-routing.py frontmatter --check`。
3. **install.sh**（design D5）：第 428 行改为
   `log_err "修好 openspec/model-routing.json，或用 install.sh --upgrade 刷新 .claude/ 后，在目标仓库根重跑：python3 .claude/hooks/model-routing.py frontmatter"`；失败分支不改 rc。
4. **README.md**：路由一节「`--check` 只检查漂移、不写。」之后补一句：「`flight-doctor.py doctor` 的 `[routing]` 段也会报漂移（`install.sh --upgrade` 结束时自动体检）。」
5. **顺手清 LOW**：
   - `tests/test_routing_frontmatter.py`：删第 4 行孤儿 `import pytest` 及随之多出的空行。
   - `tests/test_install_routing.py`：docstring 改成「routing-frontmatter 与 routing-frontmatter-hardening 的 scenario 测试（已解锁）。」，去掉 import 区多余的空行。注意本片的新 scenario 也在这个文件里，解锁后文件里若不再用 `pytest` 就别留 import。
