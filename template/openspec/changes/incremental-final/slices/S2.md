# S2 · 判定器：增量 final、自动全量、同树沿用、ship 按树判新鲜

**做什么**：
- `cmd_final` 在 G7 绿后走三条路径之一：同树沿用 / 增量 / 全量；
- 输出 `incremental` 段，写 summary 与 timeline；
- 每次结束写锚点与 final 记录；
- `ship` 判 final 新鲜改按树比较。

语义见 `specs/incremental-final` 的「final 默认增量运行」「命中触发条件时 final 自动跑全量」「同一棵代码树的 final 沿用上次结论」与 design D4–D6、D10。

**owns**
- `template/.claude/hooks/slice-gate.py`
- `tests/test_final_incremental.py`
- `tests/test_final_reuse.py`

**依赖（S1 提供的接口）**
- `run_test_gate(cmd, root, probe=False, deps=False)` → 含 `deps` / `deps_why`；deps 形状 `{"deps", "blind", "files", "nodes"}`。
- `_pytest_outcomes(root, targets, gate=None, durations=None, deps_out=None)`。
- `_anchor_write(root, entry)`、`_anchor_candidates(root, cmd_key, tiers_key, limit=10)`；锚点字段见 design D3。
- `gate-baseline.json` 的 `test.failed_nodes`。
- 共用测试工具 `tests/final_helpers.py`：`make_repo`、`baseline`、`final`、`change_and_commit`、`anchors`、`latest_anchor`、`timeline_rows`、`head`。

**做法**
1. **TDD**：逐条去掉两份测试文件的 `XF` 标记，先红后绿。护栏 `test_red_final_is_not_reused` 原本不带标记，改完须仍绿。
2. **CLI**：`final` 子命令加 `--full`。
3. **同树沿用**（design D6）：
   - `FINAL_DIR = "flight-final"`；记录文件 `<git common dir>/flight-final/<change>.json`，原子写；
   - 指纹 `_final_fps(root, change_rel, data, tiers)`：`plan_sha`、`scenario_tests` 的 sha、`cmd_key` 分别对 `gate.test` / `lint` / `typecheck` / `impacted` 与每项 check 的 `final`、分层文件 blob；
   - `cmd_final` 最开头（取 dirty 之后）：记录存在、`result.ok` 为真、指纹全等，且 `_delta(root, rec, cur_snap, head, change_rel, True, strict=True)` 去掉记账文件后为空 → 输出沿用结果：
     - `commit` 为当前 HEAD；
     - `incremental = {"mode": "reused", "from": rec.commit}`；
     - `summary` 追加「；同树沿用 <rec.commit 前 10 位>」；
     - `append_report` 照常；timeline 备注 `同树沿用 <前 10 位> ok`；
     - 退出 0，不运行 G7 及其后的任何东西；
   - 每次 final 结束（绿或红）都写记录。
4. **`_final_fresh`**：去掉祖先判断，改用 `git diff --name-only <final> HEAD`；成功且只含记账文件（或为空）→ 新鲜；任何 git 失败 → 不新鲜。
5. **取锚点与 Δ**（design D3 / D4）：
   - `cur_snap = _snapshot(root, change_rel)`；候选 = `_anchor_candidates(...)` 里 `measured` 为真的；
   - 对每条算 `_delta(root, cand, cur_snap, head, change_rel, cand.change == 本 change)`，None 跳过；取 |Δ| 最小，同样小取 `at` 最新。
6. **自动全量的判定** `_full_why(...)`，按 spec 顺序取第一条命中的原因，文本须含：
   - `--full`；
   - 「没有可用锚点」；
   - 「基线缺 failed_nodes」；
   - 全局文件的路径；
   - 未见过的非 Python 文件的路径。

   全局文件清单与文档扩展名写成模块常量。未见过的 `.py`（非测试）只进 warnings：「Δ 中 n 个 .py 文件未被任何用例加载：…」。
7. **增量运行**（design D5）：
   - 选中集合按 spec 计算并排序；为空则不运行；
   - 否则 `_pytest_outcomes(root, files, gate, deps_out=d)`：
     - 判红：FAILED / ERROR 的 nodeid 不在基线 `failed_nodes` → `G2 test：新增失败 n 条：<nodeid, …>`；
     - 超时 → `G2 test：增量重跑超时`；
     - rc ∉ {0, 1, 5} → `G2 test：增量重跑 exit <rc>` 加 `_tail`；
   - `incremental = {"mode": "incremental", "source": "builtin", "anchor": {"change", "commit"}, "delta": len(Δ), "rerun": files, "rerun_tests": n, "inherited_tests": m}`；
   - 写新锚点：`source: "final-incremental"`；旧锚点的 deps / failed / files / blind 里属于重跑文件的部分换成本次结果，其余照抄。
8. **全量运行**：
   - 有分层时沿用今天的分层全量；
   - 无分层时把 `full_suite_verdict` 换成 `run_test_gate(test_cmd, root, deps=True)` 加原有差分；
   - `incremental = {"mode": "full", "full_why": ...}`；写锚点 `source: "final-full"`。
9. **输出**（design D10）：`summary` 与 timeline 备注按 spec 拼。增量：`增量（锚点 <10 位>，重跑 a 个文件 / 沿用 c 个用例） ok|red`；全量：`全量（<原因>） ok|red`。有 `tier_sec` 时插在结论词前，结论词恒在末尾。
10. 分层叠加的细节（只重跑选中的单元层文件并挂探针、区域按需运行）由 S3 实现。本片在有分层时：Δ 不触发全量时走增量，单元层用 `_pytest_outcomes` 重跑选中文件，区域一律照旧运行。S3 会收窄这一点。

**verify**：`python3 -m pytest -q tests/test_final_incremental.py tests/test_final_reuse.py tests/test_ship_verdict.py tests/test_slice_gate_final.py tests/test_tiers_gate.py tests/test_tiers_timing.py tests/test_gate_checks_final.py tests/test_evidence_timeline.py`

**注意**
- G7 每次照跑（沿用路径除外）；G7 红时不跑测试全量 / 增量与 checks，行为同今天。
- 既有 final 测试（`test_slice_gate_final.py`、`test_tiers_gate.py`、`test_gate_checks_final.py`）必须仍绿。它们的被测仓库多半没有锚点，会走全量，结论应与今天一致。
- `timeline.py` 不改；final 行的结论词仍在末尾。
- 守护测试做 mutation 自证：
  - 把选中集合改成「全部测试文件」，`test_final_reruns_only_affected_tests` 要变红；
  - 去掉全局文件判定，`test_final_full_when_global_file_changes` 要变红。
- 只用标准库，兼容 Python 3.8；`compileall` 绿。
