Why · 01为何而做

C3 原定在机械命令的 frontmatter 写 model: sonnet，让主会话跑这些命令的那一轮换成便宜模型（审批页 docs/flight-routing-config.html v4 第 07 节，「先探针」）。2026-11-20 的探针与本机 3 周真实转录推翻了这个做法：

- 探针 1（问询之后是否仍生效）：frontmatter 的 model / effort 在同一轮内跨过 AskUserQuestion 仍然生效，下一条人类消息恢复会话模型。 - 探针 2（切一次模型的账）：切模型那一轮的首个请求整段不命中缓存，回到会话模型时还要重写这一轮新增的内容。frontmatter 引起的切换不触发 PreModelSwitch / PostModelSwitch hook（阳性对照：SDK 的 set_model 能触发），所以没法按缓存冷热决定切不切。只改 effort 不丢缓存（Opus 5.5 · 一方 API）。 - 真实账（2026-10-29 → 11-19，37 次直接调用，按官方价）： - 会话缓存还热的 18 次，切到 sonnet 后成本接近翻倍（−96%）；已凉的 19 次省 48%；合计只省 17%。 - 输出只占这些轮次成本的 10%，只降 effort 最多省约 5%。 - 7 个机械命令里，只有 /clean-after-merged（31 次）、/test-tiers（5 次）、/opsx-archive（1 次）被直接敲过。 - 探针 3（context: fork）：命令改在一个不继承对话的子 agent 里跑。主会话那一轮一个请求都不发，子 agent 的输出直接作为命令输出交给用户。frontmatter 的 model / effort 落在子 agent 上，并且压过 CLAUDE_CODE_SUBAGENT_MODEL；参数照常传入。 - 代价：子 agent 看不到对话历史，也不能问询（子 agent 工具集不含 AskUserQuestion）。 - /clean-after-merged 两条都满足：参数只有可选的 target，判定全在 merged-cleanup.py。按 31 个样本模拟，成本 $50.8 → $7.9（−84%），缓存冷热两种情况都省。

用户 2026-11-20 的选择（grill-me 访谈，均为推荐项）： - C3 方向：只把 /clean-after-merged 改成 context: fork，其余机械命令不写 model，改正过时的切模型建议，决策写进 ADR； - 模型值来源：登记路由键，由脚本按配置渲染进 frontmatter。原因是 install.sh --upgrade 会刷新 .claude/，下游手改的值会被冲掉。

What · 02变更范围

  • 路由注册表新增 cleanup.runner（内建默认 sonnet · low）：执行层键从 10 个变为 11 个。show / get 照常可用；它不进 slices.json.routing，不参与起飞与收口对账。
  • model-routing.py 新增子命令 frontmatter [--check] [--openspec DIR] [--commands DIR]：把生效的 cleanup.runner 写进 clean-after-merged.md frontmatter 的 model / effort 两行，其余行原样保留。
  • --check 只比对不写，漂移时退出 1；
  • 配置非法、命令文件缺失，或命令不是 context: fork 形态时退出 2，不写文件。最后一条用来防止误把主会话命令渲染成切模型。
  • install.sh 安装与升级末尾自动重渲：复制完 .claude/ 后，按目标仓库的 openspec/model-routing.json 运行一次 frontmatter。失败只打印警告，不中断安装。
  • /clean-after-merged 改为 context: fork 子 agent 运行：frontmatter 增加 context: fork、agent: general-purpose、background: false、model、effort。正文写明三点：看不到对话历史；不问询；最后一条回复就是交给用户的全部汇报，manual 档命令放进代码块。步骤、脚本判定与 Guardrails 不变。
  • 改正过时的切模型建议：opsx-sync / spec-html / claudemd-commit / opsx-explore 四个命令里的「先 /model sonnet 再跑，省约 5× token」统一换成一行事实说明，并指向新 ADR。理由有两条：现价 Opus 5.5 与 Sonnet 5.5 只差 2 倍；中途切换会丢缓存，回切还要再付一次。
  • 不变式测试：
  • 命令与 skill 的 frontmatter 只有 context: fork 形态才允许写 model；
  • context: fork 的命令集合等于注册表登记的集合；
  • 规划类命令与 skill 不写 context；
  • 命令与 skill 里不再出现 /model sonnet 建议；
  • 本仓库（自举）的路由配置不覆盖 fork 命令的键，模板里的 frontmatter 与内建默认一致。
  • 文档：README 路由表与 docs/WORKFLOW_zh.md 的键清单登记 cleanup.runner 和 frontmatter 子命令。
  • 新 ADR：DRAFT-mechanical-commands-run-in-isolated-subagent，部分取代 DRAFT-execution-routing-by-config 决策第 1 条里的键清单（10 → 11）。
新增：tests/test_routing_frontmatter.py、tests/test_install_routing.py、tests/test_fork_commands_docs.py、openspec/adr/DRAFT-mechanical-commands-run-in-isolated-subagent.md。修改：template/.claude/hooks/model-routing.py（注册表、新子命令）、tests/test_model_routing.py（键数 10 → 11）；install.sh（末尾重渲）；template/.claude/commands/clean-after-merged.md、opsx-sync.md、spec-html.md、claudemd-commit.md、opsx-explore.md；README.md、docs/WORKFLOW_zh.md。不变：主会话里运行的命令一律不写 model / effort；flight / ship 的 pin、resolve 与收口对账不变；merged-cleanup.py 的判定逻辑不变；规划期不变式不变（规划期产出只来自主会话或继承对话的 fork）。用户可见变化：/clean-after-merged 的汇报由子 agent 给出，主会话不再复述。命令跑完后主会话里只多出这段汇报。未验证（不编）：sonnet · low 跑 /clean-after-merged 的质量没有对照数据，合入后观察前几次的汇报；模拟账按官方价算，订阅额度的折算没有公开口径。

Design · 05技术设计

Context

现状（main @ e557aed，C4 / C1 / C2 已合入）：

  • 执行层路由：template/.claude/hooks/model-routing.py 的 REGISTRY 有 5 组 10 个键（flight 5、ship 2、archive.sync、claudemd.evidence、bulk.apply），BUILTIN 给内建默认。effective(root) 合并配置与默认；show / pin / resolve / get 四个子命令。规划期组名（PLANNING_GROUPS）被注册表拒收。
  • 命令 frontmatter：template 下的命令都没有 model / effort / context。tests/test_routing_docs.py::test_planning_docs_carry_no_routing 只检查规划类命令与 skill。
  • 过时建议：opsx-sync.md / spec-html.md / claudemd-commit.md 写着「主会话在 Opus 时先 /model sonnet 再跑，省约 5× token」，opsx-explore.md 也有类似一句。
  • 下发方式：install.sh 的 copy_tree "$TEMPLATE_SRC/.claude" "$TARGET/.claude" "$UPGRADE" … 在升级时整体覆盖 .claude/（只保留 preferences.md、settings.json）。openspec/model-routing.json 不在种子清单里，属于下游自己的数据。
  • /clean-after-merged：命令本身即逻辑，无同名 skill。判定全在 merged-cleanup.py plan / apply。它不问询，只打印计划、执行 safe 档、把 manual 档命令交给用户。已有测试钉住的内容：
  • tests/test_clean_after_merged_docs.py：plan 在 apply 之前、--git-common-dir、git worktree list、回退段、Guardrails 关键词；
  • tests/test_close_reap_docs.py：原因表的 landed / dead-attempt 两行。

官方文档（2026-11-20 读取，Claude Code 2.1.329）： - skills 的 model 字段只对当前这一轮生效，下一条人类消息恢复会话模型；带 context: fork 时它设的是子 agent 的模型。 - prompt-caching 页：命令 frontmatter 换模型就是一次模型切换，下一个请求整段不命中缓存。 - hooks 页：PreModelSwitch 只在 /model、模型选择器、/config、快速模式和 SDK 的 set_model 时运行。 - sub-agents 页：子 agent 的工具集不含 AskUserQuestion；context: fork 的子 agent 看不到对话历史。

在役 ADR：DRAFT-execution-routing-by-config。它规定执行层每个派发用途一个键、值只写模型名，「改注册表要新立 ADR」；规划期只用主会话或继承对话的 fork。

探针与数据

探针脚本在 /tmp/c3probe/（一次性，未入库）。用 Agent SDK 0.2.186 驱动本机 CLI，会话模型为 opus · medium，每组一个独立会话：普通消息 → 被测命令（中间问询一次）→ 普通消息。

| 组 | 命令那一轮的请求 | 首请求缓存 | 回到会话模型 | |---|---|---|---| | 对照（无覆盖） | 4 个，opus · medium | 读 13.3k / 写 7.1k | 全部命中 | | model: sonnet | 4 个，问询前后都是 sonnet | 读 0 / 写 20.2k（整段未命中） | 写 7.5k（重写这一轮的内容） | | effort: low | 4 个，问询前后都是 low | 与对照相同 | 全部命中 | | context: fork + model: haiku | 主会话 0 个；子 agent haiku · low | — | 只多一段命令输出 |

另外两条结果： - PreModelSwitch / PostModelSwitch 日志 hook 在 frontmatter 换模型时没有任何记录；用 SDK 的 set_model 做阳性对照，两者都触发了。 - /probe-fork develop 在子 agent 里拿到了参数 develop。

真实账：扫描 ~/.claude/projects/*/*.jsonl 主会话转录，取用户直接敲的 7 个机械命令那一轮，按官方价计算（Opus 5.5：1h 写缓存 $8、命中 $0.20、输出 $20；Sonnet 5.5 均减半）。

| 方案 | 样本 | 留在会话模型 | 方案成本 | 增减 | |---|---|---|---|---| | 主会话切 sonnet · 缓存热 | 18 | $11.79 | $23.17 | −96% | | 主会话切 sonnet · 缓存凉 | 19 | $52.17 | $27.32 | +48% | | /clean-after-merged 改 fork（sonnet · low） | 31 | $50.80 | $7.92 | +84% |

fork 的模拟口径： - 子 agent 的起始上下文取本机近 3 周 471 个子 agent 转录首请求的中位数，31k； - 每个样本保留实测的请求数、逐请求增量与输出 token； - 主会话那一轮按 0 个请求计。

成本构成：读缓存 23%、写缓存 67%、输出 10%（输出里思考 token 占 47%）。

Goals / Non-Goals

Goals - 主会话里运行的命令不切模型，用机械检查保证。 - 不需要对话历史、也不问询的机械命令以 context: fork 子 agent 运行，模型按路由配置；首个是 /clean-after-merged。 - 下游改了路由配置后，安装与升级不会冲掉 frontmatter 里的值。 - 改正命令里过时的切模型建议。

Non-Goals - 不 fork 其余 6 个机械命令。它们要么问询（verify / archive / sync / spec-html 无参数时问选哪个 change），要么依赖对话（claudemd-commit 取本会话证据，test-tiers 认转录里的人类放行）。 - 不在主会话写 effort（上限约 5%，且没有质量数据）。 - 不改 merged-cleanup.py，不改 flight / ship 的 pin / resolve / 对账。 - 不预估分钟数。

Decisions

理由

缓存热时切过去成本接近翻倍，冷时才省；frontmatter 的切换对 hook 不可见，没有办法按冷热有条件地切。静态的 frontmatter 只能二选一，而真实样本里冷热各占一半。

备选
照原方案 7 个命令都写 model: sonnet

净省 17%，热的一半样本亏一倍 → 否；

只写 effort: low
