## 怎么做（TDD：先跑 verify，看 7 条 xfail）

先做第 1 步，再做第 2 步：安装测试要求模板里的 `clean-after-merged.md` 已经是 fork 形态，否则渲染会以「非 fork 形态」拒绝。

### 1. `clean-after-merged.md`

frontmatter 换成（`description` 原文不动）：

```yaml
---
description: <原文>
context: fork
agent: general-purpose
background: false
model: sonnet
effort: low
---
```

`model` / `effort` 写内建默认。写完在 `template/` 下跑一次 `python3 .claude/hooks/model-routing.py frontmatter --check`，必须 exit 0。

在开头那段说明（「命令本身即逻辑，无同名 skill。」）之后、`**Input**` 之前加一段：

```markdown
**运行方式**：本命令在一个**不继承对话**的子 agent 里运行（frontmatter 的 `context: fork`；模型与 effort 由 `model-routing.py frontmatter` 按路由键 `cleanup.runner` 渲染，不手改）。

- **只认参数**：调用时的参数附在末尾的 `ARGUMENTS:` 行（可为空）；对话里说过的内容这里看不到。
- **不问询**：删不删、带不带 `--force`、用 `-d` 还是 `-D`，全部由脚本判定。
- **最后一条回复就是交给用户的全部汇报**（step 4 的 `done` / `failed` 与 manual 档代码块），主会话不再复述。
```

其余步骤、原因表、回退段、Guardrails、「与已有命令的配合」原样保留。全文不得出现 `AskUserQuestion`。

### 2. `install.sh`：安装与升级末尾重渲

在 `scope-seed` 那段 `if/else/fi` 之后、`# openspec/schemas/：库自有 schema，升级时刷新` 之前插入一段（安装与升级都跑）。要运行**目标里**那份脚本，不是模板源里的：

```bash
# fork 命令路由：.claude/ 刷新会冲掉 fork 命令 frontmatter 里的 model / effort，按目标仓库的 openspec/model-routing.json 写回
if [[ "${PYTHON_OK:-0}" == 1 ]]; then
  if ROUTE_OUT=$(python3 "$TARGET/.claude/hooks/model-routing.py" frontmatter --openspec "$TARGET/openspec" 2>&1); then
    while IFS= read -r line; do [[ -n "$line" ]] && log_info "fork 命令路由：$line"; done <<< "$ROUTE_OUT"
  else
    log_err "fork 命令路由渲染失败：$ROUTE_OUT"
    log_err "修好 openspec/model-routing.json 后在目标仓库根重跑：python3 .claude/hooks/model-routing.py frontmatter"
  fi
else
  log_info "未检测到 python3，fork 命令保持模板默认路由；装好 python3 后在目标仓库根运行：python3 .claude/hooks/model-routing.py frontmatter"
fi
```

失败分支不 `exit`、不改 `rc`：安装照常完成、照常退出 0。`log_err` 写 stderr，测试断言的是 stdout + stderr 合并后的内容。改完再跑一遍 `python3 -m pytest -q tests/test_install.py`，确认原有安装测试不受影响（例如有没有统计 `[err]` 行数的断言）。不改 install 的 `--help` 文本。
